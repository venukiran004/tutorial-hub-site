ANN — Artificial Neural Network (Perceptron → MLP)

Stack layers of weighted sums + non-linearities to approximate almost any function. The foundation everything else (CNN, RNN, Transformers) is built on.

1. Definition

feedforward networkneuronsactivationbackpropagation

An Artificial Neural Network (a.k.a. feedforward network / multilayer perceptron, MLP) is a function built by composing layers of neurons: each neuron computes a weighted sum of its inputs plus a bias, then applies a non-linear activation. Stacking such layers lets the network learn complex, non-linear input→output mappings, with weights fit by gradient descent via backpropagation.

•

2. Intuition & how it works

Stackingnon-linearity is essential

A single neuron is just (logistic-)regression: a=φ(wTx+b). One neuron draws a single boundary. Stacking neurons in layers lets later layers combine earlier ones into curved, composite boundaries — each hidden layer builds higher-level features from the previous layer's outputs.

 x1 ──►(h1)──►            input layer → hidden layer → output
 x2 ──►(h2)──►(o)         each ── is a weight; each (·) applies φ(Σ w·x + b)
 x3 ──►(h3)──►            depth = #layers, width = #neurons per layer

The non-linearity is essential: without it, stacking linear layers W2(W1 x)=(W2W1)x is just one linear layer. The activation is what gives the network its expressive power.

•

3. Mathematical formulation

SigmoidTanhReLUdefaultLeaky ReLU / GELUSoftmax

3.1 Forward pass

For layer ℓ with weights W[ℓ], bias b[ℓ], activation φ:

z[ℓ]=W[ℓ]a[ℓ−1]+b[ℓ],    a[ℓ]=φ(z[ℓ])

with a[0]=x. The output layer uses a task-appropriate activation (softmax for classification, identity for regression) and a matching loss (cross-entropy / MSE).

3.2 Activation functions (the non-linearity)

Activation Formula Notes
Sigmoid 11+e−z (0,1); saturates → vanishing gradients
Tanh ez−e−zez+e−z (−1,1); zero-centered; still saturates
ReLU max(0,z) default for hidden layers; cheap; can "die"
Leaky ReLU / GELU small slope / smooth fix dead ReLUs / used in transformers
Softmax ezi∑j ezj output layer for multi-class probabilities

3.3 Backpropagation — the derivation

Backprop = the chain rule applied layer by layer, reusing computation. Define the error signal δ[ℓ]=∂ L/∂z[ℓ]. Then:

δ[L]=∇a L⊙φ'(z[L]),    δ[ℓ]=(W[ℓ+1]Tδ[ℓ+1])⊙φ'(z[ℓ]) ∂ L∂ W[ℓ]=δ[ℓ]a[ℓ−1]T,    ∂ L∂ b[ℓ]=δ[ℓ]

Then gradient descent: W← W−α ∂ L/∂ W. The genius of backprop is reusing δ[ℓ+1] to get δ[ℓ] — gradients for all parameters in two passes (one forward, one backward), not one pass per parameter.

3.4 Worked backprop (one step, by hand)

Tiny net: input x=1 → hidden $h$ (sigmoid) → output $o$ (sigmoid), MSE loss L=12(o−y)2, target y=0. Weights w1=0.5, w2=0.5, biases 0.

Forward: - z1=0.5·1=0.5 ⇒ h=σ(0.5)=0.6225 - z2=0.5·0.6225=0.3112 ⇒ o=σ(0.3112)=0.5772 - L=12(0.5772)2=0.1666

Backward (using σ'=σ(1−σ)): - δ2=(o−y) o(1−o)=0.5772·0.2440=0.1409 - ∂ L/∂ w2=δ2· h=0.1409·0.6225=0.0877 - δ1=(δ2 w2) h(1−h)=0.0704·0.2350=0.01655 - ∂ L/∂ w1=δ1· x=0.01655

Update (α=0.1): w2←0.5−0.1(0.0877)=0.4912, w1←0.5−0.1(0.01655)=0.4983. Repeat → loss decreases.

3.5 Universal Approximation Theorem

A feedforward network with a single hidden layer and a non-linear activation can approximate any continuous function on a compact domain to arbitrary accuracy — given enough neurons. (It says such a net exists, not that gradient descent will find it, nor how many neurons are needed — depth is usually far more parameter-efficient than width.)

6. Advantages & disadvantages

Advantagesuniversal approximatorDisadvantagesdata- and compute-hungryblack box

Advantages — universal approximator; learns features automatically (no manual engineering); flexible for any task/modality; scales with data and compute; the base for all modern architectures.

Disadvantages — data- and compute-hungry; black box (low interpretability); many hyperparameters + tuning; prone to overfitting; sensitive to init/LR; usually beaten by gradient boosting on small tabular data.

•

7. Complexity & parameter count

A fully-connected layer with nin inputs and nout units has (nin+1)× nout parameters (the $+1$ is the bias). Example: 784→256→10 MLP = (784+1)·256 + (256+1)·10 = 200,960 + 2,570 = 203,530 params. Forward/ backward cost ≈ O(#params) per sample.

11. Interview deep dive

Q2. Explain backpropagationQ4. Why prefer depth over width?exponentiallyQ5. Why does ReLU help vs sigmoid?Q8. Why standardize inputs?Q10. What's the role of the bias?

Q1. Why do we need non-linear activations? Without them, stacked linear layers collapse to a single linear map — no extra expressive power.

Q2. Explain backpropagation. Reverse-mode autodiff: forward pass caches activations, backward pass applies the chain rule layer by layer, reusing the next layer's error signal δ to compute all gradients in two passes.

Q3. What is the universal approximation theorem? A one-hidden-layer net with a non-linear activation can approximate any continuous function on a compact set — existence, not a training guarantee.

Q4. Why prefer depth over width? Deep nets compose features and represent many functions exponentially more parameter-efficiently than a shallow wide net.

Q5. Why does ReLU help vs sigmoid? ReLU doesn't saturate for positive inputs → gradients don't vanish; it's also cheap. Downside: dead neurons (fixed by Leaky ReLU/GELU).

Q6. How are weights initialized and why does it matter? He (ReLU) / Xavier (tanh) keep activation/gradient variance ~constant across layers; bad init causes vanishing/exploding signals.

Q7. Loss for classification vs regression? Cross-entropy (with softmax) vs MSE.

Q8. Why standardize inputs? Keeps the loss surface well-conditioned so gradient descent converges faster and more stably.

Q9. How do you prevent overfitting? Dropout, weight decay (L2), early stopping, data augmentation, more data, smaller model.

Q10. What's the role of the bias? Lets the neuron shift its activation threshold independent of the inputs (like the intercept).

•

12. Common mistakes & best practices

  • ❌ Forgetting to standardize/normalize inputs.
  • ❌ Learning rate too high (divergence) or too low (no learning).
  • ❌ No non-linearity / wrong output activation+loss pairing.
  • ❌ Applying softmax and CrossEntropyLoss (it already includes log-softmax).
  • ✅ Start with Adam(W), ReLU, He init, dropout/weight decay; tune LR first.
  • ✅ Watch train vs val curves; use early stopping.
  • ✅ Overfit a tiny batch first to sanity-check the pipeline.

13. One-paragraph summary

universal approximatorbackpropagationRelated

An ANN composes layers of neurons — each a weighted sum passed through a non-linear activation — so that depth builds hierarchical features and the network becomes a universal approximator. It's trained by backpropagation (the chain rule applied in a backward pass that reuses each layer's error signal δ) plus gradient descent. Activations (ReLU default) provide the essential non-linearity; the main pitfalls are vanishing/exploding gradients (fixed by ReLU/normalization/residuals/good init) and overfitting (fixed by dropout/weight decay/early stopping). It underpins CNNs, RNNs, and Transformers, but is data/compute-hungry and a black box.

1. Definition

convolutional layersfeature mapshierarchy

A CNN is a neural network that uses convolutional layers: small filters (kernels) that slide across the input computing local weighted sums, producing feature maps. By sharing the same filter across all positions and stacking layers, CNNs learn a hierarchy of features (edges → textures → parts → objects) with far fewer parameters than a dense network.

•

2. Intuition & how it works

Local receptive fieldsWeight sharinganywheretranslation equivarianceHierarchy

A dense layer connects every pixel to every neuron — wasteful and not translation-aware. A CNN instead:

  • Local receptive fields: each neuron looks at a small patch (e.g. 3×3), because pixels near each other are related.
  • Weight sharing: the same filter slides across the whole image, so a feature (e.g. a vertical edge) is detected anywhere it appears (translation equivariance) — and it needs only K× K weights, not one per pixel.
  • Hierarchy: early layers detect edges; deeper layers combine them into textures, parts, then whole objects.
input image ─► [Conv+ReLU] ─► [Pool] ─► [Conv+ReLU] ─► [Pool] ─► flatten ─► [FC] ─► class
   (H×W×3)        feature maps      ↓ downsample          deeper features        logits

3.3 Output-size formula

O=⌊W−K+2PS⌋+1

$W$ input size, $K$ kernel, $P$ padding, $S$ stride. Above: $(3-2+0)/1+1=2$. "Same" padding (P=K−12, stride 1) keeps the size unchanged.

3.4 Pooling

Max pooling (2×2, stride 2) takes the max of each window → halves H and W, adds translation invariance and cuts computation. (Average pooling / global average pooling are alternatives; GAP often replaces the final dense layers.)

3.5 Channels & receptive field

A conv layer maps Cin channels → Cout feature maps; each filter is K× K× Cin. Stacking layers grows the receptive field (the input region one output sees), so deep layers "see" larger context.

11. Interview deep dive

Q1. Why CNNs over MLPs for images?Q2. Output-size formula?Q3. What does pooling do?invarianceequivariantQ5. Purpose of 1×1 convolutions?

Q1. Why CNNs over MLPs for images? Weight sharing + local receptive fields → far fewer params and translation equivariance; an MLP ignores spatial structure and explodes in size.

Q2. Output-size formula? O=⌊(W−K+2P)/S⌋+1.

Q3. What does pooling do? Downsamples and adds translation invariance; reduces compute and overfitting (max/avg/global pooling).

Q4. Translation equivariance vs invariance? Convolution is equivariant (shift input → shift feature map); pooling/GAP adds invariance (output unchanged by small shifts).

Q5. Purpose of 1×1 convolutions? Mix channels / change channel count cheaply (bottlenecks, dimensionality reduction) without touching spatial size.

Q6. What problem do residual connections solve? Vanishing gradients in very deep nets — the identity shortcut lets gradients flow, enabling 100+ layer networks.

Q7. How does a CNN see large context with small kernels? Stacking layers grows the receptive field; dilated convolutions expand it without more params.

Q8. How do you train a CNN with little data? Transfer learning — start from an ImageNet-pretrained backbone and fine-tune; heavy augmentation.

Q9. Why BatchNorm in CNNs? Stabilizes/normalizes activations → faster, more stable training, mild regularization.

Q10. Receptive field — why does it matter? It bounds how much of the image each prediction can depend on; too small misses global context.

•

12. Common mistakes & best practices

  • ❌ Flattening images into an MLP (throws away spatial structure).
  • ❌ Forgetting normalization of pixel values / using pretrained stats wrong.
  • ❌ No data augmentation on small datasets.
  • ✅ Use 3×3 convs + BatchNorm + ReLU blocks; pool/stride to downsample.
  • ✅ Transfer-learn from a pretrained backbone when data is limited.
  • ✅ Augment (flips, crops, color jitter); use global average pooling over giant dense heads.

1. Definition

simplerupdateresetno separate cell state

A GRU is a gated recurrent unit that, like the LSTM, controls memory with gates to defeat vanishing gradients — but with a simpler design: only two gates (update and reset) and no separate cell state (the hidden state carries everything). This cuts parameters and compute while retaining most of the LSTM's long-range modeling ability.

•

2. Intuition & how it works

Update gate ztpastnewReset gate rtuseconvex blend

The GRU keeps the LSTM's good idea (gated, additive memory) but merges roles:

  • Update gate zthow much of the past to keep vs how much new to write (it plays the combined role of the LSTM's forget + input gates).
  • Reset gate rthow much of the past to use when forming the new candidate (lets the unit drop irrelevant history).

The new hidden state is a convex blend of the old state and a candidate: ht=(1−zt)ht−1+zth̃t. When zt≈0 it copies the past (long memory); when zt≈1 it overwrites with new content.

•

3. Mathematical formulation

insideoutsidenear-identity, additive
rt = σ(Wr[ht−1,xt]+br) (reset)
zt = σ(Wz[ht−1,xt]+bz) (update)
h̃t = tanh(Wh[ rt⊙ht−1, xt ]+bh) (candidate)
ht = (1−zt)⊙ht−1+zt⊙h̃t (interpolated update)

Note the reset gate multiplies ht−1 inside the candidate, while the update gate blends old and new outside.

3.1 Worked step

Scalars: ht−1=0.5; gates compute zt=0.3 (update), candidate h̃t=0.9:

ht=(1−zt)ht−1+zth̃t=(0.7)(0.5)+(0.3)(0.9)=0.35+0.27=0.62

It kept 70% of the past and mixed in 30% of the new candidate.

3.2 Why it avoids vanishing gradients

The interpolation ht=(1−zt)ht−1+zth̃t gives ∂ ht/∂ ht−1 a term (1−zt) — a near-identity, additive path (like the LSTM cell's forget gate). When the GRU learns zt≈0, the state (and its gradient) passes through essentially unchanged across many steps → long-range memory without the repeated Whh multiplication that kills vanilla RNNs.

•

11. Interview deep dive

Q1. GRU vs LSTM — differences?Q2. What do the two gates do?UpdateresetQ4. When pick GRU over LSTM?Q5. Does GRU have a cell state?

Q1. GRU vs LSTM — differences? GRU has 2 gates (update, reset) and no separate cell state, so ~25% fewer parameters and faster; LSTM has 3 gates + a cell and can edge it out on the longest dependencies. Accuracy is often comparable — benchmark both.

Q2. What do the two gates do? Update $z$ blends old vs new state (forget+input combined); reset $r$ controls how much past enters the candidate.

Q3. How does the GRU avoid vanishing gradients? The update equation ht=(1−zt)ht−1+zth̃t has a near-identity additive path (1−zt); with zt≈0 gradients flow through almost unchanged.

Q4. When pick GRU over LSTM? Smaller datasets, faster iteration/inference, or compute-constrained settings; LSTM for the largest data / very long dependencies.

Q5. Does GRU have a cell state? No — it merges cell and hidden into a single ht.

Q6. Can GRUs be parallelized over time? No — sequential, like all RNNs.

Q7. Reset vs update gate — which gives long memory? The update gate (near 0 → keep the past); the reset gate controls short-term candidate formation.

•

  • ❌ Assuming GRU is always worse/better than LSTM (it's task-dependent — benchmark).
  • ❌ Skipping gradient clipping on long sequences.
  • ❌ Expecting parallel training over time.
  • ✅ Default to GRU for a lighter, faster recurrent baseline; clip gradients.
  • ✅ Use bidirectional only offline; dropout on non-recurrent connections.
  • ✅ For long context, compare against Transformers.

13. One-paragraph summary

updateresetRelated

A GRU is a lighter gated RNN that drops the LSTM's separate cell state and uses just two gates: an update gate $z$ (combining forget + input) and a reset gate $r$. Its hidden state is a gated interpolation ht=(1−zt)ht−1+zth̃t, whose additive near-identity path (1−zt) lets gradients persist across long sequences — solving the vanilla RNN's vanishing-gradient problem like the LSTM does, but with ~25% fewer parameters ($3H(H+D+1)$) and faster training. Accuracy is typically comparable to the LSTM (benchmark both), while both remain sequential and are surpassed by Transformers for long-context tasks.

1. Definition

cell stategatesadditive

An LSTM is a recurrent unit that augments the hidden state with a separate cell state Ct and learns three gates (forget, input, output) that regulate the flow of information into, through, and out of that cell. The gates' multiplicative control plus the cell's additive update create a stable gradient path, so LSTMs capture dependencies hundreds of steps long that vanilla RNNs cannot.

•

2. Intuition & how it works

cell stateForget gateInput gateOutput gateadditionconstant error carousel

Think of the cell state as a conveyor belt running through time, carrying memory with only minor linear interactions. Three gates (each a sigmoid producing values in [0,1]) decide:

  • Forget gatewhat to erase from the belt.
  • Input gatewhat new information to write.
  • Output gatewhat part of the belt to expose as the hidden state. 
   C_{t-1} ──►(× forget)──►(+ input·candidate)──► C_t  (cell state: additive flow)
                  ▲                ▲                │
                f_t              i_t·C̃_t          (× output, via tanh)
                                                    ▼
   h_{t-1},x_t ─► gates ─────────────────────────► h_t  (hidden state / output)

Because the cell is updated by addition (not repeated matrix multiplication), gradients flow through it almost unattenuated — the "constant error carousel."

•

3. Mathematical formulation

near-unchangedforget-gate bias to ~1

Let [ht−1,xt] be the concatenation. The gates and updates:

ft = σ(Wf[ht−1,xt]+bf) (forget)
it = σ(Wi[ht−1,xt]+bi) (input)
C̃t = tanh(WC[ht−1,xt]+bC) (candidate)
Ct = ft⊙Ct−1+it⊙C̃t (cell update)
ot = σ(Wo[ht−1,xt]+bo) (output)
ht = ot⊙tanh(Ct) (hidden state)

3.1 Worked step

Scalars: Ct−1=0.8, and the gates compute ft=0.9, it=0.5, C̃t=0.6, ot=0.8.

  • Ct=ft Ct−1+it C̃t = 0.9(0.8)+0.5(0.6)=0.72+0.30=1.02
  • ht=ottanh(Ct)=0.8·tanh(1.02)=0.8·0.770=0.616

The forget gate kept 90% of old memory and the input gate wrote 30% of new content.

3.2 Why it beats vanishing gradients

In a vanilla RNN, ∂ ht/∂ hk≈ Whht−k → vanishes/explodes. In an LSTM the cell path is ∂ Ct/∂ Ct−1=ft — an element-wise multiply by the forget gate, not a repeated weight matrix. When the model learns ft≈1, gradients pass through near-unchanged over long spans, so it can remember far-back information. (Modern LSTMs initialize the forget-gate bias to ~1 to encourage this from the start.)

1. Definition

loophidden statesame weightsvariable-length

An RNN is a neural network with a loop: at each time step it combines the current input with its previous hidden state to produce a new hidden state, then (optionally) an output. The same weights are reused at every step, so it handles variable-length sequences and shares what it learns across positions in time.

•

2. Intuition & how it works

hidden stateshares one set of weights

Reading a sentence word by word, you keep a running understanding of what you've read so far. The RNN's hidden state is that running summary: each step updates it with the new input.

x1 ─►[RNN]─► x2 ─►[RNN]─► x3 ─►[RNN]─► …      (same cell reused each step)
        │h1          │h2          │h3
   h0 ──┘       h1 ──┘       h2 ──┘            hidden state = memory passed forward

Unrolled over time, it's a very deep network that shares one set of weights across all steps — which is exactly why its gradients misbehave (below).

•

3. Mathematical formulation

unrollingsummedtruncated BPTTproduct of Jacobians< 1vanishes

3.1 The recurrence (forward pass)

ht=tanh(Wxhxt + Whhht−1+bh),    yt=Whyht+by

Whh (the recurrent weight) carries the past forward; the same $W$'s are used at every $t$.

3.2 Worked forward pass

Scalars, Wxh=0.5, Whh=0.5, b=0, tanh, h0=0, inputs xt=1:

  • h1=tanh(0.5·1+0.5·0)=tanh(0.5)=0.462
  • h2=tanh(0.5+0.5·0.462)=tanh(0.731)=0.624
  • h3=tanh(0.5+0.5·0.624)=tanh(0.812)=0.671

The state accumulates information from earlier steps.

3.3 BPTT — Backpropagation Through Time

Train by unrolling the loop and backpropagating across all steps; gradients of the loss flow backward through time and are summed for the shared weights:

∂ L∂ Whh=∑t∂ Lt∂ Whh

For long sequences, truncated BPTT backprops only $k$ steps to bound cost/memory.

3.4 Why gradients vanish/explode (the key derivation)

The gradient of a late loss w.r.t. an early state passes through a product of Jacobians:

∂ ht∂ hk=t∏i=k+1∂ hi∂ hi−1=t∏i=k+1diag(tanh') WhhT

This is essentially Whh raised to the power $(t-k)$:

  • if the largest eigenvalue / spectral norm of Whh is < 1 → the product vanishes exponentially → early inputs have ~no effect (can't learn long-range deps);
  • if > 1 → the product explodes → unstable training, NaNs.

This is the reason vanilla RNNs fail on long sequences — and the motivation for LSTM/GRU (a near-linear, gated memory path that avoids the repeated multiplication).

2.6 Backpropagation

The learning algorithm that adjusts weights using the chain rule:

∂ L∂ w = ∂ L∂ ŷ · ∂ ŷ∂ z · ∂ z∂ w 
Step 1: Forward pass   → compute predictions
Step 2: Compute loss   → how wrong are we?
Step 3: Backward pass  → compute gradients (∂L/∂w for every weight)
Step 4: Update weights → w = w - lr × ∂L/∂w
Step 5: Repeat

Real-Time Analogy: - You throw darts at a target (forward pass) - You see how far off you are (loss) - You figure out which direction to adjust (backpropagation) - You adjust your aim (weight update) - You throw again (next iteration)

2.1 Concept

An RNN processes sequences one element at a time, maintaining a hidden state that acts as memory.

         ┌──────────┐     ┌──────────┐     ┌──────────┐

ht = tanh(Wxh · xt + Whh · ht−1 + bh) yt = Why · ht + by

Where: - xt = input at time step $t$ - ht = hidden state at time $t$ (memory) - Wxh = input-to-hidden weights - Whh = hidden-to-hidden weights (recurrent weights) - Why = hidden-to-output weights

  • If |Whh| > 1: gradients → ∞ (exploding) → training diverges

import torch
import torch.nn as nn

class SimpleRNN(nn.Module):
    def __init__(self, input_size, hidden_size, output_size, num_layers=1):
        super().__init__()
        self.hidden_size = hidden_size
        self.num_layers = num_layers
        
        self.rnn = nn.RNN(
            input_size=input_size,
            hidden_size=hidden_size,
            num_layers=num_layers,
            batch_first=True,       # Input: (batch, seq_len, features)
            dropout=0.2,
        )
        self.fc = nn.Linear(hidden_size, output_size)
    
    def forward(self, x):
        # x shape: (batch_size, seq_len, input_size)
        # h0 shape: (num_layers, batch_size, hidden_size)
        h0 = torch.zeros(self.num_layers, x.size(0), self.hidden_size)
        
        out, hn = self.rnn(x, h0)
        # out shape: (batch_size, seq_len, hidden_size) — all time steps
        # hn shape:  (num_layers, batch_size, hidden_size) — last hidden state
        
        # Use last time step for classification
        out = self.fc(out[:, -1, :])
        return out

# Usage

4. LSTM (Long Short-Term Memory)

3.1 Motivation

LSTM was designed to solve the vanishing gradient problem. It introduces a cell state (long-term memory highway) and gates to control information flow.

3.2 Architecture

                        Cell State (Cₜ)
            ─────────────────────────────────────→
                  ↑ ×          ↑ +           
                  │            │             
            ┌─────┴──┐  ┌─────┴──────┐  ┌───┴────┐
            │ Forget  │  │   Input    │  │ Output│
            │  Gate   │  │   Gate     │  │  Gate │
            │  (fₜ)   │  │ (iₜ)(C̃ₜ)  │  │  (oₜ) │
            └─────────┘  └───────────┘  └────────┘
                 ↑              ↑              ↑
            ─────┴──────────────┴──────────────┴──→ hₜ
                         [hₜ₋₁, xₜ]

3.3 The Three Gates + Cell State

Gate 1: Forget Gate — "What to throw away"

ft = σ(Wf · [ht−1, xt] + bf)

Output: values between 0 (forget completely) and 1 (keep completely)

Real-Time Analogy: You're reading a book. When a new chapter starts, you forget the minor characters from the previous chapter but keep the protagonist's name.

Gate 2: Input Gate — "What new info to store"

it = σ(Wi · [ht−1, xt] + bi) C̃t = tanh(WC · [ht−1, xt] + bC)

Real-Time Analogy: While reading, you decide which new facts from this paragraph are important enough to remember.

Cell State Update

Ct = ft ⊙ Ct−1 + it ⊙ C̃t

This is the key innovation — additive updates instead of multiplicative, which prevents gradient vanishing.

Gate 3: Output Gate — "What to output"

ot = σ(Wo · [ht−1, xt] + bo) ht = ot ⊙ tanh(Ct)

Real-Time Analogy: When someone asks "What happened in the story?", you don't tell them everything you remember — you select relevant information.

3.4 Complete Walkthrough: Sentiment Analysis

Input: "The movie was not good but the acting was excellent"

Token: "The"     → Forget: keep nothing   | Input: neutral   | Cell: [neutral]
Token: "movie"   → Forget: keep context   | Input: topic     | Cell: [movie, neutral]
Token: "was"     → Forget: keep all       | Input: low       | Cell: [movie, neutral]
Token: "not"     → Forget: keep all       | Input: negation  | Cell: [movie, negation]
Token: "good"    → Forget: keep negation  | Input: neg+good  | Cell: [movie, negative]
Token: "but"     → Forget: reduce neg     | Input: contrast  | Cell: [movie, contrast]
Token: "the"     → Forget: keep contrast  | Input: low       | Cell: [movie, contrast]
Token: "acting"  → Forget: keep contrast  | Input: topic2    | Cell: [movie, acting, contrast]
Token: "was"     → Forget: keep all       | Input: low       | Cell: [movie, acting, contrast]
Token: "excellent"→ Forget: reduce neg    | Input: strong+   | Cell: [movie, mixed→positive]

Output Gate → Overall sentiment: slightly positive (mixed review)

3.5 Why LSTM Solves Vanishing Gradient

RNN:   hₜ = tanh(W·hₜ₋₁ + ...)     ← multiplicative, gradients shrink

LSTM:  Cₜ = fₜ⊙Cₜ₋₁ + iₜ⊙C̃ₜ       ← ADDITIVE, gradient flows freely
                                        (like a highway / residual connection)

The cell state acts as a gradient highway — information can flow unchanged across many time steps when ft ≈ 1.

3.6 LSTM in PyTorch

class LSTMClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, output_dim, 
                 num_layers=2, bidirectional=True, dropout=0.3):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(
            input_size=embed_dim,
            hidden_size=hidden_dim,
            num_layers=num_layers,
            batch_first=True,
            bidirectional=bidirectional,
            dropout=dropout,
        )
        direction_factor = 2 if bidirectional else 1
        self.fc = nn.Linear(hidden_dim * direction_factor, output_dim)
        self.dropout = nn.Dropout(dropout)
    
    def forward(self, x):
        # x: (batch, seq_len) — token indices
        embedded = self.dropout(self.embedding(x))    # (batch, seq_len, embed_dim)
        
        output, (hidden, cell) = self.lstm(embedded)
        # output: (batch, seq_len, hidden_dim * num_directions)
        # hidden: (num_layers * num_directions, batch, hidden_dim)
        # cell:   (num_layers * num_directions, batch, hidden_dim)
        
        # For bidirectional: concatenate last forward + first backward hidden
        if self.lstm.bidirectional:
            hidden = torch.cat((hidden[-2], hidden[-1]), dim=1)
        else:
            hidden = hidden[-1]
        
        out = self.fc(self.dropout(hidden))
        return out

# Usage
model = LSTMClassifier(vocab_size=10000, embed_dim=128, hidden_dim=256, output_dim=2)

5. GRU (Gated Recurrent Unit)

4.1 Motivation

GRU simplifies LSTM by merging the forget and input gates into a single update gate and combining cell state + hidden state. Fewer parameters → faster training with similar performance.

4.2 Architecture

         ┌───────────────────────────────────────┐
         │              GRU Cell                 │
         │                                       │
  xₜ ──→ │   ┌────────┐    ┌────────┐            │
  hₜ₋₁→ │   │ Reset  │    │ Update │            │ ──→ hₜ
         │   │ Gate rₜ│    │ Gate zₜ│            │
         │   └────────┘    └────────┘            │
         │        ↓              ↓               │
         │   Candidate h̃ₜ     Interpolation     │
         └───────────────────────────────────────┘

4.3 Mathematical Formulation

Reset Gate — "How much past to forget"

rt = σ(Wr · [ht−1, xt] + br)

Update Gate — "Balance between old and new"

zt = σ(Wz · [ht−1, xt] + bz)

Candidate Hidden State

h̃t = tanh(W · [rt ⊙ ht−1, xt] + b)

Final Hidden State

ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t

4.4 LSTM vs GRU Comparison

LSTM (4 gates equivalent):           GRU (2 gates):
─────────────────────────            ──────────────
Forget gate (fₜ)          ──→       Update gate (zₜ)  
Input gate (iₜ)           ──→       ← merged into zₜ
                                     (1 - zₜ) replaces forget
Cell state (Cₜ)           ──→       ← merged into hₜ
Output gate (oₜ)          ──→       Reset gate (rₜ)

Parameters: 4 × (n² + n·m + n)      Parameters: 3 × (n² + n·m + n)
More expressive                      Faster, less memory
Better for very long sequences       Good for shorter sequences

4.5 Real-Time Example: Weather Prediction

Task: Predict tomorrow's temperature from the last 7 days.

Day 1: 30°C  → GRU sees first temp, hₜ captures "hot"
Day 2: 31°C  → Update gate: "similar, keep old info" (zₜ ≈ low)
Day 3: 29°C  → Update gate: "slight change, update a bit"
Day 4: 15°C  → Update gate: HIGH → "big change, heavily update hₜ"
               Reset gate: HIGH → "forget old warm pattern"
Day 5: 14°C  → Update gate: low → "same cold, keep info"
Day 6: 16°C  → Update gate: low → "still cold"
Day 7: 15°C  → Update gate: low → "stable cold pattern"

Prediction: ~15°C (cold trend learned)

class GRUPredictor(nn.Module):
    def __init__(self, input_size, hidden_size, output_size, num_layers=2):
        super().__init__()
        self.gru = nn.GRU(
            input_size=input_size,
            hidden_size=hidden_size,
            num_layers=num_layers,
            batch_first=True,
            dropout=0.2,
        )
        self.fc = nn.Linear(hidden_size, output_size)
    
    def forward(self, x):

6. Transformer

5.1 Motivation: The Problems with RNN/LSTM/GRU

Problem Detail
Sequential processing Can't parallelize — must process token by token
Long-range dependency Even LSTM struggles with 500+ tokens
Training speed Slow due to sequential nature
Information bottleneck Entire sequence compressed into fixed-size hidden state

Transformer's solution: Process all tokens simultaneously using Self-Attention.

5.2 High-Level Architecture

              ┌────────────────────────────────────┐
              │           TRANSFORMER              │
              │                                    │
  Input ──→   │  ┌──────────┐    ┌──────────┐      │ ──→ Output
              │  │ ENCODER  │    │ DECODER  │      │
              │  │ (×N)     │──→ │ (×N)     │      │
              │  └──────────┘    └──────────┘      │
              └────────────────────────────────────┘

  Encoder-only:  BERT, sentence classification
  Decoder-only:  GPT, text generation
  Encoder-Decoder: T5, translation

5.3 Self-Attention Mechanism — The Core Innovation

Intuition

For every word, ask: "How much should I pay attention to every other word?" 

Sentence: "The animal didn't cross the street because it was too tired"

                                    ↑
                               What does "it" refer to?

Self-Attention scores for "it":
  The      → 0.02
  animal   → 0.85  ← HIGH attention! "it" = "animal"
  didn't   → 0.01
  cross    → 0.03
  the      → 0.01
  street   → 0.05
  because  → 0.01
  it       → 0.01
  was      → 0.01

Mathematical Formulation: Scaled Dot-Product Attention

For each token, create three vectors: - Q (Query): "What am I looking for?" - K (Key): "What do I contain?" - V (Value): "What information do I provide?"

Attention(Q, K, V) = softmax(QKT√dk) V

Where dk = dimension of key vectors (scaling factor prevents large dot products).

Step-by-Step Example

Input: "I love AI" (3 tokens)

Step 1: Embed tokens
  "I"    → x₁ = [0.2, 0.1, 0.5, 0.3]
  "love" → x₂ = [0.8, 0.3, 0.1, 0.7]
  "AI"   → x₃ = [0.1, 0.9, 0.4, 0.2]

Step 2: Create Q, K, V (by multiplying with weight matrices)
  Q₁ = x₁ · Wq,  K₁ = x₁ · Wk,  V₁ = x₁ · Wv
  Q₂ = x₂ · Wq,  K₂ = x₂ · Wk,  V₂ = x₂ · Wv
  Q₃ = x₃ · Wq,  K₃ = x₃ · Wk,  V₃ = x₃ · Wv

Step 3: Compute attention scores (Q·Kᵀ / √dₖ)
  For token "love" (Q₂):
    score(love, I)    = Q₂ · K₁ᵀ / √dₖ = 1.2
    score(love, love) = Q₂ · K₂ᵀ / √dₖ = 3.5
    score(love, AI)   = Q₂ · K₃ᵀ / √dₖ = 2.8

Step 4: Softmax → attention weights
    [1.2, 3.5, 2.8] → softmax → [0.05, 0.62, 0.33]
    "love" pays 62% attention to itself, 33% to "AI", 5% to "I"

Step 5: Weighted sum of Values
    output₂ = 0.05 · V₁ + 0.62 · V₂ + 0.33 · V₃
    → new contextualized representation of "love"

5.4 Multi-Head Attention

Instead of one attention, use multiple heads — each head learns different relationships.

MultiHead(Q,K,V) = Concat(head1, ..., headh) · WO headi = Attention(Q WiQ, K WiK, V WiV) 
Head 1: might learn syntactic relationships (subject-verb)
Head 2: might learn semantic relationships (synonyms)
Head 3: might learn positional relationships (adjacent words)
...
Head 8: might learn coreference (pronouns → nouns)

5.5 Positional Encoding

Since Transformers process all tokens in parallel (no sequential order), we must explicitly inject position information.

PE(pos, 2i) = sin(pos100002i/dmodel) PE(pos, 2i+1) = cos(pos100002i/dmodel) 
class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=5000, dropout=0.1):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len).unsqueeze(1).float()
        div_term = torch.exp(
            torch.arange(0, d_model, 2).float() * -(math.log(10000.0) / d_model)
        )
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)  # (1, max_len, d_model)
        self.register_buffer('pe', pe)
    
    def forward(self, x):
        x = x + self.pe[:, :x.size(1)]
        return self.dropout(x)

5.6 Encoder Block

Input Embeddings + Positional Encoding
         ↓
    ┌────────────────────┐
    │  Multi-Head        │
    │  Self-Attention    │ ← Each token attends to all tokens
    └────────┬───────────┘
         ↓ + residual
    ┌────────────────────┐
    │  Layer Norm        │
    └────────┬───────────┘
         ↓
    ┌────────────────────┐
    │  Feed-Forward      │ ← FFN(x) = ReLU(xW₁ + b₁)W₂ + b₂
    │  Network (FFN)     │
    └────────┬───────────┘
         ↓ + residual
    ┌────────────────────┐
    │  Layer Norm        │
    └────────┬───────────┘
         ↓
    Output (repeat N times)

5.7 Decoder Block

Output Embeddings + Positional Encoding
         ↓
    ┌────────────────────┐
    │  Masked Multi-Head │ ← Can only attend to PREVIOUS tokens
    │  Self-Attention    │   (prevents cheating during generation)
    └────────┬───────────┘
         ↓ + residual + LayerNorm
    ┌────────────────────┐
    │  Cross-Attention   │ ← Q from decoder, K/V from encoder
    │  (Encoder-Decoder) │   (attend to source sentence)
    └────────┬───────────┘
         ↓ + residual + LayerNorm
    ┌────────────────────┐
    │  Feed-Forward      │
    │  Network           │
    └────────┬───────────┘
         ↓ + residual + LayerNorm
    Output (repeat N times)

5.8 Masked Self-Attention (Causal Mask)

In the decoder, future tokens are masked so the model can't "cheat":

                I    love   AI   <end>
    I          ✓     ✗      ✗     ✗
    love       ✓     ✓      ✗     ✗
    AI         ✓     ✓      ✓     ✗
    <end>      ✓     ✓      ✓     ✓

✓ = can attend, ✗ = masked (set to -∞ before softmax)

import math
import torch
import torch.nn as nn

class TransformerClassifier(nn.Module):
    def __init__(self, vocab_size, d_model=512, nhead=8, 
                 num_layers=6, dim_feedforward=2048, 
                 num_classes=2, max_len=512, dropout=0.1):
        super().__init__()
        self.d_model = d_model
        
        # Embedding + Positional Encoding
        self.embedding = nn.Embedding(vocab_size, d_model)
        self.pos_encoding = PositionalEncoding(d_model, max_len, dropout)
        
        # Transformer Encoder
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model,
            nhead=nhead,
            dim_feedforward=dim_feedforward,
            dropout=dropout,
            batch_first=True,
        )
        self.transformer_encoder = nn.TransformerEncoder(
            encoder_layer, num_layers=num_layers
        )
        
        # Classification Head
        self.classifier = nn.Sequential(
            nn.Linear(d_model, d_model // 2),
            nn.ReLU(),
            nn.Dropout(dropout),
            nn.Linear(d_model // 2, num_classes),
        )
    
    def forward(self, src, src_mask=None, src_padding_mask=None):
        # src: (batch, seq_len)
        x = self.embedding(src) * math.sqrt(self.d_model)
        x = self.pos_encoding(x)
        
        x = self.transformer_encoder(
            x, mask=src_mask, src_key_padding_mask=src_padding_mask
        )
        
        # Global average pooling over sequence dimension
        x = x.mean(dim=1)  # (batch, d_model)
        
        return self.classifier(x)

# Usage
model = TransformerClassifier(vocab_size=30000, num_classes=3)
tokens = torch.randint(0, 30000, (16, 128))  # batch=16, seq_len=128

class RNNModel(nn.Module):
    def __init__(self, vocab_size, embed_dim=64, hidden_dim=128, output_dim=2):
        super().__init__()

        self.fc = nn.Linear(hidden_dim, output_dim)
    
    def forward(self, x):
        emb = self.embedding(x)
        _, hn = self.rnn(emb)
        return self.fc(hn[-1])

class LSTMModel(nn.Module):
    def __init__(self, vocab_size, embed_dim=64, hidden_dim=128, output_dim=2):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.lstm = nn.LSTM(embed_dim, hidden_dim, batch_first=True, 
                           num_layers=2, dropout=0.3, bidirectional=True)
        self.fc = nn.Linear(hidden_dim * 2, output_dim)
    
    def forward(self, x):
        emb = self.embedding(x)
        _, (hn, _) = self.lstm(emb)
        hidden = torch.cat((hn[-2], hn[-1]), dim=1)
        return self.fc(hidden)

class GRUModel(nn.Module):
    def __init__(self, vocab_size, embed_dim=64, hidden_dim=128, output_dim=2):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)

    def forward(self, x):
        emb = self.embedding(x)
        _, hn = self.gru(emb)
        hidden = torch.cat((hn[-2], hn[-1]), dim=1)
        return self.fc(hidden)

class TransformerModel(nn.Module):
    def __init__(self, vocab_size, embed_dim=64, nhead=4, num_layers=2, 
                 output_dim=2, max_len=50):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)
        self.pos_enc = nn.Embedding(max_len, embed_dim)
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=embed_dim, nhead=nhead, dim_feedforward=256,
            dropout=0.3, batch_first=True
        )
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers=num_layers)
        self.fc = nn.Linear(embed_dim, output_dim)
    
    def forward(self, x):
        seq_len = x.size(1)
        positions = torch.arange(seq_len, device=x.device).unsqueeze(0)
        emb = self.embedding(x) + self.pos_enc(positions)
        
        # Create padding mask
        padding_mask = (x == 0)
        
        out = self.transformer(emb, src_key_padding_mask=padding_mask)
        out = out.mean(dim=1)  # global average pooling
        return self.fc(out)

# Build vocabularies
def build_vocab_from_sentences(sentences):

    for sent in sentences:
        for word in sent.lower().split():

en_vocab = build_vocab_from_sentences(en_sentences)
fr_vocab = build_vocab_from_sentences(fr_sentences)
fr_idx2word = {v: k for k, v in fr_vocab.items()}

def encode_sentence(sent, vocab, max_len=12, add_sos=False, add_eos=False):
    tokens = []
    if add_sos:
        tokens.append(vocab["<sos>"])
    tokens += [vocab.get(w, vocab["<unk>"]) for w in sent.lower().split()]
    if add_eos:
        tokens.append(vocab["<eos>"])
    tokens += [vocab["<pad>"]] * (max_len - len(tokens))
    return tokens[:max_len]

MAX_LEN = 12

# Prepare data
src_data = torch.tensor([encode_sentence(s, en_vocab, MAX_LEN) for s in en_sentences])
tgt_input = torch.tensor([encode_sentence(s, fr_vocab, MAX_LEN, add_sos=True) for s in fr_sentences])
tgt_output = torch.tensor([encode_sentence(s, fr_vocab, MAX_LEN, add_eos=True) for s in fr_sentences])

# ============================================================
# 2. Transformer Seq2Seq Model
# ============================================================
class TranslationTransformer(nn.Module):
    def __init__(self, src_vocab_size, tgt_vocab_size, d_model=64, nhead=4,
                 num_encoder_layers=2, num_decoder_layers=2, dim_ff=256, 
                 max_len=12, dropout=0.1):
        super().__init__()
        self.d_model = d_model
        
        self.src_embedding = nn.Embedding(src_vocab_size, d_model)
        self.tgt_embedding = nn.Embedding(tgt_vocab_size, d_model)
        self.pos_encoding = nn.Embedding(max_len, d_model)
        
        self.transformer = nn.Transformer(
            d_model=d_model, nhead=nhead,
            num_encoder_layers=num_encoder_layers,
            num_decoder_layers=num_decoder_layers,
            dim_feedforward=dim_ff,
            dropout=dropout,
            batch_first=True,
        )
        
        self.fc_out = nn.Linear(d_model, tgt_vocab_size)
    
    def generate_square_subsequent_mask(self, sz):
        """Causal mask for decoder — prevents attending to future tokens."""
        mask = torch.triu(torch.ones(sz, sz), diagonal=1).bool()
        return mask
    
    def forward(self, src, tgt):
        src_seq_len = src.size(1)
        tgt_seq_len = tgt.size(1)
        
        src_positions = torch.arange(src_seq_len, device=src.device).unsqueeze(0)
        tgt_positions = torch.arange(tgt_seq_len, device=tgt.device).unsqueeze(0)
        
        src_emb = self.src_embedding(src) * math.sqrt(self.d_model) + self.pos_encoding(src_positions)
        tgt_emb = self.tgt_embedding(tgt) * math.sqrt(self.d_model) + self.pos_encoding(tgt_positions)
        
        tgt_mask = self.generate_square_subsequent_mask(tgt_seq_len).to(src.device)
        src_padding_mask = (src == 0)
        tgt_padding_mask = (tgt == 0)
        
        out = self.transformer(
            src_emb, tgt_emb,
            tgt_mask=tgt_mask,
            src_key_padding_mask=src_padding_mask,
            tgt_key_padding_mask=tgt_padding_mask,
        )
        
        return self.fc_out(out)

# ============================================================
# 3. Training
# ============================================================
model = TranslationTransformer(len(en_vocab), len(fr_vocab))
criterion = nn.CrossEntropyLoss(ignore_index=0)  # ignore padding

    loss.backward()
    optimizer.step()
    
    if (epoch + 1) % 50 == 0:
        print(f"  Epoch {epoch+1}/200 | Loss: {loss.item():.4f}")

# 4. Greedy Decoding (Inference)

def translate(model, sentence, en_vocab, fr_vocab, fr_idx2word, max_len=12):
    model.eval()
    src = torch.tensor([encode_sentence(sentence, en_vocab, max_len)]).long()
    
    # Start with <sos>
    tgt_tokens = [fr_vocab["<sos>"]]
    
    for _ in range(max_len - 1):
        tgt = torch.tensor([tgt_tokens + [0] * (max_len - len(tgt_tokens))]).long()
        with torch.no_grad():

        next_token = output[0, len(tgt_tokens) - 1].argmax().item()
        
        if next_token == fr_vocab["<eos>"] or next_token == fr_vocab["<pad>"]:
            break
        tgt_tokens.append(next_token)
    
    return " ".join([fr_idx2word.get(t, "<unk>") for t in tgt_tokens[1:]])

12. Interview Questions & Answers

Fundamentals

•

Q0: What is an ANN and how does it learn?

Forward propagationLoss calculationBackpropagationWeight update2+ hidden layershierarchical features

An ANN is a network of artificial neurons organized in layers (input → hidden → output). It learns through: 1. Forward propagation: Input data flows through the network, producing predictions. 2. Loss calculation: Compare predictions with actual values. 3. Backpropagation: Compute gradients of the loss w.r.t. each weight using the chain rule. 4. Weight update: Adjust weights using an optimizer (e.g., Adam): w = w − η · ∂ L∂ w.

This cycle repeats over many epochs until the model converges.

Q0b: What is the difference between ANN and Deep Learning?

An ANN with 2+ hidden layers is called a "deep" neural network — this is Deep Learning. The "deep" refers to depth (number of layers), not complexity. A shallow ANN (1 hidden layer) can theoretically approximate any function, but deep networks learn hierarchical features more efficiently.

•

Q1: What is a Recurrent Neural Network (RNN)?

An RNN is a neural network designed for sequential data. Unlike feedforward networks, it maintains a hidden state that gets updated at each time step, allowing it to carry information from previous inputs. The same weights are shared across all time steps (weight sharing).

•

Q2: What is the vanishing gradient problem and why does it occur in RNNs?

During backpropagation through time (BPTT), gradients are multiplied by the recurrent weight matrix at each time step. If the largest eigenvalue of this matrix is < 1, gradients exponentially decay (vanish) over long sequences, making it impossible to learn long-range dependencies. For example, in a 100-word sentence, the gradient signal from word 100 reaching word 1 is essentially zero.

•

Q3: What is the exploding gradient problem and how do you fix it?

When the eigenvalues of the weight matrix are > 1, gradients grow exponentially. Solution: Gradient Clipping — cap the gradient norm to a maximum value:

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=5.0)
•

Q4: Explain Backpropagation Through Time (BPTT).

BPTT is the training algorithm for RNNs. The network is "unrolled" across all time steps, creating a deep feedforward-like network. Standard backpropagation is then applied. The challenge is that the depth equals the sequence length, leading to vanishing/exploding gradients. Truncated BPTT limits the number of time steps to backpropagate through.

Q5: How does LSTM solve the vanishing gradient problem?

cell stateadditive

LSTM introduces a cell state (Ct) that uses additive updates instead of multiplicative:

Ct = ft ⊙ Ct−1 + it ⊙ C̃t

This creates a "gradient highway" — when ft ≈ 1, the gradient flows unchanged through many time steps (similar to skip connections in ResNets). The three gates (forget, input, output) learn which information to keep, add, or expose.

Q7: What is the difference between hidden state (ht) and cell state (Ct) in LSTM?

Cell state (Ct)Hidden state (ht)
  • Cell state (Ct)Long-term memory. Flows through the network with minimal transformation. Not directly used for predictions.
  • Hidden state (ht)Short-term memory / working memory. Derived from cell state via the output gate. Used for predictions and passed to the next time step.

Think of it as: Ct = your complete knowledge, ht = what you're actively thinking about.

Q8: What is a Bidirectional LSTM?

both directionsboth past and futureNot suitable

A Bi-LSTM processes the sequence in both directions (left-to-right and right-to-left) and concatenates the outputs:

Forward:  The → cat → sat → on → mat  →  h_fwd
Backward: mat → on → sat → cat → The  →  h_bwd
Output:   [h_fwd ; h_bwd]

This gives each token context from both past and future, improving tasks like NER, POS tagging, and text classification. Not suitable for autoregressive generation (can't look at future tokens).

•

Q9: What is a Peephole LSTM?

A variant where gates can also look at the cell state (not just ht−1 and xt):

ft = σ(Wf · [Ct−1, ht−1, xt] + bf)

This gives gates direct access to the cell state for more precise gating decisions. In practice, performance improvement is marginal.

Q12: Explain the update gate in GRU.

The update gate (zt) controls the balance between the previous hidden state and the new candidate:

ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t
  • zt ≈ 0: Keep the old hidden state (memory preservation)
  • zt ≈ 1: Replace with new candidate (update memory)

This single gate replaces both the forget and input gates of LSTM.

Q13: What is Self-Attention and why is it important?

weighted relationshipdirect connectionsO(1) path lengthFull parallelizationBetter long-range dependency

Self-Attention allows each token in a sequence to compute a weighted relationship with every other token. Unlike RNNs that process sequentially, attention creates direct connections between any two positions, enabling:

  1. O(1) path length between any two tokens (vs O(n) in RNNs)

Q14: Explain Query, Key, and Value in attention.

search engineQuery (Q)Key (K)Value (V)Library analogy

Think of it as a search engine: - Query (Q): "What am I looking for?" — the current token's question - Key (K): "What do I contain?" — each token's label/tag - Value (V): "What information do I provide?" — each token's actual content

The attention score is Q · KT (relevance), and the output is a weighted sum of Values.

Library analogy: You search (Q) for books matching your query. Each book has a title (K) and content (V). You skim titles to find relevant ones, then read their content proportionally to relevance.

•

Q15: Why do we divide by √dk in scaled dot-product attention?

Without scaling, for large dk, the dot products Q · KT become very large, pushing softmax into regions with extremely small gradients (saturation). Dividing by √dk keeps the variance of the dot products at ~1, ensuring well-behaved softmax gradients.

•

Q16: What is Multi-Head Attention?

Instead of one attention operation, we run $h$ parallel attention heads with different learned projections. Each head can attend to different aspects of the input:

Head 1: syntactic (subject-verb agreement)
Head 2: semantic (word meaning relationships)
Head 3: positional (adjacent word patterns)

Results are concatenated and projected: MultiHead = Concat(head1, ..., headh) WO

Q17: What is the purpose of Positional Encoding?

Transformers process all tokens in parallel, so they have no inherent notion of order. Positional encodings (sinusoidal or learned) are added to embeddings to inject sequence order information. Without them, "the cat sat on the mat" and "mat the on sat cat the" would be treated identically.

•

Q18: What is Masked Self-Attention in the Decoder?

The decoder uses a causal mask to prevent attending to future tokens during training. Position $i$ can only attend to positions ≤ i. This is implemented by setting future positions to −∞ before softmax, making their attention weights 0. This ensures the model learns to generate tokens autoregressively.

•

Q19: What is Cross-Attention in the Transformer Decoder?

QueryKey, Value

Cross-attention is how the decoder "looks at" the encoder output: - Query: from decoder (current translation state) - Key, Value: from encoder (source sentence representation)

This allows the decoder to focus on relevant parts of the source sentence when generating each target word. For example, when translating "I love cats" → "J'aime les chats", when generating "chats", cross-attention focuses heavily on "cats".

•

Q20: Explain the Feed-Forward Network in the Transformer.

position-wise FFNnon-linearity

After attention, each position passes through a position-wise FFN (same weights for all positions):

FFN(x) = ReLU(x W1 + b1) W2 + b2

The inner dimension (dff) is typically 4× the model dimension (e.g., 512 → 2048). This adds non-linearity and increases the model's representational capacity. Each position is processed independently.

•

Q21: Why are Residual Connections and Layer Normalization used?

Residual connectionsLayer Normalization
  • Residual connections (x + Sublayer(x)): Enable gradient flow through deep networks (same principle as ResNets). Without them, 12-layer Transformers would be untrainable.
  • Layer NormalizationStabilizes training by normalizing across features (not batch). Reduces internal covariate shift.

Together, they allow training very deep Transformers (100+ layers in some architectures).

Q26: What is Teacher Forcing?

teacher forcingground truthexposure biasScheduled sampling

During training sequence-to-sequence models, teacher forcing feeds the ground truth previous token as input to the decoder, rather than the model's own prediction. This speeds up training but can cause exposure bias — during inference, the model sees its own (possibly wrong) predictions, which it never encountered during training.

Scheduled sampling mitigates this by gradually switching from teacher forcing to model predictions during training.

Q27: What is Attention Score Visualization and why is it useful?

Attention weights can be visualized as heatmaps showing which tokens attend to which. This provides interpretability: - Verify the model learns correct word alignments (translation) - Debug incorrect predictions - Understand what the model "focuses on"

Q29: What is the difference between Pre-LayerNorm and Post-LayerNorm Transformers?

Post-LayerNorm (original):  x → Attention → Add(x) → LayerNorm

Pre-LayerNorm is more stable for deep models and is used in GPT-2, LLaMA, etc.
