Q3. What is TF-IDF and why is it better than raw Bag of Words?

TF-IDFTF(t, d)IDF(t)Why better than BoW

TF-IDF = Term Frequency × Inverse Document Frequency

TF-IDF(t, d) = TF(t, d) × logNDF(t)
  • TF(t, d): How often term $t$ appears in document $d$ (local importance)
  • IDF(t): Penalizes common terms that appear in many documents (global importance)
  • Why better than BoW: BoW treats "the" and "quantum" equally. TF-IDF downweights frequent/common words and highlights discriminative terms.

Q5. What is the "distributional hypothesis" in NLP?

"Words that occur in similar contexts tend to have similar meanings" (Harris, 1954). This is the theoretical foundation for all embedding methods — Word2Vec, GloVe, FastText, and even contextual embeddings. If "cat" and "dog" appear near "pet," "feed," "vet," they get similar vector representations.

Q7. What is subword tokenization and why is it used?

WhyBPEWordPieceSentencePiece

Q9. What is perplexity and why is it used?

Perplexity = 2H(p) = 2−1NN∑i=1log2 p(wi)
  • Measures how "surprised" the model is by test data
  • Lower perplexity = better language model
  • A perplexity of $k$ means the model is as uncertain as choosing uniformly among $k$ words
  • Use: Comparing language models (GPT-2: ~20 perplexity on WikiText)

Q10. Explain BLEU score for machine translation.

BLEU = BP · exp(N∑n=1 wn log pn)
  • pn = modified n-gram precision (clipped to reference count)
  • BP = brevity penalty (penalizes short translations)
  • Typically BLEU-4 (up to 4-grams) with uniform weights wn = 1/4
  • Limitation: Only measures precision, not recall; doesn't handle synonyms; poor correlation with human judgment for single sentences

Q11. What is attention in the context of seq2seq models?

In vanilla seq2seq, the encoder compresses the entire input into a single fixed-size vector — information bottleneck. Attention lets the decoder look back at ALL encoder hidden states and compute a weighted sum:

αij = exp(eij)∑k exp(eik),   ci = ∑j αij hj
  • eij = alignment score between decoder state $i$ and encoder state $j$
  • αij = attention weight (softmax normalized)
  • ci = context vector (weighted sum of encoder states)

Types: Bahdanau (additive), Luong (multiplicative/dot-product)

•

Q12. What are positional encodings and why are they needed?

Sinusoidal (original)Modern alternativesRoPEALiBiLearned

Transformers process all tokens in parallel (no recurrence), so they have no inherent notion of word order. Positional encodings inject position information:

Sinusoidal (original):

PE(pos, 2i) = sin(pos100002i/d),   PE(pos, 2i+1) = cos(pos100002i/d)

Modern alternatives:

Method Key Idea Used By

ALiBi Linear bias added to attention scores BLOOM, MPT
Learned Trainable embedding per position GPT-2, BERT

Q13. Why does the scaled dot-product attention divide by √dk?

Attention(Q, K, V) = softmax(QKT√dk)V

Without scaling, when dk is large, dot products grow large in magnitude → softmax becomes very peaked (near one-hot) → gradients become tiny (vanishing). Dividing by √dk keeps the variance of dot products at ~1, ensuring softmax produces well-distributed attention weights.

•

Q14. Explain multi-head attention.

Instead of one attention function, run $h$ parallel attention heads with different learned projections:

MultiHead(Q, K, V) = Concat(head1, ..., headh)WO headi = Attention(QWiQ, KWiK, VWiV)
  • Each head can attend to different aspects (syntax, semantics, coreference)
  • dk = dmodel/h per head — total compute is same as single-head
  • BERT-base: 12 heads × 64 dims = 768. GPT-3: 96 heads × 128 dims = 12288
•

Q15. What are the types of Transformer models (encoder-only, decoder-only, encoder-decoder)? How does each work and what is each best for?

Encoder-onlyDecoder-onlyEncoder-Decodersemantic search / RAG retrievalcausal masknext-token prediction
Architecture Attention Type Pre-training Best For Examples
Encoder-only Bidirectional (full) MLM (masked language model) Classification, NER, embeddings, retrieval BERT, RoBERTa, DeBERTa, E5/BGE embedders
Decoder-only Causal (left-to-right) Next-token prediction Text generation, chat, reasoning, code GPT-4, LLaMA, Mistral, Claude, Gemini
Encoder-Decoder Enc: bidirectional, Dec: causal + cross-attn Span corruption / denoising Translation, summarization, seq-to-seq T5, FLAN-T5, BART, mBART

How each works (the key difference is the attention mask):

  • Encoder-only — bidirectional, understanding models. Every token attends to all tokens (left and right), so each output embedding is a context-aware representation of the whole input. Trained by masking ~15% of tokens and predicting them (MLM) — this requires seeing both sides, which is why it can't generate left-to-right. You read the input once in parallel; there's no autoregressive loop. → Best when you need to understand or score a fixed input: sentiment/intent classification, NER, sentence embeddings for semantic search / RAG retrieval, re-rankers (cross-encoders). Not for free-form generation.

  • Decoder-only — causal, generative models. A causal mask lets position $i$ attend only to positions ≤ i, so the model never "sees the future." Trained by next-token prediction; at inference it generates autoregressively (feed output back in, one token at a time). This single objective scales beautifully and gives in-context/few-shot learning, which is why all modern LLMs (GPT, LLaMA, Claude) are decoder-only. → Best for anything open-ended: chat, instruction following, reasoning, code generation, agents, summarization-by-prompting.

  • Encoder-decoder — bidirectional read + autoregressive write. The encoder builds a full bidirectional representation of the source; the decoder generates the target autoregressively while cross-attending to the encoder output. Trained by denoising / span corruption (T5). → Best for transduction tasks with a clear input→output mapping where the input should be fully understood before writing: machine translation, summarization, grammar correction, T5-style "text-to-text."

Which to pick: understand/classify/embed a fixed text → encoder-only; generate/chat/reason → decoder-only (the default for general-purpose LLMs); strict source→target transduction → encoder-decoder. Deeper mechanics, training objectives, and worked examples: Transformers InDepth §12.

Q16. What is BERT's pre-training objective?

MLM (Masked Language Model)NSP (Next Sentence Prediction)

BERT uses two objectives: 1. MLM (Masked Language Model): Randomly mask 15% of tokens → predict them. Of the 15%: 80% replaced with [MASK], 10% random token, 10% unchanged. 2. NSP (Next Sentence Prediction): Given sentence A and B, predict if B is the actual next sentence. (Later shown to be less useful — RoBERTa drops it.)

Q18. What is the difference between fine-tuning and feature extraction?

Fine-tuningFeature extraction (frozen)Middle ground
  • Fine-tuning: Update ALL (or most) model weights on task-specific data. Higher performance but needs more data and compute. Risk of catastrophic forgetting.
  • Feature extraction (frozen): Freeze pretrained weights, only train a classification head on top. Faster, needs less data, but may underperform on domain-specific tasks.
  • Middle ground: Freeze bottom layers, fine-tune top layers (gradual unfreezing / discriminative learning rates).

Q19. What is the vanishing gradient problem in RNNs and how do LSTMs solve it?

ProblemLSTM solution

Problem: During backpropagation through time (BPTT), gradients are multiplied by the weight matrix at each step. If the largest eigenvalue < 1, gradients shrink exponentially → model can't learn long-range dependencies.

LSTM solution: Cell state Ct acts as a "conveyor belt" — information flows through with only element-wise operations (no matrix multiply). Gates (forget, input, output) control what to add/remove:

ft = σ(Wf[ht−1, xt] + bf) Ct = ft ⊙ Ct−1 + it ⊙ C̃t

Q21. What is the KV-cache in Transformer inference?

Without cacheWith cacheMemory cost

During autoregressive generation, at step $t$, the keys and values for tokens $1$ to $t-1$ don't change. The KV-cache stores previously computed K and V matrices so they're not recomputed: - Without cache: O(t2) per token → O(n3) total for $n$ tokens - With cache: $O(t)$ per token → O(n2) total - Memory cost: 2 × num_layers × dmodel × seq_len × batch_size × sizeof(dtype) - For LLaMA-70B, KV-cache for 4K context ≈ 2.5 GB per request

•

Q22. Explain Flash Attention.

IO complexityResultFlash Attention 2Flash Attention 3

Standard attention: compute full N × N attention matrix in HBM (slow GPU memory). Flash Attention tiles the computation — loads blocks of Q, K, V into SRAM (fast on-chip memory), computes local attention, and accumulates results: - IO complexity: O(N2 d / M) vs O(N2) HBM accesses (where $M$ = SRAM size) - Result: 2-4× faster, exact (not approximate), enables longer sequences - Flash Attention 2: Better parallelism across sequence length dimension - Flash Attention 3: FP8 support, async prefetching

•

Q24. What is speculative decoding?

SpeedupRejectionRequirement

Use a small "draft" model to generate $k$ tokens quickly, then verify all $k$ in parallel with the large model. If the large model agrees, accept all $k$ tokens in one step: - Speedup: 2-3× with no quality loss (mathematically equivalent to sampling from large model) - Rejection: If draft token $i$ is rejected, resample from adjusted distribution and discard tokens $i+1$ to $k$ - Requirement: Draft model must be much faster (e.g., 7B draft for 70B target)

•

Q25. What is PagedAttention (vLLM)?

KV-cache memory is wasted due to fragmentation (pre-allocated for max_seq_len). PagedAttention borrows OS virtual memory concepts: - Divide KV-cache into fixed-size "pages" (blocks) - Allocate pages on demand as sequence grows - Non-contiguous physical memory mapped via page table - Result: Near-zero waste, 2-4× higher throughput, enables continuous batching

•

Q26. Explain RoPE (Rotary Position Embedding).

AdvantagesUsed by

RoPE encodes position by rotating the query and key vectors in 2D subspaces:

f(x, m) = x · eimθ
  • Position $m$ rotates each pair of dimensions by angle mθi
  • The dot product q · k naturally depends on relative position $m - n$
  • Advantages: Relative position awareness, extrapolates to longer sequences (with NTK-aware scaling), no separate positional embedding to add
  • Used by: LLaMA, Mistral, Qwen, Gemma
•

Q27. What is BPE tokenization and how does it work step by step?

Step 1: Start with character-level vocabulary + end-of-word token
        "low" → ['l', 'o', 'w', '</w>']
        
Step 2: Count all adjacent character pairs in corpus
        ('l', 'o'): 5, ('o', 'w'): 7, ('w', '</w>'): 9, ...

Step 3: Merge the most frequent pair into a new token
        ('w', '</w>') → 'w</w>'

Step 4: Repeat steps 2-3 for desired vocabulary size (e.g., 32K, 50K)

Result: Common words are single tokens, rare words are subword pieces
        "unhappiness" → ["un", "happiness"] (2 tokens)
        "electroencephalogram" → ["electro", "ence", "phal", "ogram"] (4 tokens)

Q31. What is knowledge distillation for NLP models?

DistilBERTTinyBERTUse case

Train a smaller "student" model to mimic a larger "teacher" model:

ℒ = α · ℒCE(y, ŷstudent) + (1−α) · T2 · KL(σ(ztT) | σ(zsT))
  • $T$ = temperature (typically 2-10, softens probabilities)
  • DistilBERT: 6 layers (vs BERT's 12), 97% performance, 60% faster, 40% smaller
  • TinyBERT: Also distills attention matrices and hidden states
  • Use case: Production deployment where latency matters

Q32. Explain the Transformer feed-forward network (FFN).

Each Transformer layer has an FFN applied independently to each position:

FFN(x) = GELU(xW1 + b1)W2 + b2
  • W1 ∈ ℝdmodel × dff, W2 ∈ ℝdff × dmodel
  • Typically dff = 4 × dmodel (BERT: 768→3072→768)
  • Acts as a "memory" — stores factual associations (recent research shows FFN layers store knowledge)
  • SwiGLU (used in LLaMA): SwiGLU(x) = (Swish(xW1) ⊙ xV)W2 — better than GELU
•

Q35. How does T5 unify all NLP tasks?

Q41. How do you calculate the number of parameters in a Transformer?

For a standard Transformer with $L$ layers, $d$ model dimension, $h$ heads, vocab size $V$:

Embedding:        V × d
Per layer:
  - Attention:    4 × d² (Q, K, V projections + output)
  - FFN:          2 × d × 4d = 8d²
  - LayerNorm:    2 × 2d (two norms, each with scale+bias)
Total per layer:  ≈ 12d²
All layers:       12 × L × d²
Output head:      d × V (often tied with embedding)

GPT-3 175B: L=96, d=12288, h=96, V=50257
  Embedding:  50257 × 12288 ≈ 617M
  Layers:     96 × 12 × 12288² ≈ 174B
  Total:      ≈ 175B

Q45. What is the scaling law for LLMs?

Chinchilla-optimalundertrainedovertrained

Kaplan et al. (2020) and Chinchilla (Hoffmann et al., 2022):

L(N, D) ∝ 1N0.076 + 1D0.095
  • $N$ = number of parameters, $D$ = number of training tokens
  • Chinchilla-optimal: D ≈ 20N (train on 20 tokens per parameter)
  • GPT-3 (175B) trained on 300B tokens → undertrained by Chinchilla standards (should be 3.5T)
  • LLaMA-2 70B trained on 2T tokens → overtrained (inference-efficient)

Q46. How does DeBERTa improve over BERT?

Q48. What is prefix caching / prompt caching?

If multiple requests share the same system prompt or prefix:

Request 1: [System prompt] + "What is Python?"    → cache system prompt KV
Request 2: [System prompt] + "What is Java?"      → reuse cached KV, only compute new tokens
Request 3: [System prompt] + "What is Rust?"      → reuse cached KV
  • Saves redundant computation for shared prefixes
  • Implemented in vLLM (automatic prefix caching), SGLang (RadixAttention)
  • Benefit: 2-10× TTFT (time to first token) reduction for shared-prefix workloads

Q56. How does Sentence-BERT create sentence embeddings?

Standard BERT requires cross-encoding (pass both sentences together) — O(n2) for $n$ sentences. Sentence-BERT: 1. Encode each sentence independently through BERT 2. Apply mean pooling over token outputs 3. Train with contrastive loss (cosine similarity + triplet loss) 4. At inference: embed once, compare with cosine similarity → $O(n)$

Applications: Semantic search, clustering, duplicate detection, RAG retrieval

Q77. How does BERTScore work?

Reference: "The cat sat on the mat"
Candidate: "A cat was sitting on a mat"

1. Embed each token through BERT
2. Compute cosine similarity between every pair of (ref_token, cand_token)
3. Precision: For each cand token, max similarity to any ref token → average
4. Recall:    For each ref token, max similarity to any cand token → average
5. F1:        Harmonic mean of precision and recall
  • More robust than ROUGE (handles synonyms, paraphrases)
  • IDF weighting to downweight common words

Q85. What is tokenizer alignment and why does it matter for NER?

# Problem: Subword tokenization breaks word-label alignment
# "Washington" → ["Wash", "##ington"]  but label is B-LOC

# Solution: word_ids() mapping
encoding = tokenizer("Washington went to Washington", return_offsets_mapping=True)
word_ids = encoding.word_ids()
# [None, 0, 0, 1, 2, 3, 3, None]  (None for special tokens)

# Label alignment: assign B-label to first subtoken, I-label to rest
def align_labels(word_ids, labels):
    aligned = []
    prev_word = None
    for word_id in word_ids:
        if word_id is None:
            aligned.append(-100)  # ignore in loss
        elif word_id != prev_word:
            aligned.append(labels[word_id])
        else:
            # If B-X, change to I-X for continuation
            label = labels[word_id]
            aligned.append(label if label == 0 else label + 1)
        prev_word = word_id
    return aligned

Q94. What are adapter layers and how do they enable efficient fine-tuning?

Original Transformer Layer:
  Input → MultiHeadAttn → LayerNorm → FFN → LayerNorm → Output

With Adapters:
  Input → MultiHeadAttn → [Adapter] → LayerNorm → FFN → [Adapter] → LayerNorm → Output

Adapter architecture:
  Input (d) → Down-project (d→r) → NonLinearity → Up-project (r→d) → + Input
  
  Trainable params per layer: 2 × d × r (e.g., 2 × 768 × 64 = 98K vs 7M for full layer)
  • vs LoRA: Adapters add new parameters (sequential), LoRA modifies existing weights (parallel). LoRA has zero inference overhead.
