1. os & sys — System Interface

operating systeminterpreter-level

The os module provides a portable way to interact with the operating system — file/directory operations, environment variables, process management, and path manipulation. The sys module exposes interpreter-level information — command-line arguments, module search path, stdin/stdout, recursion limit, and Python version. Together they are the primary interface between your Python program and the underlying system.

import os
import sys

# ── Environment Variables ────────────────────────────────
os.environ["API_KEY"]             # Get (raises KeyError if missing)
os.environ.get("API_KEY", "")     # Get with default
os.getenv("DEBUG", "false")       # Shorthand for get with default
os.environ["MY_VAR"] = "value"    # Set

# ── File & Directory Operations ──────────────────────────
os.getcwd()                       # Current working directory
os.chdir("/path/to/dir")          # Change directory
os.listdir(".")                   # List directory contents
os.makedirs("a/b/c", exist_ok=True)  # Create nested dirs
os.remove("file.txt")             # Delete file
os.rmdir("empty_dir")             # Delete empty directory
os.rename("old.txt", "new.txt")   # Rename file/dir

# Walk directory tree recursively
for root, dirs, files in os.walk("project/"):
    for file in files:
        full_path = os.path.join(root, file)
        print(full_path)

# ── os.path — Path Manipulation ──────────────────────────
os.path.join("data", "raw", "train.csv")  # OS-appropriate joining
os.path.exists("file.txt")               # Check existence
os.path.isfile("file.txt")               # Is it a file?
os.path.isdir("data/")                   # Is it a directory?
os.path.basename("/path/to/file.txt")    # "file.txt"
os.path.dirname("/path/to/file.txt")     # "/path/to"
os.path.splitext("model.tar.gz")         # ("model.tar", ".gz")
os.path.abspath("relative/path")         # Absolute path
os.path.getsize("file.txt")              # File size in bytes

# NOTE: Prefer pathlib.Path over os.path for new code

# ── sys — Interpreter Interface ──────────────────────────
sys.argv              # Command-line arguments: ['script.py', 'arg1', ...]
sys.path              # Module search paths
sys.version           # Python version string
sys.version_info      # (major=3, minor=12, ...)
sys.platform          # 'linux', 'darwin', 'win32'
sys.maxsize           # Largest int for Py_ssize_t
sys.stdin             # Standard input stream
sys.stdout            # Standard output stream
sys.stderr            # Standard error stream
sys.exit(0)           # Exit with status code (0 = success)
sys.getrecursionlimit()   # Default: 1000
sys.setrecursionlimit(5000)
sys.getsizeof(obj)    # Memory size of object in bytes
sys.modules           # Dict of all loaded modules

2. datetime & time — Date/Time Handling

The datetime module provides classes for representing and manipulating dates, times, and time intervals with microsecond precision. The time module offers lower-level time functions including monotonic clocks, sleep, and epoch-based timestamps. Proper datetime handling is critical for logging, scheduling, time-series data, database timestamps, and timezone-aware applications.

from datetime import datetime, date, time, timedelta, timezone
import time as time_module

# ── Current Date/Time ────────────────────────────────────
now = datetime.now()               # Local time (naive — no timezone!)
utc_now = datetime.now(timezone.utc)  # UTC (timezone-aware) ✅
today = date.today()               # Date only (no time)

print(now)       # 2026-05-30 14:30:25.123456
print(today)     # 2026-05-30

# ── Creating datetime objects ────────────────────────────
dt = datetime(2026, 5, 30, 14, 30, 0)
d = date(2026, 5, 30)
t = time(14, 30, 0)

# ── Accessing components ─────────────────────────────────
now.year, now.month, now.day          # 2026, 5, 30
now.hour, now.minute, now.second      # 14, 30, 25
now.weekday()      # 0=Monday, 6=Sunday
now.isoweekday()   # 1=Monday, 7=Sunday

# ── Formatting (datetime → string) ──────────────────────
now.strftime("%Y-%m-%d %H:%M:%S")    # "2026-05-30 14:30:25"
now.strftime("%d/%m/%Y")              # "30/05/2026"
now.strftime("%B %d, %Y")            # "May 30, 2026"
now.isoformat()                       # "2026-05-30T14:30:25.123456"

# ── Parsing (string → datetime) ─────────────────────────
dt = datetime.strptime("2026-05-30", "%Y-%m-%d")
dt = datetime.fromisoformat("2026-05-30T14:30:00")  # Python 3.7+

# ── Common format codes ──────────────────────────────────
# %Y = 4-digit year    %m = month (01-12)     %d = day (01-31)
# %H = hour 24h        %M = minute            %S = second
# %I = hour 12h        %p = AM/PM             %f = microsecond
# %A = weekday name    %B = month name        %j = day of year
# %a = short weekday   %b = short month       %Z = timezone name

# ── timedelta — Date/Time Arithmetic ────────────────────
delta = timedelta(days=7, hours=3, minutes=30)
next_week = now + timedelta(days=7)
yesterday = now - timedelta(days=1)
diff = datetime(2026, 12, 31) - now
print(diff.days)                       # Days until end of year

# timedelta components
delta.total_seconds()                  # Total seconds as float
delta.days                             # Days component only

# ── Timezone-Aware Datetimes ─────────────────────────────
from datetime import timezone
import zoneinfo  # Python 3.9+

utc = timezone.utc
utc_now = datetime.now(utc)

# Using zoneinfo (Python 3.9+)
ist = zoneinfo.ZoneInfo("Asia/Kolkata")
ist_now = datetime.now(ist)
print(ist_now)   # 2026-05-30 20:00:25+05:30

# Convert between timezones
utc_time = datetime.now(timezone.utc)
ist_time = utc_time.astimezone(ist)

# ── time module (lower-level) ────────────────────────────
time_module.time()                     # Epoch timestamp (float)
time_module.sleep(2.5)                 # Pause execution
time_module.monotonic()                # Monotonic clock (for measuring intervals)
time_module.perf_counter()             # High-res counter (for benchmarks)

# ── Measuring execution time ─────────────────────────────
start = time_module.perf_counter()
# ... code to measure ...
elapsed = time_module.perf_counter() - start
print(f"Took {elapsed:.4f} seconds")

3. json & csv — Data Serialization

JSONCSV

JSON (JavaScript Object Notation) is the universal data interchange format for APIs, configuration files, and structured data. CSV (Comma-Separated Values) is the standard format for tabular data, spreadsheets, and data exports. Python's built-in json and csv modules handle reading, writing, and conversion between these formats and Python data structures.

import json
import csv

# ══════════════════════════════════════════════════════════
# JSON
# ══════════════════════════════════════════════════════════

# ── Dict ↔ JSON string ──────────────────────────────────
data = {"name": "Alice", "scores": [85, 92, 78], "active": True}

json_str = json.dumps(data)                    # Dict → JSON string
json_str = json.dumps(data, indent=2)          # Pretty print
json_str = json.dumps(data, sort_keys=True)    # Sort keys
parsed = json.loads(json_str)                   # JSON string → Dict

# ── Dict ↔ JSON file ────────────────────────────────────
with open("config.json", "w") as f:
    json.dump(data, f, indent=2)               # Dict → file

with open("config.json") as f:
    data = json.load(f)                         # File → Dict

# ── Custom serialization ────────────────────────────────
from datetime import datetime

class DateTimeEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, datetime):
            return obj.isoformat()
        return super().default(obj)

json.dumps({"time": datetime.now()}, cls=DateTimeEncoder)

# ── JSON type mapping ───────────────────────────────────
# Python → JSON:  dict→object, list→array, str→string, 
#                  int/float→number, True→true, False→false, None→null
# JSON → Python:  object→dict, array→list, string→str,
#                  number→int/float, true→True, false→False, null→None

# ══════════════════════════════════════════════════════════
# CSV
# ══════════════════════════════════════════════════════════

# ── Reading CSV ──────────────────────────────────────────
with open("data.csv", newline="") as f:
    reader = csv.reader(f)
    header = next(reader)           # First row as headers
    for row in reader:
        print(row)                  # Each row is a list of strings

# ── Reading CSV as dicts ─────────────────────────────────
with open("data.csv", newline="") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row["name"], row["age"])  # Access by column name

# ── Writing CSV ──────────────────────────────────────────
with open("output.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "age", "city"])        # Header
    writer.writerow(["Alice", 30, "NYC"])            # Single row
    writer.writerows([["Bob", 25, "LA"],             # Multiple rows
                      ["Charlie", 35, "Chicago"]])

# ── Writing CSV from dicts ───────────────────────────────
with open("output.csv", "w", newline="") as f:
    fields = ["name", "age", "city"]
    writer = csv.DictWriter(f, fieldnames=fields)
    writer.writeheader()
    writer.writerow({"name": "Alice", "age": 30, "city": "NYC"})
    writer.writerows([
        {"name": "Bob", "age": 25, "city": "LA"},
        {"name": "Charlie", "age": 35, "city": "Chicago"},
    ])

# ── Custom delimiters ───────────────────────────────────
with open("data.tsv", newline="") as f:
    reader = csv.reader(f, delimiter="\t")

# NOTE: Always use newline="" when opening CSV files to prevent
# issues with line endings on Windows

4. subprocess — Running External Commands

The subprocess module lets you spawn child processes, connect to their input/output/error pipes, and obtain return codes. It replaces older functions like os.system() and os.popen(). Use subprocess.run() for simple command execution and subprocess.Popen() for advanced scenarios like streaming output, piping between processes, or long-running commands.

import subprocess

# ── Basic command execution ──────────────────────────────
result = subprocess.run(
    ["ls", "-la"],                   # Command as list (preferred)
    capture_output=True,             # Capture stdout and stderr
    text=True,                       # Return strings instead of bytes
    check=True,                      # Raise CalledProcessError on failure
    timeout=30,                      # Timeout in seconds
)
print(result.stdout)                  # Command output
print(result.returncode)              # 0 = success

# ── Shell commands (use with caution) ────────────────────
# ❌ Security risk with user input — shell injection!
result = subprocess.run("echo hello", shell=True, capture_output=True, text=True)

# ── Passing input to commands ────────────────────────────
result = subprocess.run(
    ["python", "-c", "x = input(); print(f'Got: {x}')"],
    input="hello\n",
    capture_output=True,
    text=True,
)

# ── Error handling ───────────────────────────────────────
try:
    result = subprocess.run(
        ["some-command"],
        check=True,
        capture_output=True,
        text=True,
    )
except subprocess.CalledProcessError as e:
    print(f"Command failed with code {e.returncode}")
    print(f"stderr: {e.stderr}")
except FileNotFoundError:
    print("Command not found")

# ── Popen — advanced (streaming, pipes) ──────────────────
proc = subprocess.Popen(
    ["tail", "-f", "app.log"],
    stdout=subprocess.PIPE,
    text=True,
)
for line in proc.stdout:
    print(line, end="")             # Stream output line by line

# ── Piping commands ──────────────────────────────────────
ps = subprocess.Popen(["ps", "aux"], stdout=subprocess.PIPE)
grep = subprocess.Popen(
    ["grep", "python"],
    stdin=ps.stdout,
    stdout=subprocess.PIPE,
    text=True,
)
output, _ = grep.communicate()
print(output)
SUBPROCESS BEST PRACTICES:
  ✅ Use list form: ["cmd", "arg1", "arg2"] — no shell injection
  ✅ Always set check=True to catch failures
  ✅ Use capture_output=True and text=True for string output
  ✅ Set timeout to prevent hanging processes
  ❌ Avoid shell=True with user input (security risk)
  ❌ Don't use os.system() — use subprocess instead

5. argparse — Command-Line Arguments

The argparse module creates user-friendly command-line interfaces with automatic help messages, type conversion, default values, required/optional arguments, sub-commands, and input validation. It parses sys.argv and returns a namespace object with the parsed values. Every Python CLI tool and script should use argparse (or the third-party click/typer libraries) instead of manual sys.argv parsing.

import argparse

# ── Basic argument parser ────────────────────────────────
parser = argparse.ArgumentParser(
    description="Train a machine learning model",
    formatter_class=argparse.ArgumentDefaultsHelpFormatter,
)

# Positional argument (required)
parser.add_argument("data_path", help="Path to training data")

# Optional arguments
parser.add_argument("-e", "--epochs", type=int, default=10,
                    help="Number of training epochs")
parser.add_argument("-lr", "--learning-rate", type=float, default=0.001,
                    help="Learning rate")
parser.add_argument("--model", choices=["cnn", "rnn", "transformer"],
                    default="cnn", help="Model architecture")
parser.add_argument("--gpu", action="store_true",
                    help="Use GPU for training")
parser.add_argument("-v", "--verbose", action="count", default=0,
                    help="Increase verbosity (-v, -vv, -vvv)")
parser.add_argument("--tags", nargs="+", help="Experiment tags")

args = parser.parse_args()

print(args.data_path)        # Positional value
print(args.epochs)           # 10 (or user-specified)
print(args.learning_rate)    # 0.001
print(args.gpu)              # False (or True if --gpu passed)

# ── Sub-commands ─────────────────────────────────────────
parser = argparse.ArgumentParser(description="ML Pipeline CLI")
subparsers = parser.add_subparsers(dest="command")

# Train sub-command
train_parser = subparsers.add_parser("train", help="Train a model")
train_parser.add_argument("--config", required=True)

# Evaluate sub-command
eval_parser = subparsers.add_parser("evaluate", help="Evaluate a model")
eval_parser.add_argument("--model-path", required=True)
eval_parser.add_argument("--test-data", required=True)

args = parser.parse_args()
if args.command == "train":
    train(args.config)
elif args.command == "evaluate":
    evaluate(args.model_path, args.test_data)

# Usage:
# python cli.py train --config config.yaml
# python cli.py evaluate --model-path model.pt --test-data test.csv
# python cli.py --help

6. hashlib & secrets — Hashing & Security

The hashlib module provides cryptographic hash functions (MD5, SHA-256, SHA-512, etc.) for generating fixed-size digests from arbitrary data — used for file integrity checks, password hashing, and digital signatures. The secrets module generates cryptographically strong random numbers for security-sensitive operations like tokens, passwords, and session keys. Never use the random module for security purposes.

import hashlib
import secrets
import hmac

# ── Hash functions ───────────────────────────────────────
# SHA-256 (recommended for general use)
h = hashlib.sha256(b"Hello, World!")
print(h.hexdigest())   # "dffd6021bb2bd5b0af676290809ec3a53191dd81c7f70a4b28688a362182986f"
print(h.digest())       # Raw bytes

# Incremental hashing (for large files)
h = hashlib.sha256()
h.update(b"Hello, ")
h.update(b"World!")
print(h.hexdigest())    # Same result as above

# ── File hashing ─────────────────────────────────────────
def hash_file(path, algorithm="sha256", chunk_size=8192):
    """Hash a file without loading it entirely into memory."""
    h = hashlib.new(algorithm)
    with open(path, "rb") as f:
        while chunk := f.read(chunk_size):
            h.update(chunk)
    return h.hexdigest()

# ── Password hashing (use bcrypt/argon2 in production) ──
import hashlib, os
salt = os.urandom(32)
key = hashlib.pbkdf2_hmac("sha256", b"password123", salt, 100_000)

# ── HMAC (Hash-based Message Authentication Code) ────────
message = b"important data"
key = b"secret-key"
mac = hmac.new(key, message, hashlib.sha256).hexdigest()

# Verify (timing-safe comparison)
expected_mac = mac
hmac.compare_digest(mac, expected_mac)   # True — safe against timing attacks

# ══════════════════════════════════════════════════════════
# secrets — Cryptographically Secure Randomness
# ══════════════════════════════════════════════════════════

# ── Random tokens ────────────────────────────────────────
secrets.token_hex(32)         # "a3f2...c8d1" (64-char hex string)
secrets.token_urlsafe(32)     # URL-safe base64 token
secrets.token_bytes(32)       # 32 random bytes

# ── Secure random numbers ───────────────────────────────
secrets.randbelow(100)        # Random int in [0, 100)
secrets.choice(["a", "b", "c"])  # Secure random choice

# ── Generate secure password ────────────────────────────
import string
alphabet = string.ascii_letters + string.digits + "!@#$%"
password = "".join(secrets.choice(alphabet) for _ in range(16))

# ── API key generation ──────────────────────────────────
api_key = secrets.token_urlsafe(32)   # e.g., "dGhpcyBpcyBhIHRlc3Q..."
SECURITY RULES:
  ✅ Use secrets for tokens, passwords, keys (NOT random)
  ✅ Use hashlib.sha256+ for hashing (NOT md5 for security)
  ✅ Use hmac.compare_digest() for timing-safe comparisons
  ✅ Use bcrypt/argon2 for password hashing (not raw SHA)
  ✅ Use PBKDF2 with high iteration count if bcrypt unavailable
  ❌ Never use random module for security
  ❌ Never use MD5/SHA1 for security (collision-vulnerable)
  ❌ Never store passwords in plaintext

7. http & urllib — HTTP Client/Server

Python's standard library includes urllib.request for making HTTP requests and http.server for running simple HTTP servers. While requests (third-party) and httpx are preferred for production use, the stdlib modules are useful when you need zero-dependency HTTP capabilities.

# ── urllib.request — Making HTTP requests ────────────────
import urllib.request
import urllib.parse
import json

# GET request
with urllib.request.urlopen("https://api.example.com/data") as response:
    data = json.loads(response.read().decode())
    print(response.status)   # 200
    print(response.headers)

# GET with query parameters
params = urllib.parse.urlencode({"q": "python", "page": 1})
url = f"https://api.example.com/search?{params}"
with urllib.request.urlopen(url) as response:
    data = json.loads(response.read().decode())

# POST request with JSON body
data = json.dumps({"name": "Alice"}).encode("utf-8")
req = urllib.request.Request(
    "https://api.example.com/users",
    data=data,
    headers={"Content-Type": "application/json"},
    method="POST",
)
with urllib.request.urlopen(req) as response:
    result = json.loads(response.read().decode())

# Error handling
from urllib.error import HTTPError, URLError

try:
    with urllib.request.urlopen(url) as response:
        data = response.read()
except HTTPError as e:
    print(f"HTTP Error {e.code}: {e.reason}")
except URLError as e:
    print(f"Connection failed: {e.reason}")

# ── urllib.parse — URL manipulation ──────────────────────
from urllib.parse import urlparse, urlencode, quote

parsed = urlparse("https://example.com/path?key=value#section")
# ParseResult(scheme='https', netloc='example.com', path='/path', ...)

# URL encoding
encoded = quote("hello world/path")   # "hello%20world%2Fpath"

# ── http.server — Simple HTTP server ────────────────────
# Run from terminal:
# python -m http.server 8000          # Serves current directory

8. sqlite3 — Embedded Database

The sqlite3 module provides an interface to SQLite — a self-contained, serverless, zero-configuration SQL database engine. SQLite stores the entire database in a single file, making it ideal for prototyping, testing, embedded applications, local caching, and small-to-medium datasets. Python includes SQLite support in the standard library, requiring no external installation.

import sqlite3

# ── Connect & create table ───────────────────────────────
conn = sqlite3.connect("app.db")       # File-based
# conn = sqlite3.connect(":memory:")   # In-memory (testing)

cursor = conn.cursor()
cursor.execute("""
    CREATE TABLE IF NOT EXISTS users (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        name TEXT NOT NULL,
        email TEXT UNIQUE,
        age INTEGER,
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    )
""")
conn.commit()

# ── Insert data (ALWAYS use parameterized queries!) ──────
# ✅ SAFE — parameterized (prevents SQL injection)
cursor.execute(
    "INSERT INTO users (name, email, age) VALUES (?, ?, ?)",
    ("Alice", "alice@example.com", 30)
)

# Insert many rows
users = [
    ("Bob", "bob@example.com", 25),
    ("Charlie", "charlie@example.com", 35),
]
cursor.executemany(
    "INSERT INTO users (name, email, age) VALUES (?, ?, ?)", users
)
conn.commit()

# ❌ UNSAFE — string formatting (SQL injection vulnerability!)
# cursor.execute(f"SELECT * FROM users WHERE name = '{user_input}'")

# ── Query data ───────────────────────────────────────────
cursor.execute("SELECT * FROM users WHERE age > ?", (25,))
rows = cursor.fetchall()        # List of tuples
row = cursor.fetchone()         # Single row or None

# Row factory for dict-like access
conn.row_factory = sqlite3.Row
cursor = conn.cursor()
cursor.execute("SELECT * FROM users")
for row in cursor:
    print(row["name"], row["email"])  # Access by column name

# ── Context manager (auto-commit/rollback) ───────────────
with sqlite3.connect("app.db") as conn:
    conn.execute("INSERT INTO users (name, email, age) VALUES (?, ?, ?)",
                 ("Dave", "dave@example.com", 28))
    # Auto-commits on success, auto-rollbacks on exception

# ── Close connection ─────────────────────────────────────
conn.close()

9. unittest.mock — Mocking for Tests

The unittest.mock module provides tools for replacing parts of your system with mock objects during testing. Mocking lets you isolate the code under test by replacing external dependencies (databases, APIs, file systems) with controlled substitutes. Key tools: Mock (general-purpose mock), MagicMock (mock with magic methods), patch (temporarily replace objects), and PropertyMock (mock properties).

from unittest.mock import Mock, MagicMock, patch, PropertyMock

# ── Basic Mock ───────────────────────────────────────────
mock = Mock()
mock.method(1, 2, 3)           # Call mock method (returns Mock)
mock.method.assert_called_once_with(1, 2, 3)   # ✅ Verify call

# Configure return values
mock.predict.return_value = [1, 0, 1]
result = mock.predict([1, 2, 3])    # Returns [1, 0, 1]

# Configure side effects
mock.load.side_effect = FileNotFoundError("Not found")
# mock.load()  # Raises FileNotFoundError

mock.process.side_effect = [1, 2, 3]   # Return different values per call
mock.process()  # 1
mock.process()  # 2
mock.process()  # 3

# ── MagicMock (supports magic methods) ───────────────────
mock = MagicMock()
mock.__len__.return_value = 5
len(mock)  # 5

mock.__iter__.return_value = iter([1, 2, 3])
list(mock)  # [1, 2, 3]

# ── patch — Replace objects during tests ─────────────────
# Temporarily replace 'requests.get' with a mock
@patch("mymodule.requests.get")
def test_fetch_data(mock_get):
    mock_get.return_value.status_code = 200
    mock_get.return_value.json.return_value = {"data": [1, 2, 3]}

    result = fetch_data("https://api.example.com")

    mock_get.assert_called_once_with("https://api.example.com")
    assert result == {"data": [1, 2, 3]}

# patch as context manager
def test_db_call():
    with patch("mymodule.database.query") as mock_query:
        mock_query.return_value = [{"id": 1, "name": "Alice"}]
        result = get_users()
        assert len(result) == 1

# ── Spec — Catch typos in mock attributes ────────────────
class RealService:
    def fetch(self, url): ...

mock = Mock(spec=RealService)
mock.fetch("url")     # ✅ Works — method exists
# mock.ftch("url")    # ❌ AttributeError — typo caught!

# ── Assert call patterns ─────────────────────────────────

15. Interview Deep Dive

parameterized queriesuseddefined

Q1: When would you use the standard library over third-party packages?

A: Use stdlib when: (1) You need zero external dependencies (deployment simplicity). (2) The task is simple enough — json, csv, sqlite3, argparse handle basic needs well. (3) Security-sensitive code where fewer dependencies = smaller attack surface. (4) Scripts/tools that should be portable. Use third-party when: (1) Stdlib is too limited — requests over urllib, pandas over csv, click over argparse. (2) Performance — ujson over json, httpx for async HTTP. (3) Community standards — pytest over unittest, pydantic for validation.

Q2: How do you handle datetime timezone issues?

A: Always use timezone-aware datetimes: datetime.now(timezone.utc), never datetime.now() (naive). Store in UTC, convert to local time only for display. Use zoneinfo.ZoneInfo("Asia/Kolkata") (Python 3.9+) for timezone conversion. Common bugs: comparing naive and aware datetimes raises TypeError. For pre-3.9, use pytz library. In databases: store as UTC ISO 8601 strings or Unix timestamps.

Q3: Explain the difference between subprocess.run() and subprocess.Popen().

A: subprocess.run() is the high-level API — it runs a command, waits for completion, and returns a CompletedProcess with stdout, stderr, and returncode. Use for simple "run and get result" cases. subprocess.Popen() is the low-level API — it starts a process and returns immediately, allowing you to stream output, pipe between processes, and manage the process lifecycle. Use for long-running processes, streaming, or complex pipelines. Always prefer run() unless you need Popen's flexibility.

Q4: How do you prevent SQL injection in Python?

A: Always use parameterized queries (placeholders): cursor.execute("SELECT * FROM users WHERE id = ?", (user_id,)). Never use string formatting: f"SELECT * FROM users WHERE id = {user_id}". The database driver handles escaping and quoting. This applies to sqlite3, psycopg2, mysql-connector, and all DB-API 2.0 compliant drivers. ORMs like SQLAlchemy also parameterize by default.

Q5: When would you use unittest.mock.patch vs dependency injection?

A: patch is for testing existing code that directly imports dependencies — it temporarily replaces the import. Dependency injection (passing dependencies as parameters) is the cleaner design: def fetch(client=requests) — pass a mock client in tests. Prefer DI for new code (more testable, explicit). Use patch for legacy code or when the dependency is deeply embedded. Key: always patch where the object is used, not where it's defined: @patch("mymodule.requests.get"), not @patch("requests.get").

R = TypeVar("R")

def retry(func: Callable[P, R]) -> Callable[P, R]:
    @functools.wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        for attempt in range(3):
            try:
                return func(*args, **kwargs)
            except Exception:
                if attempt == 2:
                    raise
        raise RuntimeError("unreachable")
    return wrapper

# ── error: Incompatible return value type ────────────────
def get_name() -> str:
    return None          # error: Incompatible return type
                         #        (got "None", expected "str")
# Fix:
def get_name() -> str | None:
    return None


# ── error: Item "None" of "Optional[X]" has no attr ─────

    return name.upper()   # error: "None" has no attribute "upper"

# Fix:
def process(name: str | None) -> str:
    if name is None:
        return ""
    return name.upper()   # ✅ mypy knows name is str here (narrowing)

    if x > 0:

    elif x < 0:
        return "negative"
    # error: Missing return statement (what if x == 0?)

# Fix:
def classify(x: int) -> str:
    if x > 0:
        return "positive"
    elif x < 0:
        return "negative"
    return "zero"         # ✅ All paths return

def handle(value: str | int | None) -> str:
    # isinstance narrowing
    if isinstance(value, str):
        return value.upper()          # mypy knows: str
    elif isinstance(value, int):
        return str(value)             # mypy knows: int
    else:
        return "none"                 # mypy knows: None

    # assert narrowing
    assert value is not None
    # mypy knows value is str | int here

    # Assignment narrowing
    if value is None:
        value = "default"
    # mypy knows value is str | int here

10. Interview Questions
•

Q1. What is Ruff and why has it replaced multiple tools?

Answer: Ruff is a Python linter and formatter written in Rust that replaces flake8, isort, pyflakes, pycodestyle, pydocstyle, autoflake, and Black — all in one tool. It's 10-100x faster because it's compiled (Rust vs Python). It supports 800+ lint rules across 50+ plugins and can auto-fix most violations. It's the de facto standard in modern Python projects.

•

Q2. What is pyproject.toml and why is it preferred over setup.py?

Answer: pyproject.toml (PEP 518/621) is the standardized configuration file for Python projects. It replaces setup.py, setup.cfg, and individual tool configs (.flake8, mypy.ini, tox.ini) with a single TOML file. Benefits: declarative (no arbitrary Python execution), standardized (PEP 621), and all tools read from one file. setup.py is legacy and has security risks (arbitrary code execution on install).

•

Q3. Explain Poetry vs pip+requirements.txt. When would you use each?

Answerpip+requirements.txtPoetry

Answer: - pip+requirements.txt: Simple, universal, no lockfile by default. Use for simple scripts, Docker images, or when Poetry overhead isn't justified. - Poetry: Lockfile for reproducible builds, automatic venv management, dependency resolution, and PyPI publishing. Use for applications and libraries. - Key difference: Poetry resolves dependency conflicts automatically and pins all transitive dependencies in poetry.lock.

•

Q4. What is mypy strict mode and when should you use it?

Answer: mypy --strict enables all strict type checking flags: requires type annotations on all functions, disallows Any types, checks untyped code, and more. Use it for production code to catch type errors before runtime. Start with basic mode (check_untyped_defs = true) and gradually increase strictness. Use per-module overrides to relax rules for tests and migrations.

•

Q5. What is the difference between ^1.2.3 and ~1.2.3 in Poetry?

Answer: - ^1.2.3 (caret): >=1.2.3, <2.0.0 — allows minor and patch updates (default) - ~1.2.3 (tilde): >=1.2.3, <1.3.0 — allows only patch updates - Special: ^0.2.3 = >=0.2.3, <0.3.0 (0.x versions are treated as unstable) - Caret is more permissive and is Poetry's default.

•

Q6. How do you set up a new Python project with modern tooling?

Answer: 

# 1. Create project with Poetry
poetry new --src my-project
cd my-project

# 2. Add dependencies
poetry add fastapi uvicorn pydantic

# 5. Create Makefile for common tasks
# make lint, make format, make test, make check

Q7. What is py.typed and PEP 561?

Answer: py.typed is a marker file (empty) placed in a package to declare it ships type information (PEP 561). Without it, mypy ignores the package's type annotations when it's imported by other projects. Libraries should include py.typed and configure it in pyproject.toml as package data.

•

Q8. Explain the purpose of poetry.lock vs requirements.txt.

Answer: - poetry.lock: Auto-generated, pins ALL dependencies (direct + transitive) with exact versions and hashes. Ensures identical environments everywhere. Never edit manually. - requirements.txt: Manual file listing direct dependencies (often with loose versions). pip freeze can pin all, but doesn't track which are direct vs transitive. - Rule: Commit poetry.lock for applications (reproducibility), skip for libraries (let consumers resolve).

•

Q9. What Ruff rules would you enable for a production project?

Answer: E, W, F (basic style), I (imports), N (naming), UP (pyupgrade), B (bugbear — common bugs), A (builtins shadowing), C4 (comprehensions), SIM (simplify), S (security), T20 (no print), RUF (ruff-specific). Ignore E501 (line length handled by formatter) and S101 in tests (assert is fine). Use per-file-ignores for tests and __init__.py.

•

Q10. How does uv compare to pip and when would you use it?

Answer: uv is an ultra-fast Python package manager written in Rust (by the Ruff team). It's 10-100x faster than pip for installs and resolves. It replaces pip, pip-tools, virtualenv, and partially Poetry. Use it when: (1) CI/CD speed matters, (2) large dependency trees, (3) you want pip-compile + pip-sync + venv in one tool. It follows PEP 621 standards.
