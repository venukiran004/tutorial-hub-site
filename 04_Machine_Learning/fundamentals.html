Machine Learning — Fundamentals, Workflow & Core Theory

Scope: What is ML, types of ML, ML pipeline, bias-variance tradeoff, overfitting/underfitting, cross-validation, and the theoretical foundations every ML engineer must master.

1. What is Machine Learning?
•

Formal Definition

Machine LearningTom Mitchell (1997)

Machine Learning is the study of algorithms and statistical models that computer systems use to perform tasks without explicit instructions, relying instead on patterns and inference from data.

Tom Mitchell (1997): "A computer program is said to learn from experience $E$ with respect to some class of tasks $T$ and performance measure $P$, if its performance at tasks in $T$, as measured by $P$, improves with experience $E$."

Why ML Instead of Rules?

When to use ML over explicit rulesWhen NOT to use ML
Traditional Programming:
  Input: DATA + RULES → Output: ANSWERS
  Example: if email contains "buy now" AND sender not in contacts → spam

Machine Learning:
  Input: DATA + ANSWERS → Output: RULES (learned model)
  Example: Model automatically discovers patterns from labeled emails

When to use ML over explicit rules: - Rules are too complex to articulate (image recognition, NLP) - Rules change over time (fraud patterns evolve) - Rules vary per context (personalized recommendations) - Scale of data makes manual rules impractical

When NOT to use ML: - Simple deterministic logic suffices (tax calculation) - No data available or data is too scarce - Explainability is legally mandated and model is opaque - Cost of errors is catastrophic with no recovery mechanism

2. Types of Machine Learning — Deep Dive

Definition: Machine learning algorithms are categorized into four main types based on the nature of the training signal: Supervised Learning (learns from labeled input-output pairs), Unsupervised Learning (discovers hidden patterns in unlabeled data), Semi-Supervised Learning (uses a small amount of labeled data with a large amount of unlabeled data), and Reinforcement Learning (learns by interacting with an environment and receiving reward/penalty signals). The choice of learning type depends on the available data and the problem being solved.

2.3 Semi-Supervised Learning

Uses a small amount of labeled data + a large amount of unlabeled data. This is extremely common in production because labeling is expensive.

Real-World Example:
  - You have 1,000 labeled medical images (expensive radiologist time)
  - You have 100,000 unlabeled medical images (cheap to collect)
  - Semi-supervised learning leverages both

Techniques:
  1. Self-training: Train on labeled → predict unlabeled → add confident predictions → retrain
  2. Label propagation: Spread labels through a similarity graph
  3. Consistency regularization: Model should predict same for augmented versions
  4. Pseudo-labeling: Use model predictions as labels for unlabeled data (used in modern LLMs)
•

2.4 Reinforcement Learning (RL)

Model-FreeModel-BasedOn-PolicyOff-PolicyProduction RL applications

An agent learns to make decisions by performing actions in an environment and receiving rewards.

Agent ──(action)──→ Environment
  ↑                      │
  └──(state, reward)─────┘

Key Concepts:
  State (s):     Current situation
  Action (a):    What the agent does
  Reward (r):    Feedback signal (+/-)
  Policy (π):    Strategy mapping states → actions
  Value (V):     Expected cumulative reward from a state
  Q-value (Q):   Expected cumulative reward for (state, action) pair

Goal: Learn policy π* that maximizes cumulative reward = Σ γᵗ rₜ
  (γ = discount factor, 0 < γ < 1, values future rewards less)
TypeDescriptionExample
Model-FreeLearns from experience directlyQ-Learning, SARSA, PPO
Model-BasedLearns environment model firstAlphaZero, Dreamer
On-PolicyLearns from current policySARSA, A2C
Off-PolicyLearns from any policyQ-Learning, DQN

Production RL applications: Game AI (AlphaGo), robotics, autonomous driving, recommendation systems (explore/exploit), resource allocation, RLHF (Reinforcement Learning from Human Feedback for LLMs).

2.5 Self-Supervised Learning

The model creates its own supervision signal from unlabeled data.

Examples:
  - BERT: Mask 15% of tokens → predict masked tokens
  - GPT:  Predict next token from previous tokens
  - SimCLR: Compare augmented views of same image
  - DINO: Self-distillation with no labels

Why it matters:
  - Powers modern LLMs (GPT, Claude, LLaMA)
  - Learns rich representations from massive unlabeled data
  - Pre-train on unlabeled → fine-tune on small labeled dataset

🔑 Key Insight: ~90% of production ML is supervised learning on tabular data. But self-supervised pre-training is the foundation of the current AI revolution (LLMs, vision transformers). Understanding both paradigms is critical.

Definition: An ML pipeline (or ML workflow) is the end-to-end sequence of steps required to build, train, evaluate, deploy, and monitor a machine learning model. It encompasses everything from problem definition and data collection through feature engineering, model training, evaluation, deployment to production, and ongoing monitoring. A well-structured pipeline ensures reproducibility, scalability, and maintainability of ML systems.

4. Bias-Variance Tradeoff — Mathematical Foundation

Definition: The bias-variance tradeoff is the fundamental tension in machine learning between two sources of prediction error. Bias is the error from overly simplistic assumptions in the model (underfitting — the model cannot capture the true pattern). Variance is the error from the model being too sensitive to fluctuations in the training data (overfitting — the model memorizes noise). A good model minimizes both: low bias (captures the true pattern) and low variance (generalizes to unseen data). The total error is: Error = Bias² + Variance + Irreducible Noise.

•

4.1 Formal Decomposition

For a model $\hat{f}(x)$ trained on data $D$, and the true function $f(x)$ with noise $\epsilon$:

$$y = f(x) + \epsilon, \quad \text{where } \mathbb{E}[\epsilon] = 0, \text{Var}(\epsilon) = \sigma^2$$

The expected prediction error at a point $x_0$:

$$\mathbb{E}\left[(y - \hat{f}(x_0))^2\right] = \underbrace{\text{Bias}^2[\hat{f}(x_0)]}{\text{systematic error}} + \underbrace{\text{Var}[\hat{f}(x_0)]}{\text{sensitivity to training data}} + \underbrace{\sigma^2}_{\text{irreducible noise}}$$

Where:

$$\text{Bias}[\hat{f}(x_0)] = \mathbb{E}[\hat{f}(x_0)] - f(x_0)$$ $$\text{Var}[\hat{f}(x_0)] = \mathbb{E}\left[(\hat{f}(x_0) - \mathbb{E}[\hat{f}(x_0)])^2\right]$$

•

4.2 Derivation of the Decomposition

$$\mathbb{E}[(y - \hat{f})^2] = \mathbb{E}[(f + \epsilon - \hat{f})^2]$$ $$= \mathbb{E}[(f - \hat{f})^2 + 2\epsilon(f - \hat{f}) + \epsilon^2]$$ $$= \mathbb{E}[(f - \hat{f})^2] + 2\mathbb{E}[\epsilon]\mathbb{E}[(f - \hat{f})] + \mathbb{E}[\epsilon^2]$$ $$= \mathbb{E}[(f - \hat{f})^2] + 0 + \sigma^2$$

Now decompose $\mathbb{E}[(f - \hat{f})^2]$:

Let $\bar{f} = \mathbb{E}[\hat{f}]$:

$$\mathbb{E}[(f - \hat{f})^2] = \mathbb{E}[(f - \bar{f} + \bar{f} - \hat{f})^2]$$ $$= (f - \bar{f})^2 + 2(f - \bar{f})\mathbb{E}[\bar{f} - \hat{f}] + \mathbb{E}[(\bar{f} - \hat{f})^2]$$ $$= (f - \bar{f})^2 + 0 + \text{Var}[\hat{f}]$$ $$= \text{Bias}^2 + \text{Var}[\hat{f}]$$

•

"""
INTERPRETING LEARNING CURVES:

HIGH BIAS (underfitting):
  - Both curves converge to a LOW value
  - Gap between them is SMALL
  - Adding more data won't help
  → Fix: More features, more complex model, less regularization

HIGH VARIANCE (overfitting):
  - Train score is HIGH, val score is LOW
  - Large GAP between curves
  - Gap may decrease with more data

import numpy as np
from sklearn.tree import DecisionTreeRegressor

def bias_variance_decomposition(X_train_list, y_train_list, X_test, y_test, model_class, **kwargs):
    """
    Compute bias² and variance empirically over multiple bootstrap samples.
    
    Args:
        X_train_list: list of training X arrays (bootstrap resamples)
        y_train_list: list of training y arrays
        X_test: test features
        y_test: true test labels
        model_class: sklearn model class
        **kwargs: model hyperparameters
    """
    n_bootstraps = len(X_train_list)
    predictions = np.zeros((n_bootstraps, len(X_test)))
    
    for i in range(n_bootstraps):
        model = model_class(**kwargs)
        model.fit(X_train_list[i], y_train_list[i])
        predictions[i] = model.predict(X_test)
    
    # Mean prediction across bootstraps
    mean_pred = predictions.mean(axis=0)
    
    # Bias² = (mean_prediction - true_value)²
    bias_squared = np.mean((mean_pred - y_test) ** 2)
    
    # Variance = average variance of predictions
    variance = np.mean(predictions.var(axis=0))
    
    # Total error
    total_error = np.mean(np.mean((predictions - y_test) ** 2, axis=0))
    
    # Irreducible noise ≈ total - bias² - variance
    noise = total_error - bias_squared - variance
    
    return {
        'bias_squared': bias_squared,
        'variance': variance,
        'noise': noise,
        'total_error': total_error
    }

5. Overfitting & Underfitting — Detection and Solutions

Definition: Overfitting occurs when a model learns the training data too well, including its noise and random fluctuations, resulting in excellent training performance but poor generalization to unseen data. Underfitting occurs when a model is too simple to capture the underlying pattern in the data, performing poorly on both training and test data. The goal is to find the sweet spot — a model complex enough to capture the real pattern but not so complex that it memorizes training noise.

6.1 Why Cross-Validation?

Problem: Single train/test split is UNRELIABLE
  - Different splits give different performance estimates
  - Small test set → high variance in estimate
  - Wastes data (some data never used for training or testing)

Solution: K-Fold CV uses ALL data for both training AND testing (in different folds)
  → More reliable performance estimate
  → Better use of limited data
  → Detects overfitting more reliably

7. Learning Theory Fundamentals
•

7.1 PAC Learning

Probably Approximately Correct (PAC) learning — given enough data, a learning algorithm can find a hypothesis that is approximately correct with high probability.

$$P(\text{error}(h) \leq \epsilon) \geq 1 - \delta$$

Where: - $\epsilon$ = maximum acceptable error (accuracy parameter) - $\delta$ = maximum failure probability (confidence parameter) - Sample complexity: $m \geq \frac{1}{\epsilon}\left(\ln|H| + \ln\frac{1}{\delta}\right)$

Practical implication: More hypotheses (model complexity) → need more data to learn reliably.

•

7.2 VC Dimension

Vapnik-Chervonenkis dimensionStructural Risk Minimization

The Vapnik-Chervonenkis dimension measures the capacity (complexity) of a model — the largest set of points it can shatter (correctly classify in all possible labelings).

ModelVC DimensionInterpretation
Linear classifier in $\mathbb{R}^d$$d + 1$Can shatter $d+1$ points
SVM with RBF kernel$\infty$Can fit any finite dataset (risk of overfitting)
Decision stump2Can shatter 2 points
k-NN (k=1)$\infty$Memorizes all training data

Structural Risk Minimization: Choose model that minimizes:

$$\text{Test Error} \leq \text{Train Error} + \sqrt{\frac{d(\ln(2n/d) + 1) - \ln(\delta/4)}{n}}$$

The second term (complexity penalty) increases with VC dimension $d$ and decreases with sample size $n$.

•

7.3 Empirical Risk Minimization (ERM)

$$\hat{f} = \arg\min_f \frac{1}{n}\sum_{i=1}^{n} L(y_i, f(x_i))$$

We minimize the training loss (empirical risk) as a proxy for the true risk:

$$R(f) = \mathbb{E}_{(x,y) \sim P}[L(y, f(x))]$$

The central challenge of ML: We want to minimize $R(f)$ but only have access to finite samples. ERM + regularization + cross-validation is the standard approach.

9. Data Leakage — The Silent Killer
•

9.1 What is Data Leakage?

Using information during training that would NOT be available at prediction time. It creates artificially high metrics that collapse in production.

•

9.2 Types of Leakage

TYPE 1: TARGET LEAKAGE (Feature from the future)
  Example: Predicting churn using "cancellation_date" feature
  Fix: Audit every feature — "Would I know this BEFORE the prediction?"

TYPE 2: TRAIN-TEST CONTAMINATION
  Example: Fitting StandardScaler on full data, then splitting
  Fix: Fit transforms on training data ONLY

TYPE 3: TEMPORAL LEAKAGE
  Example: Random split for time series data → future in training
  Fix: Time-based split, never random for temporal data

TYPE 4: GROUP LEAKAGE
  Example: Same patient in train and test for medical imaging
  Fix: GroupKFold, split by group ID

TYPE 5: PREPROCESSING LEAKAGE
  Example: SMOTE/oversampling before train/test split
  Fix: Apply SMOTE inside CV folds only
•

9.3 How to Detect Leakage

# Red flags for data leakage:
# 1. TOO GOOD performance (>99% accuracy on real-world problem)
# 2. Feature importance shows unexpected features at top
# 3. Performance drops dramatically in production
# 4. Adding "impossible" features dramatically improves score

# Systematic check:
for feature in X.columns:
    model = LogisticRegression()
    score = cross_val_score(model, X[[feature]], y, cv=5, scoring='roc_auc').mean()
    if score > 0.95:
        print(f"⚠️ SUSPICIOUS: {feature} has AUC={score:.3f} — possible leakage!")
•

9.4 Prevention Checklist

✅ Always use Pipeline (scaler + model) for CV
✅ Temporal data → time-based split
✅ Grouped data → GroupKFold
✅ Audit every feature: "Available at prediction time?"
✅ SMOTE inside CV folds only

# Population Stability Index (PSI)
def calculate_psi(expected, actual, bins=10):
    """Measures distribution shift between expected and actual."""
    expected_pct = np.histogram(expected, bins=bins)[0] / len(expected)
    actual_pct = np.histogram(actual, bins=bins)[0] / len(actual)
    
    # Avoid division by zero
    expected_pct = np.clip(expected_pct, 0.001, None)
    actual_pct = np.clip(actual_pct, 0.001, None)
    
    psi = np.sum((actual_pct - expected_pct) * np.log(actual_pct / expected_pct))
    return psi

# PSI interpretation:
# < 0.1:  No significant shift
# 0.1-0.2: Moderate shift — investigate
# > 0.2:  Significant shift — retrain model!

12. Curse of Dimensionality

As the number of features (dimensions) increases, the data becomes increasingly sparse in the feature space. In high dimensions: (1) distances between points converge (nearest and farthest neighbors become equally far), (2) volume of data needed to maintain density grows exponentially, (3) models overfit more easily because they have many parameters relative to samples. Rule of thumb: need ~10× more data for each added dimension.

Effects on ML:
  KNN: Distance metrics become meaningless in > ~20 dimensions
  Tree models: More spurious splits on irrelevant features
  Linear models: Multicollinearity increases
  Clustering: All points appear equidistant

Solutions:
  - Feature selection (remove irrelevant features)
  - Dimensionality reduction (PCA, autoencoders)
  - Regularization (L1/L2 to penalize complexity)
  - Domain knowledge (engineer fewer, better features)
  - More data (if available)

14. Generative vs Discriminative Models

Discriminative models learn the decision boundary $P(y|x)$ directly — they model how to classify given features. Generative models learn the joint distribution $P(x, y)$ or $P(x)$ — they model how the data was generated. Discriminative models typically have higher classification accuracy; generative models can generate new data and handle missing features.

Discriminative:                    Generative:
  Logistic Regression               Naive Bayes
  SVM                               Gaussian Mixture Models
  Decision Trees / RF / XGBoost     Hidden Markov Models
  Neural Networks (most)            VAEs, GANs, Diffusion Models
  CRF                               Bayesian Networks

Key insight:
  Discriminative: P(y|x) — "given this email, is it spam?"
  Generative:     P(x,y) → P(y|x) via Bayes — "what does spam email look like?"
  
  Andrew Ng's rule: Discriminative reaches lower asymptotic error;
  Generative converges faster with less data.
15. Inductive Bias

Definition: Inductive bias is the set of assumptions a learning algorithm uses to predict outputs for inputs it has not yet encountered. Without inductive bias, a learner cannot generalize beyond the exact training examples — this is the core insight of the No Free Lunch theorem.

Every ML algorithm embeds assumptions about the data. These assumptions are what make generalization possible — and also what cause failures when the assumptions are wrong.

15.2 Why Inductive Bias Matters

Without bias (NFL Theorem):
  - No algorithm can generalize to unseen data
  - Every algorithm performs equally well/poorly averaged over ALL possible problems
  - We NEED assumptions to learn

With the RIGHT bias:
  - Model generalizes well on problems matching its assumptions
  - Learning is efficient (less data needed)
  - Convergence is faster

With the WRONG bias:
  - Model systematically fails (high bias error)
  - No amount of data will fix fundamental assumption mismatch
  - Example: Using linear regression for XOR problem
•

  - Features are independent?     → Naive Bayes
  - Smooth, local patterns?       → KNN, kernel methods
  - Unknown structure?            → Ensemble methods (combine biases)

18.4 SMOTE — How It Works

Synthetic Minority Over-sampling Technique creates synthetic minority samples by interpolating between existing minority instances.

$$x_{\text{new}} = x_i + \lambda \cdot (x_{\text{nn}} - x_i)$$

Where: - $x_i$ = a minority class instance - $x_{\text{nn}}$ = one of $x_i$'s k-nearest minority neighbors - $\lambda$ = random number in $[0, 1]$

Visualization:
  x_i ●─────────────────● x_nn
                 ▲
            x_new (random point on the line)

Steps:
  1. Pick a minority instance x_i
  2. Find its k nearest minority neighbors
  3. Randomly select one neighbor x_nn
  4. Create synthetic point between x_i and x_nn
  5. Repeat until desired balance is achieved
•

❌ DO NOT use these metrics alone:
  - Accuracy (misleading — majority class dominates)
  - AUC-ROC (can be overly optimistic with severe imbalance)

✅ USE these metrics:

  - Precision-Recall AUC (AUC-PR) — best for severe imbalance

  - Precision (when false positives are costly)
  - Matthews Correlation Coefficient (MCC) — balanced metric
  - Confusion Matrix — always inspect raw numbers

  - Mild imbalance (1:5 to 1:20):    class_weight='balanced' often sufficient
  - Moderate imbalance (1:20 to 1:100): SMOTE + proper evaluation

18.7 Cost-Sensitive Learning

Instead of treating all errors equally, assign different costs:

                    Predicted
                    Neg    Pos
  Actual  Neg    [  0   |  C_FP  ]     C_FP = Cost of false positive
          Pos    [ C_FN |   0    ]     C_FN = Cost of false negative

Example — Fraud Detection:
  C_FP = $10 (investigating a legitimate transaction)
  C_FN = $10,000 (missing a fraudulent transaction)
  → C_FN / C_FP = 1000 → weight minority class 1000x more

Implementation:
  - sklearn: class_weight={0: 1, 1: 1000}
  - XGBoost: scale_pos_weight=1000
  - Custom loss functions in deep learning

20. Bayesian Machine Learning
•

Bayesian vs Frequentist

Frequentist:  Parameters are fixed but unknown. Data is random.
              Point estimate: w* = argmax P(D|w)  (MLE)

Bayesian:     Parameters are random variables with distributions.
              Posterior:  P(w|D) = P(D|w) · P(w) / P(D)   (Bayes' theorem)
              Prior P(w): belief before seeing data
              Likelihood P(D|w): how well parameters explain data
              Posterior P(w|D): updated belief after seeing data
              Evidence P(D): normalizing constant (often intractable)

Key advantage: Bayesian gives uncertainty estimates, not just point predictions.
•

Bayesian Linear Regression

Model:      y = wᵀx + ε,   ε ~ N(0, σ²)
Prior:      w ~ N(0, Σ₀)           ← regularization built-in
Likelihood: P(y|X,w) = N(Xw, σ²I)

Posterior (conjugate → closed-form):
    P(w|X,y) = N(μ_post, Σ_post)
    Σ_post = (Σ₀⁻¹ + σ⁻² XᵀX)⁻¹
    μ_post = Σ_post (σ⁻² Xᵀy)

Prediction: P(y*|x*,D) = N(μ_postᵀ x*, x*ᵀ Σ_post x* + σ²)
    → Mean prediction + uncertainty (variance) for free!

Connection to Ridge: MAP estimate with Gaussian prior = Ridge regression.
    L2 penalty λ‖w‖² corresponds to prior variance σ²/λ.
•

Bayesian Neural Networks (BNNs)

Instead of point weights w*, maintain distributions over weights:
    P(w|D) — posterior over ALL network weights

Prediction:
    P(y*|x*,D) = ∫ P(y*|x*,w) P(w|D) dw    (marginalize over weights)

Uncertainty types:
    Epistemic (model) uncertainty: Reducible with more data.
        → Captured by posterior variance over weights.
    Aleatoric (data) uncertainty: Irreducible noise in the data.
        → Captured by predicting both mean and variance.

Practical approximations:
    • MC Dropout: Use dropout at test time, run N forward passes
      → Mean = prediction, Variance = uncertainty
    • Deep Ensembles: Train N models, use disagreement as uncertainty
    • Variational Inference: Learn approximate posterior (next section)
•

Variational Inference (VI)

Problem: P(w|D) = P(D|w)P(w)/P(D) is intractable (P(D) requires integral)

Solution: Approximate P(w|D) with a simpler distribution q(w;θ)
by minimizing KL divergence:

    KL(q(w;θ) || P(w|D)) = ∫ q(w;θ) log [q(w;θ) / P(w|D)] dw

Equivalently, maximize the ELBO (Evidence Lower Bound):
    ELBO(θ) = E_q[log P(D|w)] - KL(q(w;θ) || P(w))
              \_______________/   \_________________/
                data fit           regularization

Mean-field approximation:
    q(w;θ) = ∏_i q(wᵢ; μᵢ, σᵢ)    (each weight has independent Gaussian)
    Parameters: θ = {μᵢ, σᵢ} for each weight
    Trained with reparameterization trick: w = μ + σ ⊙ ε, ε ~ N(0,1)
•

MCMC Methods

Markov Chain Monte Carlo — sample from posterior directly.

Metropolis-Hastings:
    1. Propose w' ~ Q(w'|w_t)       (e.g., Gaussian centered at w_t)
    2. Accept with probability min(1, P(w'|D)/P(w_t|D) · Q(w_t|w')/Q(w'|w_t))
    3. If accepted: w_{t+1} = w', else w_{t+1} = w_t
    (+) Simple, general
    (-) Slow for high dimensions, random walk behavior

Hamiltonian Monte Carlo (HMC):
    • Uses gradient information to make informed proposals
    • Simulates Hamiltonian dynamics: position = parameters, momentum = auxiliary
    • Much more efficient than MH for high-dimensional problems
    • Used in Stan, NumPyro, PyMC

21. Online Learning
•

Online vs Batch Learning

Batch Learning:
    • Train on entire dataset at once
    • Retrain from scratch when new data arrives
    • Suitable when data fits in memory and distribution is static

Online Learning:
    • Update model one sample (or mini-batch) at a time
    • Never stores full dataset — process and discard
    • Adapts to changing distributions (concept drift)
    • Required when: data is streaming, too large for memory, or non-stationary

Protocol:
    for t = 1, 2, ...:
        1. Receive instance x_t
        2. Predict ŷ_t
        3. Receive true label y_t
        4. Update model based on loss(y_t, ŷ_t)
•

Regret Bounds

Regret = Σ_{t=1}^{T} loss(h_t, z_t) - min_h Σ_{t=1}^{T} loss(h, z_t)

= (Cumulative loss of online learner) - (Loss of best fixed model in hindsight)

No-regret algorithm: Regret / T → 0 as T → ∞
    • Online Gradient Descent: Regret = O(√T)
    • Exponential Weights (Hedge): Regret = O(√(T log N)) for N experts
    • AdaGrad: Adapts to geometry, O(√T) but often better in practice
•

Concept Drift

Types of Drift:
    Sudden:      P(y|x) changes abruptly (e.g., policy change)
    Gradual:     Old and new concepts mix over transition period
    Incremental: Slow, continuous change (e.g., user preferences)
    Recurring:   Patterns repeat (e.g., seasonal effects)

Detection Methods:
    ADWIN (Adaptive Windowing):
        Maintains variable-length window, splits when distributions differ.
        Automatically shrinks window when drift detected.

    DDM (Drift Detection Method):
        Monitors error rate + std. Triggers warning/drift based on thresholds.
        Warning: error > p_min + 2σ    Drift: error > p_min + 3σ

    KSWIN (Kolmogorov-Smirnov Windowed):
        Uses KS test to compare distributions of two sliding windows.
        Non-parametric, works for any distribution.

    Page-Hinkley Test:
        Monitors cumulative sum of differences from running mean.
•

┌───────────────────────────────────────────────────┐
│              Central Server                      │
│   ┌──────────────────────────────────────┐  │
│   │  1. Send global model to clients   │  │

         │          │          │
    ┌────┴───┐  ┌───┴───┐  ┌───┴───┐

    │Local   │  │Local   │  │Local   │
    │Data    │  │Data    │  │Data    │
    └────────┘  └────────┘  └────────┘

Key principle: Data never leaves the client device.
Only model updates (gradients or weights) are communicated.
•

FedAvg Algorithm

Federated Averaging (McMahan et al., 2017):

Server:
    Initialize global model w₀
    for each round t = 1, 2, ...:
        Select subset S_t of K clients (e.g., 10% of total)
        Send w_t to each client in S_t
        Receive updated models {w_t^k} from clients
        Aggregate: w_{t+1} = Σ_k (n_k/n) · w_t^k
                   where n_k = samples on client k, n = total samples

Client k:
    Receive w_t from server
    Initialize local model: w ← w_t
    for E local epochs:
        for each mini-batch b from local data:
            w ← w - η∇L(w; b)      ← standard SGD
    Send w back to server

Hyperparameters:
    E = local epochs (more → less communication, risk of divergence)
    B = local batch size
    K = fraction of clients per round
    η = local learning rate
•

Communication Efficiency

Problem: Sending full model updates is expensive (millions of params).

Solutions:
    Gradient compression: Quantize gradients (e.g., 32-bit → 1-bit)
    Sparse updates: Send only top-k% largest gradient components
    Knowledge distillation: Share predictions on public data, not weights
    FedProx: Add proximal term to limit local divergence
        L_local = L(w; D_k) + (μ/2)‖w - w_t‖²
•

Privacy Mechanisms

Differential Privacy (DP):
    Add calibrated noise to gradients before sending:
    g̃ = clip(g, C) + N(0, σ²C²I)
    Provides (ε, δ)-DP guarantees.
    Trade-off: More noise → more privacy → less accuracy.

Secure Aggregation:
    Clients encrypt their updates.
    Server computes aggregate WITHOUT seeing individual updates.
    Uses secret sharing or homomorphic encryption.

Threat Model:
    Honest-but-curious server: follows protocol but tries to infer data
    Malicious clients: can send poisoned updates (Byzantine attacks)
    Gradient inversion attacks: reconstruct training data from gradients
•

Handling Non-IID Data

Problem: Client data is rarely IID in practice.
    • Label skew: Client A has mostly cats, Client B has mostly dogs
    • Feature skew: Different image quality across devices
    • Quantity skew: Some clients have 10x more data

Solutions:
    FedProx: Proximal term prevents excessive local drift
    SCAFFOLD: Correct client drift with control variates
    Per-FedAvg: Personalization via meta-learning (MAML-style)
    Clustered FL: Group similar clients, train separate models
    Data sharing: Share small public dataset to reduce divergence

23. Optimization & Gradient Descent

How models actually learn: minimize a loss function $J(\theta)$ by iteratively adjusting parameters in the direction that reduces it. This is the engine under linear/ logistic regression, SVMs, gradient boosting, and all of deep learning.

•

23.1 Gradient descent — the core idea

downhillincreaselearning rate

Take steps downhill on the loss surface, proportional to the negative gradient:

$$\theta \leftarrow \theta - \alpha\,\nabla_\theta J(\theta)$$

  • $\nabla_\theta J$ points in the direction of steepest increase; we go the opposite way.
  • $\alpha$ is the learning rate (step size) — the single most important knob.
  • Convergence when the gradient ≈ 0 (a minimum, or a saddle point).
•

  • Saddle pointsflat in some directions; the real obstacle in deep nets (momentum/ noise helps escape).
  • Vanishing / exploding gradientsdeep models; fixed by normalization, residual connections, gradient clipping, good init (see Deep Learning).
  • Ill-conditioningelongated loss surfaces slow GD; feature scaling and adaptive optimizers help.
•

23.6 Convexity

ConvexNon-convexWhy scale features before GD?
  • Convex loss (linear/ridge/lasso/logistic/SVM) → a single global minimum; GD is guaranteed to find it. This is why these models are reliable.
  • Non-convex loss (neural nets, GBM leaf values) → many minima/saddles; GD finds a good local optimum, sensitive to initialization and LR.

Why scale features before GD? Unscaled features make the loss surface elongated/ ill-conditioned, so GD zig-zags and converges slowly (closed-form OLS is scale-immune, but GD is not).

Q1: Explain the bias-variance tradeoff with a real-world example.

linear modelpolynomial degree-20 model

A: Consider predicting house prices. A linear model (high bias) assumes prices increase linearly with size — it systematically misses curved relationships (e.g., diminishing returns for very large homes). A polynomial degree-20 model (high variance) fits every wiggle in training data, including noise — it gives wildly different predictions on new data.

The math: $\text{Error} = \text{Bias}^2 + \text{Variance} + \sigma^2$. Bias² is the systematic error from model assumptions; variance is sensitivity to training set; $\sigma^2$ is irreducible noise. Methods like Random Forest (averaging reduces variance) and boosting (sequentially reduces bias) help manage this tradeoff.

•

Q2: What is data leakage? Give 3 examples from production.

Target leakagePreprocessing leakageTemporal leakagePrevention

A: 1. Target leakage: A churn model included "support ticket about cancellation" as a feature — this happens AFTER the churn decision, not before. Model had 99% AUC in dev, 60% in production. 2. Preprocessing leakage: StandardScaler was fit on the entire dataset before train/test split. Test set statistics leaked into training, inflating metrics by ~5%. 3. Temporal leakage: A fraud model used random train/test split on time-ordered transactions. Future fraud patterns leaked into training — the model "predicted" based on patterns it shouldn't have seen yet.

Prevention: Always ask "Would this information be available at prediction time?" for every feature. Use Pipelines. Time-based splits for temporal data.

•

Q3: Why is accuracy misleading for imbalanced datasets?

PrecisionRecallAUC-PRAUC-ROC

A: With 95% negative / 5% positive data, a model that predicts ALL negative gets 95% accuracy — yet it's completely useless! Better metrics: - Precision: Of predicted positives, how many are correct? (reduces false alarms) - Recall: Of actual positives, how many did we catch? (reduces misses)
- F1: Harmonic mean of precision and recall - AUC-PR: Area under precision-recall curve — best for severe imbalance - AUC-ROC: Measures ranking quality across all thresholds

In production: Choose the metric that aligns with the business cost. For cancer detection (FN is deadly), optimize recall. For email spam (FP is annoying), optimize precision.

•

Q4: K-Fold CV vs Hold-Out — when to use each?

Hold-outK-Fold CVNested CV

A: Hold-out (single train/test split) is fine when you have abundant data (>100K samples) — the estimate is stable enough. It's also necessary for time series (test = future data).

K-Fold CV is better for smaller datasets because: (1) every sample gets used for both training and testing, (2) the estimate is more reliable (averaged over K folds), (3) you get a confidence interval via std.

Nested CV when you need unbiased estimation while also tuning hyperparameters — outer loop for estimation, inner loop for tuning.

Q6: What's the difference between parametric and non-parametric models?

A: - Parametric: Fixed number of parameters regardless of data size. Makes assumptions about data distribution (e.g., linear relationship). Examples: Linear Regression ($n+1$ parameters for $n$ features), Logistic Regression, Naive Bayes. - Non-parametric: Number of parameters grows with data. Fewer distributional assumptions. Case study — end-to-end pipeline for telecom churn (1M rows × 200 columns)

Scenario: 1M rows, 200 columns; 60 columns have ~15% missing values, 70 columns have ~10% outliers. Design the end-to-end pipeline.

1. Frame & split first. Binary classification (churn yes/no), almost certainly imbalanced. Split train/val/test up front — stratified, and time-based if churn is time-dependent — so every transform below is fit on train only (no leakage). Keep a holdout untouched.

2. EDA & leakage check. Profile distributions, the missingness pattern (MCAR/MAR/MNAR), the target rate, and drop leaky features (anything known only after churn, e.g. disconnection_date). Remove ID / constant / duplicate columns.

3. Missing values (60 cols, ~15%). Don't blanket-drop (too much loss across many columns). By type: numeric → median (robust) or model-based (KNN/iterative) imputation; categorical → a "Missing" category or mode; add a was_missing indicator when missingness is informative (often is in telecom). Fit imputers on train, apply to val/test.

4. Outliers (70 cols, ~10%). Decide real signal vs error first — in churn, extreme usage/spend is often genuine, so don't just delete. Prefer robust handling: winsorize/cap at the 1st–99th percentile, log/quantile transforms, and/or tree models that are naturally outlier-robust. Remove only confirmed data errors. Fit caps on train.

5. Feature engineering. Encode categoricals (one-hot for low-cardinality, target/frequency encoding for high-cardinality like region/plan), scale numerics only if using distance/linear models (not for trees), and build domain features (tenure buckets, usage trends/deltas, complaint counts, contract type). With 200 columns, prune via feature selection (mutual info / model importance / L1).

6. Imbalance. Use class weights or SMOTE/ADASYN on the training fold only, and evaluate with PR-AUC / recall at a business threshold, not accuracy.

7. Model. Strong baseline = gradient-boosted trees (XGBoost / LightGBM / CatBoost) — they handle mixed types, missingness (some natively), outliers, and 200 features well, and give feature importance. Cross-validated hyperparameter search; calibrate probabilities (churn scores must be reliable for targeting).

8. Evaluation. PR-AUC, ROC-AUC, lift/gain by decile (the business wants "who to target"), calibration, and a cost-based threshold (retention-offer cost vs lost-customer cost). Validate on the untouched holdout.

9. Explainability & action. SHAP for global + per-customer drivers → feeds retention actions.

10. Productionize. Wrap every transform in one sklearn Pipeline / ColumnTransformer (fit on train, serialized) so train and serve are identical; batch-score or serve via API; monitor data/churn-rate drift and performance, retrain periodically. Optionally segment customers (clustering) to tailor offers — see the K-Means notes.

1. Classification Metrics — Complete Guide

Classification metrics quantify how well a model distinguishes between classes. Every metric derives from the confusion matrix (TP, FP, FN, TN) and captures a different aspect of model performance — accuracy measures overall correctness, precision measures positive prediction quality, recall measures positive detection completeness, and F1 balances precision and recall.

•

1.1 Confusion Matrix — The Foundation

MnemonicFalse PositivePositiveFalse

Every classification metric derives from the confusion matrix.

                          PREDICTED
                    Positive    Negative
              ┌────────────┬────────────┐
  ACTUAL  Pos │     TP     │     FN     │  ← Condition Positive (P)
              ├────────────┼────────────┤
          Neg │     FP     │     TN     │  ← Condition Negative (N)
              └────────────┴────────────┘
                    ↑            ↑
            Predicted Pos  Predicted Neg

TP (True Positive):  Model said YES, reality is YES    ✅ Correct
FP (False Positive): Model said YES, reality is NO     ❌ Type I Error  (False Alarm)
FN (False Negative): Model said NO,  reality is YES    ❌ Type II Error (Missed Detection)
TN (True Negative):  Model said NO,  reality is NO     ✅ Correct

Mnemonic: The second word tells you the MODEL's prediction. The first word tells you if it was RIGHT. - False Positive = model predicted Positive, but it was False (wrong).

When to use: Only when classes are roughly balanced AND all errors have equal cost.

Precision (Positive Predictive Value)

$$\text{Precision} = \frac{TP}{TP + FP} = \frac{\text{True Positives}}{\text{All Predicted Positives}}$$

Interpretation: "Of all the items I predicted positive, what fraction are actually positive?"

When precision matters most: - Spam filter: FP = legitimate email goes to spam (annoying → lost business) - Content moderation: FP = censoring legitimate content (user frustration) - Product recommendations: FP = irrelevant recommendation (erodes trust)

Key intuition: Precision answers "Can I trust the model when it says YES?"

Recall (Sensitivity, True Positive Rate)

$$\text{Recall} = \frac{TP}{TP + FN} = \frac{\text{True Positives}}{\text{All Actual Positives}}$$

Interpretation: "Of all the actual positives, what fraction did I catch?"

When recall matters most: - Cancer detection: FN = missing cancer diagnosis (life-threatening) - Fraud detection: FN = allowing fraud through (financial loss) - Safety systems: FN = missing a hazard (catastrophic)

Key intuition: Recall answers "Did I catch all the important cases?"

F1 Score

$$F_1 = 2 \cdot \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}} = \frac{2TP}{2TP + FP + FN}$$

Why harmonic mean, not arithmetic? Because harmonic mean punishes extreme imbalances: - Precision=1.0, Recall=0.01 → F1=0.02 (harmonic) vs 0.505 (arithmetic) - The harmonic mean requires BOTH precision and recall to be high

F-beta Score (generalized):

$$F_\beta = (1 + \beta^2) \cdot \frac{\text{Precision} \times \text{Recall}}{(\beta^2 \cdot \text{Precision}) + \text{Recall}}$$

$$\text{Balanced Acc} = \frac{\text{Sensitivity}+\text{Specificity}}{2} = \frac{1}{2}!\left(\frac{TP}{TP+FN}+\frac{TN}{TN+FP}\right)$$

The average of per-class recall — the fix for accuracy under imbalance (chance level stays at 0.5 regardless of skew). Equals plain accuracy when classes are balanced.

Geometric Mean (G-Mean)

$$\text{G-Mean} = \sqrt{\text{Sensitivity}\times\text{Specificity}}$$

High only when both classes are handled well — popular for imbalanced classification; collapses to 0 if either class is ignored.

Top-k Accuracy

Fraction of samples whose true label is among the model's k highest-probability predictions. Standard for many-class problems (e.g. ImageNet top-5 accuracy).

2. Regression Metrics — Complete Guide

Regression metrics measure how closely a model's continuous predictions match actual values. Key metrics include MSE (penalizes large errors quadratically), MAE (robust to outliers), RMSE (same unit as target), R² (proportion of variance explained), and MAPE (scale-independent percentage error). The choice of metric depends on whether large errors are disproportionately costly and whether the target scale varies across datasets.

•

2.1 Core Metrics

PropertiesInterpretationAdjusted R²ProblemsBest of both worldsrelative

Mean Absolute Error (MAE)

$$\text{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|$$

Properties: - Robust to outliers (linear penalty) - Same units as the target variable - Interpretable: "On average, predictions are off by MAE" - Not differentiable at zero (subgradient methods needed) - Corresponds to median regression

Mean Squared Error (MSE)

$$\text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2$$

Properties: - Most commonly used training loss - Penalizes large errors quadratically (sensitive to outliers) - Units are squared (hard to interpret directly) - Differentiable everywhere (gradient-based optimization) - Corresponds to mean regression

Root Mean Squared Error (RMSE)

$$\text{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2} = \sqrt{\text{MSE}}$$

Properties: - Same units as target (interpretable) - Still penalizes large errors more than MAE - Standard metric for regression competitions

R² Score (Coefficient of Determination)

$$R^2 = 1 - \frac{\text{SS}{res}}{\text{SS}{tot}} = 1 - \frac{\sum(y_i - \hat{y}_i)^2}{\sum(y_i - \bar{y})^2}$$

Interpretation: - $R^2 = 1$: Perfect predictions - $R^2 = 0$: Model is no better than predicting the mean - $R^2 < 0$: Model is WORSE than predicting the mean (possible!) - $R^2 = 0.85$: Model explains 85% of the variance in the target

Adjusted R² (penalizes unnecessary features):

$$R^2_{adj} = 1 - \frac{(1-R^2)(n-1)}{n-p-1}$$

where $n$ = samples, $p$ = number of features.

Mean Absolute Percentage Error (MAPE)

$$\text{MAPE} = \frac{100\%}{n}\sum_{i=1}^{n}\left|\frac{y_i - \hat{y}_i}{y_i}\right|$$

Problems: - Undefined when $y_i = 0$ - Asymmetric: penalizes overestimates more than underestimates - Scale-dependent interpretation varies

Alternative — Symmetric MAPE (sMAPE):

$$\text{sMAPE} = \frac{100\%}{n}\sum_{i=1}^{n}\frac{2|y_i - \hat{y}_i|}{|y_i| + |\hat{y}_i|}$$

Huber Loss

$$L_\delta(y, \hat{y}) = \begin{cases} \frac{1}{2}(y - \hat{y})^2 & \text{if } |y - \hat{y}| \leq \delta \ \delta|y - \hat{y}| - \frac{1}{2}\delta^2 & \text{otherwise} \end{cases}$$

Best of both worlds: Quadratic for small errors (like MSE), linear for large errors (like MAE). The parameter $\delta$ controls the transition point.

Mean Squared Log Error (MSLE) & RMSLE

$$\text{MSLE} = \frac{1}{n}\sum_i\big(\ln(1+y_i)-\ln(1+\hat y_i)\big)^2, \qquad \text{RMSLE}=\sqrt{\text{MSLE}}$$

Penalizes relative (ratio) error, not absolute — so it's robust to large-valued targets and punishes underestimates more than overestimates. Use for targets spanning orders of magnitude (prices, counts, demand); requires non-negative values.

Median Absolute Error

$$\text{MedAE} = \text{median}\big(|y_i - \hat y_i|\big)$$

The most outlier-robust regression metric (a few wild errors don't move the median).

Max Error

$$\text{MaxError} = \max_i |y_i - \hat y_i|$$

The worst-case miss — important for safety-critical regression where the largest error matters most.

Explained Variance Score

$$\text{EV} = 1 - \frac{\operatorname{Var}(y-\hat y)}{\operatorname{Var}(y)}$$

Like R² but ignores systematic bias in the residuals; equals R² when the mean residual is 0. (See also §9.4.)

import numpy as np

def mae_from_scratch(y_true, y_pred):
    return np.mean(np.abs(y_true - y_pred))

def mse_from_scratch(y_true, y_pred):
    return np.mean((y_true - y_pred) ** 2)

def rmse_from_scratch(y_true, y_pred):
    return np.sqrt(mse_from_scratch(y_true, y_pred))

def r2_from_scratch(y_true, y_pred):
    ss_res = np.sum((y_true - y_pred) ** 2)
    ss_tot = np.sum((y_true - np.mean(y_true)) ** 2)
    return 1 - (ss_res / ss_tot)

def adjusted_r2(y_true, y_pred, n_features):
    r2 = r2_from_scratch(y_true, y_pred)
    n = len(y_true)
    return 1 - (1 - r2) * (n - 1) / (n - n_features - 1)

def huber_loss(y_true, y_pred, delta=1.0):
    error = y_true - y_pred
    is_small = np.abs(error) <= delta
    loss = np.where(is_small, 0.5 * error**2, delta * np.abs(error) - 0.5 * delta**2)
    return np.mean(loss)

3. Ranking & Information Retrieval Metrics

Ranking metrics evaluate how well a model orders items by relevance, which is critical in search engines, recommendation systems, and information retrieval. Unlike classification metrics that assess individual predictions, ranking metrics assess the quality of the entire sorted list — rewarding models that place relevant items at the top.

•

3.1 Mean Reciprocal Rank (MRR)

$$\text{MRR} = \frac{1}{|Q|}\sum_{i=1}^{|Q|}\frac{1}{\text{rank}_i}$$

Where $\text{rank}_i$ is the position of the first relevant result for query $i$.

Use case: Search engines, recommendation systems — "How quickly does the user find what they want?"

•

3.2 Normalized Discounted Cumulative Gain (NDCG)

$$\text{DCG@k} = \sum_{i=1}^{k}\frac{2^{\text{rel}_i} - 1}{\log_2(i+1)}$$

$$\text{NDCG@k} = \frac{\text{DCG@k}}{\text{IDCG@k}}$$

Where IDCG is the DCG of the ideal ranking. NDCG@k ∈ [0, 1].

Use case: Search ranking, recommendation ranking — accounts for graded relevance and position.

•

3.3 Mean Average Precision (MAP)

$$\text{AP} = \frac{1}{|\text{relevant}|}\sum_{k=1}^{n}\text{Precision}@k \cdot \text{rel}(k)$$

$$\text{MAP} = \frac{1}{|Q|}\sum_{q=1}^{|Q|}\text{AP}(q)$$

def average_precision(y_true_ranked):
    """Compute AP for a single query's ranked results.
    y_true_ranked: list of 0/1 relevance judgments in ranked order.
    """
    n_relevant = sum(y_true_ranked)
    if n_relevant == 0:
        return 0.0
    
    cumsum = 0
    ap = 0.0
    for i, rel in enumerate(y_true_ranked, 1):
        cumsum += rel
        if rel == 1:
            ap += cumsum / i
    return ap / n_relevant

# Example: Model ranked [relevant, irrelevant, relevant, relevant, irrelevant]
ap = average_precision([1, 0, 1, 1, 0])
# P@1 = 1/1, P@3 = 2/3, P@4 = 3/4
# AP = (1/1 + 2/3 + 3/4) / 3 = 0.806
•

3.4 Hit Rate / Recall@K

$$\text{Hit Rate@K} = \frac{\text{# queries where relevant item in top K}}{\text{Total queries}}$$

$$\text{Recall@K} = \frac{\text{# relevant items in top K}}{\text{Total relevant items}}$$

Use case: Recommendation systems — "Does the user's preferred item appear in the top 10 recommendations?"

4. Calibration — Are Probabilities Reliable?

Model calibration measures whether predicted probabilities match actual observed frequencies — a model that predicts 70% probability should be correct 70% of the time. Well-calibrated probabilities are essential when downstream decisions depend on confidence levels (medical diagnosis thresholds, risk scoring, cost-sensitive classification).

•

4.1 What is Calibration?

A model is well-calibrated if when it predicts 70% probability, the event actually occurs ~70% of the time.

Example:
  Model predicts P(rain) = 0.7 for 100 days
  If well-calibrated: rain on ~70 of those days
  If poorly calibrated: rain on only 30 days → overconfident!

5. Threshold Optimization

Threshold optimization adjusts the classification boundary (default 0.5) to balance precision and recall according to business requirements. By analyzing the precision-recall curve or ROC curve, you can select a threshold that minimizes the total cost of false positives and false negatives for your specific use case.

•

5.1 Why Optimize the Threshold?

Default threshold is 0.5, but this is rarely optimal for real-world problems.

Example: Fraud detection (1% fraud rate)
  At threshold 0.5: Catches 60% of fraud, but 0.5% false positive rate
  At threshold 0.3: Catches 90% of fraud, but 2% false positive rate
  At threshold 0.1: Catches 98% of fraud, but 5% false positive rate

  Business decision: Is catching 38% more fraud worth 4x more false positives?
•

5.2 Methods

from sklearn.metrics import precision_recall_curve, f1_score
import numpy as np

# Method 1: Maximize F1
precision, recall, thresholds = precision_recall_curve(y_true, y_prob)
f1_scores = 2 * precision * recall / (precision + recall + 1e-10)
optimal_idx = np.argmax(f1_scores)
optimal_threshold = thresholds[optimal_idx]
print(f"Optimal threshold (max F1): {optimal_threshold:.3f}")
print(f"F1 at optimal: {f1_scores[optimal_idx]:.4f}")

# Method 2: Target specific recall (e.g., catch 95% of fraud)
target_recall = 0.95
idx = np.argmin(np.abs(recall - target_recall))
threshold_for_target_recall = thresholds[idx]
print(f"Threshold for {target_recall:.0%} recall: {threshold_for_target_recall:.3f}")
print(f"Precision at this threshold: {precision[idx]:.4f}")

# Method 3: Youden's J statistic (maximize TPR - FPR)
from sklearn.metrics import roc_curve
fpr, tpr, roc_thresholds = roc_curve(y_true, y_prob)
j_scores = tpr - fpr
optimal_idx = np.argmax(j_scores)
optimal_threshold = roc_thresholds[optimal_idx]
print(f"Youden's optimal threshold: {optimal_threshold:.3f}")

# Method 4: Cost-based threshold optimization
def expected_cost(threshold, y_true, y_prob, cost_fp=1, cost_fn=10):
    """Minimize total cost given asymmetric error costs."""
    y_pred = (y_prob >= threshold).astype(int)
    cm = confusion_matrix(y_true, y_pred)
    tn, fp, fn, tp = cm.ravel()
    total_cost = cost_fp * fp + cost_fn * fn
    return total_cost

thresholds = np.arange(0.01, 1.0, 0.01)
costs = [expected_cost(t, y_true, y_prob, cost_fp=1, cost_fn=10) for t in thresholds]
best_threshold = thresholds[np.argmin(costs)]
print(f"Cost-optimal threshold: {best_threshold:.2f}")

Metric selection requires understanding the business cost of different error types. There is no universally best metric — the right choice depends on class balance, error asymmetry, and whether you need probabilistic outputs, hard classifications, or ranked lists.

7.1 Cost-Sensitive Evaluation

from sklearn.metrics import make_scorer

def business_cost(y_true, y_pred, cost_fp=10, cost_fn=500):
    """
    Custom metric reflecting real business costs.
    
    Example: Fraud detection
      FP (flagging legitimate) = $10 (review cost)
      FN (missing fraud) = $500 (average fraud amount)
    """
    cm = confusion_matrix(y_true, y_pred)
    tn, fp, fn, tp = cm.ravel()
    total_cost = cost_fp * fp + cost_fn * fn
    return -total_cost  # Negative because sklearn maximizes

# Use as scorer in cross-validation
business_scorer = make_scorer(business_cost, greater_is_better=True)

7.2 Revenue-Based Metrics

def lift_at_k(y_true, y_prob, k_pct=0.1):
    """
    Lift: How much better is the model vs random at top k%.
    Used in marketing (target top 10% of customers).
    
    Lift = (response rate in top k%) / (overall response rate)
    """
    n = len(y_true)
    k = int(n * k_pct)
    
    # Sort by predicted probability (descending)
    idx = np.argsort(y_prob)[::-1][:k]
    
    response_top_k = y_true[idx].mean()
    response_overall = y_true.mean()
    
    return response_top_k / response_overall

# Perfect model Lift@10% with 5% positive rate: 1/0.05 = 20x
# Random model Lift@10%: 1.0

9. Clustering & Unsupervised Evaluation Metrics

Clustering evaluation metrics assess the quality of unsupervised groupings where no ground truth labels exist. Internal metrics (silhouette score, Calinski-Harabasz, Davies-Bouldin) measure cluster compactness and separation from the data alone, while external metrics (ARI, NMI) compare against known labels when available.

9.1 Silhouette Score

Measures how similar a point is to its own cluster vs the nearest neighboring cluster.

$$s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))}$$

Where: - $a(i)$ = mean intra-cluster distance (avg distance to all other points in the same cluster) - $b(i)$ = mean nearest-cluster distance (avg distance to points in the nearest neighboring cluster)

Range: [-1, 1]

9.2 Davies-Bouldin Index

RangeLower is better

Measures the average similarity between each cluster and its most similar cluster, where similarity is the ratio of within-cluster distances to between-cluster distances.

$$DB = \frac{1}{k}\sum_{i=1}^{k}\max_{j \neq i}\frac{s_i + s_j}{d_{ij}}$$

Where: - $s_i$ = average distance of points in cluster $i$ to its centroid - $d_{ij}$ = distance between centroids of clusters $i$ and $j$

Range: [0, ∞). Lower is better (0 = perfect clustering).

from sklearn.metrics import davies_bouldin_score

db_score = davies_bouldin_score(X, labels)
print(f"Davies-Bouldin Index: {db_score:.4f}")
•

9.3 Calinski-Harabasz Index (Variance Ratio Criterion)

Ratio of between-cluster dispersion to within-cluster dispersion. Higher is better — well-separated, tight clusters score higher.

$$CH = \frac{\text{tr}(B_k)}{\text{tr}(W_k)} \cdot \frac{N - k}{k - 1}$$

Where $B_k$ = between-cluster dispersion matrix, $W_k$ = within-cluster dispersion matrix, $N$ = total points, $k$ = number of clusters.

from sklearn.metrics import calinski_harabasz_score

ch_score = calinski_harabasz_score(X, labels)
print(f"Calinski-Harabasz Index: {ch_score:.4f}")
•

9.4 Explained Variance Score

Measures the proportion of variance in the target that is explained by the prediction.

$$EVS = 1 - \frac{Var(y - \hat{y})}{Var(y)}$$

Comparison with R²: Both measure variance explained, but EVS uses variance of the residuals whereas R² uses sum of squared residuals. They are equal when the mean of residuals is zero (i.e., predictions are unbiased).

from sklearn.metrics import explained_variance_score

evs = explained_variance_score(y_true, y_pred)
print(f"Explained Variance Score: {evs:.4f}")
•

9.5 Brier Score

RangeLower is betterUse case

Measures the mean squared difference between predicted probabilities and actual binary outcomes.

$$BS = \frac{1}{N}\sum_{i=1}^{N}(p_i - o_i)^2$$

Where $p_i$ = predicted probability, $o_i$ = actual outcome (0 or 1).

Range: [0, 1]. Lower is better (0 = perfect calibration).

Use case: Calibration assessment — evaluates how well predicted probabilities match observed frequencies. Commonly used in weather forecasting, medical risk prediction, and any setting where probability estimates need to be reliable.

Q1: When would you choose AUC-PR over AUC-ROC?

A: Use AUC-PR when the dataset is highly imbalanced (e.g., 99% negative). AUC-ROC can be misleadingly high because it includes TN in its FPR calculation — a few FP among thousands of negatives looks like low FPR, but in absolute terms it could be many false alarms. AUC-PR directly measures precision vs recall, revealing how many of the positive predictions are correct.

Example: 10,000 negatives, 100 positives. A model with FPR=0.01 → 100 false positives. ROC says FPR is "only 1%" (looks great!), but PR reveals precision is 50% (TP=100, FP=100). AUC-PR exposes this reality.

•

Q2: Explain the tradeoff between precision and recall with a real example.

spam filterBusiness decision

A: Consider an email spam filter: - High precision, low recall (threshold=0.9): Only flags emails we're 99% sure are spam. Almost never sends legitimate email to spam, but misses ~40% of spam. Users see some spam in inbox. - High recall, low precision (threshold=0.1): Catches 99% of spam. But also flags 10% of legitimate emails as spam. Users miss important emails. - Business decision: Most email providers prefer high precision (never lose a real email) with moderate recall (some spam gets through — users are trained to ignore it).

The threshold controls this tradeoff. The optimal point depends on the relative cost of FP vs FN in the specific business context.

•

Q3: Why is accuracy a misleading metric? When can you still use it?

A: Accuracy is misleading when classes are imbalanced. A model predicting "not fraud" for everything gets 99.5% accuracy with 0.5% fraud rate — completely useless.

You CAN use accuracy when: 1. Classes are balanced (50/50 or close) 2. All errors have equal business cost 3. You're comparing models on the same balanced dataset 4. You're doing multi-class classification with roughly equal class sizes

Even then, F1 or MCC is more informative.

•

Q4: What is calibration and why does it matter?

Why it mattersHow to fix

A: A model is calibrated if its predicted probabilities match observed frequencies. If the model says P(fraud)=0.3 for 1000 transactions, approximately 300 should actually be fraudulent.

Why it matters: - Decision thresholds depend on correct probabilities - Risk scoring (credit, insurance) requires calibrated P(default) - Ensemble methods need comparable probabilities from different models - Business stakeholders interpret probabilities directly ("30% chance of churn")

How to fix: Platt scaling (sigmoid), isotonic regression, or temperature scaling for neural networks. Logistic regression is naturally calibrated; Random Forest and SVM are not.

•

Q5: How would you evaluate a recommendation system?

ranking metricsNDCG@KHit Rate@KMAP (Mean Average Precision)MRR (Mean Reciprocal Rank)Coverage

A: Use ranking metrics, not classification metrics: 1. NDCG@K: Are relevant items ranked higher? Accounts for position and graded relevance. 2. Hit Rate@K: Does at least one relevant item appear in top K? 3. MAP (Mean Average Precision): Average precision across all rank cutoffs. 4. MRR (Mean Reciprocal Rank): How quickly does the first relevant item appear? 5. Coverage: What fraction of items/users does the system cover? 6. Diversity: How varied are the recommendations?

Online metrics (A/B test): Click-through rate, conversion rate, engagement time, revenue per user. These are the metrics that actually determine whether the model is deployed.

•

Q6: How do you handle multi-class evaluation?

MacroMicroWeighted

A: Three averaging strategies: - Macro: Compute F1 per class, average equally → treats all classes equally regardless of size - Micro: Aggregate TP/FP/FN across classes, compute one F1 → dominated by majority class - Weighted: Macro weighted by class size → balanced between macro and micro

Choice depends on business need. If a rare class is critically important (e.g., rare disease), use macro to ensure performance on that class isn't hidden by majority class performance.

•

Q7: What is the difference between MAE and RMSE? When would you prefer each?

MAERMSE100x

A: - MAE treats all errors equally — a $10 error is 10x worse than a $1 error. Robust to outliers. - RMSE squares errors before averaging — a $10 error is 100x worse than a $1 error. Sensitive to outliers.

Choose MAE when: all errors are equally important (e.g., typical delivery time prediction). Choose RMSE when: large errors are disproportionately bad (e.g., flight delay prediction — 3 hours late is much worse than 3× a 1-hour delay).

In practice, train with MSE (differentiable) but report MAE or RMSE depending on the business context.

Comparing two models without confusion-matrix metrics (+ gain/lift, C-index)

Interview: "You trained two classifiers on the same data — compare them WITHOUT confusion-matrix-based metrics (accuracy/precision/recall/F1)."

Confusion-matrix metrics depend on a fixed threshold and ignore probability quality. Threshold-free / probabilistic / statistical alternatives: - AUC-ROC — ranking quality across all thresholds; "P(random positive scores above random negative)". Threshold-independent. - AUC-PR / Average Precision — preferred under heavy class imbalance. - Log loss (cross-entropy) — penalizes confident wrong probabilities; rewards calibration. - Brier score — MSE of predicted probabilities vs outcomes (lower better). - Calibration — reliability curve / Expected Calibration Error: are the probabilities trustworthy? - Concordance index (C-index) — generalization of AUC; standard for survival / time-to-churn models. - KS statistic — max gap between the cumulative distributions of positives vs negatives (common in credit scoring). - Gain & Lift — business-facing ranking quality (below). - Statistical significance (to prove A is really better, not lucky): McNemar's test (paired predictions), DeLong test (compare two AUCs), or a paired t-test / Wilcoxon on cross-validated fold scores. 1. Ensemble Methods — Complete Theory

Ensemble methods combine multiple models (weak learners) to produce a single strong learner with better predictive performance than any individual model. The key insight is that aggregating diverse models reduces overall error — bagging reduces variance by averaging independent models, boosting reduces bias by sequentially correcting errors, and stacking learns how to optimally combine heterogeneous models.

•

1.1 Why Ensembles Work — Condorcet's Jury Theorem

independentindependence

If each model has accuracy $p > 0.5$ (better than random) and errors are independent, the ensemble accuracy approaches 1 as the number of models increases:

$$P(\text{majority correct}) = \sum_{k=\lceil n/2 \rceil}^{n} \binom{n}{k} p^k (1-p)^{n-k}$$

For $p = 0.6$ and $n = 100$: ensemble accuracy ≈ 0.97! But this assumes independence — in practice, models are correlated, so the gain is smaller but still significant.

1.3 Bagging (Bootstrap Aggregating)

$$\hat{f}{bag}(\mathbf{x}) = \frac{1}{B}\sum{b=1}^{B}\hat{f}_b(\mathbf{x})$$

Each $\hat{f}_b$ is trained on a bootstrap sample (sampling WITH replacement). This reduces variance without increasing bias.

    max_features=1.0,      # 100% of features
    bootstrap=True,         # With replacement
    oob_score=True,         # Out-of-bag validation
    random_state=42,
    n_jobs=-1
)

1.4 AdaBoost

Boosting that focuses on misclassified examples by increasing their weights:

Algorithm:
  1. Initialize sample weights: wᵢ = 1/n for all samples
  2. For t = 1, 2, ..., T:
     a. Train weak learner hₜ on weighted data
     b. Compute weighted error: εₜ = Σ wᵢ · 𝟙(hₜ(xᵢ) ≠ yᵢ)
     c. Compute learner weight: αₜ = ½ ln((1-εₜ)/εₜ)
     d. Update sample weights:
        wᵢ ← wᵢ · exp(-αₜ · yᵢ · hₜ(xᵢ))
     e. Normalize weights to sum to 1
  3. Final: H(x) = sign(Σ αₜ · hₜ(x))
  
  Key insight: Misclassified samples get HIGHER weights → next learner
  focuses on them. Sample weights accumulate toward hard examples.

1.8 Ensemble Design Principles

1. DIVERSITY is essential — models must make DIFFERENT errors
   - Mix algorithm families (tree + linear + distance-based)
   - Vary hyperparameters (shallow + deep trees)
   - Vary features (random feature subsets)
   - Vary training data (bootstrap, different time windows)

2. Each model should be DECENT on its own (p > 0.5)

3. For STACKING:
   - Base models should be DIVERSE
   - Meta-learner should be SIMPLE (Logistic Regression, Ridge)
   - Use CV to prevent leakage (sklearn does this automatically)

4. More models is NOT always better
   - After 3-5 diverse models, returns diminish
   - Adds inference latency and complexity

2.4 Practical Tuning Strategy

PHASE 1: Quick exploration (5 minutes)
  → Random Search with 50-100 iterations
  → Identify which parameters matter most
  → Get rough parameter ranges

PHASE 2: Focused optimization (30-60 minutes)
  → Optuna with 100-200 iterations on important params
  → Fix unimportant params at defaults
  → Use early stopping

PHASE 3: Final model (10 minutes)
  → Train with best params on full training data
  → Evaluate on held-out test set (ONCE!)
  → Save model with metadata

ANTI-PATTERNS:
  ❌ Grid search over many params (exponential)
  ❌ Tuning on test set (data leakage)
  ❌ Not using early stopping (wasted compute)
  ❌ Tuning too aggressively (overfitting the validation set)
3. Handling Imbalanced Data

Imbalanced data occurs when classes are not equally represented, causing standard algorithms to be biased toward the majority class. Techniques to address this include data-level approaches (oversampling minority, undersampling majority, SMOTE), algorithm-level approaches (class weights, cost-sensitive learning), and evaluation strategies (using F1, AUC-PR instead of accuracy).

•

3.1 The Problem

Example: Fraud detection
  99.5% legitimate, 0.5% fraud
  
  Model A (predict all "legitimate"): 99.5% accuracy → USELESS!
  Model B (actual ML model):           98.0% accuracy → catches 70% of fraud
  
  Model B is clearly better, but accuracy suggests Model A is superior.
•

3.3 SMOTE (Synthetic Minority Oversampling Technique)

How SMOTE works:
  1. Select a minority sample x
  2. Find its k nearest minority neighbors (default k=5)
  3. Randomly choose one neighbor x_nn
  4. Create synthetic point between them:
     x_new = x + rand(0,1) × (x_nn - x)
  5. Repeat until minority class is balanced

  x₁ ●────────────● x₂ (nearest neighbor)
         ↑
      x_new (random point between them)

4. Pipelines — Production ML

Sklearn Pipelines chain preprocessing steps and model training into a single object that prevents data leakage, ensures reproducibility, and simplifies deployment. By encapsulating the entire workflow (scaling, encoding, imputation, feature engineering, model fitting) in one serializable object, Pipelines guarantee that the exact same transformations applied during training are applied during inference.

•

4.1 Why Pipelines?

WITHOUT Pipeline:
  scaler = StandardScaler()
  X_train_scaled = scaler.fit_transform(X_train)    # Correct
  X_test_scaled = scaler.fit_transform(X_test)      # BUG! Should be .transform()
                                                      # This is data leakage!

WITH Pipeline:
  pipe = Pipeline([('scaler', StandardScaler()), ('model', XGBClassifier())])
  pipe.fit(X_train, y_train)       # Scaler fits on train, model fits on scaled train
  pipe.predict(X_test)             # Scaler transforms test, model predicts — correct!
  
  Benefits:
  ✅ Prevents data leakage (fit on train only, transform on test)
  ✅ Single object for the full workflow
  ✅ Works with cross_val_score, GridSearchCV
  ✅ Easy serialization (joblib.dump(pipe, 'model.joblib'))
  ✅ Production-ready (one .predict() call handles everything)
•

4.4 Custom Transformers

from sklearn.base import BaseEstimator, TransformerMixin

class DateFeatureExtractor(BaseEstimator, TransformerMixin):
    """Extract useful features from datetime columns."""
    
    def __init__(self, date_column='date'):
        self.date_column = date_column
    
    def fit(self, X, y=None):
        return self  # No fitting needed
    
    def transform(self, X):
        X = X.copy()
        dt = pd.to_datetime(X[self.date_column])
        X['day_of_week'] = dt.dt.dayofweek
        X['month'] = dt.dt.month
        X['is_weekend'] = (dt.dt.dayofweek >= 5).astype(int)
        X['hour'] = dt.dt.hour
        X = X.drop(columns=[self.date_column])
        return X

class OutlierClipper(BaseEstimator, TransformerMixin):
    """Clip outliers beyond q1 - 1.5*IQR and q3 + 1.5*IQR."""
    
    def __init__(self, factor=1.5):
        self.factor = factor
    
    def fit(self, X, y=None):
        Q1 = np.percentile(X, 25, axis=0)
        Q3 = np.percentile(X, 75, axis=0)
        IQR = Q3 - Q1
        self.lower_ = Q1 - self.factor * IQR
        self.upper_ = Q3 + self.factor * IQR
        return self
    
    def transform(self, X):
        return np.clip(X, self.lower_, self.upper_)

    ('date_extractor', DateFeatureExtractor('signup_date')),
    ('preprocessor', preprocessor),
    ('outlier_clip', OutlierClipper()),
    ('model', XGBClassifier())

8. Feature Selection Methods

Feature selection reduces dimensionality by identifying the most relevant features, improving model performance, reducing overfitting, and decreasing training time. Methods fall into three categories based on how they evaluate feature importance.

•

8.1 Filter Methods (Statistical Tests — Model Independent)

Filter methods rank features using statistical measures, independent of any ML model. They are fast but don't consider feature interactions.

from sklearn.feature_selection import (
    VarianceThreshold, SelectKBest, chi2,
    mutual_info_classif, f_classif
)
import pandas as pd
import numpy as np

# ── Variance Threshold (remove near-constant features) ──
selector = VarianceThreshold(threshold=0.01)
X_filtered = selector.fit_transform(X)
print(f"Features kept: {selector.get_support().sum()} / {X.shape[1]}")

# ── Chi-Squared (for non-negative features + classification) ──
chi2_selector = SelectKBest(chi2, k=10)
X_chi2 = chi2_selector.fit_transform(X, y)
chi2_scores = pd.Series(chi2_selector.scores_, index=feature_names)
print(chi2_scores.nlargest(10))

# ── Mutual Information (captures non-linear relationships) ──
mi_selector = SelectKBest(mutual_info_classif, k=10)
X_mi = mi_selector.fit_transform(X, y)

# ── ANOVA F-test (linear relationship with target) ──
f_selector = SelectKBest(f_classif, k=10)
X_f = f_selector.fit_transform(X, y)

# ── Correlation-based (remove highly correlated features) ──
corr_matrix = pd.DataFrame(X, columns=feature_names).corr().abs()
upper = corr_matrix.where(np.triu(np.ones(corr_matrix.shape), k=1).astype(bool))
to_drop = [col for col in upper.columns if any(upper[col] > 0.95)]
print(f"Dropping {len(to_drop)} highly correlated features: {to_drop}")
X_reduced = pd.DataFrame(X, columns=feature_names).drop(columns=to_drop)

8.2 Wrapper Methods (Use Model Performance)

Wrapper methods evaluate feature subsets by training a model and measuring performance. More accurate but computationally expensive.

from sklearn.feature_selection import RFE, SequentialFeatureSelector
from sklearn.ensemble import RandomForestClassifier

estimator = RandomForestClassifier(n_estimators=100, random_state=42)

# ── Recursive Feature Elimination (RFE) ─────────────────
rfe = RFE(estimator, n_features_to_select=10, step=1)
rfe.fit(X_train, y_train)
selected_features = [f for f, s in zip(feature_names, rfe.support_) if s]
print(f"RFE selected: {selected_features}")
print(f"Feature ranking: {rfe.ranking_}")

# ── Sequential Feature Selection (forward/backward) ─────
# Forward selection: start with 0 features, add best one at a time
sfs_forward = SequentialFeatureSelector(
    estimator, n_features_to_select=10, direction='forward', cv=5, scoring='f1'
)
sfs_forward.fit(X_train, y_train)

# Backward elimination: start with all features, remove worst
sfs_backward = SequentialFeatureSelector(
    estimator, n_features_to_select=10, direction='backward', cv=5, scoring='f1'
)
sfs_backward.fit(X_train, y_train)

8.3 Embedded Methods (Built into Model Training)

Embedded methods perform feature selection as part of the model training process, combining the benefits of filter and wrapper methods.

from sklearn.feature_selection import SelectFromModel
from sklearn.linear_model import LassoCV
from sklearn.ensemble import RandomForestClassifier

# ── Lasso (L1 regularization — drives coefficients to zero) ──
lasso_selector = SelectFromModel(LassoCV(cv=5, random_state=42))
lasso_selector.fit(X_train, y_train)
X_lasso = lasso_selector.transform(X_train)
print(f"Lasso selected: {lasso_selector.get_support().sum()} features")

# ── Tree-based importance ────────────────────────────────
rf_selector = SelectFromModel(
    RandomForestClassifier(n_estimators=200, random_state=42),
    threshold='median'  # Keep features with importance above median
)
rf_selector.fit(X_train, y_train)
X_rf = rf_selector.transform(X_train)
print(f"RF selected: {rf_selector.get_support().sum()} features")

# ── ElasticNet (L1 + L2 — best of both) ──────────────────
from sklearn.linear_model import ElasticNetCV
en_selector = SelectFromModel(ElasticNetCV(cv=5, random_state=42, l1_ratio=0.5))
en_selector.fit(X_train, y_train)

Q1: Why does stacking work better than individual models?

inductive biasesweighting

A: Stacking leverages the principle that different models have different inductive biases — they make different types of errors. A random forest might struggle with linear patterns that logistic regression captures perfectly, while XGBoost might nail non-linear interactions that RF misses.

The meta-learner (usually logistic regression) learns the optimal weighting of base model predictions and can even learn which model to trust in different regions of the feature space. Key requirement: base models must be diverse (different algorithm families) and their predictions must be generated via cross-validation to prevent data leakage.

•

Q2: Explain SMOTE. What are its limitations?

LimitationsCan generate noisy samplesDoesn't address the real problemFeature space assumptionsBetter alternatives

A: SMOTE creates synthetic minority samples by interpolating between existing minority samples and their k nearest neighbors. For each minority point, it picks a random neighbor and creates a new point on the line between them.

Limitations: 1. Can generate noisy samples: If minority points overlap with majority class, SMOTE creates synthetic points in the overlap region, making the boundary noisier. 2. Doesn't address the real problem: The actual issue may be insufficient signal in features, not sample count. 3. Feature space assumptions: Interpolation in feature space may not correspond to realistic data points (e.g., interpolating between two valid images doesn't always create a valid image). 4. Must be applied only on training data: Apply inside CV folds, never before splitting.

Better alternatives: Often, class_weight='balanced' + threshold tuning outperforms SMOTE with less complexity.

•

Q3: How would you build a production ML pipeline for a new project?

Define successQuick baselineStrong baselineIterateValidateDeploy

A: 1. Define success: Business metric → ML metric → baseline target 2. Quick baseline: Logistic Regression with Pipeline (2 hours) 3. Strong baseline: XGBoost with default params (1 day) 4. Iterate: Feature engineering → Optuna tuning → ensemble if needed (1 week) 5. Validate: Final test set evaluation, threshold optimization 6. Deploy: joblib.dump(pipeline) → FastAPI → Docker → K8s 7. Monitor: Data drift (PSI), prediction drift, latency, error rates 8. Retrain: Scheduled retraining with validation gates

Critical: The Pipeline object encapsulates ALL preprocessing, ensuring consistency between training and serving.

•

Q4: When would you NOT use an ensemble?

Latency-criticalInterpretability requiredMarginal improvementSmall datasetResource-constrainedRule

A: 1. Latency-critical: Ensemble adds N× inference time. If you need <5ms latency, single model is better. 2. Interpretability required: Regulators need to understand WHY a decision was made. Single LR or decision tree is required. 3. Marginal improvement: If single model gives 92% and ensemble gives 92.5%, the complexity isn't worth it. 4. Small dataset: Ensemble may overfit when models see very similar training data. 5. Resource-constrained: Multiple models = more memory, compute, maintenance.

Rule: If a single well-tuned model (XGBoost/LightGBM) solves the problem, don't ensemble. Ensemble only when the accuracy gain justifies the complexity.

•

Q5: What is the correct way to use SMOTE with cross-validation?

A: SMOTE must be applied inside each CV fold, not before splitting:

# ❌ WRONG — data leakage!
X_res, y_res = SMOTE().fit_resample(X, y)
scores = cross_val_score(model, X_res, y_res, cv=5)

# ✅ CORRECT — SMOTE inside each fold
from imblearn.pipeline import Pipeline as ImbPipeline
pipe = ImbPipeline([
    ('smote', SMOTE()),
    ('model', XGBClassifier())
])
scores = cross_val_score(pipe, X, y, cv=5, scoring='f1')

The wrong approach generates synthetic training samples that may overlap with validation fold samples, giving inflated scores that don't reflect real-world performance.

Common Mistakes Summary
ENSEMBLES:
  ❌ Using very similar models → no diversity, no ensemble benefit
  ❌ Stacking without CV → data leakage in meta-learner
  ❌ Too many base models → diminishing returns, maintenance burden

TUNING:
  ❌ Grid search over many params → exponential time, wasteful
  ❌ Tuning on test set → evaluation leakage
  ❌ Not using early stopping → wasted compute and overfitting

IMBALANCED DATA:
  ❌ Using accuracy → misleading
  ❌ SMOTE before CV → data leakage
  ❌ SMOTE on test data → invalid evaluation
  ❌ Only trying resampling, not class weights → simple often works better

PIPELINES:
  ❌ fit_transform on test data → should be transform only
  ❌ Not using Pipeline for CV → data leakage
  ❌ Not saving Pipeline → preprocessing mismatch in production
