Model Interpretability & Explainability — Unified Reference

1. Why Interpretability Matters

Interpretability answers "why did the model make this prediction?" — a question that matters far beyond academic curiosity.

•

1.1 Trust & Adoption

  • Stakeholders (doctors, loan officers, judges) won't act on a prediction they can't understand.
  • Explanations bridge the gap between a black-box score and a human decision.
•

1.2 Debugging & Model Improvement

spurious correlationsdata leakagefeature engineering
  • Reveals spurious correlations (e.g., model using hospital ID to predict mortality).
  • Identifies data leakage — a feature that "shouldn't know" the answer but does.
  • Guides feature engineering — understanding which interactions matter.
•

1.3 Regulation & Compliance

RegulationRequirement
EU AI Act (2024)High-risk systems must provide explanations to affected individuals
GDPR Art. 22Right to "meaningful information about the logic involved"
US ECOA / FCRAAdverse-action notices must list reasons for credit denial
FDA (medical AI)Clinical decision support must be transparent
•

1.4 Fairness & Bias Detection

  • Explanations expose protected-attribute leakage (race encoded via zip code).
  • SHAP values can quantify how much a sensitive feature contributes to disparate outcomes.
  • Counterfactuals answer: "What would need to change for a different outcome?"

3.1 Permutation Feature Importance

IdeaProsCons

Idea: Shuffle one feature at a time; measure how much model performance drops.

from sklearn.inspection import permutation_importance
from sklearn.ensemble import RandomForestClassifier
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_train, y_train)

result = permutation_importance(
    model, X_test, y_test,
    n_repeats=30,
    random_state=42,
    scoring='accuracy'
)

# Top 10 features by importance
import pandas as pd
imp = pd.Series(result.importances_mean, index=X.columns)
imp.nlargest(10).plot.barh(title="Permutation Importance")

Pros: Model-agnostic, uses real performance metric, accounts for feature interactions.
Cons: Slow for large datasets, correlated features share/dilute importance.

3.4 Feature Interaction (H-Statistic)

Friedman's H-statistic measures the proportion of variance explained by the interaction between two features.

Hjk2 = ∑i [ PDjk(xj(i), xk(i)) − PDj(xj(i)) − PDk(xk(i)) ]2∑i PDjk(xj(i), xk(i))2
  • H2 = 0: no interaction
  • H2 = 1: full interaction (PD is entirely due to joint effect)
4. LIME — Local Interpretable Model-Agnostic Explanations
•

4.1 Theory

PerturbsQueriesWeightsFits

For a prediction $f(x)$, LIME: 1. Perturbs the input $x$ to generate neighbors {z1, z2, …, zN}. 2. Queries the black-box model: f(zi) for each neighbor. 3. Weights neighbors by proximity to $x$: πx(zi) = exp(−D(x, zi)2 / σ2). 4. Fits a simple interpretable model (e.g., sparse linear) on the weighted dataset.

ξ(x) = argming ∈ G   ℒ(f, g, πx) + Ω(g)

where Ω(g) controls complexity (e.g., L1 regularization or max features).

•

5. SHAP — SHapley Additive exPlanations
•

5.1 Shapley Values Theory

Shapley valueEfficiencySymmetryDummyLinearity

From cooperative game theory: the Shapley value of feature $j$ is its average marginal contribution across all possible coalitions.

φj = ∑S ⊆ N \ {j} |S|! (|N|−|S|−1)!|N|! [ f(S ∪ {j}) − f(S) ]

Properties (uniquely defining Shapley values):

PropertyMeaning
Efficiency∑j φj = f(x) − E[f(x)] — contributions sum to the prediction minus baseline
SymmetryEqual-contribution features get equal values
DummyFeature with zero contribution gets φ = 0
Linearityφ(f+g) = φ(f) + φ(g)
•

6. Anchors — Rule-Based Explanations
•

6.1 Concept

if-then rulessufficient

Anchors produce if-then rules that are sufficient for a prediction with high precision.

"IF worst radius > 17.5 AND mean concave points > 0.08 THEN predict malignant with 95% precision."

•

6.2 Algorithm

  1. Generate candidate rules (predicates on feature ranges).
  2. Use multi-armed bandit (KL-LUCB) to efficiently estimate precision.
  3. Select the shortest anchor satisfying precision threshold τ (e.g., 0.95).
•

8.2 Integrated Gradients

baselinePropertiescompletenesssensitivity

Attributes each feature by integrating gradients along a straight-line path from a baseline (e.g., black image) to the input.

IGi(x) = (xi − x'i) 1∫0 ∂ F(x' + α(x − x'))∂ xi dα

Properties: Satisfies completeness (attributions sum to $F(x) - F(x')$) and sensitivity (non-zero attribution for any feature that changes the output).

8.3 Layer-wise Relevance Propagation (LRP)

conservation rulesLRP-0LRP-εLRP-γ

Backpropagates the prediction score through the network using conservation rules:

∑j Rj(l) = ∑k Rk(l+1)

Common rules: - LRP-0: Basic redistribution proportional to activations. - LRP-ε: Adds small ε for numerical stability. - LRP-γ: Favors positive contributions.

11.1 Explanation API Design

from fastapi import FastAPI
from pydantic import BaseModel
import shap
import numpy as np

app = FastAPI()

# Pre-load model & explainer at startup
model = load_model("model.pkl")
explainer = shap.TreeExplainer(model)

class PredictionRequest(BaseModel):
    features: dict  # {"age": 35, "income": 50000, ...}

class ExplanationResponse(BaseModel):
    prediction: float
    base_value: float
    feature_contributions: dict  # {"age": 0.12, "income": -0.05, ...}

@app.post("/predict-explain", response_model=ExplanationResponse)
def predict_and_explain(req: PredictionRequest):
    x = np.array([list(req.features.values())])
    pred = model.predict(x)[0]
    sv = explainer.shap_values(x)[0]
    return ExplanationResponse(
        prediction=float(pred),
        base_value=float(explainer.expected_value),
        feature_contributions=dict(zip(req.features.keys(), sv.tolist()))
    )

12. Interview Questions
•

Q1: What is the difference between interpretability and explainability?

InterpretabilityExplainability

Interpretability refers to the degree to which a human can understand the cause of a decision — intrinsically transparent models (linear regression, small decision trees) are interpretable by design. Explainability is the ability to explain a model's decisions post-hoc, typically for complex black-box models. In practice, the terms are often used interchangeably, but interpretability implies built-in transparency while explainability implies an external explanation method applied to an opaque model.

•

Q2: Explain SHAP values and their theoretical properties.

Shapley valuesEfficiencySymmetryDummyLinearity

SHAP values are based on Shapley values from cooperative game theory. Each feature's SHAP value represents its average marginal contribution to the prediction across all possible feature coalitions. They satisfy four axioms: Efficiency (contributions sum to the difference between prediction and baseline), Symmetry (equal contributors get equal values), Dummy (irrelevant features get zero), and Linearity (additive across models). These axioms uniquely determine the attribution, making SHAP the only consistent additive feature attribution method.

•

Q3: When would you use LIME over SHAP, and vice versa?

SHAPLIME

Use SHAP when you need theoretically grounded attributions that satisfy consistency axioms, work with tree-based models (TreeSHAP is fast and exact), or want rich visualization (summary/dependence/force plots). Use LIME when you need quick, intuitive explanations for stakeholders unfamiliar with Shapley values, when working with text/image data where LIME's perturbation approach is natural, or when you need a lightweight explanation without installing SHAP's dependencies. For regulatory compliance, SHAP's formal guarantees are typically preferred.

Q4: How does Grad-CAM work, and what are its limitations?

class-specific gradientsLimitations

Grad-CAM computes class-specific gradients flowing into the final convolutional layer, global-average-pools them to get importance weights per channel, and produces a weighted combination of activation maps passed through ReLU. Limitations: (1) Resolution is limited to the spatial size of the last conv layer (coarse heatmaps), (2) it can only attribute to spatial regions, not individual pixels, (3) it may miss fine-grained discriminative features, and (4) for multi-object scenes, it may highlight the most dominant object only. Grad-CAM++ and Score-CAM address some of these issues.

Q5: What are counterfactual explanations, and why are they useful?

minimum perturbationactionableintuitivefairness auditing

Counterfactual explanations answer "What would need to change for a different outcome?" They find the minimum perturbation to the input that flips the prediction. They are useful because: (1) they are actionable — they tell users what to change (e.g., "increase income by $15K to get approved"), (2) they are intuitive — humans naturally think in counterfactual terms, (3) they support fairness auditing — you can check if flipping a protected attribute changes the outcome, and (4) they don't require access to model internals (model-agnostic).

Q6: How do you detect if a model is using spurious correlations?

Several approaches: (1) Permutation importance — if removing/shuffling a feature that shouldn't matter significantly drops performance, the model may rely on it. (2) SHAP dependence plots — check if features with no causal relationship have high SHAP values. (3) Subgroup analysis — evaluate model on slices where the spurious correlation is broken. (4) Counterfactuals — generate CFs that change only spurious features and check if predictions change. (5) Stress testing — evaluate on deliberately curated out-of-distribution data where the correlation doesn't hold. (6) Attention/Grad-CAM visualization — for vision models, check if the model focuses on background or irrelevant objects.

Q8: What is the difference between PDP and ALE plots? When would you prefer one over the other?

PDPfeature independenceALEconditional distributionPrefer ALEPrefer PDP

PDP (Partial Dependence Plots) show the marginal effect of a feature by averaging predictions over all other features' observed values. They assume feature independence — if features are correlated, PDPs can show effects at unrealistic feature combinations. ALE (Accumulated Local Effects) fix this by computing effects using only the conditional distribution of neighboring points, making them unbiased even with correlated features. Prefer ALE when features are correlated (which is common in practice). Prefer PDP when features are roughly independent and you want a more intuitive "what if I set this feature to value X" interpretation, as PDPs have a direct causal interpretation under independence.

1. Anomaly Detection Fundamentals

Anomaly detection (also called outlier detection) identifies data points, events, or observations that deviate significantly from the expected pattern of a dataset. It is used across fraud detection, network intrusion, manufacturing defect detection, medical diagnosis, and system monitoring.

TYPES OF ANOMALIES:
  Point anomaly:      Single data point deviates (e.g., fraudulent transaction)
  Contextual anomaly: Normal in one context but anomalous in another
                      (e.g., 90°F in winter vs summer)
  Collective anomaly: A collection of related data points is anomalous
                      (e.g., sequence of network packets forming an attack)

DETECTION PARADIGMS:
  Supervised:       Labeled anomalies available → binary classification
                    (rarely practical — anomalies are rare and diverse)
  Semi-supervised:  Train on ONLY normal data, detect deviations
                    (One-Class SVM, autoencoders, robust PCA)
  Unsupervised:     No labels — assume anomalies are rare and different
                    (Isolation Forest, LOF, DBSCAN, statistical methods)

KEY CHALLENGES:
  - Extreme class imbalance (0.01% - 1% anomalies)
  - Anomalies evolve over time (concept drift)
  - High-dimensional data makes distance metrics unreliable
  - Cost of false positives vs false negatives varies by domain
  - Ground truth labels are often unavailable or expensive
ANOMALY SCORE vs BINARY LABEL:
  Most methods produce a continuous anomaly score
  Threshold converts score → binary label
  
  Score advantages:
  - Rank anomalies by severity
  - Adjust sensitivity via threshold
  - Combine multiple detectors
  
  Threshold strategies:
  - Fixed percentile (top 1% = anomaly)
  - Statistical (mean + 3σ)
  - Domain-specific (fraud: $10K+ = suspicious)
  - Adaptive (changes with data distribution)

2. Statistical Methods

Statistical methods detect anomalies by assuming the data follows a known distribution and flagging points that fall in low-probability regions. They are interpretable, fast, and work well when distributional assumptions hold.

2.1 Z-Score Method

import numpy as np
import pandas as pd

def zscore_anomaly(data, threshold=3.0):
    """Flag points more than `threshold` standard deviations from mean."""
    mean = np.mean(data)
    std = np.std(data)
    z_scores = np.abs((data - mean) / std)
    return z_scores > threshold

# Assumes Gaussian distribution
# 3σ rule: ~99.7% of normal data within ±3σ
# Sensitive to outliers in mean/std calculation

2.2 Modified Z-Score (Robust)

def modified_zscore(data, threshold=3.5):
    """Uses median and MAD — robust to outliers."""
    median = np.median(data)
    mad = np.median(np.abs(data - median))  # Median Absolute Deviation
    modified_z = 0.6745 * (data - median) / mad
    return np.abs(modified_z) > threshold

# MAD is robust — not affected by extreme outliers
# 0.6745 is the 75th percentile of standard normal
# Preferred over Z-score when outliers contaminate mean/std

2.3 IQR Method

def iqr_anomaly(data, factor=1.5):
    """Interquartile Range method — non-parametric."""
    Q1 = np.percentile(data, 25)
    Q3 = np.percentile(data, 75)
    IQR = Q3 - Q1
    lower = Q1 - factor * IQR
    upper = Q3 + factor * IQR
    return (data < lower) | (data > upper)

# factor=1.5 → mild outliers
# factor=3.0 → extreme outliers
# Non-parametric — no distributional assumptions
# Used by box plots

2.4 Grubbs' Test

from scipy import stats

def grubbs_test(data, alpha=0.05):
    """Test for a single outlier in univariate data."""
    n = len(data)
    mean = np.mean(data)
    std = np.std(data, ddof=1)
    
    # Find the most extreme value
    abs_deviations = np.abs(data - mean)
    max_idx = np.argmax(abs_deviations)
    G = abs_deviations[max_idx] / std
    
    # Critical value
    t_critical = stats.t.ppf(1 - alpha / (2 * n), n - 2)
    G_critical = ((n - 1) / np.sqrt(n)) * np.sqrt(t_critical**2 / (n - 2 + t_critical**2))
    
    return G > G_critical, max_idx

# Detects ONE outlier at a time
# Apply iteratively for multiple outliers
# Assumes approximately Gaussian data

2.5 Mahalanobis Distance (Multivariate)

from scipy.spatial.distance import mahalanobis
from sklearn.covariance import EllipticEnvelope, MinCovDet

def mahalanobis_anomaly(X, threshold_percentile=97.5):
    """Multivariate anomaly detection using Mahalanobis distance."""
    # Robust covariance estimation
    robust_cov = MinCovDet().fit(X)
    distances = robust_cov.mahalanobis(X)
    
    threshold = np.percentile(distances, threshold_percentile)
    return distances > threshold, distances

# Accounts for correlations between features
# MinCovDet makes it robust to outliers in covariance estimation
# Under Gaussian: Mahalanobis² ~ chi-squared(d) distribution
# Use chi-squared critical value as threshold

# Sklearn wrapper:
ee = EllipticEnvelope(contamination=0.01)
predictions = ee.fit_predict(X)  # -1 = outlier, 1 = inlier

3. Distance-Based Methods

Distance-based methods flag points that are far from their neighbors, based on the intuition that normal points cluster together while anomalies are isolated in feature space.

3.1 KNN-Based Anomaly Detection

from sklearn.neighbors import NearestNeighbors

def knn_anomaly(X, k=5, threshold_percentile=95):
    """Anomaly score = distance to k-th nearest neighbor."""
    nn = NearestNeighbors(n_neighbors=k + 1)  # +1 because self is included
    nn.fit(X)
    distances, _ = nn.kneighbors(X)
    
    # Score = distance to k-th neighbor (or mean of k distances)
    anomaly_scores = distances[:, -1]  # k-th neighbor distance
    threshold = np.percentile(anomaly_scores, threshold_percentile)
    
    return anomaly_scores > threshold, anomaly_scores

# Variants:
# - k-th NN distance: Simple, effective
# - Average k-NN distance: More stable
# - Relative distance: Compare to neighbors' neighbor distances (→ LOF)

4. Density-Based Methods (LOF)

Local Outlier Factor (LOF)

LOF compares the local density of a point to the densities of its neighbors. A point with substantially lower density than its neighbors is considered an outlier. This allows LOF to detect anomalies in datasets with clusters of varying densities—where global methods fail.

LOF ALGORITHM:
  1. Find k nearest neighbors of each point
  2. Compute reachability distance:
     reach_dist(A, B) = max(k_distance(B), dist(A, B))
  3. Compute Local Reachability Density (LRD):
     LRD(A) = 1 / (avg reachability distance of A to its k neighbors)
  4. Compute LOF:
     LOF(A) = avg(LRD of A's neighbors) / LRD(A)
  
  LOF ≈ 1:   Point has similar density to neighbors (normal)
  LOF >> 1:  Point has much lower density than neighbors (outlier)
  LOF << 1:  Point has higher density than neighbors (dense core point)
from sklearn.neighbors import LocalOutlierFactor

# ── Unsupervised LOF ────────────────────────────────────
lof = LocalOutlierFactor(
    n_neighbors=20,          # k in kNN
    contamination=0.05,       # Expected fraction of anomalies
    metric='euclidean',
    novelty=False              # False = unsupervised (fit_predict)
)
predictions = lof.fit_predict(X)  # -1 = outlier, 1 = inlier
scores = -lof.negative_outlier_factor_  # Higher = more anomalous

# ── Novelty detection (semi-supervised) ──────────────────

lof_novelty.fit(X_train_normal)  # Train on normal data only

LOF STRENGTHS:
  ✓ Detects local anomalies (different density regions)
  ✓ No distributional assumptions
  ✓ Works with any distance metric
  
LOF LIMITATIONS:
  ✗ O(n² log n) — slow for large datasets
  ✗ Sensitive to k choice
  ✗ Curse of dimensionality (distances become meaningless)
  ✗ Not designed for streaming data

5. Isolation Forest

Isolation Forest isolates anomalies by randomly partitioning feature space with axis-aligned splits. Anomalies, being rare and different, require fewer splits to isolate and thus have shorter average path lengths in the ensemble of random trees.

ISOLATION FOREST INTUITION:
  Normal points:   Deep in the tree (many splits to isolate)
  Anomalies:       Shallow in the tree (few splits to isolate)
  
  ALGORITHM:
  1. Build ensemble of isolation trees (iTree):
     a. Randomly select a feature
     b. Randomly select a split value between min/max of that feature
     c. Recursively partition until:
        - Point is isolated (leaf node)
        - Tree reaches max depth (log₂(n))
  2. Anomaly score = average path length across all trees
  3. Score normalized using:
     s(x, n) = 2^(-E(h(x)) / c(n))
     where c(n) = average path length of unsuccessful BST search
     
  Score interpretation:
    s → 1:    Anomaly (short path length)
    s → 0.5:  Normal (average path length)
    s → 0:    Dense cluster (long path length)
from sklearn.ensemble import IsolationForest

    random_state=42,

6. One-Class SVM

One-Class SVM learns a decision boundary around normal data in a high-dimensional feature space (via kernel mapping). Points outside this boundary are classified as anomalies. It is the SVM adaptation for novelty detection—trained exclusively on normal data.

ONE-CLASS SVM THEORY:
  Goal: Find the smallest hypersphere (or hyperplane) that
        encloses most of the training data
  
  ν-SVM formulation:
    min  ½||w||² + 1/(νn) Σξᵢ - ρ
    s.t. w·φ(xᵢ) ≥ ρ - ξᵢ,  ξᵢ ≥ 0
  
  ν parameter:
    - Upper bound on fraction of outliers in training data
    - Lower bound on fraction of support vectors
  
  Kernel trick: Maps data to high-dimensional space where a
  hyperplane can separate normal from anomalous
  
  RBF kernel (most common): K(x,y) = exp(-γ||x-y||²)
  γ controls the influence radius of each training point
from sklearn.svm import OneClassSVM

    gamma='scale',         # 1/(n_features * X.var())
    nu=0.05,               # ~5% of training data can be outliers
)

ONE-CLASS SVM vs ISOLATION FOREST:
  
  One-Class SVM:
    ✓ Works well in high-dimensional spaces (kernel trick)
    ✓ Theoretically grounded (margin maximization)
    ✓ Good when clean normal data is available (semi-supervised)
    ✗ O(n²) to O(n³) training — doesn't scale
    ✗ Sensitive to kernel and γ choice
    ✗ Requires feature scaling
    
  Isolation Forest:
    ✓ O(n log n) — scales to millions of records
    ✓ No kernel/feature scaling needed
    ✓ Works unsupervised (no clean training data needed)
    ✗ Less effective in very high dimensions
    ✗ Axis-aligned splits can miss patterns

  Rule of thumb:
    Small data + clean normals → One-Class SVM
    Large data + no labels → Isolation Forest
    Varying densities → LOF
    Very high dimensions → Isolation Forest or autoencoder

7. Autoencoder-Based Detection

Autoencoders learn to compress and reconstruct normal data. Since they are trained only on normal patterns, anomalous inputs produce high reconstruction error, serving as an anomaly score. This approach handles complex, high-dimensional, and nonlinear data.

import torch
import torch.nn as nn

class AnomalyAutoencoder(nn.Module):
    def __init__(self, input_dim, latent_dim=16):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, 64),
            nn.ReLU(),
            nn.Linear(64, 32),
            nn.ReLU(),
            nn.Linear(32, latent_dim),
        )
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 32),
            nn.ReLU(),
            nn.Linear(32, 64),
            nn.ReLU(),
            nn.Linear(64, input_dim),
        )
    
    def forward(self, x):
        latent = self.encoder(x)
        reconstructed = self.decoder(latent)
        return reconstructed

# ── Training (on normal data only) ───────────────────────
model = AnomalyAutoencoder(input_dim=X_train.shape[1])
criterion = nn.MSELoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

for epoch in range(100):
    recon = model(X_train_normal_tensor)
    loss = criterion(recon, X_train_normal_tensor)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

# ── Anomaly detection (reconstruction error) ─────────────
with torch.no_grad():
    recon = model(X_test_tensor)
    errors = torch.mean((X_test_tensor - recon) ** 2, dim=1)
    threshold = torch.quantile(errors, 0.95)
    anomalies = errors > threshold

Variational Autoencoder (VAE) for Anomaly Detection

class VAEAnomaly(nn.Module):
    def __init__(self, input_dim, latent_dim=16):
        super().__init__()
        self.encoder = nn.Sequential(nn.Linear(input_dim, 64), nn.ReLU())
        self.fc_mu = nn.Linear(64, latent_dim)
        self.fc_logvar = nn.Linear(64, latent_dim)
        self.decoder = nn.Sequential(
            nn.Linear(latent_dim, 64), nn.ReLU(),
            nn.Linear(64, input_dim)
        )
    
    def reparameterize(self, mu, logvar):
        std = torch.exp(0.5 * logvar)
        eps = torch.randn_like(std)
        return mu + eps * std
    
    def forward(self, x):
        h = self.encoder(x)
        mu, logvar = self.fc_mu(h), self.fc_logvar(h)
        z = self.reparameterize(mu, logvar)
        recon = self.decoder(z)
        return recon, mu, logvar

# Anomaly score = reconstruction error + KL divergence
# VAE captures both reconstruction quality AND latent space regularity
# Anomalies produce high reconstruction error AND unusual latent codes

9. Evaluation Metrics for Anomaly Detection

Standard accuracy is misleading for anomaly detection due to extreme class imbalance (99%+ normal). Specialized metrics focus on the detector's ability to identify anomalies without overwhelming analysts with false alarms.

KEY METRICS:
  Precision:  TP / (TP + FP)  — "Of flagged anomalies, how many are real?"
  Recall:     TP / (TP + FN)  — "Of all real anomalies, how many were caught?"
  F1-Score:   2 * P * R / (P + R) — Balance precision and recall
  
  THRESHOLD-FREE METRICS:
  PR-AUC:     Area under Precision-Recall curve
              (preferred over ROC-AUC for imbalanced data)
  ROC-AUC:    Area under ROC curve (can be misleadingly high)
  
  WHY PR-AUC > ROC-AUC for anomaly detection:
  ROC-AUC uses FPR = FP/(FP+TN). When TN is huge (99%+),
  even many false positives barely change FPR.
  PR-AUC focuses on positive class performance, which is
  what matters for anomaly detection.
from sklearn.metrics import (
    precision_recall_curve, average_precision_score,
    roc_auc_score, f1_score, classification_report
)

# ── Threshold-free evaluation ────────────────────────────
pr_auc = average_precision_score(y_true, anomaly_scores)
roc_auc = roc_auc_score(y_true, anomaly_scores)

# ── At a specific threshold ──────────────────────────────
predictions = (anomaly_scores > threshold).astype(int)
print(classification_report(y_true, predictions))

# ── Find optimal threshold via PR curve ──────────────────
precision, recall, thresholds = precision_recall_curve(y_true, anomaly_scores)
f1_scores = 2 * precision * recall / (precision + recall + 1e-8)
best_threshold = thresholds[np.argmax(f1_scores)]
DOMAIN-SPECIFIC METRIC PRIORITIES:
  Fraud detection:     High recall (catch most fraud), tolerate FPs
  Manufacturing QA:    High precision (minimize false rejects)
  Network security:    High recall (can't miss intrusions)
  Medical diagnosis:   High recall (can't miss disease)
  
  COST-SENSITIVE:
  Total cost = C_FP × FP + C_FN × FN
  Set threshold to minimize total cost, not maximize F1

import pandas as pd
import numpy as np
from sklearn.ensemble import IsolationForest
from sklearn.preprocessing import StandardScaler
import joblib
import logging

class ProductionAnomalyDetector:
    def __init__(self, contamination=0.01, model_path="anomaly_model.pkl"):
        self.contamination = contamination
        self.model_path = model_path
        self.scaler = StandardScaler()
        self.model = IsolationForest(
            n_estimators=200,
            contamination=contamination,
            random_state=42,
            n_jobs=-1
        )
        self.logger = logging.getLogger(__name__)
    
    def train(self, X_train):
        """Train on historical normal data."""
        X_scaled = self.scaler.fit_transform(X_train)
        self.model.fit(X_scaled)
        
        # Compute training score distribution for adaptive threshold
        self.train_scores = self.model.score_samples(X_scaled)
        self.threshold = np.percentile(self.train_scores,
                                        self.contamination * 100)
        self.save()
    
    def predict(self, X):
        """Score new data and flag anomalies."""
        X_scaled = self.scaler.transform(X)
        scores = self.model.score_samples(X_scaled)
        is_anomaly = scores < self.threshold
        
        return {
            "scores": scores,
            "is_anomaly": is_anomaly,
            "severity": self._compute_severity(scores),
        }
    
    def _compute_severity(self, scores):
        """Map scores to severity levels."""
        severity = np.where(
            scores < np.percentile(self.train_scores, 0.1), "CRITICAL",
            np.where(scores < np.percentile(self.train_scores, 1), "HIGH",
            np.where(scores < np.percentile(self.train_scores, 5), "MEDIUM",
            "LOW")))
        return severity
    
    def save(self):
        joblib.dump({
            "model": self.model,
            "scaler": self.scaler,
            "threshold": self.threshold,
            "train_scores": self.train_scores,
        }, self.model_path)
    
    def load(self):
        data = joblib.load(self.model_path)
        self.model = data["model"]
        self.scaler = data["scaler"]
        self.threshold = data["threshold"]
        self.train_scores = data["train_scores"]

            return False
        
        baseline = np.mean(self.anomaly_rate_history[:5])
        current = np.mean(self.anomaly_rate_history[-5:])

        return False

# ── RRCF (Robust Random Cut Forest) ─────────────────────
# Used by Amazon Kinesis Analytics
# pip install rrcf
import rrcf

forest = []
num_trees = 40
tree_size = 256

for tree_idx in range(num_trees):
    tree = rrcf.RCTree()
    forest.append(tree)

for index, point in enumerate(data_stream):
    for tree in forest:
        if len(tree.leaves) > tree_size:
            tree.forget_point(index - tree_size)
        tree.insert_point(point, index=index)
    
    # Average CoDisplacement across forest
    avg_codisp = np.mean([tree.codisp(index) for tree in forest])
    if avg_codisp > threshold:
        alert(point)

Q1: What is the difference between outlier detection and novelty detection?

A: Outlier detection (unsupervised) identifies anomalies within a dataset that may contain anomalies — the model learns what's normal and abnormal simultaneously. Novelty detection (semi-supervised) trains on clean normal data and then detects whether new observations are novel/anomalous. Example: Isolation Forest is typically used for outlier detection; One-Class SVM and autoencoders are used for novelty detection. In sklearn, LocalOutlierFactor(novelty=True) enables novelty detection mode. The key difference: outlier detection operates on contaminated data; novelty detection assumes clean training data.

Q2: Why is Isolation Forest preferred for large-scale anomaly detection?

A: (1) Speed: O(n log n) training, O(n) scoring — linearly scalable. (2) Subsampling: Uses only 256 samples per tree by default, so training cost is constant regardless of dataset size. (3) No distance computation: Avoids the curse of dimensionality that plagues KNN/LOF. (4) No feature scaling needed: Random splits are scale-invariant. (5) Works unsupervised: Doesn't need clean normal data. Limitation: axis-aligned splits can miss anomalies in correlated features — Extended Isolation Forest fixes this with random hyperplane splits.

Q3: How do you set the contamination parameter?

A: (1) Domain knowledge: If you know ~1% of transactions are fraudulent, set contamination=0.01. (2) Validation set: If labeled anomalies exist for validation, tune contamination to maximize F1 or PR-AUC. (3) Conservative default: Start with 0.01-0.05 and adjust based on analyst feedback. (4) Adaptive: Monitor flagged anomaly rate; if too many false positives, decrease contamination. (5) Avoid using contamination: Instead, use raw anomaly scores and set a domain-specific threshold on the score distribution. In production, the threshold is often set by business requirements (e.g., "flag top 100 most suspicious transactions daily").

Q4: How do you evaluate an anomaly detection model without labels?

A: (1) Internal metrics: Silhouette score (if treating normals as one cluster), anomaly score distribution bimodality. (2) Expert review: Sample top-scored anomalies and have domain experts label them — compute precision@k. (3) Downstream impact: Does the detector improve a business metric (reduced fraud losses, faster incident detection)? (4) Stability analysis: Consistent results across random seeds and subsamples? (5) Injection test: Inject synthetic anomalies with known patterns and check if the model catches them. (6) A/B test: Compare detector vs baseline (random flagging) on analyst efficiency.

Q5: How would you handle anomaly detection in high-dimensional data?

A: High dimensionality causes distance metrics to become meaningless (curse of dimensionality), making KNN/LOF unreliable. Solutions: (1) Dimensionality reduction first: PCA, UMAP, or autoencoders to reduce dimensions, then apply anomaly detection in the reduced space. (2) Isolation Forest: Doesn't use distances, works in high dimensions. (3) Autoencoder-based: Learns compressed representation; anomalies have high reconstruction error. (4) Feature selection: Use domain knowledge to select relevant features. (5) Subspace methods: Detect anomalies in different feature subsets (Feature Bagging). (6) COPOD/ECOD: Analyze marginal distributions independently, then combine — avoids curse of dimensionality.

Q6: How do you handle concept drift in anomaly detection?

A: Normal behavior changes over time (e.g., seasonal spending patterns). Solutions: (1) Sliding window retraining: Periodically retrain on recent data. (2) Online/streaming models: Use algorithms that incrementally update (Half-Space Trees, RRCF). (3) Drift detection: Monitor the anomaly rate — sudden spikes may indicate drift, not real anomalies. (4) Seasonal adjustments: If patterns are seasonal, train separate models per season or use time-aware features. (5) Feedback loop: Human reviewers label flagged items; use this to update the model. (6) Ensemble rotation: Maintain multiple models from different time periods, weight by recency.

Q8: How would you design a fraud detection system?

A: Architecture: (1) Rule-based layer: Catch known fraud patterns (velocity checks, blocked countries). (2) ML scoring layer: Ensemble of Isolation Forest + supervised model (if labels exist). Features: transaction amount, time since last transaction, device fingerprint, IP geolocation, merchant category deviation. (3) Real-time scoring: Feature store for pre-computed features + model serving (latency < 100ms). (4) Threshold tiers: Auto-block (high confidence fraud), review queue (medium), pass (low risk). (5) Feedback loop: Analyst decisions feed back for retraining. (6) Monitoring: Track precision@k daily, false positive rate, model drift. (7) Regulatory compliance: Explainable decisions (SHAP), audit trail, GDPR considerations. Key challenge: Adversarial drift — fraudsters adapt; must continuously update rules and retrain models.

Q9: When would you use supervised classification vs unsupervised anomaly detection?

A: Supervised: When sufficient labeled anomalies exist AND anomaly patterns are stable over time. Use XGBoost/LightGBM with class weights or SMOTE. Advantage: Higher accuracy for known anomaly types. Limitation: Can't detect new/unseen anomaly types. Unsupervised: When labels are unavailable, expensive to obtain, or anomalies are diverse/evolving. Use Isolation Forest, LOF, or autoencoders. Advantage: Detects unknown anomaly types. Limitation: Higher false positive rate. Hybrid approach (recommended): Supervised model for known patterns + unsupervised detector for novel anomalies. This is common in production fraud detection and security systems.

Q10: What is the role of autoencoders in anomaly detection?

A: Autoencoders learn to compress and reconstruct normal data. Training: Feed only normal data → model learns normal patterns. Detection: Anomalous inputs produce high reconstruction error because the model hasn't learned their patterns. Advantages: Handles complex data (images, sequences, high-dimensional tabular), learns nonlinear relationships, natural anomaly score. Disadvantages: Requires clean training data, architecture design is tricky, might reconstruct anomalies well if they're similar to normals. VAE advantage: Variational autoencoders add a probabilistic latent space — anomalies produce both high reconstruction error AND unusual latent codes, giving two complementary signals. In practice: Use reconstruction error percentile (e.g., 99th) as threshold. Validate with domain experts.
