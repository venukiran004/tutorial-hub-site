Lasso Regression (L1 Regularization)

Linear regression with an L1 penalty that drives some coefficients to exactly zero — fitting and selecting features at the same time.

•

1. Definition

plusabsolutesparse

Lasso (Least Absolute Shrinkage and Selection Operator) minimizes RSS plus λ times the sum of absolute coefficient values:

J(β)=∑i(yi−xiTβ)2 + λ∑j|βj|

The L1 penalty produces sparse solutions: many coefficients become exactly 0.

•

2. Intuition & how it works — the geometry

Like ridge, lasso penalizes big coefficients — but with the absolute value instead of the square. That small change has a big effect: L1 can push a coefficient all the way to zero and keep it there, removing the feature.

   L2 (Ridge): circle           L1 (Lasso): diamond
      ___                           /\
     /   \  ellipse                /  \   ellipse tends to
    | .   | touches the           /    \  touch a CORNER →
     \___/  side (β≠0)            \    /  one coordinate = 0
                                   \  /
                                    \/

Minimizing RSS subject to a budget on coefficient size means intersecting the elliptical RSS contours with the constraint region. The diamond has corners on the axes, and the contour usually first touches a corner — where some βj=0. As λ grows, more coefficients snap to zero (the regularization path).

•

3. Mathematical formulation — full derivations

not differentiable at 0coordinate descentLARSsubgradientsoft-thresholding operator0.3

3.1 Why no closed form

|βj| is not differentiable at 0, so we can't set a gradient to zero globally. Lasso is solved by coordinate descent (optimize one βj at a time) or LARS.

3.2 Subgradient → soft-thresholding (the key step)

For one standardized coordinate, holding the others fixed, the optimum uses the subgradient of |βj| (which is $[-1,1]$ at 0). The solution is the soft-thresholding operator:

 β̂j=Sλ/2(zj)=sign(zj) (|zj|−λ2)+ 

where zj is the unregularized (OLS) coordinate update and (·)+=max(·,0). Read it literally: any coordinate whose signal |zj| is below the threshold λ/2 is set to exactly 0 — that is the selection mechanism. (Compare ridge, which scales each coefficient by 11+λ — never zero.)

3.3 Worked example — soft-thresholding zeroes small signals

With threshold λ/2 = 0.5:

OLS signal zj|zj|−0.5Lasso β̂j
0.80.30.3 (shrunk, kept)
0.3−0.2 → 00 (dropped)
−1.20.7−0.7 (shrunk, kept)

Two features survive (shrunk toward 0), one is eliminated — selection and shrinkage together.

3.4 Bayesian view

Lasso is the MAP estimate under a Laplace (double-exponential) prior p(βj)∝ e−|βj|/b. The Laplace prior's sharp peak at 0 is what produces sparsity (vs ridge's smooth Gaussian prior).

•

12. Interview deep dive

Q2. Derive the lasso updateQ3. Why no closed form?Q5. Bayesian prior?Q6. Max features when $p>n$?Q8. How do you choose λ?Q9. Lasso vs stepwise selection?

Q1. Why does L1 give sparsity but L2 doesn't? The L1 constraint region (diamond) has corners on the axes (coordinates = 0) and the loss contour tends to touch a corner; L2's circle has no corners. Algebraically, L1's soft-thresholding zeroes small coefficients; L2 only scales them.

Q2. Derive the lasso update. Per coordinate, the subgradient optimum is soft-thresholding Sλ/2(zj)=sign(zj)(|zj|−λ/2)+.

Q3. Why no closed form? |β| is non-differentiable at 0 → solved by coordinate descent / LARS.

Q4. Lasso with correlated features? It arbitrarily keeps one and drops the rest — the motivation for Elastic Net.

Q5. Bayesian prior? Laplace (double-exponential), sharply peaked at 0.

Q6. Max features when p>n? At most $n$ (a structural limitation).

Q7. Does "coefficient = 0" mean the feature is useless? Not necessarily — a correlated twin may have absorbed its signal.

Q8. How do you choose λ? Cross-validation (LassoCV); inspect the regularization path.

Q9. Lasso vs stepwise selection? Lasso is a continuous, convex relaxation of subset selection — more stable and computationally tractable.

Q10. Why standardize? L1 penalizes raw coefficient magnitudes, which depend on feature scale.

•

13. Common mistakes & best practices

  • ❌ Using lasso for selection on highly collinear features (unstable) — use Elastic Net.
  • ❌ Forgetting to standardize.
  • ❌ Treating zeroed features as proven irrelevant.
  • ✅ Tune alpha with LassoCV; inspect the path.
  • ✅ Use lasso as a fast feature-selection pre-step, then refit on survivors.
•

14. One-paragraph summary

exactly zerosoft-thresholdingRelated

Lasso adds an L1 penalty λ‖β‖1 to OLS, and because the L1 geometry has corners on the axes it drives many coefficients to exactly zero — doing feature selection and shrinkage together. It has no closed form (the absolute value is non-smooth) and is solved by coordinate descent via soft-thresholding Sλ/2(z)=sign(z)(|z|−λ/2)+, equivalently the MAP estimate under a Laplace prior. It excels in high-dimensional sparse problems but is unstable with correlated features (keeps one arbitrarily) and caps at $n$ selected features when p>n — both fixed by Elastic Net. Standardize and tune λ by CV.

Supervised dimensionality reduction (and a classifier) that projects data to maximize class separation — PCA's label-aware cousin.

1. Definition

separates classesclassifier

LDA finds the linear projection that best separates classes: it maximizes the distance between class means while minimizing the spread within each class. It doubles as a classifier (assuming each class is Gaussian with a common covariance, giving a linear decision boundary).

•

2. Intuition & how it works

class means are far aparttight

PCA picks the direction of most variance — but that may not separate classes. LDA picks the direction where the class means are far apart and each class is tight. The projection makes classes as distinguishable as possible.

PCA axis (max variance)        LDA axis (max separation)
 ○○●●○●○●  ← classes overlap     ○○○○ | ●●●●  ← classes split cleanly
•

3. Mathematical formulation — Fisher's criterion

Within-classBetween-classFisher ratiogeneralized eigenproblemat most $C-1$As a classifier (Gaussian view)

Define scatter matrices:

  • Within-class: SW=∑c∑i∈ c(xi−μc)(xi−μc)T
  • Between-class: SB=∑c nc(μc−μ)(μc−μ)T (μ = global mean)

Maximize the Fisher ratio (separation / spread):

J(w)=wT SBwwT SWw

Setting the derivative to zero gives the generalized eigenproblem:

SBw=λ SWw Longleftrightarrow  SW−1SBw=λw

The top eigenvectors are the discriminant directions; because SB has rank ≤ C−1, there are at most $C-1$ useful components (e.g. 1 for binary classification).

As a classifier (Gaussian view): assuming each class ~𝒩(μc,Σ) with shared Σ, the Bayes decision rule is linear in x (the quadratic terms cancel). Relaxing to per-class covariance gives QDA (quadratic boundary).

•

Use when: supervised dimensionality reduction, classes are roughly Gaussian with similar covariance, or you want a fast linear classifier + 2-D visualization. 12. Interview deep dive

Q1. LDA vs PCA?Q2. What does LDA maximize?Q3. Why at most $C-1$ components?Q4. LDA vs QDA?Q5. LDA vs logistic regression?generative

Q1. LDA vs PCA? PCA is unsupervised (max variance); LDA is supervised (max between/within-class scatter) — LDA keeps discriminative directions PCA may discard.

Q2. What does LDA maximize? Fisher's ratio wT SBwwT SWw, solved as SW−1SBw=λw.

Q3. Why at most $C-1$ components? SB has rank ≤ C−1 (built from $C$ class means around the global mean).

Q4. LDA vs QDA? LDA assumes a shared covariance → linear boundary; QDA allows per-class covariance → quadratic boundary (more flexible, more parameters).

Q5. LDA vs logistic regression? Both linear classifiers; LDA is generative (models class Gaussians), logistic is discriminative — LDA is better with small data when its assumptions hold, logistic more robust otherwise.

Q6. What if SW is singular? Use shrinkage LDA or reduce dimensions (PCA) first.

Q7. Is LDA scale-sensitive? Yes — standardize features.

•

13. Common mistakes & best practices

  • ❌ Using LDA when class covariances differ a lot (use QDA).
  • ❌ Ignoring the $C-1$ dimension cap.
  • ❌ Running on p>n without shrinkage.
  • ✅ Standardize; use shrinkage='auto' for high-dimensional/collinear data.
  • ✅ Use LDA both to reduce dims and as a fast baseline classifier.
•

14. One-paragraph summary

LDA is supervised dimensionality reduction that maximizes Fisher's ratio of between-class to within-class scatter, solved as the generalized eigenproblem SW−1SBw=λw, yielding at most $C-1$ discriminant directions — and, assuming Gaussian classes with shared covariance, a linear classifier. Unlike PCA it uses labels, so it preserves class-separating directions, but it is linear, assumes equal-covariance Gaussians (relax to QDA otherwise), needs an invertible SW (use shrinkage when p>n), and is scale-sensitive.

1. Definition

histogramsleaf-wiseGOSSEFB

LightGBM is a gradient-boosting framework that bins continuous features into histograms, grows trees leaf-wise (best-first) rather than level-wise, and uses GOSS and EFB to cut the cost of finding splits — XGBoost-level accuracy, much faster, especially on large high-dimensional data.

•

2. Intuition & how it works

Histogram binningLeaf-wise growthGOSS + EFB

Three ideas make it "light":

  1. Histogram binningbucket each feature into ~255 bins; only consider bin edges as split candidates → big speedup, negligible accuracy loss.
  2. Leaf-wise growthsplit the single leaf with the highest loss reduction next (not level-by-level), reaching low loss with fewer leaves — but can grow deep/imbalanced (overfit risk), controlled by num_leaves/max_depth.
  3. GOSS + EFB reduce data/features scanned per split.
Level-wise (XGBoost default)      Leaf-wise (LightGBM)
        o                                o
       / \                              / \
      o   o                            o   o
     / \ / \                          / \
    o  o o  o                        o   o   ← keeps splitting the worst leaf
•

3. Mechanisms (what's distinctive)

large-gradientrandomly subsampleEFB (Exclusive Feature Bundling)bundles
  • GOSS (Gradient-based One-Side Sampling): keep all large-gradient instances (the under-fit, informative ones), randomly subsample small-gradient ones, reweighting to stay unbiased — fewer rows per split, similar accuracy.
  • EFB (Exclusive Feature Bundling): in sparse/high-dim data many features are rarely non-zero simultaneously (e.g. one-hot columns); EFB bundles mutually-exclusive features into one, shrinking dimensionality.
  • Split gain uses the same gradient/Hessian similarity score as XGBoost, computed over histogram bins.
•

4. Assumptions

Tree-based → no statistical assumptions. Practical: enough data per leaf (leaf-wise overfits small data), bounded effective depth, small learning rate.

Q1. LightGBM vs XGBoost?Q2. Leaf-wise growth and its risk?Q3. What does GOSS do?Q4. What does EFB do?Q5. Why histograms?Q6. num_leaves vs max_depth?

Q1. LightGBM vs XGBoost? Histogram binning + leaf-wise growth + GOSS/EFB → faster, lower memory on big data; XGBoost is level-wise (default), robust, safer on small data.

Q2. Leaf-wise growth and its risk? Always splits the highest-loss leaf → fewer leaves per loss, but can grow deep/imbalanced and overfit; bound with num_leaves/max_depth.

Q3. What does GOSS do? Keeps large-gradient samples, subsamples small-gradient ones (reweighted) — fewer rows per split without bias.

Q4. What does EFB do? Bundles mutually-exclusive sparse features to reduce dimensionality.

Q5. Why histograms? Far fewer split candidates (bin edges) → speed + memory.

Q6. num_leaves vs max_depth? num_leaves is the real complexity control; keep it < 2max_depth or the depth cap is meaningless.

Q7. Why overfit on small data? Leaf-wise growth chases a few high-loss points; regularize / fewer leaves.

histogram binningleaf-wiseGOSSEFBRelated

LightGBM speeds up gradient boosting with histogram binning (few split candidates), leaf-wise best-first growth (fewer leaves for the same loss), GOSS (keep large-gradient rows, subsample the rest) and EFB (bundle exclusive sparse features). The result is XGBoost-level accuracy that's much faster and lighter on large, high-dimensional, categorical-rich data — at the cost of overfitting small datasets via leaf-wise growth, so the critical knob is num_leaves (with min_data_in_leaf and regularization), plus early stopping.

1. Definition

conditional expectationlinear combinationsquared errorin the parameters

Linear regression models the conditional expectation of a continuous target $y$ as a linear combination of input features:

𝔼[y | x] = ŷ = β0 + β1 x1 + β2 x2 + … + βp xp = xTβ

It learns the coefficients β that make predictions as close as possible to the observed targets, where "close" is measured by squared error. "Linear" refers to linearity in the parameters β — not in the features (you can feed it x2 and it's still linear regression).

•

2. Intuition & how it works

pricesizesloperesidualWhy squared error?maximum-likelihood

Plot house price against size. Linear regression draws the single straight line sitting "in the middle" of the cloud of points — the line whose vertical gaps (residuals) to the points are smallest in total squared terms.

  • Each coefficient βj is the slope in that direction: "holding everything else fixed, one more unit of xj changes the prediction by βj."
  • The intercept β0 is the prediction when all features are 0.
  • A residual ei = yi − ŷi is the leftover error for point $i$. We want the line that minimizes ∑ ei2.
price │              •  ← actual point
      │           ╱  ↕ residual eᵢ = yᵢ − ŷᵢ
      │        •╱
      │      ╱•          ╱ = fitted line ŷ = β₀ + β₁·size
      │   •╱             minimizes Σ eᵢ²  (squared vertical gaps)
      └──────────────── size

Why squared error? Three reasons: (1) it's smooth and differentiable, so we can solve it with calculus; (2) it penalizes large misses much more than small ones; (3) it's the maximum-likelihood solution when noise is Gaussian (§3.6).

3. Mathematical formulation — full derivations

This is the section interviewers probe. We derive everything from first principles.

3.1 The objective

Choose β to minimize the residual sum of squares (RSS), also the cost $J$:

J(β) = RSS = n∑i=1(yi − ŷi)2 = n∑i=1(yi − xiTβ)2

3.2 Simple regression — deriving slope & intercept by calculus

With one feature, J(β0,β1)=∑i (yi−β0−β1 xi)2. Minimize by setting both partial derivatives to zero (the normal equations):

∂ J∂ β0 = −2∑i(yi−β0−β1 xi)=0   ⇒   ȳ = β0 + β1x̄   ⇒   β0 = ȳ−β1x̄ ∂ J∂ β1 = −2∑i xi(yi−β0−β1 xi)=0   ⇒   ∑i xi yi = β0∑i xi + β1∑i xi2

Substitute β0=ȳ−β1x̄ into the second equation and simplify (using ∑ xi yi − nx̄ȳ=∑(xi−x̄)(yi−ȳ) and ∑ xi2 − nx̄2 = ∑(xi−x̄)2):

 β1 = ∑i(xi−x̄)(yi−ȳ)∑i(xi−x̄)2 = Cov(x,y)Var(x) 

Two facts worth remembering: the slope is covariance over variance, and the line always passes through the centroid (x̄,ȳ).

3.6 Geometric view — projection

ŷ = Xβ̂ = X(XT X)−1XTH, the "hat" matrixy. $H$ projects $y$ orthogonally onto the column space of $X$. The residual e = y−ŷ is orthogonal to every feature: XT e = 0. Intuition: OLS finds the point in the space spanned by the features that is closest (in Euclidean distance) to $y$.

3.7 Probabilistic view — OLS is the MLE under Gaussian noise

Assume yi = xiTβ + εi with εi~𝒩(0,σ2) iid. The log-likelihood is

ℓ(β) = −n2log(2πσ2) − 12σ2∑i(yi−xiTβ)2

Only the last term depends on β, and it is −12σ2RSS. Maximizing the likelihood = minimizing RSS, so the MLE equals the OLS estimate. This is why squared error is the "right" loss under Gaussian noise.

Q1. Derive the OLS solution. Minimize ‖ y−Xβ‖2; gradient −2XT(y−Xβ)=0 ⇒ XT Xβ=XT y ⇒ β̂=(XT X)−1XT y.

Q2. Why squared error, not absolute error? Squared error is smooth (closed-form solution) and is the MLE under Gaussian noise; MAE (quantile/LAD regression) is robust to outliers but non-differentiable at 0.

Q3. What is the Gauss–Markov theorem? Under linearity, independence, homoscedasticity, exogeneity, OLS is the minimum-variance linear unbiased estimator — no normality required.

Q4. When is normality needed? Not for point estimates or BLUE — only for valid confidence intervals / p-values in small samples (large samples lean on the CLT).

Q5. R² vs adjusted R²? R² never decreases when adding features; adjusted R² penalizes extra predictors, so use it to compare models of different sizes.

Q6. Does multicollinearity hurt prediction? Often not much — it mainly inflates coefficient variance and ruins interpretability. Detect with VIF; fix with Ridge.

Q7. How do you model non-linearity while staying "linear"? Add polynomial / interaction / spline features — the model stays linear in the parameters.

Q8. Homoscedasticity is violated — are coefficients wrong? No, they stay unbiased; only the standard errors are wrong. Use robust (HC) standard errors or WLS.

Q9. Normal equation vs gradient descent — when each? Normal equation for small $p$ (exact, no tuning); gradient descent for large $n$/$p$ or ill-conditioned data.

Q10. What is the hat matrix? H=X(XT X)−1XT projects $y$ onto the feature column space; ŷ = Hy; its diagonal gives leverage.

Q11. Why can't OLS solve p>n? XT X is singular (rank deficient) → not invertible. Ridge fixes it by adding λ I.

Q12. Interpret a coefficient. "Holding other features fixed, a one-unit increase in xj changes the predicted $y$ by βj." (Causal only under exogeneity.)

Q13. What does a residuals-vs-fitted plot tell you? Curvature ⇒ non-linearity; funnel ⇒ heteroscedasticity; a clear pattern ⇒ a missing feature/term.

Q14. Linear regression vs logistic regression? Same linear core; linear predicts an unbounded continuous value (MSE loss), logistic squashes it to a probability (log-loss) for classification.

Q15. How do outliers affect OLS? Squared error gives them outsized influence; a single high-leverage outlier can swing the line — use robust regression or remove it.

Linear regression fits ŷ = Xβ by minimizing squared error, giving the closed form β̂=(XT X)−1XT y (equivalently the MLE under Gaussian noise, equivalently an orthogonal projection of $y$ onto the feature space). 1. Definition

Logistic regression predicts the probability that an observation belongs to the positive class by passing a linear score through the sigmoid (logistic) function:

P(y=1|x) = σ(xTβ) = 11+e−xTβ

A threshold (default 0.5) turns the probability into a class label. It is a linear model for the log-odds of the outcome.

•

2. Intuition & how it works

sigmoidstraight decision boundary

Linear regression outputs any real number — useless for a probability that must lie in $[0,1]$. The sigmoid bends the unbounded linear score into an S-curve between 0 and 1:

P(y=1) 1 ┤            ╭────────
         │         ╱
     0.5 ┤───────╱   ← decision boundary at score z = 0
         │     ╱
       0 ┤────╯
         └──────────────────── z = xᵀβ
        −∞        0         +∞
  • Large positive score → probability near 1.
  • Score 0 → probability 0.5 (the boundary).
  • Large negative score → probability near 0.

The model draws a straight decision boundary in feature space but expresses confidence smoothly as you move away from it.

•

3. Mathematical formulation — full derivations

oddslog-oddsodds ratioBernoullilog-loss / binary cross-entropyno closed-form solution

3.1 From odds to the logit

Define the odds of the positive class as p1−p. Logistic regression assumes the log-odds are linear in the features:

lnp1−p = xTβ  (the "logit")

Solve for $p$ to recover the sigmoid:

p1−p=exTβ  ⇒  p = exTβ1+exTβ = 11+e−xTβ = σ(xTβ)

So eβj is the odds ratio: the multiplicative change in odds per unit increase of xj.

3.2 The sigmoid and its derivative

σ(z)=11+e−z,    σ'(z)=σ(z)(1−σ(z))

Proof: σ'(z)=e−z(1+e−z)2=11+e−z·e−z1+e−z=σ(z)(1−σ(z)). This tidy derivative is what makes the gradient clean.

3.3 The loss — from maximum likelihood to cross-entropy

Each label is Bernoulli: P(y|x)=py(1−p)1−y. The likelihood over $n$ independent samples is ∏i piyi(1−pi)1−yi. Take the negative log-likelihood → the log-loss / binary cross-entropy:

ℒ(β) = −n∑i=1[yiln pi + (1−yi)ln(1−pi)],    pi=σ(xiTβ)

Minimizing log-loss is maximizing the Bernoulli likelihood.

3.4 The gradient (the classic whiteboard derivation)

For one sample with z=xTβ and p=σ(z):

∂ℒ∂ p=−yp+1−y1−p=p−yp(1−p),    ∂ p∂ z=p(1−p)

Chain them — the $p(1-p)$ terms cancel beautifully:

∂ℒ∂ z=p−y  ⇒  ∇βℒ=(p−y) x

Over the whole dataset:

 ∇βℒ = XT(p−y) 

Identical in form to linear regression's gradient — just with the predicted probability p in place of ŷ.

3.5 No closed form, but convex

Setting ∇=0 gives XT(p−y)=0, which is non-linear in β (because p=σ) → no closed-form solution. But the loss is convex (its Hessian XT S X with S=diag(pi(1−pi))succeq0 is positive semi-definite), so iterative methods reach the global optimum:

  • Gradient descent: β←β−α XT(p−y).
  • Newton's method / IRLS (used by lbfgs/newton-cg): uses the Hessian to converge in few iterations.

3.6 Worked example

Predict pass/fail from hours studied with β0=−4, β1=1.5.

  • For 3 hours: z=−4+1.5(3)=0.5, p=σ(0.5)=11+e−0.5=0.62 → predict pass (62%).
  • Odds ratio: eβ1=e1.5=4.48 → each extra hour multiplies the odds of passing by ~4.5×.
  • One gradient step (sample y=1, p=0.62, x=[1,3]): ∇=(p−y)x=(0.62−1)[1,3]=[−0.38,−1.14]. Update β←β−α∇ increases both coefficients (gradient is negative), pushing $p$ toward 1 — exactly what we want for a true positive.

3.7 Multiclass — softmax

For $K$ classes, generalize the sigmoid to the softmax: P(y=k|x)=exTβk∑jexTβj (multinomial logistic regression), or train one-vs-rest binary models.

1. Definition

Naive Bayes predicts the class with the highest posterior probability via Bayes' theorem, assuming all features are independent given the class:

P(y| x1,…,xp)∝ P(y)p∏j=1 P(xj| y)

The "naive" part is that product — it pretends features don't interact.

•

2. Intuition & how it works

Why it works despite being "wrong"argmax

To classify an email as spam, ask: "how likely is each word under spam vs ham?" Multiply those per-word likelihoods with the prior probability of spam and pick the bigger result. The independence assumption is what lets us multiply per-feature probabilities instead of estimating an impossible joint distribution.

Why it works despite being "wrong": even when features are correlated, Naive Bayes often still ranks the correct class highest — it only needs the right argmax, not perfectly calibrated probabilities.

•

3. Mathematical formulation (with a worked calculation)

Bayes' theoremWorked examplepredict NoLaplace (add-one) smoothingLog space

Bayes' theorem: P(y|x)=P(y)P(x| y)P(x). P(x) is constant across classes, so

ŷ=argmaxy P(y)∏j P(xj| y)

The independence assumption turns the intractable joint P(x| y) into a product of 1-D likelihoods we can estimate.

Worked example. Predict Play from Outlook, Wind. Training counts:

Yes (9)No (5)
Outlook=Sunny2/93/5
Wind=Strong3/93/5

Priors P(Yes)=9/14, P(No)=5/14. Query (Sunny, Strong):

Yes: 914·29·39=0.0476,    No: 514·35·35=0.129

Normalize: P(No|x)=0.1290.0476+0.129=0.73 → predict No.

Laplace (add-one) smoothing. If a value never co-occurs with a class, P=0 zeroes the whole product. Fix with a pseudo-count α:

P(xj| y)=count(xj,y)+αcount(y)+α K

($K$ = number of values of xj.) Log space avoids underflow from multiplying many small probabilities: maximize log P(y)+∑jlog P(xj| y).

1. Definition

PCA finds a new orthogonal coordinate system (the principal components) such that the first axis captures the most variance, the second the most of the remaining variance, and so on. Projecting onto the top $m$ components reduces dimensionality while preserving as much variance as possible.

•

2. Intuition & how it works

Imagine an elongated cloud of 2-D points. PCA finds the long axis of the cloud (most spread = PC1) and the perpendicular short axis (PC2). Re-express each point in those axes; drop the short one → 1-D data that keeps most of the information.

 x₂ │      ╱ PC1 (max variance)
    │    ╱•••
    │  ╱••••• ╲ PC2 (⟂, less variance)
    │╱•••••
    └────────── x₁

PCA is unsupervised — it knows nothing about labels; it just chases variance.

•

3. Mathematical formulation — derivation

covariance matrixMaximize projected varianceeigenvalueexplained variance ratioWorked sketchProcedure

Center the data ($X$ has zero mean). The covariance matrix is Σ=1n XT X.

Maximize projected variance. Find the unit direction w maximizing the variance of projections Var(Xw)=wTΣw subject to ‖w‖=1. Lagrangian wTΣw−λ(wTw−1); set derivative to 0:

Σw=λw

So principal components are eigenvectors of the covariance matrix, and the variance captured by each is its eigenvalue λ. The explained variance ratio of component $i$ is λi/∑jλj.

SVD link (how it's actually computed): X=UDVT → the columns of $V$ are the principal components and λi=di2/n. SVD is numerically preferred over forming Σ.

Worked sketch. Covariance Σ=[

Procedure: standardize → covariance (or SVD) → eigen-decompose → sort by eigenvalue → project onto top $m$ components.

1. Definition

Polynomial regression models the target as a polynomial of the features and is fit as ordinary linear regression on expanded features (x, x2, …, xd). It is non-linear in $x$ but linear in the coefficients β — so all of linear regression's machinery applies.

•

2. Intuition & how it works

Worked exampleinteraction terms

A straight line can't fit a U-shape. But if we invent a new feature x2 and regress on both $x$ and x2, the same linear machinery bends the fit into a parabola; add x3 for an S-curve, and so on.

y │        •            degree 1 (line): underfits
  │      •  ╱· · · ·     degree 2 (parabola): good fit
  │    • ╱               degree 15: wiggles through every point (overfit)
  │  •_╱
  └──────────── x

Worked example. Fit degree 2 → ŷ = 1 + 0.5x + 2x2. At x=3: $1+1.5+18=20.5$. We never left linear regression; we just fed it [x, x2] as columns. For multiple features, "polynomial" also includes interaction terms xixj — often the most useful part.

•

3. Mathematical formulation

Feature explosionDegree controls bias–varianceRunge's phenomenon

Build the design matrix Φ of polynomial/interaction features and solve plain OLS:

β̂=(ΦTΦ)−1ΦT y,    Φ=[1,x,x2,…,xd]

Feature explosion. With $p$ features and degree $d$, the number of terms is (p+dd). For p=10, d=3 → 286 features. This is the central practical cost.

Degree controls bias–variance: low $d$ → high bias (underfit); high $d$ → high variance (overfit, wild oscillation between points = Runge's phenomenon).

1. Definition

ensemble of decision treesmajority voteaverage

A Random Forest is an ensemble of decision trees, each trained on a bootstrap sample of the rows and a random subset of features at each split. Predictions are the majority vote (classification) or average (regression) across all trees.

•

2. Intuition & how it works

high varianceaverageBagging (bootstrap aggregating)Random feature subsettingdecorrelates

A single deep tree overfits — low bias, high variance. Train many trees on slightly different data and average them: random errors cancel, signal remains. Two randomizations keep trees from being identical (which would make averaging useless):

  1. Bagging (bootstrap aggregating): each tree sees a different random sample of rows (with replacement).
  2. Random feature subsetting: each split considers only a random subset of features → decorrelates the trees so one dominant feature doesn't make them all alike.
•

3. Mathematical formulation

lowering correlation ρfree, built-in validation estimatebiasedpermutation importance

3.1 Why averaging works (the variance formula)

Averaging $B$ identically-distributed trees with variance σ2 and pairwise correlation ρ gives ensemble variance

Var=ρσ2 + 1−ρBσ2

More trees ($B$) shrink the second term; lowering correlation ρ (feature subsetting) shrinks the first — the key insight and why feature subsetting matters.

3.2 Prediction

  • Classification: ŷ=mode{Tb(x)} (or average class probabilities).
  • Regression: ŷ=1B∑b Tb(x).

3.3 Out-of-bag (OOB) error

Each bootstrap omits ~37% of rows (lim(1−1n)n=e−1=0.368). Predict each row using only the trees that didn't see it → a free, built-in validation estimate, no separate hold-out needed.

3.4 Feature importance

Average impurity decrease per feature (fast, but biased toward high-cardinality features) — or permutation importance (slower, unbiased).

•

4. Assumptions

Inherits trees' near-absence of statistical assumptions: no linearity, distribution, or scaling assumptions. Implicitly assumes trees can be made diverse (enough features/rows to decorrelate) and the training data is representative.

•

2. Intuition & how it works

Plain OLS can hand you huge, opposing coefficients when features are correlated — great on training data, terrible on new data. Ridge says: "fit the data, but keep the coefficients small." λ is the price per unit of coefficient size.

  • λ=0 → OLS (no shrinkage).
  • λ→∞ → all coefficients → 0 (model → the mean).
  • Intermediate λ → the sweet spot from cross-validation.

Why it stabilizes. If two features are near-identical, OLS might pick β=(+1000,−998) (huge, unstable). Ridge prefers β≈(+1,+1) — same prediction, tiny coefficients — because the penalty punishes 10002 enormously.

3. Mathematical formulation — full derivations

3.1 The closed form

J(β)=(y−Xβ)T(y−Xβ)+λβTβ

Gradient: ∇β J = −2XT(y−Xβ)+2λβ = 0. Solve:

XT Xβ+λβ = XT y  ⇒  (XT X+λ I)β = XT y  β̂ridge = (XT X+λ I)−1XT y 

Compare OLS's (XT X)−1XT y: ridge just adds λ to the diagonal.

3.2 Why it always has a solution

XT X is PSD with eigenvalues ≥0; adding λ I shifts them to ≥λ>0, making (XT X+λ I) strictly positive definite → always invertible, even when XT X is singular (perfect collinearity, or p>n). OLS cannot solve those; ridge can.

3.3 SVD view — exactly how it shrinks

Write X=U D VT (SVD, singular values dj). Then the fitted values are

ŷridge = ∑j uj dj2dj2+λ ujT y

Each direction is scaled by the shrinkage factor dj2dj2+λ∈(0,1). Directions with small dj (low-variance, the unstable ones) are shrunk most — exactly where OLS blows up. The effective degrees of freedom are ∑j dj2dj2+λ≤ p.

3.4 Bayesian view

Ridge is the MAP estimate with a Gaussian prior β~𝒩(0,τ2 I) and Gaussian likelihood: the log-posterior is −12σ2RSS−12τ2‖β‖2, i.e. ridge with λ=σ2/τ2. A tighter prior (small τ) = larger λ = more shrinkage.

1. Definition

maximum-margin hyperplanesupport vectorskernel trick

An SVM finds the maximum-margin hyperplane separating classes — the boundary as far as possible from the nearest points of each class (the support vectors). For non-linear data, the kernel trick maps inputs into a higher-dimensional space where a linear separator exists. SVR is the regression variant.

•

2. Intuition & how it works

Many lines separate two classes; SVM picks the one with the biggest "buffer zone," because a wide margin generalizes best. Only the points on the buffer's edge — the support vectors — matter; the rest could be deleted without changing the boundary.

  • Hard margin: perfect separation (rarely works on real data).
  • Soft margin: allow some violations via C (handles noise/overlap).

3. Mathematical formulation — full derivation

large Csmall Cdualonly through dot productskernel trickonly

3.1 Margin

Decision function ŷ=sign(wTx+b). The two margin planes are wTx+b=±1; the distance between them is 2‖w‖. Maximizing the margin = minimizing ‖w‖.

3.2 Soft-margin primal

minw,b,ξ 12‖w‖2 + C∑iξi  s.t.  yi(wTxi+b)≥ 1−ξi, ξi≥0

ξi = slack (how far a point intrudes). C trades margin width vs violations: large C = punish violations → narrow margin (overfit risk); small C = tolerate violations → wide margin (underfit risk). (C≈ 1/λ.)

3.3 Lagrangian dual (where kernels enter)

Introducing multipliers αi≥0 and eliminating w,b gives the dual:

maxα ∑iαi − 12∑i,jαiαj yi yj xiTxj  s.t.  0≤αi≤ C, ∑iαi yi=0

with w=∑iαi yixi. Two crucial facts:

  1. The data appears only through dot products xiTxj → the kernel trick.
  2. By KKT conditions, αi>0 only for support vectors → the solution is sparse in the data.

3.4 Hinge-loss view (link to other linear models)

minw λ2‖w‖2 + ∑imax(0, 1−yi(wTxi+b))

SVM = L2-regularized hinge loss (vs logistic's log-loss).

3.5 The kernel trick

Replace dot products with a kernel K(xi,xj)=φ(xi)Tφ(xj), which computes a dot product in a high-dimensional space without computing φ. The XOR problem isn't linearly separable in 2D but is after a degree-2 polynomial map — at the cost of one (xTz+1)2 evaluation.

3.6 SVR (regression)

SVR fits a function flat within an ε-tube around the data, penalizing only points outside the tube (ε-insensitive loss) — the regression mirror of the margin.

Q1. What are support vectors? The training points on/inside the margin — the only ones that define the boundary; removing the rest changes nothing.

Q12. Why is SVM slow on big data? Kernel matrix / QP is O(n2)–O(n3).

1. Definition

nearby points stay nearbyplots

t-SNE embeds high-dimensional points into 2-D/3-D so that nearby points stay nearby. It models pairwise similarities as probabilities in both spaces and arranges the low-d points to match the high-d neighbor distribution. It's built for plots, not as a preprocessing step.

•

2. Intuition & how it works

For each point, ask "who are my neighbors and how close?" in the original space, then place points on a 2-D canvas so those neighbor relationships are reproduced. Crowded faraway points are pushed apart by a heavy-tailed distribution in the low-d space, which spreads clusters out so they're visible.

•

3. Mathematical formulation

High-d similaritiesperplexityLow-d similaritiesObjectiveKL divergencecrowding problem

High-d similarities (Gaussian, symmetrized): pij∝exp(−‖ xi−xj‖2/2σi2). Each σi is set so the neighborhood has a target perplexity (a smooth measure of the effective number of neighbors).

Low-d similarities (Student-t, 1 dof — heavy tail):

qij=(1+‖ yi−yj‖2)−1∑k≠ l(1+‖ yk−yl‖2)−1

Objective: minimize the KL divergence between the two distributions by gradient descent:

KL(P‖ Q)=∑i≠ jpijlogpijqij

The Student-t tail solves the crowding problem (in high-d there's "more room"), letting clusters separate. Because KL is asymmetric, t-SNE prioritizes preserving local (small distance) structure and largely ignores global distances.

wj*=−∑i∈ Ijgi∑i∈ Ijhi+λ,    score=−12∑j(∑i∈ Ijgi)2∑i∈ Ijhi+λ+γ T

Gain=12[(∑L g)2∑L h+λ+(∑R g)2∑R h+λ−(∑L∪ Rg)2∑L∪ Rh+λ]−γ

A split is kept only if gain > γ → built-in pruning. This Newton + regularization recipe is XGBoost's core.

Native API & DMatrix

The sklearn wrapper above hides XGBoost's own data structure. The native API trains on a DMatrix — XGBoost's internal, optimized matrix that stores the data in a compressed, column-block format, pre-buckets features into histogram bins, and caches the gradients/ Hessians. It's what makes XGBoost fast and memory-efficient, and it natively encodes missing values and per-row weights.

import xgboost as xgb

dtrain = xgb.DMatrix(X_train, label=y_train, missing=np.nan, weight=sample_weight)
dvalid = xgb.DMatrix(X_val,   label=y_val)
dtest  = xgb.DMatrix(X_test)

params = {"max_depth": 6, "eta": 0.03, "subsample": 0.8,
          "lambda": 1.0, "objective": "binary:logistic", "eval_metric": "logloss",
          "tree_method": "hist"}        # "gpu_hist" for GPU

booster = xgb.train(
    params, dtrain, num_boost_round=2000,
    evals=[(dvalid, "valid")], early_stopping_rounds=50, verbose_eval=False,
)
pred = booster.predict(dtest)           # probabilities

Why it matters: the sklearn XGBClassifier/XGBRegressor build a DMatrix internally, so you rarely touch it — but the native xgb.train + DMatrix path is preferred for large data, custom objectives, xgb.cv, fine-grained control, and is what most XGBoost docs/ examples use. Use QuantileDMatrix to save memory with the histogram method.

12. Interview deep dive

second-orderQ2. How does it pick splits?default directionQ4. XGBoost vs LightGBM?Q5. Why second-order?Q6. What does min_child_weight do?

Q1. What makes XGBoost "extreme" vs vanilla GBM? Regularized objective (γ T+12λ∑ wj2), second-order Taylor (gradient + Hessian), sparsity-aware split finding, parallel/cache-optimized engineering.

Q2. How does it pick splits? Similarity-gain formula; keep only if gain > γ (built-in pruning).

Q3. How does it handle missing values? Learns a default direction per split.

Q4. XGBoost vs LightGBM? LightGBM = histogram + leaf-wise + GOSS/EFB → faster on big data; XGBoost = level-wise default, very robust.

Q5. Why second-order? Newton steps use curvature for better-sized updates than gradient-only boosting.

Q6. What does min_child_weight do? Minimum sum of Hessians in a leaf — a regularizer (larger = more conservative splits).

Q7. Role of gamma? Minimum gain required to make a split (complexity penalty / pruning).

Q8. How to prevent overfitting? Low eta, shallow depth, subsampling, lambda/ alpha/gamma, early stopping.

Q9. What is a DMatrix? XGBoost's internal optimized data structure — compressed column blocks with pre-binned features and cached gradients/Hessians; it encodes missing values and row weights and is what xgb.train consumes (the sklearn wrapper builds one internally). Use QuantileDMatrix to cut memory with tree_method="hist".

13. Common mistakes & best practices

  • ❌ High learning rate + few rounds.
  • ❌ No early stopping; no regularization on noisy data.
  • ❌ One-hot encoding very high-cardinality categoricals.
  • ✅ Low eta (0.01–0.05) + many rounds + early stopping.
  • ✅ Tune depth, min_child_weight, gamma, subsampling, lambda.
  • ✅ Use GPU/hist for large data.

14. One-paragraph summary

regularized objectivesecond-order Taylor expansionRelated

XGBoost upgrades gradient boosting with a regularized objective (γ T+12λ∑ wj2) and a second-order Taylor expansion, so splits are chosen by the similarity-gain (∑ g)2∑ h+λ and pruned when gain < γ — Newton-style steps plus native regularization. Add sparsity-aware/missing-value handling, parallel split finding, and GPU support, and you get a robust, top-accuracy tabular workhorse whose main costs are many hyperparameters and overfitting risk if under-regularized; tune a low learning rate with early stopping and depth/min_child_weight/gamma/sampling.
