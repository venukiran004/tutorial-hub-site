Q2. What is the bias-variance tradeoff? Derive the decomposition.

Derivation sketchImplications

For any estimator f̂, the expected MSE at point $x$ decomposes as:

E[(y−f̂(x))2] = (E[f̂(x)] − f(x))2Bias2 + E[(f̂(x)−E[f̂(x)])2]Variance + σε2Irreducible error

Derivation sketch: Let μ = E[f̂(x)], f = true function, noise ε~(0,σ2):

E[(y−f̂)2] = E[(f+ε−f̂)2] = E[((f−μ)+(μ−f̂)+ε)2]

Cross terms cancel (by independence of noise and f̂):

= (f−μ)2 + E[(f̂−μ)2] + σ2 = Bias2 + Variance + σ2

Implications: - High bias (underfitting): $k$ too small in KNN, tree depth too shallow - High variance (overfitting): k=1 in KNN, unlimited depth in trees - Irreducible error: noise in the labels — cannot be reduced by any model

Q3. What is overfitting and how do you prevent it?

Formally: model has low training error ε̂train but high test error ε̂test.

The generalisation gap = ε̂test − ε̂train.

By Rademacher complexity, for model class ℱ with probability ≥ 1−δ:

εtest(f) ≤ ε̂train(f) + 2mathfrakRn(ℱ) + √log(1/δ)2n

Prevention methods: - L1/L2 regularization — constrain $||w||$ - Dropout, weight decay in neural nets - Cross-validation for model selection - Early stopping — implicit regularization - Data augmentation — increase effective $n$ - Ensemble methods — reduce variance

Q4. What is the difference between a parameter and a hyperparameter?

ParameterHyperparameter
  • Parameter: Learned during training by optimizing a loss function. e.g., w in linear regression, attention weights. Not set by the user.
  • Hyperparameter: Governs the learning process / model capacity. Set before training. e.g., λ in regularization, $k$ in KNN, tree depth, learning rate.

Hyperparameters cannot be optimized via the same training objective — they are tuned via cross-validation, Bayesian optimization, or random search.

Q5. Explain the curse of dimensionality.

In $d$ dimensions, the volume of a hypersphere of radius $r$ is:

Vd(r) = πd/2Γ(d/2+1)rd

The fraction of volume of the unit hypercube [0,1]d within distance ε of a corner:

Vd(ε)1 = πd/2εdΓ(d/2+1) → 0 as d→∞

Implications: 1. Distance concentration: All pairwise distances converge as d→∞ 2. Data sparsity: $n$ samples needed grows exponentially with $d$ 3. KNN deteriorates: nearest neighbor is not much closer than farthest 4. Volume concentration: For uniform data in [0,1]d, 95% of data is within ε of the boundary

Q6. What is cross-validation? Derive bias-variance of k-fold estimate.

k-Fold CV procedureStratified k-fold

k-Fold CV procedure: 1. Partition data $D$ into $k$ equal folds D1,…,Dk 2. For each fold $i$: train on D\ Di, evaluate on Di 3. CV error: ε̂CV = 1k∑i=1k ε̂i

Bias-variance tradeoff of the CV estimator: - Small $k$ (e.g., k=2): train on 50% → model smaller → overestimates error (high bias) - Large $k$ (LOOCV, k=n): nearly unbiased but high variance (each model is ~identical) - k=5 or k=10 recommended as the sweet spot

Stratified k-fold preserves class proportions in each fold — critical for imbalanced datasets.

Q8. Define precision, recall, F1-score with derivations.

F1 = Harmonic meanFβ-score

Given confusion matrix:

Precision = TPTP+FP,   Recall = TPTP+FN

F1 = Harmonic mean of Precision and Recall:

F1 = 21Prec+1Rec = 2· P· RP+R

Why harmonic mean? It's the lowest of the two — if either is 0, F1=0. Arithmetic mean would allow a trivially high value from one high component.

Fβ-score weights recall β times more than precision:

Fβ = (1+β2)P· Rβ2· P+R

β>1 → recall more important (medical); β<1 → precision more important (spam filter).

Q11. What is the train/validation/test split? Why is data hygiene critical?

Train (60–70%)Validation (15–20%)Test (15–20%)Contamination sources

A clean three-way split prevents data leakage: - Train (60–70%): Model learns parameters w - Validation (15–20%): Tune hyperparameters, select architecture - Test (15–20%): Single final evaluation — simulate production

Contamination sources: Fitting scalers/encoders on whole dataset, hyperparameter tuning with test set, temporal ordering violation in time-series.

Q12. What is data leakage and why is it dangerous?

Target leakageTrain-test contaminationTemporal leakageDetection

Data leakage occurs when the training set contains information unavailable at prediction time, inflating performance: 1. Target leakage: Features derived from the target variable 2. Train-test contamination: Normalization/imputation fitted on full dataset 3. Temporal leakage: Using future signals to predict past events

Detection: Suspiciously high validation performance; feature importance of unexpected features; correlation between "post-event" features and target.

Q15. Generative vs discriminative models — mathematical distinction.

DiscriminativeGenerativeNg & Jordan (2002)

Discriminative: Model P(y|x) directly.

ŷ = argmaxy P(y|x)

Generative: Model joint P(x,y) = P(x|y)P(y), then apply:

P(y|x) = P(x|y)P(y)P(x)

Ng & Jordan (2002): Generative models (Naive Bayes) converge faster with less data but to a higher asymptotic error. Discriminative models (Logistic Regression) reach lower error given enough data.

Q19. What is Maximum Likelihood Estimation (MLE)? Derive for linear regression.

MLE: θ̂ = argmaxθ P(y|X;θ)

Under the linear model yi = wTxi + εi, εi~𝒩(0,σ2):

P(y|X;w,σ2) = n∏i=1 1√2πσ2e−(yi−wTxi)22σ2

Log-likelihood:

ℓ(w) = −n2log(2πσ2) − 12σ2∑i(yi−wTxi)2

Maximising ℓ(w) ≡ minimising ∑i(yi−wTxi)2 (MSE). QED.

Similarly, for logistic regression with Bernoulli likelihood → minimise binary cross-entropy.

Q21. Explain how linear regression works with full mathematical derivation.

ModelLoss function (MSE)Gradient Descent updateProbabilistic view

Model:

ŷ = wTx + b = d∑j=1 wj xj + b

Loss function (MSE):

ℒ(w) = 1nn∑i=1 (yi − ŷi)2 = 1n||y − Xw||2

Closed-form solution (Normal Equation): Set ∇wℒ = 0:

∂ ℒ∂ w = 2nXT(Xw − y) = 0 ⇒ w* = (XTX)−1XTy

Complexity: O(d3) for the matrix inverse — infeasible for large $d$.

Gradient Descent update:

wt+1 = wt − η · 2nXT(Xwt − y)

Probabilistic view: Assuming yi = wTxi + εi with εi ~ 𝒩(0,σ2), maximizing the likelihood gives the same MSE objective. MSE minimization ≡ MLE under Gaussian noise.

Gauss-Markov assumptions (BLUE guarantee): 1. Linearity: y = Xβ + ε 2. Strict exogeneity: E[ε|X] = 0 3. No multicollinearity: XTX invertible (full rank) 4. Homoscedasticity: Var(εi) = σ2 constant 5. No autocorrelation: Cov(εi, εj) = 0

Under these, OLS is the Best Linear Unbiased Estimator (BLUE).

Q22. How does logistic regression work? Derive the loss and gradient.

Model — Sigmoid functionWhy sigmoid?convexGradient (elegant form)Multi-class extension (Softmax)

Model — Sigmoid function:

p̂i = P(yi=1|xi) = σ(wTxi) = 11+e−wTxi

Why sigmoid? It maps (−∞, +∞) to $(0,1)$ and is the canonical link function for Bernoulli likelihood. The log-odds (logit) are linear:

logp1−p = wTx

Loss — Binary Cross-Entropy (MLE derivation): Likelihood: ℒ(w) = ∏i=1n p̂iyi(1−p̂i)1−yi

Taking −log:

J(w) = −1nn∑i=1 [yilogp̂i + (1−yi)log(1−p̂i)]

This is convex in w — has a unique global minimum (no closed form though).

Gradient (elegant form):

∇w J = 1nXT(p̂ − y) = 1nn∑i=1 (p̂i − yi)xi

The gradient has the same form as linear regression but with the sigmoid squashing!

Multi-class extension (Softmax):

P(y=k|x) = ewkTxK∑j=1 ewjTx

Loss becomes categorical cross-entropy: J = −1n∑i ∑k yiklogp̂ik

Q23. Explain SVM with full mathematical derivation: primal, dual, KKT, and kernel trick.

Primal problem — Hard-margin SVMLagrangianKKT conditionsDual problemKernel trickMercer's theorem

Primal problem — Hard-margin SVM: Find hyperplane wTx+b = 0 that maximizes margin 2||w||:

minw,b 12||w||2   s.t.   yi(wTxi+b) ≥ 1   ∀ i

Soft-margin (slack variables ξi ≥ 0):

minw,b,ξ 12||w||2 + C∑iξi   s.t.   yi(wTxi+b) ≥ 1−ξi

$C$ controls bias-variance tradeoff: large $C$ → small margin, low bias; small $C$ → wide margin, high bias.

Lagrangian:

ℒ = 12||w||2 − ∑i αi[yi(wTxi+b)−1]

KKT conditions (stationarity + complementary slackness): - ∂ℒ∂w = 0 ⇒ w = ∑i αi yi xi (representer theorem) - ∂ℒ∂ b = 0 ⇒ ∑i αi yi = 0 - αi ≥ 0, and αi[yi(wTxi+b)−1] = 0 (only support vectors have αi > 0)

Dual problem: Substituting back:

maxα ∑iαi − 12∑i,jαiαj yi yj xiTxj   s.t.   αi≥ 0, ∑iαi yi=0

Decision: ŷ = sign(∑i αi yi xiTx + b)

Kernel trick: Replace xiTxj with K(xi,xj) = φ(xi)Tφ(xj) — no explicit φ needed! By Mercer's theorem, any symmetric positive semi-definite function is a valid kernel.

Q24. How does a Decision Tree work? Derive impurity measures mathematically.

Entropy (ID3, C4.5)Information GainGini Impurity (CART)MSE for regression treesPredictionComplexity

Tree building — greedy recursive splitting: At each node, find feature $j$ and threshold $t$ that minimize impurity:

split* = argminj,t |SL||S|H(SL) + |SR||S|H(SR)

Entropy (ID3, C4.5):

H(S) = −C∑c=1 pc log2 pc

where pc = fraction of samples with class $c$. Range: [0, log2 C].

Information Gain:

IG(S, j, t) = H(S) − [|SL||S|H(SL) + |SR||S|H(SR)]

Gini Impurity (CART):

G(S) = 1 − C∑c=1 pc2 = ∑c≠ c' pc pc' = probability of misclassification

Range: $[0, 1 - 1/C]$. Faster to compute than entropy (no log). Slightly favors larger partitions.

MSE for regression trees:

Impurity(S) = 1|S|∑i∈ S(yi − ȳS)2

Prediction: - Classification: majority class in leaf - Regression: mean of $y$ in leaf

Complexity: Tree is a piecewise constant function. Axis-aligned splits create rectangular decision regions. Θ(nd log n) training, O(depth) inference.

Q25. What is Random Forest? Derive bias-variance reduction through bagging.

Bagging (Bootstrap Aggregating)Bias-variance analysis of baggingFeature randomnessdecorrelatesOut-of-Bag (OOB) ErrorPermutation Importance

Bagging (Bootstrap Aggregating): Train $T$ trees {ht} on bootstrap samples {Dt} (n samples with replacement, ~63.2% unique):

ŷ = 1TT∑t=1 ht(x)   (regression)

Bias-variance analysis of bagging:

Var(h̄) = 1−ρTσ2 + ρσ2

where ρ = average pairwise correlation between trees, σ2 = variance of each tree.

  • First term: → 0 as T→∞ (why more trees always helps)
  • Second term: irreducible correlation floor

Feature randomness: At each split, consider only m = √d (classif.) or m = d/3 (regress.) random features. This decorrelates trees, reducing ρ and lowering variance.

Out-of-Bag (OOB) Error: Each sample is OOB for ~37% of trees. OOB error ≈ unbiased estimate of generalization error (no separate validation set needed).

Feature Importance — Mean Decrease Impurity (MDI):

FI(j) = 1T∑t ∑node v ∈ ht splits on j pv · Δ Gv

where pv = |Sv|/n and Δ Gv = impurity decrease at node $v$.

Permutation Importance: Shuffle feature $j$ in validation set, measure drop in score. Less biased than MDI for high-cardinality features.

Q27. How does K-Nearest Neighbors work? Analyze its complexity and theoretical properties.

AlgorithmDistance metricsComplexityCurse of dimensionality for KNNDecision boundary

Algorithm: Given test point x, find $k$ training points with smallest distance:

ŷ = {
majority({yi : i ∈ 𝒩k(x)}) classification
1k∑i∈𝒩k(x) yi regression

Distance metrics: - Lp norm: d(x,z) = (∑j |xj−zj|p)1/p - p=2: Euclidean; p=1: Manhattan; p=∞: Chebyshev

Theoretical guarantee (Cover & Hart 1967): As n→∞ with k→∞ and k/n→ 0:

ε* ≤ εKNN ≤ 2ε*(1−ε*)

where ε* = Bayes error. So 1-NN error ≤ twice the Bayes error — remarkable!

Complexity: Brute force: $O(nd)$ per query. KD-trees: O(dlog n) for low $d$. Ball trees: better for moderate $d$.

Curse of dimensionality for KNN: In $d$ dimensions, the expected distance to the nearest neighbor scales as n−1/d — points are far apart, making local neighborhoods meaningless.

Decision boundary: Voronoi tessellation of the training data for k=1.

Q28. Explain the Naive Bayes classifier with full mathematical derivation.

Bayes' theoremNaive independence assumptionPredictionGaussian Naive BayesMultinomial Naive Bayes (text)

Bayes' theorem:

P(y=c|x) = P(x|y=c)· P(y=c)P(x)

Naive independence assumption: P(x|y=c) = ∏j=1d P(xj|y=c)

Prediction: ŷ = argmaxc P(y=c)∏j=1d P(xj|y=c)

In log-space (numerically stable):

ŷ = argmaxc [log P(y=c) + d∑j=1 log P(xj|y=c)]

Gaussian Naive Bayes:

P(xj|y=c) = 1√2πσjc2exp(−(xj−μjc)22σjc2)

Parameters: μ̂jc = 1nc∑i:yi=cxij, σ̂jc2 = 1nc∑i:yi=c(xij−μ̂jc)2

Multinomial Naive Bayes (text): P(wj|c) = count(wj,c)+α∑j'count(wj',c)+dα with Laplace smoothing α.

Why it works despite the naive assumption: The decision boundary needs $P(y|x)$ to be calibrated, not the joint to be exactly modelled. The ranking P(y=1|x) > P(y=0|x) is often preserved even with violated independence.

Q29. What is K-Means clustering? Derive the algorithm and its EM connection.

E-step (Assignment)M-step (Update)EM connectionK-Means++ initializationLimitations

Objective (WCSS — Within-Cluster Sum of Squares):

J({μk}) = K∑k=1 ∑x∈ Ck||x−μk||2

Lloyd's Algorithm (alternating optimization): - E-step (Assignment): zi = argmink ||xi − μk||2 - M-step (Update): μk = 1|Ck|∑i:zi=kxi

Guaranteed to converge (objective decreases monotonically) but to a local minimum.

Q31. What is PCA? Derive it from variance maximisation and SVD.

Q34. What is LightGBM? Explain GOSS, EFB, and leaf-wise growth.

Level-wise (XGBoost) vs Leaf-wise (LightGBM): - Level-wise: grow all leaves on a level before going deeper — balanced but slower - Leaf-wise: always split leaf with maximum gain — deeper one branch, much lower loss per tree

Gradient-based One-Side Sampling (GOSS): Keep all instances with large gradients |gi| ≥ threshold (top $a$%), sample fraction $b$ of small-gradient instances, reweight: wi = 1−ab for sampled instances.

Why? Instances with large gi contribute more information to learning. Random sampling wastes compute on already-learned instances.

Exclusive Feature Bundling (EFB): Mutually exclusive features (features that rarely take non-zero values together) are bundled into one feature, reducing dimensionality. Finding optimal bundles is NP-hard → greedy approximation.

Histogram-based splits: Bin continuous features into $B$ bins (B ≤ 255). Compute gradient histograms: $O(nd)$ → $O(nB)$ per level. Memory: $O(B)$ instead of $O(n)$ per feature.

Problem: Maximise marginal log-likelihood with latent variables Z:

log p(X|θ) ≥ ∑Z q(Z)logp(X,Z|θ)q(Z) = ℒ(q,θ)

E-step: Maximise ELBO over $q$ with θ fixed:

q*(Z) = p(Z|X,θold)

M-step: Maximise $Q$ over θ:

θnew = argmaxθ Q(θ|θold)

Convergence: Each EM step increases log p(X|θ) (or leaves it unchanged). Converges to local maximum.

Q44. What is early stopping? Derive its regularization equivalence.

Early stopping terminates training when validation loss stops improving (with patience $p$):

best_loss = inf; patience_counter = 0
for epoch in range(max_epochs):
    train(); val_loss = evaluate()
    if val_loss < best_loss - tol:
        best_loss = val_loss; save_checkpoint()
        patience_counter = 0
    else:
        patience_counter += 1
        if patience_counter >= p: break

Theoretical equivalence: For SGD on L2-regularized models, early stopping at step $T$ is equivalent to L2 regularization with λ = 1/(Tη) where η = step size. Early stopping implicitly constrains the model's movement from initialization — a soft form of the norm-ball constraint.

Feature Engineering & Data (Q51–Q65)

•

Q51. What is feature engineering and why does it matter?

Creating new or transformed features from raw data to improve model performance. Often has more impact than choosing a fancy algorithm.

•

Q52. How do you handle missing values?

  • Drop rows/columns (if small fraction).
  • Impute: mean/median (numerical), mode (categorical), KNN imputation, model-based imputation.
  • Treat missing as a category (for tree models).
  • Flag missingness as a binary feature.
•

Q53. What is feature scaling and when is it necessary?

Standardization (Z-score)Min-Max Normalization
  • Standardization (Z-score): Mean=0, Std=1.
  • Min-Max Normalization: Scale to [0, 1]. Necessary for: KNN, SVM, PCA, gradient descent-based models. Not necessary for: tree-based models.
•

Q54. How do you encode categorical variables?

One-hot encodingLabel encodingTarget encodingEmbedding
  • One-hot encoding: Binary column per category (for nominal with few categories).
  • Label encoding: Integer per category (for ordinal or tree models).
  • Target encoding: Replace category with mean target value (risk of leakage — use CV carefully).
  • Embedding: Learned dense vectors (deep learning).
•

Q55. What is multicollinearity and how do you detect/fix it?

Multicollinearity: High correlation between features. Causes unstable coefficient estimates in linear models. Detection: VIF (Variance Inflation Factor) > 10 is problematic. Fix: Remove correlated features, PCA, Ridge regression.

•

Q56. What is the difference between feature selection and feature extraction?

Feature selectionFeature extraction
  • Feature selection: Choose a subset of original features (Filter, Wrapper, Embedded methods).
  • Feature extraction: Create new features from originals (PCA, autoencoders, polynomial features).
•

Q57. What are wrapper methods for feature selection?

Wrapper methods use a model to evaluate feature subsets. Examples: Recursive Feature Elimination (RFE), Forward/Backward selection. Expensive but account for feature interactions.

•

Q58. How do you handle outliers?

Detect: IQR method (< Q1 - 1.5IQR or > Q3 + 1.5IQR), Z-score, visualization. Handle: Remove, cap/floor (winsorization), transform (log), use robust models (tree-based, L1 regression).

•

Q59. What is target encoding and what is its risk?

Target encoding replaces a categorical value with its mean target value. Risk: data leakage if computed on the full dataset before splitting. Fix: compute only within cross-validation folds.

•

Q60. What is the pipeline concept in ML?

An ML pipeline chains preprocessing steps (scaling, encoding, imputation) and the model into a single object. Prevents data leakage (all steps are fit only on training data), simplifies deployment, and enables clean CV.

•

Q61. What is dimensionality reduction and why is it useful?

Reducing the number of features while preserving information. Benefits: reduces overfitting, speeds up training, removes noise, helps visualization.

•

Q62. What is polynomial feature engineering?

Creating new features as products/powers of existing features (e.g., x₁², x₁·x₂). Adds expressiveness to linear models but increases dimensionality rapidly.

•

Q63. How do you deal with skewed distributions?

Apply transformations: log (for right skew), square root, Box-Cox, Yeo-Johnson. Assess with skewness metric and Q-Q plot.

•

Q64. What is binning / discretization?

Converting continuous features into discrete bins (e.g., age → young/middle/senior). Useful for adding non-linearity to linear models and capturing threshold effects.

•

Q65. What is the difference between train-time and inference-time feature engineering?

Train-time: Statistics (mean, std, encodings) computed on training data only. Inference-time: Apply the same transformations using train-set statistics. Never refit scalers/encoders on new data.

Model Evaluation & Deployment (Q66–Q80)

•

Q66. What is RMSE? When is it preferred over MAE?

RMSE = √(mean(yᵢ − ŷᵢ)²). Preferred when large errors are especially undesirable (penalizes them more). MAE is preferred when all errors matter equally or outliers should not dominate.

•

Q67. What is log loss (cross-entropy loss)?

Log loss = −(1/n)·Σ[yᵢ·log(pᵢ) + (1−yᵢ)·log(1−pᵢ)]. Measures quality of probability estimates. Lower = better calibrated predictions.

•

Q68. What is calibration in ML models?

A well-calibrated model's predicted probabilities match empirical frequencies (if it predicts 70% for 100 samples, ~70 should be positive). Calibrate using Platt scaling or isotonic regression.

•

Q69. What is model interpretability vs. explainability?

InterpretabilityExplainability
  • Interpretability: Inherent simplicity of the model (linear regression, decision tree).
  • Explainability: Post-hoc methods applied to black-box models (LIME, SHAP).
•

Q70. What is SHAP and how does it work?

SHAP (SHapley Additive exPlanations) assigns each feature a contribution to the model's prediction using game theory (Shapley values). Satisfies efficiency, symmetry, and dummy axioms.

•

Q71. What is A/B testing in ML model deployment?

Randomly split users between model A (control) and model B (treatment). Measure business metrics to determine if model B is statistically significantly better.

•

Q72. What is shadow deployment / canary release?

ShadowCanary
  • Shadow: New model receives same traffic as production model but responses are not served to users — used to compare outputs safely.
  • Canary: Route a small % of real traffic to the new model. If healthy, gradually increase.
•

Q73. What is concept drift and how do you detect it?

Concept drift: The statistical relationship between features and target changes over time. Detection: Monitor prediction distribution, feature distribution (KL divergence, PSI), model performance metrics. Tools: Evidently AI, Alibi Detect.

•

Q74. What is the difference between covariate shift and label shift?

Covariate shiftLabel shift
  • Covariate shift: Input distribution P(X) changes but P(Y|X) stays same.
  • Label shift: Output distribution P(Y) changes. Both degrade model performance; handled by importance weighting or retraining.
•

Q75. What is model versioning and why does it matter?

Tracking different trained model versions (code, data, hyperparameters, metrics). Enables reproducibility, rollback, and comparison. Tools: MLflow, DVC, W&B.

•

Q76. What is the difference between online and offline evaluation?

OfflineOnline
  • Offline: Evaluation on a held-out dataset before deployment (fast, cheap, may not reflect production).
  • Online: Evaluation in live production using real user feedback or business metrics (accurate, slow, expensive).
•

Q77. What is the Matthews Correlation Coefficient (MCC)?

MCC = (TP·TN − FP·FN) / √((TP+FP)(TP+FN)(TN+FP)(TN+FN)). A balanced metric even for imbalanced classes. Range: −1 to +1; +1 is perfect.

•

Q78. How do you assess if a model is production-ready?

  • Performance meets business KPI threshold.
  • Latency within SLA.
  • Bias/fairness checks passed.
  • Tested for edge cases and failure modes.
  • Monitoring and alerting configured.
  • Rollback plan exists.
•

Q79. What is feature drift monitoring?

Tracking whether feature distributions shift between training data and live data. Use PSI (Population Stability Index), KS-test, Wasserstein distance. High drift signals a need to retrain.

•

Q80. What is a champion-challenger model strategy?

The champion is the current best production model. Challengers are new candidates. Route a portion of traffic to challengers; promote one to champion if it consistently beats the current champion.

Advanced Topics (Q81–Q100)

•

Q81. What is AutoML?

Automated Machine Learning automates the end-to-end ML pipeline: feature engineering, model selection, hyperparameter tuning. Tools: AutoSklearn, H2O AutoML, Google AutoML, TPOT.

•

Q82. What is meta-learning / few-shot learning?

Meta-learning: "Learning to learn" — models that can adapt to new tasks with very few examples. Approaches: MAML (model-agnostic meta-learning), Prototypical Networks.

•

Q83. What is multi-task learning?

A single model is trained on multiple related tasks simultaneously, sharing representations. Often improves generalization compared to training separate models for each task.

•

Q84. What is federated learning?

Training a model across multiple decentralized devices/servers holding local data, without sharing raw data with a central server. Preserves privacy; used in mobile (Gboard, iOS).

•

Q85. What is differential privacy in ML?

A mathematical framework guaranteeing that model outputs do not reveal information about individual training samples. Implemented by adding calibrated noise (e.g., Laplace/Gaussian mechanism) during training.

•

Q86. What is graph machine learning?

ML applied to graph-structured data (social networks, molecules, knowledge graphs). Methods: Graph Neural Networks (GNNs), node/edge classification, graph classification.

•

Q87. What is the kernel density estimation (KDE)?

A non-parametric way to estimate the probability density function (PDF) of a variable. Places a kernel (e.g., Gaussian) at each data point and sums them for a smooth distribution estimate.

•

Q88. What is isotonic regression?

A non-parametric regression that fits a monotonically increasing (or decreasing) function to data. Used for probability calibration (convert raw scores to calibrated probabilities).

•

Q89. What is quantile regression?

Estimates the conditional median (or any quantile) of the response instead of the mean. Useful when understanding the range of outcomes matters (e.g., predicting 90th percentile delivery time).

•

Q90. What is survival analysis?

Analysis of time-to-event data (e.g., time until customer churn, machine failure). Handles censored observations (event not yet occurred). Methods: Kaplan-Meier, Cox Proportional Hazards.

•

Q91. What is the Vapnik-Chervonenkis (VC) dimension?

A measure of the capacity (complexity) of a statistical classification model. Higher VC dimension → model can fit more complex functions → higher risk of overfitting with limited data.

•

Q92. What is stochastic gradient descent (SGD) vs. mini-batch SGD?

SGDMini-batch
  • SGD: Update weights after each single sample. Noisy but fast per update.
  • Mini-batch: Update after a small batch (32–256). Balances stability and speed. Most common in practice.
•

Q93. What is the difference between parametric and non-parametric hypothesis tests in ML evaluation?

ParametricNon-parametric
  • Parametric (t-test): Assumes data follows a distribution.
  • Non-parametric (Wilcoxon, Mann-Whitney): No distributional assumption. Preferred for comparing classifier performance across CV folds.
•

Q94. What is label smoothing?

Instead of hard 0/1 labels, use soft labels (e.g., 0.9/0.1). Prevents overconfident predictions and improves calibration. Common in deep learning classification.

•

Q95. What is knowledge distillation?

A smaller "student" model is trained to mimic the output distribution of a larger "teacher" model. Produces compact, efficient models that retain much of the teacher's performance.

•

Q96. What is an ensemble and what are the most common ensemble strategies?

Combining multiple models to improve performance. Strategies: Bagging (Random Forest), Boosting (XGBoost), Stacking (meta-learner), Blending (hold-out based stacking).

•

Q97. What is stacking (stacked generalization)?

Train several base models (level-0), then train a meta-model (level-1) on their out-of-fold predictions. The meta-model learns how to best combine base model outputs.

•

Q98. What is the role of a validation set during Bayesian hyperparameter optimization?

The validation set provides the objective function score that the Bayesian optimizer uses to build its surrogate model. It must be held out from training to provide unbiased feedback about hyperparameter configurations.

•

Q99. How do you handle high cardinality categorical features?

Options: Target encoding (with CV), frequency encoding, grouping rare categories into "Other", entity embeddings (neural networks), hashing trick.

•

Q100. What is the difference between a discriminative and generative model? Give examples.

DiscriminativeGenerative
  • Discriminative: Learns boundary P(Y|X). Examples: Logistic Regression, SVM, Neural Networks.
  • Generative: Learns joint distribution P(X,Y) = P(X|Y)·P(Y). Examples: Naive Bayes, HMMs, VAEs, GANs. Generative models can also synthesize new data.

  • Boosting: Train models sequentially; each corrects errors of the previous; reduces bias. Examples: AdaBoost, Gradient Boosting, XGBoost.
•

Q102. How does AdaBoost work?

  1. Train a weak learner on the data.
  2. Increase weights of misclassified samples.
  3. Train the next learner on re-weighted data.
  4. Final prediction = weighted vote of all learners. Each learner's vote weight αt = 12ln1−εtεt where εt is its error rate.
•

Q103. What is the objective function of Gradient Boosting?

At each step $t$, fit a new tree ht(x) to the negative gradient of the loss function:

rit = −∂ L(yi, Ft−1(xi))∂ Ft−1(xi)

For MSE loss, residuals = negative gradient. For log-loss, pseudo-residuals are log-odds based.

•

Q104. What hyperparameters are most important in XGBoost and how do they affect the model?

  • n_estimators: More trees → better fit, risk of overfitting.
  • learning_rate (eta): Shrinks each tree's contribution; lower requires more trees.
  • max_depth: Tree complexity; 3–6 typical.
  • subsample: Row sampling each iteration; reduces overfitting.
  • colsample_bytree: Feature sampling; reduces correlation between trees.
  • lambda / alpha: L2/L1 regularization on leaf weights.
  • min_child_weight: Minimum sum of hessians in a leaf; controls pruning.
•

Q105. How does LightGBM differ from XGBoost?

  • Leaf-wise growth (best leaf first) vs XGBoost's level-wise → fewer nodes, faster, can overfit on small data.
  • Histogram-based binning → O(n) vs O(n log n) split finding.
  • Gradient-based One-Side Sampling (GOSS) — drops low-gradient instances.
  • Exclusive Feature Bundling (EFB) — bundles sparse mutually exclusive features.
  • Generally 10× faster than XGBoost on large datasets.
•

Q106. What is CatBoost and when is it preferred?

CatBoost handles categorical features natively without label encoding: - Uses Ordered Target Statistics (OTS) to avoid target leakage. - Ordered boosting prevents prediction shift. - Often best out-of-the-box for datasets with many high-cardinality categoricals.

•

Q107. What is stacking (stacked generalization)?

Use predictions from base models (Level 0) as features for a meta-learner (Level 1):

from sklearn.ensemble import StackingClassifier
estimators = [("rf", RandomForestClassifier()), ("svm", SVC(probability=True))]
stack = StackingClassifier(estimators=estimators, final_estimator=LogisticRegression())

Cross-validation is used during training to prevent target leakage into meta-features.

•

Q108. What is blending vs stacking?

BlendingStacking
  • Blending: Hold-out set used to train meta-model (simpler but wastes data).
  • Stacking: Full OOF (out-of-fold) cross-validation used to generate meta-features (better but complex).
•

Q109. What is a random subspace method?

Train each base learner on a random subset of features (not samples). The diversification in feature subsets reduces correlation between models. Random Forest applies both bootstrap sampling (rows) AND random subspaces (features).

•

Q110. When does an ensemble NOT help?

  • If all base models make equally correlated errors.
  • If one model is vastly better than others (blending dilutes it).
  • When interpretability is required (ensembles are black boxes).
  • When inference latency is critical (ensembles are slow to predict).
•

Q111. What is the bias-variance trade-off in the context of ensembles?

MSE = Bias2 + Variance + Irreducible Noise
  • Bagging reduces variance (averaging reduces fluctuation) with minimal bias change.
  • Boosting reduces bias (each new model corrects errors) but can increase variance if over-iterated.
•

Q112. What is isotonic regression and when is it used in ensemble learning?

A non-parametric monotone regression used for calibration. It fits a piecewise constant non-decreasing function to predicted probabilities to make them better calibrated:

from sklearn.isotonic import IsotonicRegression
cal = IsotonicRegression(out_of_bounds="clip")
calibrated_probs = cal.fit_transform(raw_probs, true_labels)
•

Q113. What is early stopping in boosting?

Stop adding trees when validation loss stops improving:

xgb_model = XGBClassifier(n_estimators=1000, early_stopping_rounds=50)
xgb_model.fit(X_train, y_train, eval_set=[(X_val, y_val)], verbose=100)
# Automatically stops at the best n_estimators
•

Q114. What is the role of n_estimators vs max_depth in Random Forest?

  • n_estimators: More trees → better generalization (diminishing returns after ~200-500; never hurts accuracy, only speed).
  • max_depth: Deeper trees → higher variance. Use None (full depth) with enough trees OR limit depth to tune bias-variance.
•

Q115. What is feature importance in Gradient Boosting vs Random Forest?

Both use gain-based importance (total reduction in loss attributed to each feature). However: - Can be biased toward high-cardinality features. - SHAP values are more reliable — they are model-agnostic and consistent. - Permutation importance is unbiased but slower.

•

Q116. What is histogram-based gradient boosting (HistGradientBoosting in sklearn)?

Bins feature values into fixed-width histograms before finding splits. Much faster than exact split finding for large datasets (n > 10,000):

from sklearn.ensemble import HistGradientBoostingClassifier
clf = HistGradientBoostingClassifier(max_iter=500, learning_rate=0.05, max_leaf_nodes=31)
•

Q117. What is DART (Dropouts for Additive Regression Trees)?

Applies dropout to trees during boosting (randomly drops some previously learned trees). Prevents over-specialization of later trees and reduces overfitting. Available in XGBoost and LightGBM as booster="dart".

•

Q118. How do you handle class imbalance in XGBoost?

# scale_pos_weight balances positive/negative class weights
ratio = (y_train == 0).sum() / (y_train == 1).sum()
model = XGBClassifier(scale_pos_weight=ratio, eval_metric="aucpr")

Also: enable_categorical=True, sample weighting, or focal loss.

•

Q119. What are warm starts in ensemble models?

Continue training from a previously fitted model without starting over:

rf = RandomForestClassifier(n_estimators=100, warm_start=True)
rf.fit(X, y)               # Trains 100 trees
rf.n_estimators = 200      # Add 100 more trees
rf.fit(X, y)               # Trains only the additional 100 trees
•

Q120. What is the difference between model accuracy and model calibration?

Accuracy/AUCCalibration
  • Accuracy/AUC: How often the model predicts the correct class/rank.
  • Calibration: How well predicted probabilities match empirical frequencies. A model predicting 0.8 for 1,000 cases should see ~800 positives. Evaluate with reliability diagrams and Expected Calibration Error (ECE).

Q121. What is the difference between first-order and second-order optimization?

  • Second-order: Uses Hessian ∇²f. Newton's method, L-BFGS — faster convergence but quadratic memory cost O(n²). Used for small ML models (sklearn solver="lbfgs").

Q123. What is momentum in gradient descent?

Accumulates a velocity vector in directions of persistent gradient:

vt = β vt−1 + (1−β)∇ L θ ← θ − α vt

Dampens oscillations in narrow valleys and accelerates in persistent directions. Typical β = 0.9.

•

Q124. How does the Adam optimizer work?

Combines momentum (first moment mt) and RMSprop (second moment vt):

mt = β1 mt−1 + (1−β1)gt vt = β2 vt−1 + (1−β2)gt2 m̂t = mt1−β1t,   v̂t = vt1−β2t θ ← θ − α√v̂t+εm̂t

Defaults: β1=0.9, β2=0.999, ε=10−8.

•

Q125. What is the learning rate schedule and common strategies?

Step decayCosine annealingWarmup + decayReduce on plateauCyclical LR
  • Step decay: Reduce LR by factor γ every N epochs.
  • Cosine annealing: LR follows cosine curve from αmax to αmin.
  • Warmup + decay: Linear increase then decay (common in Transformers).
  • Reduce on plateau: Reduce when validation loss stops improving.
  • Cyclical LR: Oscillates between bounds — escapes local minima.
•

Q126. What is the vanishing/exploding gradient problem in classical ML?

In deep models, gradients are products of many partial derivatives. If Jacobians < 1 repeatedly → gradients shrink to zero (vanishing). If > 1 → explode. Primarily affects RNNs and very deep networks. Fixed by normalization, gradient clipping, and skip connections.

•

Q127. What is feature scaling and why does it matter for gradient descent?

Without scaling, features with large ranges dominate the gradient and the loss surface becomes elongated — gradient descent zigzags slowly. StandardScaler or MinMaxScaler creates symmetric loss contours for faster convergence.

•

Q128. What is the saddle point problem in optimization?

A point where the gradient is zero but is neither a local min nor max (curvature is positive in some directions, negative in others). In high-dimensional spaces, saddle points are far more common than local minima. First-order methods can escape via noise in SGD.

•

Q129. What is line search in optimization?

ExactBacktracking / Armijo

After computing the gradient direction, find the optimal step size along that direction: - Exact: Minimize loss along direction analytically (expensive). - Backtracking / Armijo: Start with large step, reduce until sufficient decrease condition is met. Used in L-BFGS and coordinate descent methods.

•

Q130. What is coordinate descent?

Optimize one parameter at a time while holding others fixed. Efficient when each 1D minimization has a closed form (e.g., Lasso via soft thresholding). Used in sklearn's LinearRegression with solver="coordinate_descent" for Lasso.

•

Q131. What is the difference between convex and non-convex optimization in ML?

ConvexNon-convex
  • Convex: Any local minimum is global. Guaranteed convergence to optimal. Linear/Logistic regression with L2 loss.
  • Non-convex: Multiple local minima. Neural networks, matrix factorization. No guarantee of global opt — but practical results are often very good.
•

Q132. What is subgradient descent used for?

For non-differentiable loss functions (e.g., hinge loss in SVM, L1 regularization). A subgradient is any element of the subdifferential. Convergence is slower than smooth gradient descent.

•

Q133. What is proximal gradient descent?

Handles regularized objectives by splitting into smooth + non-smooth parts:

θt+1 = proxα g(θt − α ∇ f(θt))

For Lasso, the prox operator is soft-thresholding:

prox(z, λ) = sign(z)max(|z|−λ, 0)
•

Q134. What is the generalization gap and how do training dynamics affect it?

Gap between training loss and validation loss. Large gap = overfitting. Affected by: - Learning rate (too high → noisy final solution, poor generalization). - Batch size (smaller batches → flatter minima → better generalization). - Number of epochs (more → overfitting without regularization). - Model capacity vs dataset size.

•

Q135. What is double descent in ML?

The test error curve shows two U-shapes as model capacity increases. After the classical bias-variance peak (interpolation threshold), adding more capacity paradoxically reduces test error again. Observed in neural networks and other over-parameterized models.

•

Q136. What is a loss landscape and how does its shape affect training?

Visualization of loss as a function of model parameters. Sharp minima generalize poorly (sensitive to perturbations); flat minima generalize better. SGD's noise helps find flatter minima than full-batch gradient descent.

•

Q137. How do you diagnose underfitting vs overfitting from learning curves?

UnderfittingOverfitting
from sklearn.model_selection import learning_curve
train_sizes, train_scores, val_scores = learning_curve(estimator, X, y, cv=5)
  • Underfitting: Both curves converge to high error.
  • Overfitting: Large gap between training (low error) and validation (high error) that doesn't close with more data.
•

Q138. What is the effect of batch size on generalization?

Larger batches → more accurate gradient estimates, faster convergence per epoch BUT often converge to sharper minima (worse generalization). "Large batch training harm" — mitigation: increase LR proportionally (linear scaling rule), use LR warmup.

•

Q139. What is the Polyak-Ruppert averaging scheme?

Average model weights across the last T iterations instead of using the final weights:

θ̄ = 1TT∑t=T0 θt

Often improves generalization and smooths out SGD's noise (implemented as SWA — Stochastic Weight Averaging in PyTorch).

•

Q140. What is hyperparameter optimization beyond grid search?

Random SearchBayesian OptimizationHyperbandBOHB
  • Random Search: Sample random configs; better than grid for high-dimensional spaces.
  • Bayesian Optimization: Use Gaussian Process to model performance surface; prioritize promising regions.
  • Hyperband: Adaptive resource allocation — promote best candidates, early-stop others.
  • BOHB: Combines Bayesian and Hyperband.
  • Tools: Optuna, Ray Tune, Hyperopt.

Bayesian & Probabilistic ML (Q141–Q155)

•

Q141. What is Bayesian inference?

Update beliefs about model parameters given observed data using Bayes' theorem:

P(θ | X) = P(X | θ) · P(θ)P(X)
  • P(θ): Prior — beliefs before data.
  • P(X|θ): Likelihood — probability of data given parameters.
  • P(θ|X): Posterior — updated beliefs.
•

Q142. What is the difference between MLE and MAP estimation?

  • MLE (Maximum Likelihood Estimation): Find θ maximizing P(X|θ). No prior. Prone to overfitting.
  • MAP (Maximum A Posteriori): Find θ maximizing P(θ|X) ∝ P(X|θ)P(θ). Equivalent to MLE + regularization (L2 prior = Gaussian, L1 prior = Laplace).
•

Q143. What is a Gaussian Process (GP)?

A distribution over functions where any finite set of function values follows a multivariate Gaussian distribution. Defined by mean function $m(x)$ and covariance kernel $k(x, x')$. Used for regression with uncertainty estimates, Bayesian optimization.

•

Q144. What is the Naive Bayes assumption and when does it fail?

Features are conditionally independent given the class: P(x1,...,xn|y) = ∏i P(xi|y). Fails when features are correlated (e.g., adjacent pixels in images, word co-occurrences). Despite this "naive" assumption, it works surprisingly well for text classification.

•

Q145. What is Bayesian Linear Regression?

Places a prior on weights w ~ 𝒩(0, σp2 I) and computes the posterior analytically. Returns a distribution over predictions (not a point estimate):

α = 1/σ_prior², β = 1/σ_noise²
S_N = (αI + βΦᵀΦ)⁻¹   # Posterior covariance
m_N = β·S_N·Φᵀ·t        # Posterior mean

Provides calibrated uncertainty — variance grows in low-data regions.

•

Q146. What is a Dirichlet distribution and where is it used in ML?

The Dirichlet is the conjugate prior to the categorical/multinomial distribution. Used in: - LDA (Latent Dirichlet Allocation) as prior over topic distributions. - Bayesian classification as prior over class probabilities. Parameters α > 1 encourage uniform distributions; α < 1 encourages sparse distributions.

•

Q147. What is variational inference?

Approximate the true posterior P(θ|X) with a simpler distribution q(θ) by minimizing KL divergence. Equivalent to maximizing the ELBO (Evidence Lower Bound):

ELBO = 𝔼q[log P(X|θ)] − KL(q(θ) | P(θ))

Used in VAEs, topic models, and scalable Bayesian DL.

•

Q148. What is MCMC (Markov Chain Monte Carlo)?

Metropolis-HastingsGibbs SamplingHMC (Hamiltonian MC)

A family of algorithms to sample from the posterior when it's intractable. Constructs a Markov chain whose stationary distribution is the target posterior: - Metropolis-Hastings: Accept/reject samples probabilistically. - Gibbs Sampling: Sample each variable from its conditional. - HMC (Hamiltonian MC): Uses gradient info for efficient sampling.

•

Q149. What is Bayesian Optimization and how does it work?

Efficiently optimize expensive black-box functions (e.g., hyperparameter tuning): 1. Fit a surrogate model (GP or TPE) over evaluated configurations. 2. Use an acquisition function (EI, UCB) to select the next point to evaluate. 3. Evaluate the objective, update surrogate. Finds good optima in far fewer evaluations than random/grid search.

•

Q150. What is the expected improvement (EI) acquisition function?

EI(x) = 𝔼[max(f(x) − f*, 0)]

Balances exploration (high uncertainty) and exploitation (high predicted value). The point with highest EI is evaluated next. Other acquisition functions: Upper Confidence Bound (UCB), Probability of Improvement (PI).

•

Q151. What is a Bayesian Network?

A DAG where nodes are random variables and edges represent conditional dependencies. Joint probability factors as:

P(X1,...,Xn) = ∏i P(Xi | Parents(Xi))

Used for probabilistic reasoning, causal inference, medical diagnosis.

•

Q152. What is calibration error and how do you measure it?

Expected Calibration Error (ECE)Maximum Calibration Error (MCE)Reliability diagram
  • Expected Calibration Error (ECE): Weighted average of |confidence - accuracy| across probability bins.
  • Maximum Calibration Error (MCE): Worst bin.
  • Reliability diagram: Plot mean predicted probability vs fraction of positives per bin. A perfectly calibrated model's reliability diagram is the diagonal.
•

Q153. What is Platt scaling?

Post-hoc calibration: fit a logistic regression on a held-out set using raw model scores as input:

from sklearn.calibration import CalibratedClassifierCV
cal_model = CalibratedClassifierCV(base_model, method="sigmoid", cv=5)
cal_model.fit(X, y)

method="isotonic" for non-monotone calibration.

•

Q154. What is a Bayesian A/B test vs frequentist A/B test?

FrequentistBayesian
  • Frequentist: Computes p-value and requires pre-defined sample size; no "peeking" rule.
  • Bayesian: Computes P(B > A) directly from posterior. Can stop early, incorporates priors, and gives probability statements rather than binary reject/fail-to-reject.
•

Q155. What is Thompson Sampling?

A Bayesian exploration strategy for multi-armed bandits: sample one reward estimate from each arm's posterior, then choose the arm with highest sample. Over time, posteriors tighten around true means — naturally balances exploration and exploitation.

Q157. What is the train-serve skew problem?

Discrepancy between the data distribution during training and the data distribution in production. Causes silent model degradation. Q158. What is data drift vs concept drift?

  • Label shift: Output distribution P(Y) changes (upstream business change). Detect with: statistical tests (KS, PSI), embedding drift monitoring, prediction distribution monitoring.

Q162. What is shadow mode deployment?

Q163. What is canary deployment for ML models?

Q166. What is online learning and how does sklearn support it?

Q167. What is model distillation in traditional ML?

Train a smaller, faster model (student) to mimic a larger, more complex model (teacher). The student is trained on soft labels (teacher's predicted probabilities) rather than hard labels. Achieves near-teacher accuracy at a fraction of inference cost.

Q168. What is the curse of dimensionality and its effects?

Mitigation: PCA/dimensionality reduction, feature selection, regularization.

Q172. What is model quantization in scikit-learn / traditional ML?

Q173. What is the holdout strategy for time-series data?

Q174. What is label leakage vs feature leakage?

Q175. What is the difference between offline and online metrics in ML?

Fairness, Causality & Advanced Topics (Q176–Q200)

•

Q176. What is algorithmic bias and how do you measure it?

Demographic parityEqual opportunityEqualized oddsCalibration

Systematic unfair outcomes against certain groups: - Demographic parity: P(Ŷ=1|A=0) = P(Ŷ=1|A=1) — equal positive prediction rates. - Equal opportunity: Equal true positive rates across groups. - Equalized odds: Equal TPR and FPR across groups. - Calibration: Equal calibration across groups. Tools: Fairlearn, AIF360.

•

Q177. What is the impossibility theorem in ML fairness?

It is mathematically impossible to simultaneously satisfy all fairness criteria (demographic parity, equal opportunity, calibrated predictions) when base rates differ across groups (Chouldechova 2017, Kleinberg et al. 2016). You must choose which fairness criterion matters most for the specific use case.

•

Q178. What is causal inference and how does it differ from standard ML?

Standard MLCausal inference
  • Standard ML: Learns correlations P(Y|X) — "what is the prediction?"
  • Causal inference: Estimates interventional distributions P(Y|do(X=x)) — "what happens if we change X?" Correlation ≠ causation. Required for: policy decisions, A/B test analysis, treatment effect estimation.
•

Q179. What is a directed acyclic graph (DAG) in causality?

Encodes causal assumptions: nodes = variables, edges = direct causal effects. Used to identify confounders, determine adjustment sets (backdoor criterion), and derive identification formulas for causal effects.

•

Q180. What is the Potential Outcomes Framework (Rubin Causal Model)?

ATE = 𝔼[Y(1) − Y(0)]

$Y(1)$ = outcome if treated, $Y(0)$ = outcome if untreated. The fundamental problem: we can only observe one. Estimation methods: RCT, matching, IPW, DID, instrumental variables, regression discontinuity.

•

Q181. What is propensity score matching?

Estimate the propensity score e(x) = P(T=1|X=x) (probability of treatment given covariates). Match treated and control units with similar propensity scores to reduce confounding bias in observational studies.

•

Q182. What is uplift modeling (heterogeneous treatment effect estimation)?

Predict the causal effect of a treatment on an individual (not just on average):

τ(x) = 𝔼[Y(1) − Y(0) | X=x]

Methods: S-Learner, T-Learner, X-Learner, causal forests (GRF). Used in marketing targeting — treat customers who would be positively influenced, not those who would buy anyway.

•

Q183. What is federated learning?

Training ML models across distributed devices without centralizing data: 1. Server sends global model to devices. 2. Each device trains locally on private data. 3. Devices send gradients/model updates (not data) to server. 4. Server aggregates (FedAvg) and sends updated global model. Used by: mobile keyboards, healthcare, banking.

•

Q184. What is differential privacy and how does it apply to ML?

Provides formal privacy guarantees: any individual's data has bounded influence on model outputs. Adding carefully calibrated Gaussian/Laplace noise to gradients (DP-SGD). Quantified by privacy budget ε — lower = more private but less accurate.

•

Q185. What is active learning?

Uncertainty samplingDiversity sampling (core-set)Expected Model Change

Query the human labeler only for the most informative unlabeled examples: - Uncertainty sampling: Query instances where the model is most uncertain. - Diversity sampling (core-set): Query diverse representative examples. - Expected Model Change: Query instances that would most change the model. Reduces labeling cost dramatically.

•

Q186. What is semi-supervised learning?

Pseudo-labelingLabel spreading/Label propagationSelf-training

Use large amounts of unlabeled data together with small amounts of labeled data: - Pseudo-labeling: Train on labeled data, predict on unlabeled, add high-confidence predictions as labels, retrain. - Label spreading/Label propagation: Propagate labels through a graph of similar examples. - Self-training: Iterative pseudo-labeling.

•

Q187. What is transfer learning in traditional ML?

Reuse features or model components learned on a source task for a related target task. In non-deep ML: - Use pretrained embeddings (word2vec, fastText) as features. - Fine-tune a decision tree on a new dataset using a pre-built ensemble as a starting point. - Domain adaptation via importance weighting (CORAL, MMD).

Q188. What is multi-task learning?

Q192. What is PAC learning (Probably Approximately Correct)?

A framework for analyzing the sample complexity of learning algorithms: - "Probably": with probability ≥ 1-δ. - "Approximately": error ≤ ε. PAC-learnable = there exists an algorithm that, with poly(1/ε, 1/δ, n) samples, outputs a hypothesis with error ≤ ε. VC dimension bounds sample complexity.

Q193. What is the VC dimension?

The largest set of points that a hypothesis class can shatter (classify in all 2^n ways). Measures model capacity: - Hyperplanes in ℝd: VC dim = d+1. - Decision stumps: VC dim = 2. High VC dim → more expressive, more data needed.

Q194. What is Rademacher complexity?

A more refined measure of model capacity than VC dimension. Measures how well a hypothesis class fits random noise labels. Lower Rademacher complexity → better generalization guarantees.

Q201. What is the difference between cosine similarity and Euclidean distance? When should you use each?

Cosine similarityangleEuclidean (L2) distancestraight-line gapKey relationshipL2-normalized

Both quantify how "close" two vectors a,b∈ℝd are, but along different notions of closeness:

cos(a,b) = a·b|a| |b|∈[−1,1]      dL2(a,b)=√∑i (ai−bi)2∈[0,∞)
  • Cosine similarity measures the angle between the vectors — orientation only, magnitude-invariant. Same direction → 1 regardless of length. (Cosine distance = 1−cos.)
  • Euclidean (L2) distance measures the straight-line gap between the points — sensitive to both direction and magnitude. Smaller → more similar.

Key relationship — for L2-normalized vectors (|a|=|b|=1) they are monotonically equivalent:

dL22 = |a|2 + |b|2 − 2 a·b = 2 − 2cos(a,b)

So on normalized vectors, ranking by smallest L2 = largest cosine = largest dot product. This is exactly why vector DBs normalize embeddings and search by fast dot product.

import numpy as np

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

def euclidean_distance(a, b):
    return np.sqrt(np.sum((a - b) ** 2))

a, b = np.array([1., 2., 3.]), np.array([2., 4., 6.])  # b = 2a (same direction)
cosine_similarity(a, b)   # 1.0   → identical orientation
euclidean_distance(a, b)  # 3.74  → far apart in magnitude
Use cosineUse Euclidean
Text/embedding semantic search (length ≠ meaning)Magnitude is meaningful (counts, physical units)
High-dim sparse data (TF-IDF, bag-of-words)Low-dim dense geometric data, K-Means clustering
You care about direction / topicYou care about absolute position

Rule of thumb: for embeddings, normalize and use cosine (≡ dot product). For raw feature vectors where scale matters, use Euclidean — but standardize features first so one large-scale feature doesn't dominate the distance.

Q1. What is the scikit-learn Estimator API and why does it matter?

Answer:

Every algorithm in scikit-learn is an object exposing the same methods: fit(X, y) to learn, predict(X)/transform(X) to apply, plus score, get_params, and set_params. This uniformity means you can swap one model for another without touching the surrounding code.

from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier

for clf in (LogisticRegression(max_iter=200), RandomForestClassifier()):
    clf.fit(X_train, y_train)           # identical calls
    print(clf.score(X_test, y_test))    # identical interface

Key takeaway: Learned attributes carry a trailing underscore (coef_, feature_importances_); constructor hyperparameters do not. Once you know one estimator, you know them all.

Q2. What is the difference between fit, transform, and fit_transform?

Answer:

  • fit learns parameters (e.g., a scaler's mean/std) and stores them.
  • transform applies those learned parameters to data.
  • fit_transform does both in one call and is often optimized.
scaler.fit(X_train)            # learns μ, σ from train
X_tr = scaler.transform(X_train)
X_te = scaler.transform(X_test)   # SAME μ, σ applied to test

Key takeaway: Call fit/fit_transform on training data only, then transform everything else. Calling fit_transform on the test set leaks information and inflates your scores.

Q3. What is data leakage and how do you prevent it?

Answer:

Data leakage is when information from outside the training fold sneaks into the model — most commonly by fitting preprocessing on the whole dataset before splitting. The model then looks great in validation but fails in production.

# WRONG — scaler sees test statistics
X_all = StandardScaler().fit_transform(X)
X_tr, X_te = train_test_split(X_all, ...)

# RIGHT — preprocessing inside a Pipeline, re-fit per CV fold
pipe = Pipeline([('sc', StandardScaler()), ('clf', LogisticRegression())])
cross_val_score(pipe, X, y, cv=5)

Key takeaway: Wrap all preprocessing in a Pipeline so it is re-fit on each fold's training portion. Also watch for target leakage (features computed from the target) and temporal leakage (future data in time series).

Q4. Why use a Pipeline instead of applying transforms manually?

Answer:

A Pipeline chains preprocessing and the estimator into one object. Benefits: (1) no leakage — preprocessing is re-fit on each CV fold; (2) one serializable artifact; (3) works with GridSearchCV so you tune preprocessing and model together; (4) identical transforms guaranteed at train and inference time.

pipe = Pipeline([('sc', StandardScaler()), ('clf', SVC())])
GridSearchCV(pipe, {'clf__C': [0.1, 1, 10]}, cv=5).fit(X_train, y_train)

Key takeaway: Pipeline step parameters are addressed with stepname__param in grids.

Q5. What does ColumnTransformer do?

Answer:

It applies different transformers to different column subsets in parallel — e.g., scale numeric columns while one-hot encoding categoricals — and concatenates the results.

ColumnTransformer([
    ('num', StandardScaler(), numeric_cols),
    ('cat', OneHotEncoder(handle_unknown='ignore'), categorical_cols),
], remainder='drop')   # or 'passthrough'

Key takeaway: Real datasets are mixed-type; ColumnTransformer is the standard way to handle them. Use remainder='passthrough' to keep untouched columns.

Q6. When do you need to scale features, and which scaler?

Answer:

Scale for distance- and gradient-based models: SVM, KNN, logistic/linear regression with regularization, neural nets, PCA, K-Means. Tree-based models (Decision Tree, Random Forest, gradient boosting) are scale-invariant and need none.

ScalerUse when
StandardScalerDefault for most models
MinMaxScalerBounded [0,1] needed
RobustScalerOutliers present (uses median/IQR)
MaxAbsScalerSparse data

Key takeaway: Scaling never hurts tree models but is mandatory for distance-based ones. Fit the scaler on train only.

Q7. Explain train_test_split and the role of stratify.

Answer:

It randomly partitions data into train and test sets. stratify=y keeps the class distribution identical in both splits — essential for classification, especially imbalanced data.

train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

Key takeaway: Always stratify for classification; never shuffle time series (split chronologically). random_state makes the split reproducible.

Q8. What is cross-validation and which splitter do you choose?

Answer:

Cross-validation repeatedly splits the data into train/validation folds and averages the scores, giving a lower-variance estimate of generalization than a single split.

  • StratifiedKFold — classification (preserves class ratios).
  • KFold — regression.
  • GroupKFold — a group (patient/user) must not span folds.
  • TimeSeriesSplit — temporal data (train always precedes test).
cross_val_score(model, X, y, cv=StratifiedKFold(5), scoring='f1_weighted')

Key takeaway: Match the splitter to the data's structure; the wrong CV (e.g., shuffled KFold on time series) gives optimistic, invalid estimates.

Q9. Compare Ridge, Lasso, and ElasticNet.

Answer:

All add a penalty to linear regression to control overfitting:

  • Ridge (L2): shrinks coefficients toward zero but never to exactly zero; handles multicollinearity; keeps all features.
  • Lasso (L1): drives some coefficients to exactly zero → automatic feature selection; arbitrarily picks one among correlated features.
  • ElasticNet (L1+L2): blends both via l1_ratio; better than Lasso with correlated features.

Key takeaway: Use Ridge when all features matter, Lasso for sparse/interpretable models, ElasticNet when features are correlated. All require scaling because the penalty is scale-dependent.

Q10. How does C in SVM / LogisticRegression relate to regularization?

Answer:

C is the inverse of regularization strength. Small C = strong regularization (simpler model, more bias); large C = weak regularization (fits training data harder, more variance).

LogisticRegression(C=0.01)   # heavy regularization
LogisticRegression(C=100)    # almost unregularized

Key takeaway: It is inverted relative to alpha in Ridge/Lasso, where larger alpha means more regularization. Easy to confuse in interviews.

Q11. Random Forest vs Gradient Boosting — how do they differ?

Answer:

Both are tree ensembles but combine trees differently. Random Forest (bagging) trains many deep trees independently on bootstrap samples and averages them — reduces variance. Gradient Boosting trains shallow trees sequentially, each correcting the previous ensemble's errors — reduces bias.

Key takeaway: RF is a robust low-effort baseline; boosting (XGBoost/LightGBM) usually wins on tabular data with proper tuning.

Q12. When would you pick LightGBM over XGBoost or CatBoost?

Answer:

  • LightGBM: fastest on large datasets (histogram + leaf-wise growth), low memory; can overfit small data via num_leaves.
  • XGBoost: strong regularization, GPU support, very mature.
  • CatBoost: best native categorical handling (ordered target encoding), great defaults.

Key takeaway: Start with LightGBM for speed, reach for CatBoost when you have many high-cardinality categoricals, and use XGBoost as a strong, well-documented alternative.

Q13. GridSearchCV vs RandomizedSearchCV vs HalvingRandomSearchCV?

Answer:

  • GridSearchCV: exhaustive over the grid — guaranteed best in the grid but explodes combinatorially.
  • RandomizedSearchCV: samples n_iter random combinations from distributions — far more efficient for large/continuous spaces.
  • HalvingRandomSearchCV: successive halving — trains many candidates on little data, keeps the best for more data; fastest.

Key takeaway: Use Grid for tiny spaces, Randomized for large ones, Halving when compute is the bottleneck.

Q14. Why is accuracy a poor metric for imbalanced data? What instead?

Answer:

With 99% negatives, a model predicting "negative" for everything scores 99% accuracy while being useless. Use metrics that focus on the minority class: precision, recall, F1, PR-AUC, and Matthews Correlation Coefficient.

from sklearn.metrics import average_precision_score, f1_score
average_precision_score(y_test, y_prob)   # PR-AUC — robust to imbalance

Key takeaway: Prefer PR-AUC over ROC-AUC under severe imbalance — ROC-AUC can look deceptively high.

Q15. Explain precision, recall, and F1.

Answer:

  • Precision = TP / (TP + FP): of predicted positives, how many are correct.
  • Recall = TP / (TP + FN): of actual positives, how many were caught.
  • F1 = harmonic mean of precision and recall.
from sklearn.metrics import classification_report
print(classification_report(y_test, y_pred, digits=3))

Key takeaway: Optimize precision when false positives are costly (spam), recall when false negatives are costly (cancer screening), and F1 when you need one balanced number.

Q16. What does the confusion matrix tell you?

Answer:

It tabulates predictions against actual labels: rows = actual, columns = predicted. The off-diagonal cells are the errors (false positives and false negatives), which precision/recall are derived from.

from sklearn.metrics import confusion_matrix
confusion_matrix(y_test, y_pred)
# [[TN FP]
#  [FN TP]]

Key takeaway: It exposes which kind of error your model makes, not just how often — crucial for choosing the right metric and threshold.

Q17. What is ROC-AUC and how does it differ from PR-AUC?

Answer:

ROC-AUC plots TPR vs FPR across thresholds; 1.0 is perfect, 0.5 is random. It is threshold-independent. PR-AUC plots precision vs recall and is more informative when positives are rare because it ignores the large number of true negatives.

Key takeaway: ROC-AUC for roughly balanced data; PR-AUC for severe imbalance. Both summarize ranking quality across all thresholds.

Q18. How do you handle a 1:100 class imbalance?

Answer:

Layered approach: (1) use PR-AUC/F1, not accuracy; (2) class_weight='balanced'; (3) resample with SMOTE inside an imbalanced-learn pipeline (train-time only); (4) tune the decision threshold on validation; (5) collect more minority data if possible.

from imblearn.over_sampling import SMOTE
from imblearn.pipeline import Pipeline as ImbPipeline
ImbPipeline([('smote', SMOTE()), ('clf', LGBMClassifier())])

Key takeaway: SMOTE must be applied only during fit — the imbalanced-learn pipeline handles this automatically; never resample the test set.

Q19. What is SMOTE and how is it different from random oversampling?

Answer:

SMOTE (Synthetic Minority Over-sampling) creates new synthetic minority samples by interpolating between a minority point and its k nearest neighbors. Random oversampling just duplicates existing minority rows.

Key takeaway: Duplicates encourage overfitting to exact copies; SMOTE generates plausible new points and generalizes better. ADASYN is a variant focusing synthesis near the decision boundary.

Q20. What is model calibration and when do you need it?

Answer:

Calibration ensures predicted probabilities match real frequencies — when the model says 0.7, ~70% of such cases should be positive. Needed when decisions rest on probability thresholds (fraud, medical risk) or when comparing models by log loss.

from sklearn.calibration import CalibratedClassifierCV
CalibratedClassifierCV(rf, method='isotonic', cv=5).fit(X_train, y_train)

Key takeaway: Random Forest and SVM are often poorly calibrated; logistic regression usually is not. Use Platt ('sigmoid') for small data, isotonic for larger.

Q21. SimpleImputer vs KNNImputer vs IterativeImputer?

Answer:

  • SimpleImputer: fills with mean/median/most_frequent/constant — fast, no relationships used.
  • KNNImputer: fills from the k nearest complete rows — captures local structure, slower.
  • IterativeImputer (MICE): models each feature from the others round-robin — most powerful, experimental.

Key takeaway: Median is the safe default for skewed numeric data; most_frequent for categoricals. Put the imputer in the Pipeline so statistics are learned per fold.

Q22. Compare OneHotEncoder, OrdinalEncoder, and LabelEncoder.

Answer:

  • OneHotEncoder: one binary column per category — for nominal features.
  • OrdinalEncoder: integer codes for ordered categories (low<med<high) — for features.
  • LabelEncoder: integer codes for the target y only.

Key takeaway: Never use LabelEncoder on features — its arbitrary integers imply a false ordering. Use handle_unknown='ignore' on OneHotEncoder to survive unseen categories at inference.

Q23. What is the difference between predict and predict_proba?

Answer:

predict returns the final class label (using a 0.5 threshold for binary); predict_proba returns class probabilities, letting you choose a custom threshold or rank by confidence.

clf.predict(X)[:3]                 # array([1, 0, 1])
clf.predict_proba(X)[:3].round(2)  # array([[0.2, 0.8], [0.7, 0.3], [0.4, 0.6]])

Key takeaway: For imbalanced problems, use predict_proba plus a tuned threshold rather than the default 0.5.

Q24. How do you choose the classification threshold?

Answer:

Compute precision/recall across thresholds and pick the one optimizing your objective (max F1, or a target recall).

from sklearn.metrics import precision_recall_curve
import numpy as np
p, r, thr = precision_recall_curve(y_test, y_prob)
best = thr[np.argmax(2*p[:-1]*r[:-1] / (p[:-1]+r[:-1]+1e-9))]
y_pred = (y_prob >= best).astype(int)

Key takeaway: Tune the threshold on a validation set, never on the test set, and align it with the business cost of FP vs FN.

Q25. Filter vs wrapper vs embedded feature selection?

Answer:

  • Filter (SelectKBest, VarianceThreshold): score features by a statistic independent of any model — fast.
  • Wrapper (RFE, SequentialFeatureSelector): repeatedly train a model and add/drop features — accurate but expensive.
  • Embedded (SelectFromModel, Lasso): selection happens during model fitting via importances/coefficients.

Key takeaway: Embedded methods are usually the best speed/quality trade-off; always do selection inside CV to avoid leakage.

Q26. PCA vs feature selection — when to use which?

Answer:

PCA creates new uncorrelated features (linear combinations) maximizing variance; the originals are lost, hurting interpretability. Feature selection keeps a subset of the original features.

Key takeaway: Use PCA to denoise/speed up when interpretability does not matter; use feature selection when you must explain which original features drive predictions (finance, healthcare). PCA usually hurts tree models.

Q27. How does PCA work, and when does it fail?

Answer:

PCA finds orthogonal directions (eigenvectors of the covariance matrix) of maximum variance and projects data onto the top components.

PCA(n_components=0.95).fit_transform(X_scaled)   # keep 95% of variance

It fails when relationships are non-linear (variance ≠ class separability), features aren't scaled, or outliers dominate the variance.

Key takeaway: Always StandardScale before PCA; consider Kernel PCA or UMAP for non-linear structure.

Q28. Why does scikit-learn distinguish leaf attributes with a trailing underscore?

Answer:

It is a naming convention: any attribute set during fit (learned from data) ends with _ (coef_, cluster_centers_, n_features_in_). Constructor hyperparameters never do.

Key takeaway: Accessing a _ attribute before calling fit raises NotFittedError — a quick way to tell learned state from configuration.

Q29. When would you write a custom transformer, and what is the contract?

Answer:

When you need preprocessing that sklearn doesn't provide (domain feature engineering, custom clipping, smoothed target encoding). Inherit BaseEstimator + TransformerMixin, implement fit (learn state into _ attributes) and transform.

class Clipper(BaseEstimator, TransformerMixin):
    def __init__(self, factor=1.5): self.factor = factor
    def fit(self, X, y=None): self.bounds_ = ...; return self
    def transform(self, X): return ...

Key takeaway: Keep __init__ free of logic (just store args) so get_params/set_params and cloning work — required for GridSearchCV.

Q30. How do you persist a model for production?

Answer:

Serialize the entire Pipeline with joblib so preprocessing travels with the model.

import joblib
joblib.dump(pipeline, 'model.joblib')
model = joblib.load('model.joblib')

Key takeaway: Pin the scikit-learn version (cross-version unpickling is unsafe), and never load joblib/pickle files from untrusted sources — they can execute arbitrary code. For language-agnostic, optimized inference, export to ONNX.

Q31. What does cross_val_score actually return, and how do you read it?

Answer:

An array of one score per fold. Report mean ± std to convey both performance and stability.

s = cross_val_score(model, X, y, cv=5, scoring='roc_auc')
print(f"{s.mean():.3f} ± {s.std():.3f}")

Key takeaway: A large std signals an unstable model or too-small folds. Use cross_validate for multiple metrics and train scores in one pass.

Q32. How do you diagnose underfitting vs overfitting in scikit-learn?

Answer:

Compare train and validation scores (e.g., via learning_curve). High bias (underfit): both low and close. High variance (overfit): train high, validation much lower.

from sklearn.model_selection import learning_curve
sizes, train, val = learning_curve(model, X, y, cv=5)

Key takeaway: Underfitting → add complexity/features; overfitting → regularize, add data, or simplify. The train–val gap is the key signal.

Q33. What is the purpose of random_state?

Answer:

It seeds the internal RNG so stochastic operations (splits, bootstrap sampling, K-Means init, SGD shuffling) are reproducible across runs.

Key takeaway: Set it everywhere (split, model, CV) for reproducible experiments — but never tune over random seeds to cherry-pick results.

Q34. How do you tune preprocessing and model hyperparameters jointly?

Answer:

Put everything in a Pipeline and reference step parameters with the stepname__param syntax inside a single search.

GridSearchCV(pipe, {
    'prep__num__imputer__strategy': ['mean', 'median'],
    'clf__C': [0.1, 1, 10],
}, cv=5).fit(X_train, y_train)

Key takeaway: This searches preprocessing and model together while keeping all transforms re-fit per fold — the leak-free, idiomatic way to tune.

Q35. Random Forest vs XGBoost vs LightGBM vs CatBoost — when do you pick each?

Answer:

  • Random Forest: bagging — many independent deep trees averaged. Robust low-effort baseline, parallel (n_jobs=-1), hard to overfit, but a black box and can't extrapolate.
  • XGBoost: boosting with strong L1/L2 regularization, native NaN handling, GPU. Competition staple; more params, slower than LightGBM.
  • LightGBM: histogram + leaf-wise growth — fastest on large data, native categoricals, low memory; num_leaves can overfit small datasets.
  • CatBoost: ordered target encoding for categoricals, great defaults, ordered boosting reduces target leakage; slower on purely numeric data.

Key takeaway: Start with LightGBM for speed, reach for CatBoost with many high-cardinality categoricals, use XGBoost as a well-documented strong alternative, and RF as a simple baseline. Leaf-wise (LightGBM) grows the highest-loss leaf; level-wise (XGBoost) grows balanced trees.

Q36. What is the bias–variance trade-off and how do you diagnose it in sklearn?

Answer:

Total error = bias² + variance + irreducible noise. High bias = underfitting (model too simple); high variance = overfitting (model memorizes noise). Diagnose with learning_curve (score vs training size) and validation_curve (score vs one hyperparameter): both curves low and close → high bias; large persistent train–val gap → high variance.

from sklearn.model_selection import learning_curve
sizes, train, val = learning_curve(model, X, y, cv=5)

Key takeaway: Underfit → add complexity/features; overfit → regularize, add data, or simplify. Bagging reduces variance; boosting reduces bias.

Q37. Walk through backpropagation in a 2-layer neural network.

Answer:

Forward: z1 = XW1 + b1 → a1 = ReLU(z1) → z2 = a1·W2 + b2 → a2 = softmax(z2). Loss L = -Σ y·log(a2). Backward (chain rule from output to input):

  1. dz2 = a2 − y (softmax + cross-entropy simplify to this)
  2. dW2 = a1ᵀ·dz2, db2 = Σ dz2
  3. da1 = dz2·W2ᵀ
  4. dz1 = da1 ⊙ (z1 > 0) (ReLU derivative)
  5. dW1 = Xᵀ·dz1, db1 = Σ dz1

Update each: W -= lr·dW.

Key takeaway: The output gradient a2 − y is the clean result of softmax+CE cancelling; gradients then flow backward layer by layer.

Q38. How does PCA work mathematically, and when does it fail?

Answer:

(1) Center the data; (2) compute the covariance matrix; (3) eigen-decompose it — eigenvectors are the principal components, eigenvalues are the variance explained; (4) project onto the top-k eigenvectors. SVD is the numerically stable equivalent. It fails when relationships are non-linear (variance ≠ class separability), features aren't scaled, or outliers dominate the variance.

PCA(n_components=0.95).fit_transform(X_scaled)   # keep 95% variance

Key takeaway: Always StandardScale before PCA; for non-linear structure use Kernel PCA or UMAP. PCA usually hurts tree models.

Q39. Explain Gini impurity vs entropy for decision-tree splits.

Answer:

Both measure node impurity. Gini = 1 − Σ pᵢ² (binary: 2p(1−p)); entropy = −Σ pᵢ·log pᵢ. A pure node = 0; a 50/50 binary split is maximal. At each node the tree picks the split maximizing information gain = parent_impurity − weighted_child_impurity.

Key takeaway: Gini and entropy give very similar trees; Gini is the default because it avoids the logarithm (faster). Pure nodes have impurity 0.

Q40. Why does K-Means++ initialization beat random initialization?

Answer:

Random init can place centroids close together, causing poor convergence or empty clusters. K-Means++ picks the first centroid at random, then each subsequent one with probability proportional to squared distance from the nearest chosen centroid — spreading them out. This yields faster convergence and clustering closer to the global optimum (and is n_init'd to keep the best run).

Key takeaway: It's sklearn's default (init='k-means++'); still set n_init>1 because K-Means only finds a local optimum.

Q41. Why scale attention scores by √dₖ in self-attention?

Answer:

Dot products Q·Kᵀ have variance proportional to dₖ (sum of dₖ unit-variance products). Large values push softmax into saturation where gradients vanish, making attention nearly one-hot and untrainable. Dividing by √dₖ normalizes the variance back to ~1, keeping softmax in its sensitive region.

scores = Q @ K.T / np.sqrt(d_k)

Key takeaway: Without scaling, deep transformers fail to learn — hence "scaled dot-product attention."

Q42. How does BPE tokenization work and why do LLMs use it?

Answer:

Byte-Pair Encoding starts from a character-level vocabulary, then iteratively counts adjacent token pairs and merges the most frequent pair into a new token, repeating until a target vocab size. LLMs use it because it (1) handles any text with no true OOV (falls back to characters), (2) compresses common words into single tokens, (3) captures sub-word morphology ("running" → "run"+"ning"), and (4) gives a fixed vocabulary (~32K–100K).

Key takeaway: GPT models use BPE (tiktoken); BERT uses the similar WordPiece. The key trade-off is vocabulary size vs ability to represent rare words.

Q43. Greedy decoding vs beam search for sequence generation?

Answer:

Greedy always takes the highest-probability next token — fast O(V·T), but locally-best ≠ globally-best. Beam search keeps the top-B partial sequences at each step O(B·V·T), giving higher-quality output (standard for translation/ASR). Larger beams help up to a point, then produce generic/repetitive text.

Key takeaway: Beam search optimizes likelihood and suits accuracy-critical tasks; for open-ended/creative generation, sampling (temperature, top-p) is preferred because beam search yields bland, repetitive text.

# Linear Regression (gradient descent) — dL/dw = (2/n) Xᵀ(Xw − y)
class LinearRegressionGD:
    def __init__(self, lr=0.01, epochs=1000): self.lr, self.epochs = lr, epochs
    def fit(self, X, y):
        n, d = X.shape; self.w, self.b = np.zeros(d), 0.0
        for _ in range(self.epochs):
            err = (X @ self.w + self.b) - y
            self.w -= self.lr * (2/n) * (X.T @ err)
            self.b -= self.lr * (2/n) * err.sum()
    def predict(self, X): return X @ self.w + self.b

def knn_predict(Xtr, ytr, Xte, k=5):

def kmeans(X, k, iters=100):
    C = X[np.random.choice(len(X), k, replace=False)]

        d = np.linalg.norm(X[:, None] - C, axis=2)
        lab = d.argmin(1)
        newC = np.array([X[lab==j].mean(0) if (lab==j).any() else C[j] for j in range(k)])
        if np.allclose(newC, C): break
        C = newC
    return lab, C

def self_attention(X, Wq, Wk, Wv):

# K-Fold split from scratch (no leakage: test fold never trains)
def kfold(n, k=5, seed=42):
    idx = np.arange(n); np.random.RandomState(seed).shuffle(idx)
    sizes = np.full(k, n//k); sizes[:n%k] += 1
    cur = 0
    for s in sizes:
        te = idx[cur:cur+s]; tr = np.concatenate([idx[:cur], idx[cur+s:]])
        yield tr, te; cur += s

Question: Three friends each independently lie with probability 1/3. All three say it's raining. What is the probability that it's actually raining?

P(all say raining | R) â€” actually raining, all tell truth:

P(all say rain | R) = (23)3 = 827

P(all say raining | R') â€” not raining, all lie:

P(all say rain | R') = (13)3 = 127

Bayes' Theorem:

P(R | all say rain) = P(all say rain | R) · P(R)P(all say rain) = 827 · 12827 · 12 + 127 · 12 = 854854 + 154 = 89 ≈ 0.889

import random

def simulate(n_trials=1000000):

def stone_game_probability(n_rounds, p_a_wins_round=0.5):
    """
    Calculate P(B wins) over n rounds.
    Assumes each round is independent.
    """
    from scipy.stats import binom

    # B wins if B wins more than n/2 rounds
    p_b = 1 - p_a_wins_round
    b_wins_prob = 0

    for k in range(n_rounds // 2 + 1, n_rounds + 1):
        b_wins_prob += binom.pmf(k, n_rounds, p_b)

    return b_wins_prob

Q9. Second Largest Element in BST (LinkedIn â€” Data Scientist)

Question: Find the second largest element in a Binary Search Tree.

Solution:

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

def second_largest_bst(root):
    """
    The largest is the rightmost node.
    The second largest is either:
    1. Parent of the rightmost node (if rightmost has no left subtree)
    2. Rightmost node of the left subtree of the largest
    """
    if not root:
        return None

    current = root
    parent = None

    # Find the largest (rightmost) node
    while current.right:
        parent = current
        current = current.right

    # Case 1: Largest node has a left subtree
    # â†’ Second largest is the rightmost of that left subtree
    if current.left:
        node = current.left
        while node.right:
            node = node.right
        return node.val

    # Case 2: Largest node has no left subtree
    # â†’ Second largest is its parent
    return parent.val if parent else None

# Alternative: In-order traversal (reverse)
def second_largest_inorder(root):
    stack = []
    count = 0
    current = root

    while stack or current:
        while current:
            stack.append(current)
            current = current.right  # Reverse in-order

        current = stack.pop()
        count += 1
        if count == 2:
            return current.val
        current = current.left

    return None

Time Complexity: O(h) where h = height of BST. O(log n) for balanced BST.

# Sample size calculation
from scipy.stats import norm
import numpy as np

def required_sample_size(baseline_rate, mde, alpha=0.05, power=0.80):
    """
    baseline_rate: current conversion rate
    mde: minimum detectable effect (relative)
    """
    p1 = baseline_rate
    p2 = baseline_rate * (1 + mde)

    z_alpha = norm.ppf(1 - alpha/2)
    z_beta = norm.ppf(power)

    pooled_p = (p1 + p2) / 2

    n = ((z_alpha * np.sqrt(2 * pooled_p * (1 - pooled_p)) +
          z_beta * np.sqrt(p1*(1-p1) + p2*(1-p2))) / (p2 - p1)) ** 2

    return int(np.ceil(n))

Q23. Bayesian A/B testing vs frequentist (Spotify — Data Scientist)

Question: Compare Bayesian and frequentist approaches to A/B testing. When to use each?

Solution:

import numpy as np
from scipy import stats

# Frequentist A/B Test
def frequentist_ab_test(control_conversions, control_total,
                        treatment_conversions, treatment_total, alpha=0.05):
    p1 = control_conversions / control_total
    p2 = treatment_conversions / treatment_total

    # Pooled proportion
    p_pool = (control_conversions + treatment_conversions) / (control_total + treatment_total)
    se = np.sqrt(p_pool * (1 - p_pool) * (1/control_total + 1/treatment_total))

    z = (p2 - p1) / se
    p_value = 2 * (1 - stats.norm.cdf(abs(z)))

    return {
        'control_rate': p1,
        'treatment_rate': p2,
        'lift': (p2 - p1) / p1 * 100,
        'z_statistic': z,
        'p_value': p_value,
        'significant': p_value < alpha
    }

# Bayesian A/B Test
def bayesian_ab_test(control_conversions, control_total,
                     treatment_conversions, treatment_total,
                     n_simulations=100000):
    # Beta posterior (uninformative prior: Beta(1,1))
    control_samples = np.random.beta(
        control_conversions + 1,
        control_total - control_conversions + 1,
        n_simulations
    )
    treatment_samples = np.random.beta(
        treatment_conversions + 1,
        treatment_total - treatment_conversions + 1,
        n_simulations
    )

    prob_treatment_better = np.mean(treatment_samples > control_samples)
    expected_lift = np.mean((treatment_samples - control_samples) / control_samples) * 100

    return {
        'P(treatment > control)': prob_treatment_better,
        'expected_lift': expected_lift,
        'lift_95_ci': np.percentile(
            (treatment_samples - control_samples) / control_samples * 100,
            [2.5, 97.5]
        )
    }

# Example
freq = frequentist_ab_test(500, 10000, 550, 10000)
bayes = bayesian_ab_test(500, 10000, 550, 10000)
print("Frequentist:", freq)
print("Bayesian:", bayes)

Key Insight: Frequentist answers "would we see this result by chance?" Bayesian answers "what's the probability treatment is better?" Bayesian is preferred when you need to make continuous decisions (e.g., bandits).

Q25. Power analysis — sample size calculation (Netflix — Data Scientist)

Question: Calculate the required sample size for an A/B test detecting a 2% lift with 80% power.

Solution:

from scipy import stats
import numpy as np

def sample_size_proportions(p1, mde, alpha=0.05, power=0.80):
    """Calculate sample size per group for proportion test.

    Args:
        p1: baseline conversion rate
        mde: minimum detectable effect (absolute)
        alpha: significance level
        power: statistical power (1 - beta)
    """
    p2 = p1 + mde

    z_alpha = stats.norm.ppf(1 - alpha / 2)  # Two-tailed
    z_beta = stats.norm.ppf(power)

    p_avg = (p1 + p2) / 2

    n = ((z_alpha * np.sqrt(2 * p_avg * (1 - p_avg)) +
          z_beta * np.sqrt(p1 * (1 - p1) + p2 * (1 - p2))) ** 2) / (mde ** 2)

    return int(np.ceil(n))

# Example: 5% baseline, detect 0.5% absolute lift
n = sample_size_proportions(p1=0.05, mde=0.005)
print(f"Sample size per group: {n:,}")  # ~31,234

# Power curve
mdes = np.arange(0.001, 0.02, 0.001)
sizes = [sample_size_proportions(0.05, mde) for mde in mdes]

for mde, size in zip(mdes, sizes):
    print(f"MDE: {mde:.1%} → n = {size:>10,}")

# Multi-variant test correction (Bonferroni)
def sample_size_multivariate(p1, mde, num_variants, alpha=0.05, power=0.80):
    adjusted_alpha = alpha / num_variants  # Bonferroni correction
    return sample_size_proportions(p1, mde, adjusted_alpha, power)

n_multi = sample_size_multivariate(0.05, 0.005, num_variants=3)
print(f"\n3-variant test sample size: {n_multi:,}")

Key Insight: Smaller MDE requires exponentially more samples. Bonferroni correction for multiple variants increases required sample size. Always calculate sample size BEFORE running the test.

import numpy as np

class LinearRegressionGD:
    def __init__(self, learning_rate=0.01, n_iterations=1000, batch_size=None):
        self.lr = learning_rate
        self.n_iter = n_iterations
        self.batch_size = batch_size  # None=batch, 1=SGD, >1=mini-batch

    def fit(self, X, y):
        n_samples, n_features = X.shape
        self.weights = np.zeros(n_features)
        self.bias = 0
        self.loss_history = []

        for _ in range(self.n_iter):
            if self.batch_size:
                # Mini-batch or SGD
                indices = np.random.choice(n_samples, self.batch_size, replace=False)
                X_batch, y_batch = X[indices], y[indices]
            else:
                X_batch, y_batch = X, y

            # Forward pass
            y_pred = X_batch @ self.weights + self.bias

            # Compute gradients
            dw = (1 / len(X_batch)) * X_batch.T @ (y_pred - y_batch)
            db = (1 / len(X_batch)) * np.sum(y_pred - y_batch)

            # Update parameters
            self.weights -= self.lr * dw
            self.bias -= self.lr * db

            # Track loss
            mse = np.mean((X @ self.weights + self.bias - y) ** 2)
            self.loss_history.append(mse)

        return self

    def predict(self, X):
        return X @ self.weights + self.bias

# Test

Q27. Build a decision tree from scratch (Amazon — Data Scientist)

Question: Implement a decision tree classifier using information gain.

Solution:

import numpy as np
from collections import Counter

class DecisionTree:
    def __init__(self, max_depth=10, min_samples=2):
        self.max_depth = max_depth
        self.min_samples = min_samples

    def _entropy(self, y):
        counts = Counter(y)
        probs = [c / len(y) for c in counts.values()]
        return -sum(p * np.log2(p) for p in probs if p > 0)

    def _information_gain(self, X, y, feature, threshold):
        left_mask = X[:, feature] <= threshold
        right_mask = ~left_mask

        if sum(left_mask) == 0 or sum(right_mask) == 0:
            return 0

        parent_entropy = self._entropy(y)
        n = len(y)
        left_entropy = self._entropy(y[left_mask])
        right_entropy = self._entropy(y[right_mask])

        child_entropy = (sum(left_mask)/n * left_entropy +
                        sum(right_mask)/n * right_entropy)

        return parent_entropy - child_entropy

    def _best_split(self, X, y):
        best_gain = 0
        best_feature = None
        best_threshold = None

        for feature in range(X.shape[1]):
            thresholds = np.unique(X[:, feature])
            for threshold in thresholds:
                gain = self._information_gain(X, y, feature, threshold)
                if gain > best_gain:
                    best_gain = gain
                    best_feature = feature
                    best_threshold = threshold

        return best_feature, best_threshold, best_gain

    def _build_tree(self, X, y, depth=0):
        # Base cases
        if (depth >= self.max_depth or len(set(y)) == 1 or
            len(y) < self.min_samples):
            return Counter(y).most_common(1)[0][0]

        feature, threshold, gain = self._best_split(X, y)

        if gain == 0:
            return Counter(y).most_common(1)[0][0]

        left_mask = X[:, feature] <= threshold
        left_tree = self._build_tree(X[left_mask], y[left_mask], depth + 1)
        right_tree = self._build_tree(X[~left_mask], y[~left_mask], depth + 1)

        return {'feature': feature, 'threshold': threshold,
                'left': left_tree, 'right': right_tree}

    def fit(self, X, y):
        self.tree = self._build_tree(X, y)
        return self

    def _predict_one(self, x, tree):
        if not isinstance(tree, dict):
            return tree
        if x[tree['feature']] <= tree['threshold']:
            return self._predict_one(x, tree['left'])
        return self._predict_one(x, tree['right'])

    def predict(self, X):
        return np.array([self._predict_one(x, self.tree) for x in X])

import numpy as np
from collections import defaultdict

def k_fold_split(X, y, k=5, shuffle=True, stratified=False):
    """Generate k-fold train/test splits."""
    n = len(X)
    indices = np.arange(n)

    if stratified:
        # Group indices by class
        class_indices = defaultdict(list)
        for i, label in enumerate(y):
            class_indices[label].append(i)

        folds = [[] for _ in range(k)]
        for label, idx_list in class_indices.items():
            if shuffle:
                np.random.shuffle(idx_list)
            for i, idx in enumerate(idx_list):
                folds[i % k].append(idx)
    else:
        if shuffle:
            np.random.shuffle(indices)
        folds = np.array_split(indices, k)

    for i in range(k):
        test_idx = np.array(folds[i])
        train_idx = np.concatenate([folds[j] for j in range(k) if j != i])
        yield train_idx, test_idx

def cross_validate(model_class, X, y, k=5, metric_fn=None, **model_params):
    """Run k-fold CV and return scores."""
    if metric_fn is None:
        metric_fn = lambda y_true, y_pred: np.mean(y_true == y_pred)

    scores = []
    for fold, (train_idx, test_idx) in enumerate(k_fold_split(X, y, k, stratified=True)):
        X_train, X_test = X[train_idx], X[test_idx]
        y_train, y_test = y[train_idx], y[test_idx]

        model = model_class(**model_params)
        model.fit(X_train, y_train)
        y_pred = model.predict(X_test)

        score = metric_fn(y_test, y_pred)
        scores.append(score)
        print(f"Fold {fold+1}: {score:.4f}")

    print(f"\nMean: {np.mean(scores):.4f} ± {np.std(scores):.4f}")
    return scores

Key Insight: Stratified CV maintains class proportions in each fold — critical for imbalanced data. k=5 or k=10 is standard. Leave-one-out (k=n) has high variance, rarely used.

Q32. Multi-armed bandit vs traditional A/B test (DoorDash — Data Scientist)

Question: When would you use a multi-armed bandit instead of a traditional A/B test?

import numpy as np

class EpsilonGreedyBandit:
    """Multi-armed bandit with epsilon-greedy strategy."""

    def __init__(self, n_arms, epsilon=0.1):
        self.n_arms = n_arms
        self.epsilon = epsilon
        self.counts = np.zeros(n_arms)
        self.values = np.zeros(n_arms)

    def select_arm(self):
        if np.random.random() < self.epsilon:
            return np.random.randint(self.n_arms)  # Explore
        return np.argmax(self.values)  # Exploit

    def update(self, arm, reward):
        self.counts[arm] += 1
        n = self.counts[arm]
        self.values[arm] += (reward - self.values[arm]) / n

class ThompsonSamplingBandit:
    """Thompson Sampling for Beta-Bernoulli bandits."""

    def __init__(self, n_arms):
        self.n_arms = n_arms
        self.successes = np.ones(n_arms)  # Prior: Beta(1,1)
        self.failures = np.ones(n_arms)

    def select_arm(self):
        samples = [np.random.beta(self.successes[i], self.failures[i])
                   for i in range(self.n_arms)]
        return np.argmax(samples)

    def update(self, arm, reward):
        if reward:
            self.successes[arm] += 1
        else:
            self.failures[arm] += 1

# Simulation: Compare A/B test vs bandit
def simulate(true_rates, n_rounds=10000):
    n_arms = len(true_rates)

    # A/B test: equal allocation
    ab_rewards = []
    for _ in range(n_rounds):
        arm = np.random.randint(n_arms)
        reward = np.random.random() < true_rates[arm]
        ab_rewards.append(reward)

    # Thompson Sampling
    ts = ThompsonSamplingBandit(n_arms)
    ts_rewards = []
    for _ in range(n_rounds):
        arm = ts.select_arm()
        reward = np.random.random() < true_rates[arm]
        ts.update(arm, reward)
        ts_rewards.append(reward)

    print(f"A/B test total reward: {sum(ab_rewards)}")
    print(f"Thompson Sampling reward: {sum(ts_rewards)}")
    print(f"Regret reduction: {sum(ts_rewards) - sum(ab_rewards)}")

simulate([0.05, 0.06, 0.04])  # Variant B is best

Key Insight: A/B test: best for causal inference and statistical rigor. Bandit: best when opportunity cost of exploration is high (e.g., homepage recommendations). Thompson Sampling is the most practical bandit algorithm.

Q33. Design an experiment for a two-sided marketplace (Uber — Data Scientist)

Question: Uber wants to test a new pricing algorithm. How would you design the experiment considering network effects?

Solution:

"""
Two-Sided Marketplace Experiment Design:

CHALLENGE: User-level randomization causes interference
- If treatment riders get better prices → more rides → fewer drivers for control riders
- This is the "interference" or "spillover" problem

SOLUTIONS:

1. GEO-BASED RANDOMIZATION (preferred)
   - Randomize at city/region level
   - Each market gets either treatment or control
   - No cross-contamination between groups
"""

import numpy as np
import pandas as pd

def geo_randomization(markets, treatment_fraction=0.5):
    """Stratified geo-randomization."""
    # Stratify by market size
    markets = markets.sort_values('size')
    markets['stratum'] = pd.qcut(markets['size'], q=4, labels=False)

    assigned = []
    for _, stratum_df in markets.groupby('stratum'):
        n_treatment = int(len(stratum_df) * treatment_fraction)
        indices = stratum_df.index.tolist()
        np.random.shuffle(indices)
        for i, idx in enumerate(indices):
            assigned.append({
                'market': stratum_df.loc[idx, 'market_name'],
                'group': 'treatment' if i < n_treatment else 'control'
            })

    return pd.DataFrame(assigned)

"""
2. TIME-BASED SWITCHBACK
   - Alternate treatment/control within same market over time
   - Each market serves as its own control
   - Handles market-level confounders
"""

def switchback_design(markets, n_periods=14, period_hours=6):
    """Generate switchback schedule."""
    schedule = []
    for market in markets:
        for period in range(n_periods * (24 // period_hours)):
            # Randomize with constraints (no more than 3 consecutive same treatment)
            group = 'treatment' if np.random.random() > 0.5 else 'control'
            schedule.append({
                'market': market,
                'period': period,
                'group': group
            })
    return pd.DataFrame(schedule)

"""
3. ANALYSIS: Difference-in-Differences
   Pre-period: Compare treatment and control markets
   Post-period: Measure change in outcome
   DiD estimate = (Treatment_post - Treatment_pre) - (Control_post - Control_pre)
"""

def diff_in_diff(data, treatment_col, time_col, outcome_col, post_period):
    """Simple Difference-in-Differences estimator."""
    groups = {}
    for treat in [0, 1]:
        for post in [0, 1]:
            mask = (data[treatment_col] == treat) & ((data[time_col] >= post_period) == post)
            groups[(treat, post)] = data.loc[mask, outcome_col].mean()

    did_estimate = (groups[(1,1)] - groups[(1,0)]) - (groups[(0,1)] - groups[(0,0)])
    return did_estimate

markets = pd.DataFrame({
    'market_name': [f'city_{i}' for i in range(20)],
    'size': np.random.randint(10000, 1000000, 20)
})
print(geo_randomization(markets))

Key Insight: Network effects violate SUTVA (Stable Unit Treatment Value Assumption). Geo-randomization + DiD is the gold standard for marketplace experiments. Switchback handles within-market seasonality.

Q34. Design a feature store (Databricks — Staff Data Scientist)

Question: Design a feature store that serves both batch training and real-time inference.

Solution:

"""
Feature Store Architecture:

┌──────────────┐    ┌─────────────────┐    ┌──────────────┐
│  Raw Data    │───→│ Feature Pipeline │───→│ Feature Store│
│  (S3/Kafka)  │    │ (Spark/Flink)   │    │              │
└──────────────┘    └─────────────────┘    │ ┌──────────┐ │
                                           │ │  Offline  │ │←── Training
                                           │ │  (Parquet)│ │
                                           │ └──────────┘ │
                                           │ ┌──────────┐ │
                                           │ │  Online   │ │←── Serving
                                           │ │  (Redis)  │ │
                                           │ └──────────┘ │
                                           └──────────────┘
"""

from dataclasses import dataclass, field
from typing import Dict, List, Optional, Any
from datetime import datetime
import json

@dataclass
class FeatureDefinition:
    name: str
    entity: str  # e.g., "user", "item"
    dtype: str
    description: str
    source: str
    freshness_sla: str  # e.g., "1h", "1d"
    version: int = 1
    tags: List[str] = field(default_factory=list)

class FeatureStore:
    def __init__(self):
        self.registry: Dict[str, FeatureDefinition] = {}
        self.offline_store: Dict[str, List[Dict]] = {}  # entity_key -> features
        self.online_store: Dict[str, Dict] = {}  # entity_key -> latest features

    def register_feature(self, feature_def: FeatureDefinition):
        """Register a feature definition in the registry."""
        key = f"{feature_def.entity}/{feature_def.name}/v{feature_def.version}"
        self.registry[key] = feature_def
        return key

    def ingest_batch(self, entity: str, feature_name: str, data: List[Dict]):
        """Ingest batch features (for training)."""
        for record in data:
            entity_key = f"{entity}:{record['entity_id']}"
            if entity_key not in self.offline_store:
                self.offline_store[entity_key] = []
            self.offline_store[entity_key].append({
                'feature': feature_name,
                'value': record['value'],
                'timestamp': record.get('timestamp', datetime.now().isoformat())
            })
            # Also update online store with latest
            if entity_key not in self.online_store:
                self.online_store[entity_key] = {}
            self.online_store[entity_key][feature_name] = record['value']

    def get_training_features(self, entity: str, entity_ids: List[str],
                             feature_names: List[str],
                             point_in_time: Optional[str] = None) -> List[Dict]:
        """Get historical features for training (point-in-time correct)."""
        results = []
        for eid in entity_ids:
            entity_key = f"{entity}:{eid}"
            features = {'entity_id': eid}

            if entity_key in self.offline_store:
                for record in self.offline_store[entity_key]:
                    if record['feature'] in feature_names:
                        if point_in_time is None or record['timestamp'] <= point_in_time:
                            features[record['feature']] = record['value']

            results.append(features)
        return results

    def get_online_features(self, entity: str, entity_id: str,
                           feature_names: List[str]) -> Dict:
        """Get latest features for real-time serving (<10ms)."""
        entity_key = f"{entity}:{entity_id}"
        stored = self.online_store.get(entity_key, {})
        return {f: stored.get(f) for f in feature_names}

# Usage
fs = FeatureStore()

# Register features
fs.register_feature(FeatureDefinition(
    name="purchase_count_30d", entity="user",
    dtype="int", description="Purchases in last 30 days",
    source="orders_table", freshness_sla="1h"
))

# Ingest data
fs.ingest_batch("user", "purchase_count_30d", [
    {"entity_id": "u1", "value": 5, "timestamp": "2024-01-15"},
    {"entity_id": "u2", "value": 12, "timestamp": "2024-01-15"},
])

# Training: point-in-time features

print("Training:", train_data)

# Serving: real-time features
online = fs.get_online_features("user", "u1", ["purchase_count_30d"])
print("Online:", online)

Key Insight: Feature stores solve training-serving skew. Offline store (Parquet/Delta) for training, online store (Redis/DynamoDB) for serving. Point-in-time joins prevent data leakage.

import numpy as np
from scipy import stats

class HypothesisTesting:
    @staticmethod
    def two_sample_ttest(a, b, alpha=0.05):
        n_a, n_b = len(a), len(b)
        mean_a, mean_b = np.mean(a), np.mean(b)
        var_a, var_b = np.var(a, ddof=1), np.var(b, ddof=1)
        se = np.sqrt(var_a/n_a + var_b/n_b)
        t = (mean_a - mean_b) / se
        df = (var_a/n_a + var_b/n_b)**2 / ((var_a/n_a)**2/(n_a-1) + (var_b/n_b)**2/(n_b-1))
        p = 2 * (1 - stats.t.cdf(abs(t), df))
        pooled = np.sqrt(((n_a-1)*var_a + (n_b-1)*var_b) / (n_a+n_b-2))
        return {"t": round(t,4), "p": round(p,6), "reject": p < alpha,
                "cohens_d": round((mean_a-mean_b)/pooled, 4)}

    @staticmethod
    def chi_square(observed, expected=None, alpha=0.05):
        if expected is None:
            expected = np.full_like(observed, observed.mean(), dtype=float)
        chi2 = np.sum((observed - expected)**2 / expected)
        df = len(observed) - 1
        p = 1 - stats.chi2.cdf(chi2, df)
        return {"chi2": round(chi2,4), "p": round(p,6), "reject": p < alpha}

    @staticmethod
    def anova(*groups, alpha=0.05):
        k, N = len(groups), sum(len(g) for g in groups)
        grand = np.mean(np.concatenate(groups))
        ss_b = sum(len(g) * (np.mean(g) - grand)**2 for g in groups)
        ss_w = sum(np.sum((g - np.mean(g))**2) for g in groups)
        f = (ss_b/(k-1)) / (ss_w/(N-k))
        p = 1 - stats.f.cdf(f, k-1, N-k)
        return {"f": round(f,4), "p": round(p,6), "reject": p < alpha,
                "eta_sq": round(ss_b/(ss_b+ss_w), 4)}

# Use: t-test (2 groups) | chi-square (categorical) | ANOVA (3+ groups)
# Always report effect size + confidence intervals, not just p-values

Key Insight: Effect size matters more than p-value. Always check assumptions: t-test needs normality or n=30, chi-square needs expected=5. In consulting, report CIs alongside p-values.

import numpy as np
from scipy import stats
import math

class ABTest:
    @staticmethod
    def sample_size(baseline, mde, alpha=0.05, power=0.8):
        p1, p2 = baseline, baseline * (1 + mde)
        p_avg = (p1 + p2) / 2
        za = stats.norm.ppf(1 - alpha/2)
        zb = stats.norm.ppf(power)
        n = ((za * np.sqrt(2*p_avg*(1-p_avg)) +
              zb * np.sqrt(p1*(1-p1) + p2*(1-p2))) / (p2-p1))**2
        return math.ceil(n)

    @staticmethod
    def proportion_test(c_conv, c_tot, t_conv, t_tot, alpha=0.05):
        pc, pt = c_conv/c_tot, t_conv/t_tot
        pp = (c_conv+t_conv) / (c_tot+t_tot)
        se = np.sqrt(pp*(1-pp)*(1/c_tot + 1/t_tot))
        z = (pt - pc) / se
        p = 2 * (1 - stats.norm.cdf(abs(z)))
        return {"control": round(pc,4), "treatment": round(pt,4),
                "lift": round((pt-pc)/pc*100, 2), "p": round(p,6),
                "significant": p < alpha}

    @staticmethod
    def bonferroni(p_values, alpha=0.05):
        n = len(p_values)
        return {"adjusted_alpha": alpha/n,
                "significant": [min(p*n, 1.0) < alpha for p in p_values]}

ab = ABTest()
print(f"Need {ab.sample_size(0.10, 0.05):,} per group for 5% MDE")

Key Insight: Don't peek at results early (inflates false positives). Always calculate sample size first. Multiple variants need Bonferroni correction.

import numpy as np

class TSForecaster:
    @staticmethod
    def exponential_smoothing(data, alpha=0.3):
        result = np.zeros_like(data, dtype=float)
        result[0] = data[0]
        for t in range(1, len(data)):
            result[t] = alpha * data[t] + (1-alpha) * result[t-1]
        return result

    @staticmethod
    def holt_winters(data, alpha=0.3, beta=0.1, gamma=0.1, season=12, horizon=12):
        n = len(data)
        level, trend = data[0], (data[season] - data[0]) / season
        seasonal = [data[i] - data[0] for i in range(season)]
        for t in range(season, n):
            prev = level
            level = alpha*(data[t]-seasonal[t%season]) + (1-alpha)*(level+trend)
            trend = beta*(level-prev) + (1-beta)*trend
            seasonal[t%season] = gamma*(data[t]-level) + (1-gamma)*seasonal[t%season]
        return [level + h*trend + seasonal[(n+h)%season] for h in range(1, horizon+1)]

    @staticmethod
    def ml_features(dates, values):
        """Lag + rolling features for XGBoost forecasting."""
        import pandas as pd
        df = pd.DataFrame({'date': dates, 'value': values})
        df['dow'] = df['date'].dt.dayofweek
        df['month'] = df['date'].dt.month
        for lag in [1, 7, 30]:
            df[f'lag_{lag}'] = df['value'].shift(lag)
        for w in [7, 30]:
            df[f'roll_mean_{w}'] = df['value'].rolling(w).mean()
        return df.dropna()

# ARIMA: interpretable, univariate | Prophet: seasonality + holidays
# XGBoost: non-linear, multivariate | LSTM: deep patterns, needs more data
# Always use time-based splits, never random!

import pandas as pd

class FeatureSelector:
    @staticmethod
    def correlation_filter(X, y, threshold=0.05):

            for f in remaining:
                s = score_fn(model_fn, X[selected+[f]], y)
                if s > best_s: best_s, best_f = s, f
            if best_f:
                selected.append(best_f)
                remaining.remove(best_f)
        return selected

    @staticmethod
    def lasso(X, y, alpha=0.01, iters=1000):
        n, p = X.shape
        w, lr = np.zeros(p), 0.001
        for _ in range(iters):
            w = w - lr * (-2 * X.T @ (y - X @ w) / n)
            w = np.sign(w) * np.maximum(np.abs(w) - lr * alpha, 0)
        return np.where(np.abs(w) > 1e-6)[0].tolist()

Q1. Compute sum of any rectangle in a matrix â€” Prefix Sum (Meta â€” ML Engineer)

Question: Given a 2D matrix of integers, preprocess it so you can answer any rectangular sub-matrix sum query in O(1).

class MatrixRectangleSum:
    def __init__(self, matrix):
        if not matrix or not matrix[0]:
            self.prefix = []
            return

        m, n = len(matrix), len(matrix[0])
        # Build 2D prefix sum
        self.prefix = [[0] * (n + 1) for _ in range(m + 1)]

        for i in range(1, m + 1):
            for j in range(1, n + 1):
                self.prefix[i][j] = (
                    matrix[i-1][j-1]
                    + self.prefix[i-1][j]
                    + self.prefix[i][j-1]
                    - self.prefix[i-1][j-1]
                )

    def query(self, r1, c1, r2, c2):
        """Sum of submatrix from (r1,c1) to (r2,c2) inclusive. O(1)."""
        return (
            self.prefix[r2+1][c2+1]
            - self.prefix[r1][c2+1]
            - self.prefix[r2+1][c1]
            + self.prefix[r1][c1]
        )

def next_greater_element(arr):
    """O(n) using monotonic stack."""
    n = len(arr)
    result = [-1] * n
    stack = []  # Stores indices

    for i in range(n):
        # Pop all elements smaller than current
        while stack and arr[stack[-1]] < arr[i]:
            idx = stack.pop()
            result[idx] = arr[i]
        stack.append(i)

    return result

def next_greater_circular(arr):
    """Handle circular array by traversing twice."""
    n = len(arr)
    result = [-1] * n
    stack = []

    for i in range(2 * n):
        idx = i % n

            result[stack.pop()] = arr[idx]

class FocalLoss(nn.Module):
    def __init__(self, alpha=0.25, gamma=2.0):
        super().__init__()
        self.alpha = alpha
        self.gamma = gamma

def calculate_iou(box1, box2):
    """
    Calculate IoU for two bounding boxes.
    Each box: [x1, y1, x2, y2] (top-left, bottom-right)

    IoU = Area of Intersection / Area of Union
    """
    # Intersection coordinates
    x1_inter = max(box1[0], box2[0])
    y1_inter = max(box1[1], box2[1])
    x2_inter = min(box1[2], box2[2])
    y2_inter = min(box1[3], box2[3])

    # Intersection area
    inter_width = max(0, x2_inter - x1_inter)
    inter_height = max(0, y2_inter - y1_inter)
    intersection = inter_width * inter_height

    # Union area
    area1 = (box1[2] - box1[0]) * (box1[3] - box1[1])
    area2 = (box2[2] - box2[0]) * (box2[3] - box2[1])
    union = area1 + area2 - intersection

    # IoU
    return intersection / union if union > 0 else 0.0

class SlidingWindowRateLimiter:
    def __init__(self, max_requests, window_seconds):
        self.max_requests = max_requests
        self.window = window_seconds
        self.requests = defaultdict(deque)  # user_id â†’ timestamps

    def is_allowed(self, user_id):
        now = time.time()
        window_start = now - self.window

        # Remove expired requests
        user_queue = self.requests[user_id]
        while user_queue and user_queue[0] < window_start:
            user_queue.popleft()

        # Check limit
        if len(user_queue) < self.max_requests:
            user_queue.append(now)
            return True
        return False

# â•â•â•â•â•â•â•â•â•â•â•â•â•â•â• TOKEN BUCKET ALGORITHM â•â•â•â•â•â•â•â•â•â•â•â•â•â•â•

class TokenBucketRateLimiter:
    def __init__(self, rate, capacity):
        """
        rate: tokens added per second
        capacity: max tokens (burst size)
        """
        self.rate = rate
        self.capacity = capacity
        self.buckets = {}  # user_id â†’ (tokens, last_refill)

    def is_allowed(self, user_id):
        now = time.time()

        if user_id not in self.buckets:
            self.buckets[user_id] = (self.capacity - 1, now)
            return True

        tokens, last_refill = self.buckets[user_id]

        # Refill tokens
        elapsed = now - last_refill
        tokens = min(self.capacity, tokens + elapsed * self.rate)

        if tokens >= 1:
            self.buckets[user_id] = (tokens - 1, now)
            return True

        self.buckets[user_id] = (tokens, now)
        return False

import numpy as np

# Simple 2-layer neural network from scratch
class SimpleNN:
    def __init__(self, input_size, hidden_size, output_size):
        # Xavier initialization
        self.W1 = np.random.randn(input_size, hidden_size) * np.sqrt(2.0 / input_size)
        self.b1 = np.zeros((1, hidden_size))
        self.W2 = np.random.randn(hidden_size, output_size) * np.sqrt(2.0 / hidden_size)
        self.b2 = np.zeros((1, output_size))

    def relu(self, z):
        return np.maximum(0, z)

    def relu_derivative(self, z):
        return (z > 0).astype(float)

    def sigmoid(self, z):
        return 1 / (1 + np.exp(-np.clip(z, -500, 500)))

    def forward(self, X):
        # Layer 1
        self.z1 = X @ self.W1 + self.b1
        self.a1 = self.relu(self.z1)
        # Layer 2
        self.z2 = self.a1 @ self.W2 + self.b2
        self.a2 = self.sigmoid(self.z2)
        return self.a2

    def backward(self, X, y, output, lr=0.01):
        m = X.shape[0]

        # Output layer gradients
        dz2 = output - y                          # (m, output_size)
        dW2 = (self.a1.T @ dz2) / m               # (hidden, output)
        db2 = np.sum(dz2, axis=0, keepdims=True) / m

        # Hidden layer gradients (chain rule!)
        dz1 = (dz2 @ self.W2.T) * self.relu_derivative(self.z1)
        dW1 = (X.T @ dz1) / m
        db1 = np.sum(dz1, axis=0, keepdims=True) / m

        # Update weights
        self.W2 -= lr * dW2
        self.b2 -= lr * db2
        self.W1 -= lr * dW1
        self.b1 -= lr * db1

import numpy as np

class KMeans:
    def __init__(self, k=3, max_iters=100, init='kmeans++'):
        self.k = k
        self.max_iters = max_iters
        self.init = init

    def _init_centroids(self, X):
        if self.init == 'random':
            indices = np.random.choice(len(X), self.k, replace=False)
            return X[indices].copy()

        # K-Means++ initialization
        centroids = [X[np.random.randint(len(X))]]
        for _ in range(1, self.k):
            distances = np.min([np.sum((X - c)**2, axis=1) for c in centroids], axis=0)
            probs = distances / distances.sum()
            centroids.append(X[np.random.choice(len(X), p=probs)])
        return np.array(centroids)

    def fit(self, X):
        self.centroids = self._init_centroids(X)

        for _ in range(self.max_iters):
            # Assign clusters
            distances = np.array([np.sum((X - c)**2, axis=1) for c in self.centroids])
            labels = np.argmin(distances, axis=0)

            # Update centroids
            new_centroids = np.array([X[labels == i].mean(axis=0)
                                      if np.any(labels == i) else self.centroids[i]
                                      for i in range(self.k)])

            if np.allclose(self.centroids, new_centroids):
                break
            self.centroids = new_centroids

        self.labels_ = labels
        self.inertia_ = sum(np.sum((X[labels == i] - self.centroids[i])**2)
                           for i in range(self.k))
        return self

    def predict(self, X):
        distances = np.array([np.sum((X - c)**2, axis=1) for c in self.centroids])
        return np.argmin(distances, axis=0)

import numpy as np

class LogisticRegression:
    def __init__(self, lr=0.01, n_iters=1000, reg='l2', lambda_=0.01):
        self.lr = lr
        self.n_iters = n_iters
        self.reg = reg
        self.lambda_ = lambda_

    def _sigmoid(self, z):
        return 1 / (1 + np.exp(-np.clip(z, -500, 500)))

    def _loss(self, y, y_hat):
        # Binary cross-entropy + regularization
        bce = -np.mean(y * np.log(y_hat + 1e-8) + (1 - y) * np.log(1 - y_hat + 1e-8))
        if self.reg == 'l2':
            bce += self.lambda_ * np.sum(self.weights**2) / (2 * len(y))
        elif self.reg == 'l1':
            bce += self.lambda_ * np.sum(np.abs(self.weights)) / len(y)
        return bce

    def fit(self, X, y):
        n_samples, n_features = X.shape
        self.weights = np.zeros(n_features)
        self.bias = 0
        self.losses = []

        for i in range(self.n_iters):
            z = X @ self.weights + self.bias
            y_hat = self._sigmoid(z)

            # Gradients
            dw = (1 / n_samples) * (X.T @ (y_hat - y))
            db = (1 / n_samples) * np.sum(y_hat - y)

            # Add regularization gradient
            if self.reg == 'l2':
                dw += (self.lambda_ / n_samples) * self.weights
            elif self.reg == 'l1':
                dw += (self.lambda_ / n_samples) * np.sign(self.weights)

            self.weights -= self.lr * dw
            self.bias -= self.lr * db

            if i % 100 == 0:
                loss = self._loss(y, y_hat)
                self.losses.append(loss)

        return self

    def predict_proba(self, X):
        return self._sigmoid(X @ self.weights + self.bias)

    def predict(self, X, threshold=0.5):
        return (self.predict_proba(X) >= threshold).astype(int)

import numpy as np

class NeuralNetwork:
    def __init__(self, input_dim, hidden_dim, output_dim, lr=0.01):
        self.lr = lr
        # Xavier initialization
        self.W1 = np.random.randn(input_dim, hidden_dim) * np.sqrt(2.0 / input_dim)
        self.b1 = np.zeros((1, hidden_dim))
        self.W2 = np.random.randn(hidden_dim, output_dim) * np.sqrt(2.0 / hidden_dim)
        self.b2 = np.zeros((1, output_dim))

    def _relu(self, z):
        return np.maximum(0, z)

    def _relu_deriv(self, z):
        return (z > 0).astype(float)

    def _softmax(self, z):
        exp_z = np.exp(z - np.max(z, axis=1, keepdims=True))
        return exp_z / exp_z.sum(axis=1, keepdims=True)

    def forward(self, X):
        self.z1 = X @ self.W1 + self.b1
        self.a1 = self._relu(self.z1)
        self.z2 = self.a1 @ self.W2 + self.b2
        self.a2 = self._softmax(self.z2)
        return self.a2

    def backward(self, X, y_onehot):
        m = X.shape[0]

        # Output layer gradient
        dz2 = self.a2 - y_onehot  # softmax + cross-entropy shortcut
        dW2 = (1/m) * self.a1.T @ dz2
        db2 = (1/m) * np.sum(dz2, axis=0, keepdims=True)

        # Hidden layer gradient
        dz1 = (dz2 @ self.W2.T) * self._relu_deriv(self.z1)
        dW1 = (1/m) * X.T @ dz1
        db1 = (1/m) * np.sum(dz1, axis=0, keepdims=True)

        # Update
        self.W2 -= self.lr * dW2
        self.b2 -= self.lr * db2
        self.W1 -= self.lr * dW1
        self.b1 -= self.lr * db1

    def train(self, X, y, epochs=100):
        n_classes = len(np.unique(y))
        y_onehot = np.eye(n_classes)[y]

        for epoch in range(epochs):
            probs = self.forward(X)
            self.backward(X, y_onehot)

            if epoch % 20 == 0:
                loss = -np.mean(np.sum(y_onehot * np.log(probs + 1e-8), axis=1))
                acc = np.mean(np.argmax(probs, axis=1) == y)
                print(f"Epoch {epoch}: loss={loss:.4f}, acc={acc:.4f}")

    def predict(self, X):
        return np.argmax(self.forward(X), axis=1)

import numpy as np
from collections import Counter

class DecisionTreeSimple:
    def __init__(self, max_depth=5, min_samples=2, n_features=None):
        self.max_depth = max_depth
        self.min_samples = min_samples
        self.n_features = n_features  # For random subspace

    def _entropy(self, y):
        counts = Counter(y)
        probs = [c / len(y) for c in counts.values()]
        return -sum(p * np.log2(p) for p in probs if p > 0)

    def _best_split(self, X, y):
        best_gain, best_feat, best_thresh = 0, None, None
        parent_ent = self._entropy(y)

        # Random feature subset
        features = np.random.choice(X.shape[1], self.n_features, replace=False)

        for feat in features:
            thresholds = np.unique(X[:, feat])
            for thresh in thresholds:
                left = y[X[:, feat] <= thresh]
                right = y[X[:, feat] > thresh]
                if len(left) == 0 or len(right) == 0:
                    continue
                gain = parent_ent - (len(left)/len(y) * self._entropy(left) +
                                     len(right)/len(y) * self._entropy(right))
                if gain > best_gain:
                    best_gain, best_feat, best_thresh = gain, feat, thresh

        return best_feat, best_thresh

    def _build(self, X, y, depth=0):
        if depth >= self.max_depth or len(set(y)) == 1 or len(y) < self.min_samples:
            return Counter(y).most_common(1)[0][0]

        feat, thresh = self._best_split(X, y)
        if feat is None:
            return Counter(y).most_common(1)[0][0]

        left_mask = X[:, feat] <= thresh
        return {
            'feature': feat, 'threshold': thresh,
            'left': self._build(X[left_mask], y[left_mask], depth + 1),
            'right': self._build(X[~left_mask], y[~left_mask], depth + 1)
        }

    def fit(self, X, y):
        if self.n_features is None:
            self.n_features = int(np.sqrt(X.shape[1]))
        self.tree = self._build(X, y)
        return self

    def _predict_one(self, x, tree):
        if not isinstance(tree, dict):
            return tree
        if x[tree['feature']] <= tree['threshold']:
            return self._predict_one(x, tree['left'])
        return self._predict_one(x, tree['right'])

    def predict(self, X):
        return np.array([self._predict_one(x, self.tree) for x in X])

class RandomForest:
    def __init__(self, n_trees=100, max_depth=10, min_samples=2):
        self.n_trees = n_trees
        self.max_depth = max_depth
        self.min_samples = min_samples
        self.trees = []

    def fit(self, X, y):
        self.trees = []
        n_samples = len(X)

        for _ in range(self.n_trees):
            # Bootstrap sample
            indices = np.random.choice(n_samples, n_samples, replace=True)
            X_boot, y_boot = X[indices], y[indices]

            tree = DecisionTreeSimple(
                max_depth=self.max_depth,
                min_samples=self.min_samples,
                n_features=int(np.sqrt(X.shape[1]))
            )
            tree.fit(X_boot, y_boot)
            self.trees.append(tree)

        return self

    def predict(self, X):
        # Majority vote
        predictions = np.array([tree.predict(X) for tree in self.trees])
        return np.array([Counter(predictions[:, i]).most_common(1)[0][0]
                        for i in range(len(X))])

    def feature_importance(self, X, y):
        """Permutation importance."""
        baseline = np.mean(self.predict(X) == y)
        importances = []
        for feat in range(X.shape[1]):
            X_perm = X.copy()
            X_perm[:, feat] = np.random.permutation(X_perm[:, feat])
            score = np.mean(self.predict(X_perm) == y)
            importances.append(baseline - score)
        return np.array(importances)

import numpy as np
from collections import Counter

class Word2Vec:
    def __init__(self, vocab_size, embed_dim=50, lr=0.01, n_neg=5):
        self.embed_dim = embed_dim
        self.lr = lr
        self.n_neg = n_neg
        # Target and context embeddings
        self.W_target = np.random.randn(vocab_size, embed_dim) * 0.01
        self.W_context = np.random.randn(vocab_size, embed_dim) * 0.01

    def _sigmoid(self, x):
        return 1 / (1 + np.exp(-np.clip(x, -10, 10)))

    def train_pair(self, target_idx, context_idx, neg_indices):
        """Train one skip-gram pair with negative sampling."""
        # Positive sample
        target_vec = self.W_target[target_idx]
        context_vec = self.W_context[context_idx]

        score = self._sigmoid(np.dot(target_vec, context_vec))
        grad_ctx = (score - 1) * target_vec  # Want sigmoid → 1
        grad_tgt = (score - 1) * context_vec

        # Update context embedding
        self.W_context[context_idx] -= self.lr * grad_ctx

        # Negative samples
        for neg_idx in neg_indices:
            neg_vec = self.W_context[neg_idx]
            score = self._sigmoid(np.dot(target_vec, neg_vec))
            grad_neg = score * target_vec  # Want sigmoid → 0
            grad_tgt += score * neg_vec
            self.W_context[neg_idx] -= self.lr * grad_neg

        # Update target embedding
        self.W_target[target_idx] -= self.lr * grad_tgt

    def get_embedding(self, word_idx):
        return self.W_target[word_idx]

    def most_similar(self, word_idx, top_k=5):
        target = self.W_target[word_idx]
        # Cosine similarity
        norms = np.linalg.norm(self.W_target, axis=1)
        similarities = (self.W_target @ target) / (norms * np.linalg.norm(target) + 1e-8)
        top_indices = np.argsort(similarities)[::-1][1:top_k+1]
        return [(idx, similarities[idx]) for idx in top_indices]

# Training loop
def train_word2vec(corpus, embed_dim=50, window=2, n_neg=5, epochs=5, lr=0.025):
    # Build vocabulary
    words = corpus.split()
    word_counts = Counter(words)
    vocab = {w: i for i, w in enumerate(word_counts.keys())}
    idx_to_word = {i: w for w, i in vocab.items()}

    # Negative sampling distribution (f(w)^0.75)
    freqs = np.array([word_counts[idx_to_word[i]] for i in range(len(vocab))])
    neg_dist = freqs ** 0.75
    neg_dist /= neg_dist.sum()

    model = Word2Vec(len(vocab), embed_dim, lr, n_neg)
    word_indices = [vocab[w] for w in words]

    for epoch in range(epochs):
        total_loss = 0
        for i, target_idx in enumerate(word_indices):
            # Context window
            start = max(0, i - window)
            end = min(len(word_indices), i + window + 1)

            for j in range(start, end):
                if j == i:
                    continue
                context_idx = word_indices[j]
                neg_indices = np.random.choice(len(vocab), n_neg, p=neg_dist)
                model.train_pair(target_idx, context_idx, neg_indices)

        print(f"Epoch {epoch+1}/{epochs} complete")

    return model, vocab, idx_to_word

import numpy as np

def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    Q, K, V: (batch, seq_len, d_k)
    Returns: (batch, seq_len, d_v), attention_weights
    """
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(0, 2, 1) / np.sqrt(d_k)  # (batch, seq_q, seq_k)

    if mask is not None:
        scores = np.where(mask == 0, -1e9, scores)

    # Softmax along last axis
    exp_scores = np.exp(scores - np.max(scores, axis=-1, keepdims=True))
    attention_weights = exp_scores / exp_scores.sum(axis=-1, keepdims=True)

    output = attention_weights @ V  # (batch, seq_q, d_v)
    return output, attention_weights

class MultiHeadAttention:
    def __init__(self, d_model, n_heads):
        assert d_model % n_heads == 0
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads

        # Linear projections
        self.W_q = np.random.randn(d_model, d_model) * 0.02
        self.W_k = np.random.randn(d_model, d_model) * 0.02
        self.W_v = np.random.randn(d_model, d_model) * 0.02
        self.W_o = np.random.randn(d_model, d_model) * 0.02

    def _split_heads(self, x):
        """(batch, seq, d_model) → (batch, n_heads, seq, d_k)"""
        batch, seq, _ = x.shape
        x = x.reshape(batch, seq, self.n_heads, self.d_k)
        return x.transpose(0, 2, 1, 3)

    def _merge_heads(self, x):
        """(batch, n_heads, seq, d_k) → (batch, seq, d_model)"""
        batch, _, seq, _ = x.shape
        x = x.transpose(0, 2, 1, 3)
        return x.reshape(batch, seq, self.d_model)

    def forward(self, Q, K, V, mask=None):
        # Project
        Q = Q @ self.W_q
        K = K @ self.W_k
        V = V @ self.W_v

        # Split into heads
        Q = self._split_heads(Q)
        K = self._split_heads(K)
        V = self._split_heads(V)

        # Attention per head
        d_k = Q.shape[-1]
        scores = Q @ K.transpose(0, 1, 3, 2) / np.sqrt(d_k)
        if mask is not None:
            scores = np.where(mask == 0, -1e9, scores)

        exp_scores = np.exp(scores - np.max(scores, axis=-1, keepdims=True))
        attn_weights = exp_scores / exp_scores.sum(axis=-1, keepdims=True)
        attn_output = attn_weights @ V

        # Merge heads and project
        output = self._merge_heads(attn_output)
        output = output @ self.W_o

        return output, attn_weights

import numpy as np

def compute_roc_curve(y_true, y_scores):
    """Compute ROC curve points."""
    # Sort by score descending
    sorted_indices = np.argsort(-y_scores)
    y_sorted = y_true[sorted_indices]
    scores_sorted = y_scores[sorted_indices]

    # Get unique thresholds
    thresholds = np.unique(scores_sorted)[::-1]

    tpr_list, fpr_list = [0], [0]
    total_pos = np.sum(y_true == 1)
    total_neg = np.sum(y_true == 0)

    for thresh in thresholds:
        y_pred = (y_scores >= thresh).astype(int)
        tp = np.sum((y_pred == 1) & (y_true == 1))
        fp = np.sum((y_pred == 1) & (y_true == 0))

        tpr = tp / total_pos if total_pos > 0 else 0
        fpr = fp / total_neg if total_neg > 0 else 0

        tpr_list.append(tpr)
        fpr_list.append(fpr)

    return np.array(fpr_list), np.array(tpr_list)

def compute_auc(fpr, tpr):
    """Trapezoidal rule for AUC."""
    sorted_idx = np.argsort(fpr)
    fpr_sorted = fpr[sorted_idx]
    tpr_sorted = tpr[sorted_idx]

    auc = 0
    for i in range(1, len(fpr_sorted)):
        auc += (fpr_sorted[i] - fpr_sorted[i-1]) * (tpr_sorted[i] + tpr_sorted[i-1]) / 2
    return auc

def auc_wilcoxon(y_true, y_scores):
    """AUC via Wilcoxon-Mann-Whitney statistic.
    AUC = P(score(pos) > score(neg)) for random pos/neg pair."""
    pos_scores = y_scores[y_true == 1]
    neg_scores = y_scores[y_true == 0]

    count = 0
    for ps in pos_scores:
        count += np.sum(ps > neg_scores) + 0.5 * np.sum(ps == neg_scores)

    return count / (len(pos_scores) * len(neg_scores))

# Test
np.random.seed(42)

y_scores = np.array([0.1, 0.4, 0.35, 0.8, 0.2, 0.7, 0.3, 0.9, 0.6, 0.5])

fpr, tpr = compute_roc_curve(y_true, y_scores)
auc_trap = compute_auc(fpr, tpr)
auc_wmw = auc_wilcoxon(y_true, y_scores)

print(f"AUC (trapezoidal): {auc_trap:.4f}")
print(f"AUC (Wilcoxon): {auc_wmw:.4f}")

# Verify with sklearn
from sklearn.metrics import roc_auc_score
print(f"AUC (sklearn): {roc_auc_score(y_true, y_scores):.4f}")

Key Insight: AUC = probability that a random positive example scores higher than a random negative. AUC=0.5 is random, AUC=1.0 is perfect. Insensitive to class imbalance (unlike accuracy). Wilcoxon interpretation is the most intuitive.

Q23. Explain the bias-variance tradeoff with mathematical derivation (Two Sigma — ML Engineer)

Question: Derive the bias-variance decomposition of MSE. Show how model complexity affects each component.

Solution:

"""
Bias-Variance Decomposition:

For a model f̂(x) predicting y = f(x) + ε where ε ~ N(0, σ²):

E[(y - f̂(x))²] = Bias²(f̂) + Var(f̂) + σ²

Where:
- Bias²(f̂) = (E[f̂(x)] - f(x))²  → Error from wrong assumptions
- Var(f̂) = E[(f̂(x) - E[f̂(x)])²]  → Sensitivity to training data
- σ² = Irreducible error (noise)

High bias → Underfitting (too simple)
High variance → Overfitting (too complex)
"""

import numpy as np

def bias_variance_experiment(true_fn, model_class, X_test, n_datasets=200,
                              n_samples=50, noise_std=0.3):
    """Empirically measure bias and variance."""
    predictions = np.zeros((n_datasets, len(X_test)))

    for i in range(n_datasets):
        # Generate new training set
        X_train = np.random.uniform(-3, 3, n_samples)
        y_train = true_fn(X_train) + np.random.normal(0, noise_std, n_samples)

        # Fit model
        model = model_class()
        model.fit(X_train.reshape(-1, 1), y_train)
        predictions[i] = model.predict(X_test.reshape(-1, 1))

    y_true = true_fn(X_test)

    # Bias² = (mean prediction - true)²
    mean_pred = predictions.mean(axis=0)
    bias_sq = np.mean((mean_pred - y_true) ** 2)

    # Variance = E[(prediction - mean prediction)²]
    variance = np.mean(predictions.var(axis=0))

    # Total error
    total_error = np.mean((predictions - y_true) ** 2)

    return {
        'bias²': bias_sq,
        'variance': variance,
        'noise': noise_std ** 2,
        'total_error': total_error,
        'decomposition_check': bias_sq + variance + noise_std**2
    }

# Compare simple vs complex models
from sklearn.linear_model import LinearRegression
from sklearn.preprocessing import PolynomialFeatures
from sklearn.pipeline import make_pipeline

true_fn = lambda x: np.sin(x) + 0.5 * x
X_test = np.linspace(-3, 3, 100)

class PolyModel:
    def __init__(self, degree=1):
        self.degree = degree
    def fit(self, X, y):
        self.model = make_pipeline(PolynomialFeatures(self.degree), LinearRegression())
        self.model.fit(X, y)
    def predict(self, X):
        return self.model.predict(X)

for degree in [1, 3, 5, 10, 15]:
    class ModelDeg:
        def __init__(self, d=degree):
            self.d = d
        def fit(self, X, y):
            self.m = make_pipeline(PolynomialFeatures(self.d), LinearRegression()).fit(X, y)
        def predict(self, X):
            return self.m.predict(X)

    result = bias_variance_experiment(true_fn, ModelDeg, X_test)
    print(f"Degree {degree:2d}: Bias²={result['bias²']:.4f}, "
          f"Var={result['variance']:.4f}, Total={result['total_error']:.4f}")

Key Insight: Simple models: high bias, low variance. Complex models: low bias, high variance. Sweet spot minimizes total error. Regularization reduces variance at cost of small bias increase. Cross-validation finds the sweet spot empirically.

Q24. Explain gradient boosting internals — XGBoost vs LightGBM (Shopee — ML Engineer)

Question: What are the key differences between XGBoost and LightGBM? When to use each?

Solution:

"""
GRADIENT BOOSTING: Additive ensemble of weak learners (trees)

XGBoost vs LightGBM Comparison:

┌─────────────────┬──────────────────────┬──────────────────────┐
│ Aspect          │ XGBoost              │ LightGBM             │
├─────────────────┼──────────────────────┼──────────────────────┤
│ Tree growth     │ Level-wise (BFS)     │ Leaf-wise (best-first)│
│ Speed           │ Slower               │ 2-10x faster         │
│ Memory          │ Higher               │ Lower                │
│ Accuracy        │ Similar              │ Similar/better       │
│ Overfitting     │ More robust          │ Prone (use max_depth)│
│ Categorical     │ Needs encoding       │ Native support       │
│ Missing values  │ Learns direction     │ Learns direction     │
│ Histogram       │ Optional (approx)    │ Default              │
│ Best for        │ Small-medium data    │ Large data           │
└─────────────────┴──────────────────────┴──────────────────────┘
"""

import numpy as np

class GradientBoostingSimple:
    """Simplified gradient boosting for regression."""

    def __init__(self, n_estimators=100, learning_rate=0.1, max_depth=3):
        self.n_estimators = n_estimators
        self.lr = learning_rate
        self.max_depth = max_depth
        self.trees = []

    def _build_stump(self, X, residuals, depth=0):
        """Build a simple decision tree stump."""
        if depth >= self.max_depth or len(X) < 4:
            return np.mean(residuals)

        best_mse = float('inf')
        best_split = None

        for feat in range(X.shape[1]):
            for thresh in np.percentile(X[:, feat], np.arange(10, 100, 10)):
                left_mask = X[:, feat] <= thresh
                right_mask = ~left_mask
                if sum(left_mask) < 2 or sum(right_mask) < 2:
                    continue

                mse = (np.var(residuals[left_mask]) * sum(left_mask) +
                       np.var(residuals[right_mask]) * sum(right_mask)) / len(residuals)

                if mse < best_mse:
                    best_mse = mse
                    best_split = (feat, thresh,
                                  self._build_stump(X[left_mask], residuals[left_mask], depth+1),
                                  self._build_stump(X[right_mask], residuals[right_mask], depth+1))

        return best_split if best_split else np.mean(residuals)

    def _predict_tree(self, x, tree):
        if not isinstance(tree, tuple):
            return tree
        feat, thresh, left, right = tree
        if x[feat] <= thresh:
            return self._predict_tree(x, left)
        return self._predict_tree(x, right)

    def fit(self, X, y):
        self.base_pred = np.mean(y)
        current_pred = np.full(len(y), self.base_pred)

        for i in range(self.n_estimators):
            residuals = y - current_pred  # Negative gradient of MSE
            tree = self._build_stump(X, residuals)
            self.trees.append(tree)

            # Update predictions
            tree_preds = np.array([self._predict_tree(x, tree) for x in X])
            current_pred += self.lr * tree_preds

            if i % 20 == 0:
                mse = np.mean((y - current_pred) ** 2)
                print(f"Iter {i}: MSE={mse:.4f}")

        return self

    def predict(self, X):
        pred = np.full(len(X), self.base_pred)
        for tree in self.trees:
            pred += self.lr * np.array([self._predict_tree(x, tree) for x in X])
        return pred

Key Insight: GB fits trees to negative gradient of loss. XGBoost: level-wise growth, more regularization knobs. LightGBM: leaf-wise growth, histogram binning, GOSS for faster training. Always use early stopping.

Question: Derive batch normalization forward and backward pass. Why does it help training?

Solution:

import numpy as np

class BatchNorm:
    def __init__(self, num_features, momentum=0.1, eps=1e-5):
        self.gamma = np.ones(num_features)   # Scale
        self.beta = np.zeros(num_features)    # Shift
        self.eps = eps
        self.momentum = momentum

        # Running stats for inference
        self.running_mean = np.zeros(num_features)
        self.running_var = np.ones(num_features)

    def forward(self, x, training=True):
        """
        x: (batch_size, num_features)

        Forward pass:
        1. μ = mean(x) over batch
        2. σ² = var(x) over batch
        3. x̂ = (x - μ) / √(σ² + ε)
        4. y = γ * x̂ + β
        """
        if training:
            self.batch_mean = x.mean(axis=0)
            self.batch_var = x.var(axis=0)

            # Normalize
            self.x_norm = (x - self.batch_mean) / np.sqrt(self.batch_var + self.eps)

            # Update running stats
            self.running_mean = (1 - self.momentum) * self.running_mean + self.momentum * self.batch_mean
            self.running_var = (1 - self.momentum) * self.running_var + self.momentum * self.batch_var

            # Cache for backward
            self.x = x
        else:
            self.x_norm = (x - self.running_mean) / np.sqrt(self.running_var + self.eps)

        return self.gamma * self.x_norm + self.beta

    def backward(self, dout):
        """
        Backward pass through batch norm.
        dout: gradient from next layer (batch_size, num_features)
        """
        N = dout.shape[0]

        # Gradients for gamma and beta
        self.dgamma = np.sum(dout * self.x_norm, axis=0)
        self.dbeta = np.sum(dout, axis=0)

        # Gradient through normalization
        dx_norm = dout * self.gamma

        std_inv = 1 / np.sqrt(self.batch_var + self.eps)

        dx = (1 / N) * std_inv * (
            N * dx_norm -
            np.sum(dx_norm, axis=0) -
            self.x_norm * np.sum(dx_norm * self.x_norm, axis=0)
        )

        return dx

"""
Why BatchNorm helps:
1. Reduces internal covariate shift
2. Allows higher learning rates
3. Acts as regularization (batch statistics add noise)
4. Smooths loss landscape → easier optimization

Layer Norm vs Batch Norm:
- BatchNorm: normalize across batch dim → depends on batch size
- LayerNorm: normalize across feature dim → batch-independent
- LayerNorm preferred for NLP/Transformers (variable seq lengths)
"""

Key Insight: BN normalizes activations to zero mean, unit variance, then applies learnable scale/shift. Enables higher learning rates and faster convergence. Use LayerNorm for transformers (batch-independent).

- Collaborative Filtering (ALS / Matrix Factorization)
- Content-based (TF-IDF / embeddings similarity)
- Popular items / trending

STAGE 2: Scoring/Ranking (precision-focused, complex)
- Deep model (Wide & Deep / DeepFM / Two-Tower)

- Predict P(click), P(purchase), expected revenue

STAGE 3: Re-ranking (business logic)
- Diversity (MMR - Maximal Marginal Relevance)
- Freshness boost for new items
- Suppress already-purchased items
- Sponsored items insertion

import numpy as np
from scipy.sparse import csr_matrix

# Stage 1: Matrix Factorization (ALS)
class ALSRecommender:
    def __init__(self, n_factors=50, n_iters=20, reg=0.1):
        self.n_factors = n_factors
        self.n_iters = n_iters
        self.reg = reg

    def fit(self, interactions):
        """interactions: (n_users, n_items) sparse matrix"""
        n_users, n_items = interactions.shape

        # Initialize factors
        self.user_factors = np.random.randn(n_users, self.n_factors) * 0.01
        self.item_factors = np.random.randn(n_items, self.n_factors) * 0.01

        R = interactions.toarray() if hasattr(interactions, 'toarray') else interactions

        for iteration in range(self.n_iters):
            # Fix items, solve for users
            for u in range(n_users):
                items_u = np.where(R[u] > 0)[0]
                if len(items_u) == 0:
                    continue
                V_u = self.item_factors[items_u]
                r_u = R[u, items_u]
                self.user_factors[u] = np.linalg.solve(
                    V_u.T @ V_u + self.reg * np.eye(self.n_factors),
                    V_u.T @ r_u
                )

            # Fix users, solve for items
            for i in range(n_items):
                users_i = np.where(R[:, i] > 0)[0]
                if len(users_i) == 0:
                    continue
                U_i = self.user_factors[users_i]
                r_i = R[users_i, i]
                self.item_factors[i] = np.linalg.solve(
                    U_i.T @ U_i + self.reg * np.eye(self.n_factors),
                    U_i.T @ r_i
                )

            if iteration % 5 == 0:
                pred = self.user_factors @ self.item_factors.T
                mask = R > 0
                rmse = np.sqrt(np.mean((R[mask] - pred[mask]) ** 2))
                print(f"Iter {iteration}: RMSE={rmse:.4f}")

    def recommend(self, user_id, n=10, exclude_seen=True):
        scores = self.user_factors[user_id] @ self.item_factors.T
        if exclude_seen:
            # Would mask already-interacted items
            pass
        return np.argsort(-scores)[:n]

# Stage 3: Diversity re-ranking (MMR)
def mmr_rerank(scores, embeddings, lambda_=0.5, n=10):
    """Maximal Marginal Relevance for diverse recommendations."""
    selected = []
    candidates = list(range(len(scores)))

    for _ in range(n):
        best_score = -float('inf')
        best_idx = None

        for idx in candidates:
            relevance = scores[idx]

            if selected:
                similarities = [np.dot(embeddings[idx], embeddings[s]) /
                              (np.linalg.norm(embeddings[idx]) * np.linalg.norm(embeddings[s]) + 1e-8)
                              for s in selected]
                max_sim = max(similarities)
            else:
                max_sim = 0

            mmr_score = lambda_ * relevance - (1 - lambda_) * max_sim

            if mmr_score > best_score:
                best_score = mmr_score
                best_idx = idx

        selected.append(best_idx)
        candidates.remove(best_idx)

    return selected

# Test
R = np.random.randint(0, 2, (100, 50)).astype(float)
als = ALSRecommender(n_factors=10, n_iters=10)
als.fit(R)
recs = als.recommend(0, n=5)
print(f"Recommendations for user 0: {recs}")

        user_id = transaction['user_id']
        now = transaction['timestamp']

        # Velocity features
        recent_txns = [t for t in self.user_history[user_id]
                       if (now - t['timestamp']).total_seconds() < 3600]

        features = {
            # Transaction features
            'amount': transaction['amount'],
            'amount_log': np.log1p(transaction['amount']),
            'is_international': int(transaction.get('country') != transaction.get('home_country')),

            # Velocity features (1 hour window)

            'total_amount_1h': sum(t['amount'] for t in recent_txns),
            'avg_amount_1h': np.mean([t['amount'] for t in recent_txns]) if recent_txns else 0,
            'max_amount_1h': max([t['amount'] for t in recent_txns], default=0),

            # Time features
            'hour_of_day': now.hour,
            'is_weekend': int(now.weekday() >= 5),
            'is_night': int(now.hour < 6 or now.hour > 22),

            # Deviation features

            'new_device': int(transaction.get('device_id') not in
                            [t.get('device_id') for t in self.user_history[user_id][-100:]]),
            'new_merchant_category': 0,
        }

        # Amount z-score
        amounts = [t['amount'] for t in self.user_history[user_id][-100:]]
        if len(amounts) > 5:

            std_amt = np.std(amounts) + 1e-8
            features['amount_vs_avg'] = (transaction['amount'] - mean_amt) / std_amt

        # Update history
        self.user_history[user_id].append(transaction)

    """Multi-layer fraud detection system."""

    def __init__(self, model=None, threshold_block=0.9, threshold_review=0.5):
        self.feature_engine = FraudFeatureEngine()

        self.threshold_block = threshold_block

    def score(self, transaction):

        # Layer 1: Hard rules (deterministic)
        for rule in self.rules:
            if rule['check'](features, transaction):
                return {
                    'decision': rule['action'],
                    'reason': f"Rule: {rule['name']}",
                    'score': 1.0,
                    'features': features
                }

        # Layer 2: ML model
        if self.model:
            feature_vector = np.array(list(features.values())).reshape(1, -1)
            fraud_prob = self.model.predict_proba(feature_vector)[0][1]
        else:
            # Heuristic fallback
            fraud_prob = min(1.0, (
                0.1 * features['is_international'] +
                0.2 * features['new_device'] +
                0.15 * features['is_night'] +
                0.1 * min(features['txn_count_1h'] / 10, 1) +
                0.15 * min(features['amount_vs_avg'] / 5, 1)
            ))

        # Decision
        if fraud_prob >= self.threshold_block:
            decision = 'block'
        elif fraud_prob >= self.threshold_review:
            decision = 'review'
        else:
            decision = 'allow'

        return {
            'decision': decision,
            'score': fraud_prob,
            'features': features
        }

"""
Model Monitoring Architecture:

│  Predictions │───→│  Monitoring     │───→│  Alert System │
│  + Ground    │    │  Dashboard      │    │  - Slack      │

└──────────────┘    │  - Performance  │    │  - Auto-retrain│
                    │  - Data quality │    └───────────────┘
                    └─────────────────┘
"""

import numpy as np
from scipy import stats
from collections import deque

class DataDriftDetector:
    """Detect data distribution shifts using statistical tests."""

    def __init__(self, reference_data, window_size=1000):
        self.reference = reference_data
        self.window_size = window_size
        self.current_window = deque(maxlen=window_size)

    def ks_test(self, feature_idx):
        """Kolmogorov-Smirnov test for distribution shift."""
        ref = self.reference[:, feature_idx]
        curr = np.array(list(self.current_window))[:, feature_idx]
        stat, p_value = stats.ks_2samp(ref, curr)
        return {'statistic': stat, 'p_value': p_value, 'drift': p_value < 0.05}

    def psi(self, feature_idx, n_bins=10):
        """Population Stability Index."""
        ref = self.reference[:, feature_idx]
        curr = np.array(list(self.current_window))[:, feature_idx]

        # Create bins from reference data
        bins = np.percentile(ref, np.linspace(0, 100, n_bins + 1))
        bins[0], bins[-1] = -np.inf, np.inf

        ref_counts = np.histogram(ref, bins=bins)[0] / len(ref)
        curr_counts = np.histogram(curr, bins=bins)[0] / len(curr)

        # Avoid log(0)
        ref_counts = np.clip(ref_counts, 0.001, None)
        curr_counts = np.clip(curr_counts, 0.001, None)

        psi = np.sum((curr_counts - ref_counts) * np.log(curr_counts / ref_counts))

        # PSI interpretation: <0.1 no drift, 0.1-0.25 moderate, >0.25 significant
        return {'psi': psi, 'drift': 'none' if psi < 0.1 else 'moderate' if psi < 0.25 else 'significant'}

    def add_batch(self, data):
        for row in data:
            self.current_window.append(row)

class ConceptDriftDetector:
    """Detect prediction performance degradation."""

    def __init__(self, window_size=500, threshold=0.05):
        self.window_size = window_size
        self.threshold = threshold
        self.errors = deque(maxlen=window_size * 2)

    def page_hinkley_test(self):
        """Page-Hinkley test for change detection."""
        if len(self.errors) < self.window_size:
            return {'drift': False, 'reason': 'insufficient data'}

        errors = np.array(self.errors)
        cumsum = np.cumsum(errors - np.mean(errors))

        m_t = cumsum[-1]
        M_t = np.max(cumsum)

        ph_stat = M_t - m_t
        return {
            'drift': ph_stat > self.threshold * len(errors),
            'ph_statistic': ph_stat,
            'mean_error': np.mean(errors[-self.window_size:])
        }

    def add_prediction(self, y_true, y_pred):
        error = abs(y_true - y_pred)
        self.errors.append(error)

class ModelMonitor:
    """Complete model monitoring system."""

    def __init__(self, reference_data, reference_labels, reference_preds):
        self.data_drift = DataDriftDetector(reference_data)
        self.concept_drift = ConceptDriftDetector()

        # Baseline metrics
        self.baseline_metrics = self._compute_metrics(reference_labels, reference_preds)
        self.alerts = []

    def _compute_metrics(self, y_true, y_pred):
        return {
            'accuracy': np.mean(y_true == (y_pred > 0.5).astype(int)),
            'mean_prediction': np.mean(y_pred),
            'prediction_std': np.std(y_pred),
        }

    def monitor_batch(self, X_batch, y_true_batch, y_pred_batch):
        """Monitor a batch of predictions."""
        report = {'timestamp': 'now', 'alerts': []}

        # Data drift check
        self.data_drift.add_batch(X_batch)
        if len(self.data_drift.current_window) >= self.data_drift.window_size:
            for feat_idx in range(X_batch.shape[1]):
                psi_result = self.data_drift.psi(feat_idx)
                if psi_result['drift'] != 'none':
                    report['alerts'].append(
                        f"Data drift on feature {feat_idx}: PSI={psi_result['psi']:.4f} ({psi_result['drift']})"
                    )

        # Performance drift
        current_metrics = self._compute_metrics(y_true_batch, y_pred_batch)
        for metric, value in current_metrics.items():
            baseline = self.baseline_metrics[metric]
            if abs(value - baseline) / (baseline + 1e-8) > 0.1:
                report['alerts'].append(
                    f"Performance drift: {metric} changed from {baseline:.4f} to {value:.4f}"
                )

        report['metrics'] = current_metrics
        report['n_alerts'] = len(report['alerts'])

        return report

import numpy as np

class SGDMomentum:
    def __init__(self, lr=0.01, momentum=0.9):
        self.lr = lr
        self.momentum = momentum
        self.velocity = None

    def step(self, params, grads):
        if self.velocity is None:
            self.velocity = [np.zeros_like(p) for p in params]

        for i in range(len(params)):
            self.velocity[i] = self.momentum * self.velocity[i] - self.lr * grads[i]
            params[i] += self.velocity[i]
        return params

class RMSProp:
    def __init__(self, lr=0.001, decay=0.99, eps=1e-8):
        self.lr = lr
        self.decay = decay
        self.eps = eps
        self.cache = None

    def step(self, params, grads):
        if self.cache is None:
            self.cache = [np.zeros_like(p) for p in params]

        for i in range(len(params)):
            self.cache[i] = self.decay * self.cache[i] + (1 - self.decay) * grads[i]**2
            params[i] -= self.lr * grads[i] / (np.sqrt(self.cache[i]) + self.eps)
        return params

class Adam:
    """Adam = Momentum + RMSProp + Bias correction"""
    def __init__(self, lr=0.001, beta1=0.9, beta2=0.999, eps=1e-8):
        self.lr = lr
        self.beta1 = beta1
        self.beta2 = beta2
        self.eps = eps
        self.m = None  # First moment (mean)
        self.v = None  # Second moment (variance)
        self.t = 0

    def step(self, params, grads):
        if self.m is None:
            self.m = [np.zeros_like(p) for p in params]
            self.v = [np.zeros_like(p) for p in params]

        self.t += 1

        for i in range(len(params)):
            # Update biased moments
            self.m[i] = self.beta1 * self.m[i] + (1 - self.beta1) * grads[i]
            self.v[i] = self.beta2 * self.v[i] + (1 - self.beta2) * grads[i]**2

            # Bias correction (critical for early steps)
            m_hat = self.m[i] / (1 - self.beta1**self.t)
            v_hat = self.v[i] / (1 - self.beta2**self.t)

            # Update parameters
            params[i] -= self.lr * m_hat / (np.sqrt(v_hat) + self.eps)

        return params

# Comparison on Rosenbrock function
def rosenbrock(x, y):
    return (1 - x)**2 + 100 * (y - x**2)**2

def rosenbrock_grad(x, y):
    dx = -2 * (1 - x) - 400 * x * (y - x**2)
    dy = 200 * (y - x**2)
    return np.array([dx, dy])

    'Adam': Adam(lr=0.01)

    loss = rosenbrock(x, y)

class ModelVersion:
    model_id: str
    version: str
    model: object  # Loaded model
    traffic_pct: float  # Traffic allocation for A/B

class ModelServingPlatform:
    """Production model serving with versioning and A/B testing."""

    def __init__(self):
        self.models: Dict[str, list] = {}  # model_id -> [versions]
        self.cache = {}
        self.metrics = {"requests": 0, "cache_hits": 0, "errors": 0}

    def deploy_model(self, model_id: str, version: str, model: object,
                     traffic_pct: float = 100.0):
        """Deploy a model version with traffic allocation."""
        mv = ModelVersion(model_id, version, model, traffic_pct)
        if model_id not in self.models:
            self.models[model_id] = []
        self.models[model_id].append(mv)
        # Normalize traffic percentages
        total = sum(m.traffic_pct for m in self.models[model_id])
        for m in self.models[model_id]:
            m.traffic_pct = m.traffic_pct / total * 100

    def predict(self, model_id: str, features: Dict,
                request_id: str = None) -> Dict:
        """Route request to appropriate model version."""
        self.metrics["requests"] += 1
        start = time.time()

        # Check cache
        cache_key = f"{model_id}:{hashlib.md5(str(features).encode()).hexdigest()}"
        if cache_key in self.cache:
            self.metrics["cache_hits"] += 1
            return {**self.cache[cache_key], "cached": True}

        # Select model version (A/B routing)
        version = self._route_request(model_id, request_id)
        if not version:
            self.metrics["errors"] += 1
            return {"error": f"Model {model_id} not found"}

        try:
            prediction = version.model.predict(features)
            result = {
                "prediction": prediction,
                "model_version": version.version,
                "latency_ms": (time.time() - start) * 1000,
                "cached": False
            }
            self.cache[cache_key] = result
            return result
        except Exception as e:
            self.metrics["errors"] += 1
            return {"error": str(e), "model_version": version.version}

    def _route_request(self, model_id: str, request_id: str = None):
        """Route to model version based on traffic split."""
        versions = self.models.get(model_id, [])
        if not versions:
            return None

        # Deterministic routing for consistency
        if request_id:
            hash_val = int(hashlib.md5(request_id.encode()).hexdigest(), 16) % 100
        else:
            hash_val = random.randint(0, 99)

        cumulative = 0
        for v in versions:
            cumulative += v.traffic_pct
            if hash_val < cumulative:
                return v
        return versions[-1]

    def rollback(self, model_id: str, to_version: str):
        """Rollback to a specific version (100% traffic)."""
        versions = self.models.get(model_id, [])
        for v in versions:
            v.traffic_pct = 100.0 if v.version == to_version else 0.0

    def get_metrics(self):
        cache_rate = self.metrics["cache_hits"] / max(self.metrics["requests"], 1)
        return {**self.metrics, "cache_hit_rate": f"{cache_rate:.1%}"}

# Load Balancer → API Gateway → Model Router → Model Container
# Sidecar: Monitoring, Logging, Feature Store lookup
# Key: Canary deployment (5% → 25% → 100%) with auto-rollback on metric degradation

import numpy as np
from typing import Dict, List
from scipy import stats
from collections import deque

class ModelMonitor:
    """Production model monitoring for drift and degradation."""

    def __init__(self, window_size: int = 1000):
        self.reference_stats = {}
        self.window_size = window_size
        self.prediction_buffer = deque(maxlen=window_size)
        self.actual_buffer = deque(maxlen=window_size)
        self.alerts = []

    def set_reference(self, feature_data: Dict[str, np.ndarray],
                      predictions: np.ndarray):
        """Set reference distribution from training/validation data."""
        for feat_name, values in feature_data.items():
            self.reference_stats[feat_name] = {
                "mean": np.mean(values),
                "std": np.std(values),
                "min": np.min(values),
                "max": np.max(values),
                "distribution": np.histogram(values, bins=50)
            }
        self.reference_stats["predictions"] = {
            "mean": np.mean(predictions),
            "std": np.std(predictions)
        }

    def check_data_drift(self, current_data: Dict[str, np.ndarray],
                         threshold: float = 0.05) -> Dict:
        """Detect data drift using KS test and PSI."""
        drift_results = {}

        for feat_name, current_values in current_data.items():
            if feat_name not in self.reference_stats:
                continue

            ref = self.reference_stats[feat_name]

            # KS Test
            ks_stat, ks_p = stats.ks_2samp(
                np.random.choice(current_values, min(500, len(current_values))),
                np.random.normal(ref["mean"], ref["std"], 500)
            )

            # PSI (Population Stability Index)
            psi = self._calculate_psi(
                ref["distribution"], current_values
            )

            is_drifted = ks_p < threshold or psi > 0.2
            drift_results[feat_name] = {
                "ks_statistic": round(ks_stat, 4),
                "ks_p_value": round(ks_p, 6),
                "psi": round(psi, 4),
                "drifted": is_drifted,
                "severity": "HIGH" if psi > 0.25 else ("MEDIUM" if psi > 0.1 else "LOW")
            }

            if is_drifted:
                self.alerts.append(f"⚠️ Drift in {feat_name}: PSI={psi:.3f}")

        return drift_results

    def check_performance_degradation(self, predictions: np.ndarray,
                                       actuals: np.ndarray) -> Dict:
        """Monitor model performance over time."""
        self.prediction_buffer.extend(predictions)
        self.actual_buffer.extend(actuals)

        if len(self.actual_buffer) < 100:
            return {"status": "insufficient_data"}

        preds = np.array(self.prediction_buffer)
        acts = np.array(self.actual_buffer)

        # Current performance
        accuracy = np.mean((preds > 0.5) == acts)

        # Prediction distribution shift
        pred_mean = np.mean(preds)
        ref_mean = self.reference_stats.get("predictions", {}).get("mean", 0.5)
        pred_drift = abs(pred_mean - ref_mean) / (ref_mean + 1e-6)

        return {
            "current_accuracy": round(accuracy, 4),
            "prediction_mean": round(pred_mean, 4),
            "reference_mean": round(ref_mean, 4),
            "prediction_drift_pct": round(pred_drift * 100, 2),
            "alert": pred_drift > 0.1 or accuracy < 0.7
        }

    def _calculate_psi(self, ref_histogram, current_values, bins=50):
        """Population Stability Index."""
        ref_counts, bin_edges = ref_histogram
        curr_counts, _ = np.histogram(current_values, bins=bin_edges)

        ref_pct = ref_counts / ref_counts.sum() + 1e-6
        curr_pct = curr_counts / curr_counts.sum() + 1e-6

        psi = np.sum((curr_pct - ref_pct) * np.log(curr_pct / ref_pct))
        return psi

# PSI interpretation: <0.1 = stable, 0.1-0.25 = moderate drift, >0.25 = significant
# Monitor: data drift (features), concept drift (relationship), performance metrics
# Automate: alert → investigate → retrain → redeploy pipeline

from typing import Dict, List, Optional, Any
from dataclasses import dataclass, field
from datetime import datetime
import hashlib

class FeatureDefinition:

    description: str

@dataclass
class FeatureGroup:
    name: str
    entity_key: str  # e.g., "user_id", "product_id"
    features: List[FeatureDefinition]
    online: bool = True  # Serve in real-time
    offline: bool = True  # Available for training

class FeatureStore:
    """Simplified feature store for ML training and serving."""

    def __init__(self):
        self.feature_groups: Dict[str, FeatureGroup] = {}
        self.online_store: Dict[str, Dict] = {}  # Fast key-value
        self.offline_store: List[Dict] = []  # Historical data
        self.lineage: Dict[str, Dict] = {}

    def register_feature_group(self, fg: FeatureGroup):
        """Register a new feature group."""
        self.feature_groups[fg.name] = fg
        self.lineage[fg.name] = {
            "created": datetime.now().isoformat(),
            "features": [f.name for f in fg.features],
            "entity_key": fg.entity_key
        }

    def ingest(self, group_name: str, entity_id: str,
               features: Dict[str, Any], timestamp: datetime = None):
        """Ingest features for an entity."""
        ts = timestamp or datetime.now()
        record = {
            "entity_id": entity_id,
            "features": features,
            "timestamp": ts.isoformat(),
            "group": group_name
        }

        # Online store (latest value)
        key = f"{group_name}:{entity_id}"
        self.online_store[key] = {**features, "_ts": ts.isoformat()}

        # Offline store (append for history)
        self.offline_store.append(record)

    def get_online_features(self, group_name: str,
                             entity_ids: List[str]) -> List[Dict]:
        """Get latest features for real-time inference."""
        results = []
        for eid in entity_ids:
            key = f"{group_name}:{eid}"
            features = self.online_store.get(key, {})
            results.append({"entity_id": eid, "features": features})
        return results

    def get_training_data(self, group_name: str,
                           start_date: str = None,
                           end_date: str = None) -> List[Dict]:
        """Get historical features for model training (point-in-time correct)."""
        data = [r for r in self.offline_store if r["group"] == group_name]
        if start_date:
            data = [r for r in data if r["timestamp"] >= start_date]
        if end_date:
            data = [r for r in data if r["timestamp"] <= end_date]
        return data

Key Insight: Feature stores solve the #1 ML production problem: training-serving skew. Same transformation code runs for both batch (training) and real-time (serving). Key components: offline store (S3/HDFS), online store (Redis/DynamoDB), feature registry (metadata), and point-in-time correct joins. 6. Fraud Detection — AI, ML, DS

One-sentence idea: Fraud detection is a rare-event, adversarial, drifting-label problem — the positive class is <1% of data, fraudsters actively adapt to whatever model you deploy, and true labels (chargebacks/confirmed fraud) often arrive weeks after the transaction — so the modeling challenge is as much about data engineering, imbalance handling, and real-time infrastructure as it is about picking an algorithm; GenAI now adds an investigation/reasoning layer on top of the classic ML detection layer.

Key Definitions (read first)

TermPlain-language definition
Class imbalanceFraud is typically 0.1–1% of transactions — accuracy is meaningless (99%+ accuracy by predicting "never fraud"); precision/recall/PR-AUC are the real metrics.
Label latencyThe true fraud/not-fraud label (chargeback confirmed) often arrives days-to-months after the transaction — you must train and deploy before labels are complete, and handle label noise/leakage carefully.
Concept drift (adversarial)Fraud patterns change because fraudsters adapt to your current model, unlike natural drift — this is drift with an adversary actively probing your decision boundary.
Velocity featuresRate-of-activity features (transactions per card per hour, distinct merchants per user per day) — fraud rings show up as bursts, not single anomalous transactions.
PR-AUC (Precision-Recall AUC)Preferred over ROC-AUC under heavy imbalance — ROC-AUC can look great while precision on the positive class is terrible, because it's dominated by the (huge) negative class's true-negative rate.
Cost-sensitive learningWeighting the loss function by the asymmetric cost of errors — a missed fraud (false negative) typically costs far more than a false alarm (false positive), so the model should be penalized accordingly, not treat both errors equally.
SMOTESynthetic Minority Oversampling — generates synthetic minority-class (fraud) samples by interpolating between a real minority sample and its nearest minority neighbors, rather than just duplicating existing ones.
Alert fatigueToo many false-positive alerts overwhelm human fraud investigators, causing them to reflexively dismiss/rubber-stamp alerts — a model that's "accurate" in isolation can still fail operationally by generating unusable alert volume.

Problem framing (what makes fraud detection distinct from generic classification)

  1. Extreme imbalancestandard accuracy/loss functions and even standard train/test splits need adjustment; a model can trivially "win" on accuracy by predicting the majority class.
  2. Adaptive adversaryunlike churn or disease prediction, the "true function" being modeled actively changes in response to your model's deployment (fraudsters test what gets through) — requires continuous retraining, not a "train once, done" mindset.
  3. Label latency & leakage riskwaiting for confirmed chargebacks means training data is always somewhat stale/incomplete; naive feature engineering can leak future information (e.g., "was this transaction disputed" as a feature is leakage if the model is meant to score before a dispute exists).
  4. Asymmetric, business-defined costsa false negative (missed fraud) costs the transaction amount + potential fines; a false positive (blocked legitimate customer) costs customer trust/churn + investigator time — the right operating threshold is a business decision, not a default 0.5 cutoff.
  5. Real-time constraintthe scoring decision (approve/decline/step-up-auth) often must happen in under ~100ms at the point of transaction, which shapes the whole serving architecture, not just the model choice.

Feature engineering — the highest-leverage layer

  • Velocity/aggregation featurescount/sum/avg of transactions per entity (card, device, IP, account) over sliding windows (last 1h/24h/7d): transaction count, total amount, distinct merchants, distinct countries.
  • Entity-graph featuresshared device/IP/address/payment-method across accounts; fraud rings show up as densely connected subgraphs an individual-transaction model can't see (§ graph-based below).
  • Behavioral deviationdistance from the user's own historical pattern (typical spend amount/category/geolocation/time-of-day) — a $2,000 purchase is normal for one user and highly anomalous for another; per-entity baselining beats a single global threshold.
  • Device/session fingerprintingdevice ID, browser fingerprint, IP reputation/geolocation mismatch (billing country ≠ IP country), new-device-for-this-account flags.
  • Merchant/category risk priorshistorical fraud rate by merchant category code, merchant risk tier.

Handling imbalance

  • ResamplingSMOTE (synthetic minority interpolation) or ADASYN oversample the minority class; random undersampling of the majority class; both risk overfitting to synthetic patterns or discarding useful majority-class signal if overdone — often combined (e.g., SMOTE + Tomek links cleanup).
  • Class weighting / cost-sensitive lossclass_weight='balanced' or scale_pos_weight in XGBoost penalizes misclassifying the minority class more heavily, without altering the data itself — often preferred over resampling because it doesn't distort the data distribution the model learns from.
  • Threshold tuning, not 0.5since classes are imbalanced and error costs are asymmetric, pick the decision threshold from the precision-recall curve at the point matching the business's actual cost trade-off, not the default midpoint.
  • Metric choicePR-AUC, precision@k (top-k highest-risk transactions, matching investigator capacity), and recall-at-fixed-false-positive-rate are the metrics that actually mean something under 0.1% positive prevalence; ROC-AUC can be misleadingly high.

Latency optimization for real-time fraud scoring

  • Precompute, don't recomputemaintain velocity/aggregate features as continuously-updated rolling counters in the online feature store (updated on each event) rather than scanning raw transaction history per request; approximate structures (HyperLogLog for distinct counts, count-min sketch for frequency) trade a little accuracy for large speed/memory wins at high cardinality.
  • Model-level optimizationgradient-boosted trees (XGBoost/LightGBM) are already fast at inference, but for the tightest latency budgets: reduce feature count to the highest-importance subset, export to a fast runtime (ONNX/Treelite) instead of the native Python library, and quantize/distill neural scorers the same way as LLM inference optimization (file 22 §1) if a deep model is in the path.
  • Two-tier scoringa very cheap, low-latency first-pass model (or a rules engine) filters the obviously-clean majority of transactions in microseconds; only the harder/ambiguous slice goes to the full-feature, higher-latency model — matches the model-cascading cost lever (§3) applied to latency instead of just cost.
  • Colocate feature store and model servernetwork hops between the online feature store and the inference service are often a bigger latency line item than the model's own compute time; colocation/caching at the edge of the request path matters as much as model choice.

Model validation strategy — why standard k-fold CV is dangerous here

  • Time-based splits, not random k-fold. Fraud data is temporal and patterns drift, so a random split leaks future information into training (a transaction from next month ends up in the training fold, teaching the model patterns it couldn't have known at decision time). Use forward-chaining/time-based cross-validation — train on data up to time T, validate on T+1, roll forward — so validation always mimics the real deployment condition of "predict the future from the past."
  • Backtesting against known fraud wavesreplay the model against historical periods that contained specific fraud campaigns/rings to confirm it would have caught them, not just that it scores well on an aggregate held-out set — aggregate metrics can hide total misses on a specific attack pattern.
  • Champion/challenger deploymentrun a new model (challenger) alongside the live model (champion) scoring the same live traffic without acting on its output, comparing precision/recall/PR-AUC on realized outcomes over weeks before promoting it — because offline validation can't fully capture adversarial adaptation or label latency effects.
  • Shadow mode before full cutoveridentical to the RAG/agent shadow-deployment pattern (§2/§3): the new model's decisions are logged, not acted on, until its real-world performance is confirmed, specifically because fraud's adversarial drift means offline test-set performance is necessary but not sufficient evidence.
  • Drift-triggered revalidationmonitor PSI (Population Stability Index) on key features and the model's score distribution in production; a significant shift auto-triggers a revalidation/retrain cycle rather than waiting for a scheduled quarterly review, since adversarial drift doesn't wait for your calendar (see Model Drift and Degradation for PSI worked examples).

Where GenAI/agentic systems fit on top of classic fraud ML

  • Fraud investigation copilot/agentgiven an ML-flagged case, an agent pulls the account's transaction history, related-entity graph, and prior case notes (RAG over case management + transaction data), summarizes the suspicious pattern in plain language, and drafts the investigator's case notes/SAR (Suspicious Activity Report) filing — cuts investigator time-per-case, doesn't replace the ML score.
  • Anomaly explanationLLM generates a human-readable rationale from SHAP/feature-importance output ("flagged mainly due to: new device + 3x normal transaction amount + billing/IP country mismatch") — improves investigator trust and speed, addressing the classic "black box model" complaint.
  • Multi-agent investigation workflowa supervisor agent routes a case to a retrieval agent (pull related transactions/entities), a risk-scoring tool call (the classic ML model as a tool the agent calls, not replaced by the LLM), and a report-drafting agent — with a mandatory human-approval interrupt before any account action (block/freeze), exactly the HITL pattern from §3/§5.
  • Synthetic fraud data generationLLMs/generative models can help synthesize plausible-but-rare fraud pattern examples to augment training data for pattern types with too few real labeled examples — used carefully, validated against real distributions, not as a wholesale replacement for real data.
  • Adaptive rule/narrative draftingsummarizing emerging fraud patterns from recent case clusters into human-readable analyst alerts faster than a manual rule-writing cycle.
  • Guardrailthe LLM layer should never be the sole decision-maker on blocking an account or a transaction — it's a reasoning/explanation/investigation-acceleration layer on top of the calibrated, auditable ML score, with a human (or a deterministic rule) making/approving the final action, for both accuracy and regulatory-auditability reasons.

Q&A Drill

•

Q1. Why is accuracy the wrong metric for a fraud model, and what do you use instead?

With fraud typically <1% of transactions, predicting "not fraud" for everything already scores ~99%+ accuracy while catching zero fraud. Use PR-AUC, precision/recall at a business-chosen operating threshold, precision@k (matches investigator review capacity), and recall at a fixed false-positive-rate budget instead.

•

Q2. Explain SMOTE and one risk of overusing it.

SMOTE generates synthetic minority-class samples by interpolating between a real fraud example and its nearest fraud neighbors in feature space, rather than duplicating existing rows. Overusing it risks creating synthetic samples in regions that don't correspond to real fraud behavior, causing the model to learn decision boundaries that overfit to artifacts of the interpolation rather than genuine fraud patterns — validate on real, untouched fraud examples, not synthetic ones.

•

Q3. Why is class-weighting sometimes preferred over resampling?

Class weighting changes the loss function's penalty for minority-class errors without altering the underlying data distribution the model sees, so it avoids the distortion risk of oversampling (synthetic pattern overfitting) or undersampling (discarding real majority-class signal) — often a simpler, safer first lever than SMOTE.

•

Q4. What is label latency in fraud detection and why does it complicate training?

Confirmed fraud labels (chargebacks) often arrive weeks after the transaction, so at training time your most recent data has incomplete/optimistic labels (fraud that hasn't been reported yet looks "clean"). This requires either a labeling lag/holdout window before using recent data as ground truth, or explicit modeling of label uncertainty — training on too-recent data without accounting for this silently biases the model toward under-flagging.

•

Q5. Give an example of feature leakage specific to fraud detection.

Using "was this transaction disputed/charged back" or any field only populated after a fraud investigation concludes as an input feature — the model would be scoring using information that doesn't exist yet at the actual decision point (transaction time), producing unrealistically good offline metrics that collapse in production.

•

Q6. Why are graph-based methods particularly suited to fraud, beyond tabular models?

Fraud rings and mule-account networks show up as patterns across entities — shared devices, IPs, or payment methods linking accounts that look individually unremarkable — which a per-transaction tabular model literally cannot see, since it only has features about one transaction/entity at a time. Graph features or GNNs surface these connected-component/community patterns directly.

•

Q7. Why is the feature store often the hardest part of a real-time fraud system, not the model?

Velocity/aggregation features (transactions per card in the last hour) require a continuously-maintained sliding-window computation that must return in milliseconds at request time and must match, exactly, however those same features were computed for training — this is a streaming-infrastructure problem (training/serving skew, low-latency lookups) that's often harder than picking or tuning the model itself.

•

Q8. What's the right way to fold an LLM/agent into a fraud pipeline, and what's the boundary you shouldn't cross?

Use the LLM/agent layer for investigation acceleration — summarizing a flagged case, explaining the ML score's drivers in plain language, drafting investigator notes/SAR filings, and orchestrating retrieval across case/transaction data (RAG + tool-calling the ML model as a scoring tool). The boundary: the LLM should not be the final, sole decision-maker on blocking a transaction or account — that stays with the calibrated ML score plus deterministic rules plus, for high-stakes actions, a human-approval gate (HITL interrupt) — both for accuracy and for regulatory auditability of the decision.

•

Q9. How do you handle concept drift caused by adaptive fraudsters, specifically (vs. natural drift elsewhere in ML)?

Because the drift is adversarial (fraud patterns shift in response to your deployed model), a "retrain periodically on a schedule" approach lags behind an active adversary. Combine continuous/frequent retraining with drift monitoring (population stability index on key features/scores, precision/recall tracked on a rolling window as ground truth arrives), an ensemble of unsupervised anomaly detectors (Isolation Forest/autoencoders) to catch genuinely novel patterns supervised models haven't seen labeled examples of yet, and a fast human-feedback loop from investigators back into retraining data.

•

Q10. What's "alert fatigue" and how does it change what "good" model performance means operationally?

If a model flags far more transactions than investigators can meaningfully review, investigators start rubber-stamping/dismissing alerts reflexively, so a model that's statistically "good" (decent precision/recall) can still fail operationally by exceeding review capacity. This is why precision@k (calibrated to actual investigator throughput) and a tiered response (auto-block only the highest-confidence band, route the ambiguous middle to review, auto-approve the clear-low-risk band) matter as much as the raw metric.

•

Q11. Why is random k-fold cross-validation actively dangerous for validating a fraud model, and what do you use instead?

Random k-fold shuffles time, so folds can contain future transactions in training and past transactions in validation — the model gets credit for "predicting" patterns it could never have seen yet at real decision time, and offline metrics overstate real performance. Use forward-chaining/time-based CV (train on the past, validate on the immediate future, roll forward) so validation always matches the actual temporal constraint of production scoring.

•

Q12. Give two concrete techniques for keeping real-time fraud scoring under a tight latency budget.

(1) Precompute velocity/aggregate features as continuously-updated online counters rather than scanning raw history per request, using approximate structures (HyperLogLog, count-min sketch) at high cardinality; (2) two-tier scoring — a cheap fast pass (rules or a lightweight model) clears the obviously-clean majority in microseconds, reserving the full-feature/heavier model for the ambiguous minority that actually needs it.
