Agentic AI Scenario-Based Questions — Part 1 (Q1–Q50)

Q1. Scenario: You're designing a multi-agent system for customer support that handles billing, technical, and general inquiries.

QuestionAnswer

Question: How do you design the router agent to classify and dispatch user queries to the correct specialist agent? Answer: Implement a router agent with an LLM-based classifier that analyzes user intent from the query. Use few-shot examples for each category, structured output (JSON with category and confidence), and fallback rules. Include a confidence threshold — queries below 0.7 confidence go to a general agent or request clarification. Add keyword-based pre-filtering for efficiency (e.g., "invoice", "payment" → billing). Log routing decisions for evaluation and retrain the classifier monthly on misrouted queries.

Q2. Scenario: Your agentic system makes API calls to external services, but one service has rate limits of 100 requests/minute.

QuestionAnswer

Question: How do you handle rate limiting in an agent that needs to make many external API calls? Answer: Implement a rate limiter middleware with token bucket algorithm, queue excess requests with exponential backoff, batch multiple agent requests into single API calls where possible, cache responses to avoid duplicate calls, implement circuit breaker pattern (stop calling after repeated failures), and use async execution to process other tasks while waiting. Add retry logic with jitter to prevent thundering herd. Monitor rate limit headers from API responses to adapt dynamically.

Q3. Scenario: Your AI agent performs web research but sometimes returns hallucinated URLs and fake citations.

QuestionAnswer

Question: How do you ensure the agent only returns verified, real information from web research? Answer: Implement verification steps: validate URLs with HTTP HEAD requests before returning, cross-reference facts across multiple sources, use structured search APIs (Google Search, Bing) rather than relying on LLM memory, extract and cite actual page content with timestamps, implement a fact-checking agent that verifies claims against retrieved documents, flag confidence levels for each claim, and never generate URLs from memory — only return URLs actually retrieved during the search process.

Q4. Scenario: You're building an agent that writes and executes Python code to analyze data, but code execution poses security risks.

QuestionAnswer

Question: How do you sandbox code execution in an agentic system safely? Answer: Use Docker containers with resource limits (CPU, memory, network disabled), restrict allowed imports to a whitelist (pandas, numpy, matplotlib — no os, subprocess, socket), set execution timeouts (30 seconds max), run as non-root user with read-only filesystem except for output directory, use gVisor or Firecracker for additional isolation, implement output size limits, scan generated code for dangerous patterns before execution, and maintain separate execution environments per user session.

Q5. Scenario: Your multi-agent system has a planning agent, a research agent, and a writing agent, but they produce inconsistent outputs.

QuestionAnswer

Question: How do you maintain coherent shared state across multiple agents in a pipeline? Answer: Implement a shared state object (like LangGraph's State) that all agents read from and write to with structured schemas. Use typed dictionaries with clear field ownership (planner writes "plan", researcher writes "findings", writer writes "draft"). Implement state validation between agent transitions, immutable state history for debugging, and version tracking. Each agent should receive only the state fields it needs (principle of least privilege) and declare its output schema explicitly.

Q6. Scenario: Your agent tends to get stuck in loops, repeatedly trying the same failed action.

QuestionAnswer

Question: How do you detect and break agent loops in an autonomous system? Answer: Implement loop detection: track action history and detect repeated action sequences (same tool + same args within last N steps), set maximum iteration limits per task (e.g., 10 steps), implement a "reflection" step that triggers after 3 consecutive similar actions, add escalation logic (after K failures, try alternative approach or escalate to human), use a decreasing temperature to change behavior on retries, and implement a watchdog timer that terminates runaway agents. Log all actions for post-mortem analysis.

QuestionAnswer

Question: How do you implement persistent memory for an agentic system across sessions? Answer: Implement tiered memory: short-term (current conversation in context window), medium-term (session summary stored in database, loaded on reconnect), long-term (user preferences, past decisions, key facts stored in vector DB or knowledge graph). Q14. Scenario: Your multi-agent system needs agents to communicate and collaborate on complex tasks.

QuestionAnswer

Question: What communication patterns work best for multi-agent collaboration? Answer: Common patterns: (1) Hub-and-spoke — supervisor agent delegates to specialists and aggregates results. (5) Blackboard — shared workspace where agents contribute independently. Q21. Scenario: Your agent executes a 5-step workflow but step 3 fails. You want to retry from step 3, not restart from step 1.

QuestionAnswer

Q22. Scenario: Your agent generates SQL queries but the generated SQL sometimes has syntax errors or returns wrong results.

QuestionAnswer

Question: How do you validate and self-correct agent-generated SQL? Answer: Multi-step validation: (1) syntax check — parse with sqlparse to catch syntax errors, (2) dry run — use EXPLAIN to validate without execution, (3) schema validation — verify referenced tables and columns exist, (4) result validation — check if results are reasonable (row count, data types, null ratios), (5) self-correction loop — if query fails, feed error message back to agent for correction (max 3 retries). Add few-shot examples of correct SQL for the specific schema, include schema information in the prompt, and log successful queries as future examples.

QuestionAnswer
